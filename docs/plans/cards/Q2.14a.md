# Q2.14a: flip readiness as a number

- goal: a number for "is `DWELLER_PROCESS=site` ready to be the default" (Q2.14). A scheduled CI job, not required, runs the whole browser suite with `DWELLER_PROCESS=site` in the environment and prints passed over total and the failing names. A test that sets the variable itself is not changed. The count is the flip's burn-down; each failing group becomes a row of the readiness list.
- design: `.github/workflows/site-mode.yml` (`site-mode`), on `schedule` (`41 5 * * *`, daily, clear of `fuzz` at 03:23 and `conformance` at 03:17 Monday) and `workflow_dispatch`.
  - job `shard`: four Ubuntu shards, the same split as `ci.yml` (`tests/browser-times.txt`, Linux column). The setup steps are copied from `ci.yml` with its cache keys, so a run on `main` restores the ANGLE, wasmtime and `aye` caches that `ci` saved. The test step sets `DWELLER_PROCESS=site` and runs `.github/scripts/site-mode-shard.sh run SHARD 4`.
  - `site-mode-shard.sh run` runs the shard's tests once. It does not use `browser-shard.sh`, because that script re-runs failed tests and would turn a failure into green. It reads the `test NAME ... ok|FAILED` lines between `running N tests` and the failure report (so output that a failed test printed is not counted), writes `target/site-mode/ok.txt` and `failed.txt`, and checks them against the `test result:` line. Failing tests exit 0. The exit is 1 only when there is no `test result:` line (the build broke or the test binary died) or the counts do not agree. The two lists go up as the artifact `site-mode-N`.
  - job `count` (`if: always()`): downloads the artifacts and writes `site-mode-shard.sh summary 4 DIR` to `$GITHUB_STEP_SUMMARY`: `passed / total`, how many shards finished, and the failing names, sorted, under one heading per prefix up to the second underscore (`window_renderer`, ...). It is then red when a shard did not finish.
- files: `.github/workflows/site-mode.yml`, `.github/scripts/site-mode-shard.sh`, `docs/plans/cards/Q2.14a.md` (new)
- verify: `ruby -ryaml -e 'YAML.load_file(".github/workflows/site-mode.yml")'`, `actionlint`, `bash -n` on the script and `python3 browser/tools/check_taste.py` pass. The script was run offline against a fake `cargo` with libtest logs: 3 ok + 3 FAILED gives `5 / 8 passed` over two shards, grouped; a log with no `test result:` line, or with counts that do not agree, exits 1. On CI, after the merge: `gh workflow run site-mode`, and the `count` job's summary shows the count on `main`.
