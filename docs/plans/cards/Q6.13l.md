# Q6.13l: the test262 runner and `import()`, modules that import themselves

- goal: two clusters of `test262/language` that fail in the runner, not in the engine: "Failed to fetch module" (210) and "assert is not defined" / "$DONE is not defined" in module tests (about 100).
- cause:
  - a script test was written to a temporary file in the system's temporary directory, so `import('./x_FIXTURE.js')` resolved there and found nothing;
  - a module test was written, with the harness in front, to a temporary `.mjs` next to the test. A test that imports itself by its own name then loaded the original file: a second module instance, without the harness.
- design (`browser/tools/test262.py`, `Runner.run_one`):
  - a script whose source has `import(` gets its temporary file next to the test;
  - a module runs at its own path: `dweller js --test262-module TEST`, with the harness files in a temporary script named by `DWELLER_TEST262_HARNESS`, which the engine runs as a classic script first (`browser/js/t262-harness.aye`), so `assert`, `$DONE` and the rest are globals of the realm, as INTERPRETING.md of test262 describes the host.
  - `browser/main.aye` and `js.aye`: the `--test262-module` form (a module whatever its extension). The usage line is unchanged: `cli::errors` pins it, and the flag is the runner's.
- no test is skipped or loosened: the judge is unchanged, only where the files are and how the harness is installed.
- files: `browser/tools/test262.py`, `browser/main.aye`, `browser/js/js.aye`, `browser/js/t262-harness.aye` (new).
