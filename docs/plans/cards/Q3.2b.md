# Q3.2b: CORS preflight, its cache, and redirects in CORS mode

- goal: a cross-origin `fetch` or XHR with a method or header outside the CORS safelist works the way Fetch and Chromium say. net sends an `OPTIONS` preflight first and checks it, caches the result, and checks each redirect of a CORS request. Before this step (Q3.2a), such a request was not sent and failed as a network error.
- cause: Q3.2a moved the CORS check into `net/` but did not add a preflight. That cost 18 WPT `xhr` subtests, and real sites that send JSON `Content-Type` or custom headers cross-origin did not work.
- design:
  - `needsPreflight` (was `corsSendable`, Chromium `NeedsPreflight`): the request is cross-origin in mode `Cors` and its method or a header is not safelisted (`corsSafelisted`).
  - `preflight` (`net/preflight.aye`, https://fetch.spec.whatwg.org/#cors-preflight-fetch): `OPTIONS` through `request` with `Access-Control-Request-Method` and, when there are any, `Access-Control-Request-Headers` (`unsafeHeaderNames`: lower case, sorted, unique), credentials `Omit`. The response must be 2xx and not redirected, pass `corsCheck` with the request's credentials, and allow the method and headers (`preflightAllows`, Chromium `PreflightResult::EnsureAllowedRequest`: safelisted methods always pass; `*` only without credentials; `authorization` is never covered by `*`). A failed preflight is `FetchError.Network`, and the real request is not sent.
  - Cache (`PreflightCache` in `Session`, per process until net moves to the browser process in Q2.4): key = origin, URL and `include`. A result is kept for `Access-Control-Max-Age` (`preflightMaxAge`: 5 s by default, 7200 s at most, Chromium's limits). A hit that allows the request skips the preflight. A new result replaces the old one.
  - Redirects (`corsRedirect`, https://fetch.spec.whatwg.org/#http-redirect-fetch), in http.aye `transfer` and in the loader's `finishRequest`: the 3xx response of a cross-origin hop must pass `corsCheck`. A cross-origin location with credentials fails. A hop to another origin from a URL that is cross-origin to the page taints the origin to `null` (`Response.tainted` for the synchronous path; the loader clears the request's initiator). The new URL gets its own preflight when it needs one.
  - `corsCheck` now takes the URL and the header lines (it also checks a redirect hop). `corsChecked` uses the `null` origin for a tainted response.
  - `sharedBusy`: a preflight that runs while a synchronous request waits on the loader's multi handle uses a new easy handle, not the session's handle that is in use.
  - JS: XHR `responseURL` was "" for an asynchronous request without a redirect (`fetchTake` gives no URL). Because of this, `Access-Control-Expose-Headers` filtering was skipped for every asynchronous cross-origin XHR. `responseURL` now falls back to the resolved request URL. `corsFiltered` drops `set-cookie` and `set-cookie2` also when they are listed. A synchronous XHR with a network error now throws `NetworkError` from `send()` (XHR standard).
- not done: the XHR "upload has listeners" preflight flag (Dweller has no `XMLHttpRequest.upload`). The `Origin` header of a tainted request is still the page's origin, not `null`. The preflight sends the page's full URL as the Referer, not the URL that the referrer policy gives (`cors-preflight-referrer`, 0/12). The response type is not `cors` for a same-origin final URL that was reached through a cross-origin redirect (JS does not know about the taint). The value checks of `accept`, `accept-language` and `content-language` (`cors-preflight-not-cors-safelisted`). Rejection of a malformed `Access-Control-Allow-*` list (`cors-preflight-response-validation`). The cache expires on the wall clock, so `access-control-basic-allow-preflight-cache-timeout` fails under `dweller wpt`'s virtual clock.
- files: `browser/net/{preflight,preflight-allows,preflight-cache,preflight-result,preflight-index,preflight-max-age,unsafe-header-names,next-unsafe-name,bytes-before,token-listed,cors-redirect,shared-busy}.aye` (new), `browser/net/needs-preflight.aye` (was `cors-sendable.aye`), unit tests `browser/net/{needs-preflight,preflight-allows,preflight-cache,unsafe-header-names}_test.aye`, `browser/net/{cors-check,cors-checked,net,http,loader,session}.aye`, `browser/engine/{prelude.aye,fetch-api.js}`, `browser/tests/server.py` (`/preflight/NAME`), `browser/tests/net/cors-preflight.{html,txt}` (new), `browser/tests/net/cors.{html,txt}`, `tests/browser.rs` (`cors_preflight`), `docs/browser.md`.
- verify: `cors_preflight` (from `127.0.0.1` to `localhost`: a PUT with `x-test` is preceded by exactly one OPTIONS; the same PUT again sends no OPTIONS; a denied preflight leaves the PUT unsent; a redirect is preflighted again at the new URL; a redirect to a URL with credentials fails; the same for synchronous XHR). The fetch, xhr, jsdom, samesite and cors tests in one run. `aye test browser`, `aye check browser`, `check_taste.py`. WPT `fetch/api` and `xhr`.
