# Q2.7: site-lock audit of the renderer's messages

- goal: with `DWELLER_PROCESS=tab`, every renderer→browser message that names or implies a site is checked against the browser's own record (the renderer's site lock `tp.site` from Q2.6b, and the top URL it committed, `topOf(tp)`); a message outside it kills the renderer through the one bad-message path (`takeMessages` → `badMessage`: `bad message: REASON PID` on stderr, `dropTabProcess`, the Q2.5 sad tab). Without the flag nothing changes.
- design:
  - `ui/in-site-lock.aye` `inSiteLock(tp, href)`: the site of `href` (`writeSite`: scheme + eTLD+1, `file:` for every file URL, nothing for `data:`, `about:`, `blob:` and other schemes) is empty, or the lock, or the site of the browser's committed top. A siteless URL passes, as `about:blank` and `data:` inherit or are opaque (the reference: `CanAccessDataForOrigin` looks at the precursor of an opaque origin; Dweller's opaque documents are in their creator's renderer). The top's site is part of it only for agent navigations, which still commit across sites in the current renderer (Q2.6b Left); for every other commit the top's site is the lock.
  - the renderer never names an origin: cookies, storage and fetches name a document index (`doc`) that the browser gave in `FetchHead`; the browser takes the URL from its own `tp.docs`. So the check is on that recorded URL, never on a field of the message.
  - new kills: `loaded` while a navigation is open whose URL is outside the lock (`commit outside site lock`; the reference: `CanCommitURL`) unless the browser itself failed that navigation's fetch (`tp.nav_failed`, set by `answerFetch` on a network error and by `failSwap`; cleared by `beginNavigation` and `queueNavigate`), because an error page commits the URL it could not load in the current renderer; `cookie_get` and `cookie_set` on a document outside the lock (`cookie outside site lock`); `storage` on a document outside the lock (`storage outside site lock`).
  - until Q2.9 a cross-site iframe lives in its parent's renderer, so a real page has documents of other sites in `tp.docs`. The renderer therefore no longer asks for their cookies or storage (`renderer/store-doc.aye` returns no document when `outsideTop`: an http(s) document whose scheme or site differs from the top it navigated to, `r.top`, recorded from the navigation's `FetchHead`): `document.cookie` is empty and a set is dropped (what the jar already did for a third-party frame: Dweller blocks third-party cookies), and `localStorage`/`sessionStorage` of a cross-site frame read nothing and keep nothing. Before this card a renderer could read any site's `localStorage` by loading it in a frame. Only a compromised renderer asks, and it is killed.
  - fetches of a cross-site frame still name that frame (its own initiator, `Origin`, `Sec-Fetch-Site`), because a real frame makes them; the browser still pins `top` (`topClaimed`), the referrer, the method and the headers, and the cookie context comes from the browser's top, so a cross-site frame's request carries no cookies.
  - compromise hooks: `DWELLER_TEST_EVIL=site` (the renderer asks for a cross-site frame's cookies or storage) and `commit` (on a `navigate` to another site than its top, the renderer reports `loaded` for it at once, without fetching), only honoured with `DWELLER_TEST=1` (`renderer/evil-test.aye`). The earlier hooks the test reuses (`initiator`, `pushstate`) are unchanged.
- message table (`ipc/from-renderer.aye` lists the 20 renderer→browser types; `ui/renderer-sent.aye` checks them). Every message first: decoded well formed (`decode-error`, else kill with the error's name), a renderer type (`not from a renderer`), and on the tab's frame (or frame 0 for `hello` and `pong`).

| Message | Names a site? | What the browser checks (card) | Failure |
|---|---|---|---|
| `hello{version, pid}` | no | first message only, frame 0, the version, the pid it spawned (Q2.2a) | kill `unexpected hello` |
| `loaded{title, url}` | the committed URL | a navigation is open (or an agent's), the URL is the one navigated to, its document, or its origin (`commitMatches`, Q2.3d/Q2.6a); an agent commit `agentCommitAllowed`; new: in the site lock unless the browser failed the navigation (Q2.7) | kill `bad url`, `commit outside site lock` |

| `same_document{url, index, nulls, state}` | the new URL | no navigation open, same origin as the committed URL (so in the lock, since the commit was), the entry index and state (Q2.6a) | kill `bad url`, `bad same_document` |

| `agent_reply{id, answer}` | no | the request id is open for this renderer (Q2.3b) | kill `bad agent_reply` |
| `fetch{doc, nav, url, referrer, top, headers, ...}` | the initiator (as `doc`), `top`, `referrer` | the ids in order; `doc` is a document the browser recorded; `nav` only for the URL the browser is navigating; `top` same site as the browser's top; the referrer same origin as the document; method and headers allowed (no `Cookie`, `Origin`, `Sec-*`, `Host`) (Q2.4a, Q2.4d); the initiator's scheme rules (`file:`) give a network error; a navigation's response outside the lock swaps the renderer (Q2.6b) | kill `bad fetch` |

| `cookie_set{doc, line}` | the document | as `cookie_get` | kill `bad cookie`, `cookie outside site lock` |
| `storage{doc, context, session, op, ...}` | the document | `doc` recorded, the op known (Q2.4b); new: the document is in the lock (Q2.7); the area's origin comes from the recorded URL | kill `bad storage`, `storage outside site lock` |
| `pong{n}` | no | frame 0, a ping open, the same `n` (Q2.5) | kill `bad pong` |

## Status: done, 2026-11-08

Left:
- Q2.9: a cross-site frame in its parent's renderer gets no cookies or storage under the flag (in-process mode: unchanged). Chromium partitions a third-party frame's storage by the top site instead; with OOPIFs the frame gets its own locked renderer and the question goes away.
- agent navigations (`agent_acts`): a cross-site one commits in the current renderer and moves the browser's top there, so `inSiteLock` accepts the top's site too; while an agent acts, `fetchNavigates` lets the renderer fetch any http URL as a navigation (`agentCommitAllowed`), with the browser's credentials. The agent path should swap renderers as Q2.6b does.
- the earlier `DWELLER_TEST_EVIL` hooks (`url`, `pushstate`, `initiator`, `cookie`, `storage`, `frame`, `ack`, `agent`, `malformed`, ...) are not gated by `DWELLER_TEST=1`; the new ones are. Gating the old ones means adding `DWELLER_TEST=1` to their tests.
- a renderer whose first navigation it reports without fetching commits that (browser-chosen) URL: it has no lock yet and the top is the URL itself. It gets no other site's data from this.
- `blob:` URLs have no site in `writeSite` (Chromium uses the inner origin), so a `blob:` document passes `inSiteLock`; its cookies and storage then use its own URL's origin.
