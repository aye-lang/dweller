# Q1.10e: nightly fuzz job, corpus kept, crashes filed as issues

- goal: every night CI runs each `dweller fuzz` target for 10 minutes on Ubuntu, keeps its corpus between runs, and turns a crash into an artifact plus a `fuzz` issue (one per crash signature, later hits comment on it). The job is green when nothing crashed.
- design:
  - `dweller fuzz --list` prints the registered targets one per line (`browser/fuzz/list-targets.aye`), so the workflow reads its matrix from the binary and a new target (Q1.10b–d) runs without a workflow edit.
  - `.github/workflows/fuzz.yml`: `schedule` (03:23 UTC) and `workflow_dispatch` with `seconds` (default 600) and `plant` (default 0). Job `targets` sets up and builds the way ci.yml does (`setup-ubuntu.sh`, ANGLE and wasmtime caches, the pinned aye from `AYE_REV`, `browser/build.sh target/dweller-fuzz`), then turns `fuzz --list` into a JSON list. Job `fuzz` is a `fail-fast: false` matrix over that list; it builds again (about 40 s), then runs `browser/tools/fuzz.py run TARGET --minutes SECONDS/60 --corpus target/fuzz-corpus/TARGET --report ...`.
  - corpus: `actions/cache/restore` with key `fuzz-corpus-TARGET-RUNID-ATTEMPT` and restore-key `fuzz-corpus-TARGET-` (the newest earlier run), then the repository seeds `browser/tests/fuzz/TARGET/*` are copied over it (the seeds win; files only the cache has stay), and `actions/cache/save` stores it again even when the fuzz step failed. The driver is blind (Q1.10a2 waits on aye-lang/aye#26), so today the kept corpus equals the seeds; when coverage lands, the inputs the driver adds to that directory carry to the next night with no workflow change.
  - `fuzz.py` gained `--corpus DIR` and `--report FILE` (the unique crashes as JSON: key, message, hits, minimized input).
  - on a crash the step exits 1, `crashes/` is uploaded as artifact `fuzz-crashes-TARGET`, and `.github/scripts/fuzz-file-issues.py` files `fuzz TARGET: KEY` (KEY is fuzz.py's crash key: the panic's `file:line:col`, else the panic text, the signal or `timeout`, cut to 100 characters) with the label `fuzz`, or comments on the open issue with exactly that title (`gh issue list --label fuzz --search 'in:title "KEY"'`). Token: the workflow `GITHUB_TOKEN`; top-level `contents: read`, the fuzz job adds `issues: write` only.
  - planted crash: `.github/scripts/fuzz-plant.sh` (run only when `plant=1`, never committed into the source) makes the HTML target slice past its input when the input contains `<noembed>`, a dictionary token that no seed contains, so only a mutant reaches it. A planted run does not save the corpus.
