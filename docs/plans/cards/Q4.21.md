## Q4.16a estimates that are now wrong

- Q4.16b (done): matched on mistral, `metric` 152 → 10 µs a call (87 ms for 8714). It does not cover zol, where `metric` is 770 µs because layout is dirty (cost 1).
- Q4.16c: still about right. `canvasDraw` is 7.9 ms a frame (was 9.3); half of it is `drawImage` sampling and compositing, a fifth path fill.
- Q4.16d (done, bbc −700 ms): not measurable on its own; bbc's VM time halved (5410 → 2629 ms) mostly because core-js stopped running. The `<deduplicated_symbol>` is now hot in engine code (cost 3), not in the VM.
- Q4.16e (done, bbc −250 ms): ~10 ms.
- Q4.16f (done, bbc −250 ms): the `concat` polyfill is gone (native `concat` 26 ms); its share is inside the halving above.
- Q4.16g (done, bbc −300 ms, mistral −0.5 ms a frame): right for bbc (the replace wrapper is gone), wrong for mistral: axept's core-js still replaces built-ins (cost 10).
- Q4.16h (bbc −220 ms): now ~60 ms. `call` misses 908k (kinds 2 and 5) at ~60 ns.
- Q4.16i (bbc −150 ms): now ~100 ms (2.13M primitive-receiver loads); zol ~40 ms (`toLowerCase` 760k).
- Q4.16j (bbc −70 ms): now ~25 ms (array `length` 524k); zol ~55 ms (1.08M).
- Q4.16k (mistral −1 ms a frame): wrong cause and size. The sort has no comparator; the cost is a number-to-string conversion with `snprintf` on each compare, 2.7 ms a frame, not the comparator call through `callAt`.
- Q4.16l (bbc −400 ms): now ~160 ms (`ruleObject` 104, `selectorText` 60).

## Ranked next steps (expected saving on the real sites)

1. new (proposed Q4.16n): `ImageCache` finds an entry by a hash map from href, and `fillImagesWith`/`prefetchImages` skip image elements whose chosen URL did not change since the last fill. Files: `browser/engine/images.aye`. Expected: zol −1800 ms per 10 s of scroll (`images` 18.7 → ~2 ms a layout; it is 43 ms of every scroll frame on average), mistral −300 ms per 10 s. Evidence: cost 3, and `fillImagesWith` 297 of mistral's relayout (cost 4). Verify: zol `images` phase ms; W7 zol p95.
2. Q4.6 follow-up (proposed Q4.6c): forced reads on zol. (a) `relayoutDirty` compacts the box tree, or drops only the dirty subtrees, instead of a full layout at `relayout:dropped`: −1100 ms per run (cost 5); (b) then the incremental relayout per read (1476 × 2.2 ms): find which script writes between reads (`DWELLER_LAYOUT_WHY` shows `relayout` with no other reason). Evidence: cost 1 and 5. Verify: `layout_full` count and `script_layout` ms on zol.
3. Q4.16c (canvas `drawImage` rows premultiplied, no per-pixel `mix`/`premul`; add path fill to its scope): mistral −1500 ms per 10 s (half of cost 2). Evidence: cost 2.
4. Q4.16k re-scoped: a sort with no comparator converts each element to a string once, not on each compare (V8 `third_party/v8/builtins/array-sort.tq`, `SortCompareDefault`), and `formatNumber` gets a shortest-digits algorithm instead of the `snprintf`/`strtod` loop (Grisu, V8 `src/numbers/fast-dtoa.cc`, BSD). Mistral −900 ms per 10 s (−2.6 ms a frame). Evidence: cost 6.
5. new: mistral's idle relayout. `layoutShared` skips `loadWebFonts` and `fillImagesWith` when no font face and no image changed (−590 ms per 10 s), then find why every animation frame relays out (Q4.15b: 1714 ms per 10 s). Evidence: cost 4.
6. new: find why axept's core-js replaces `endsWith`, `trim` and the classof path on mistral (the Q4.16g method: `target/dweller js` with core-js's feature tests). −350 ms per 10 s. Evidence: cost 10.
7. new: an inline cache for DOM wrapper properties (kind 6 on DOM objects: `getAttribute`, `ownerDocument`, `nodeType`, `className`): zol −250 ms per run. Evidence: cost 7.
8. Q4.16l: bbc −160 ms per run.
9. Q4.16i: bbc −100 ms per run, zol −40 ms.
10. Q4.16h: bbc −60 ms per run, mistral −0.1 ms a frame.
11. Q4.16j: zol −55 ms, bbc −25 ms per run.
