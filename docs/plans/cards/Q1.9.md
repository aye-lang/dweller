# Q1.9: session restore

- done: the window's tabs (each tab's entry URLs, current entry and title) and the selected tab come back in a window started again on the same profile, after a clean quit or a SIGKILL. `window_session_restore_after_kill` kills a window (two tabs: one with two entries, back on the first; the second shown) once its session file holds that state, starts it again three times and checks the shown tab, `history N of M` and `tabs 2, showing K` (the first tab on entry 1 of 2, then forward to entry 2). `window_session_restore_after_quit` does the same after a run that ends normally, then checks that `DWELLER_RESTORE=0` starts fresh and that a torn file (its first half) starts a new tab and logs `the saved session is unreadable: starting with a new tab`.
- reference read: `components/sessions/core/session_service_commands.cc` (the commands per tab: navigation entries, selected index, selected tab in window; restore builds tabs from them) and `command_storage_backend.cc` (an append-only command log with a header and a version, rewritten from scratch on a schedule, read on start; a truncated last record is dropped).
- format: one file, `<profile>/session`, written whole by atomic replace (`net.writeAtomic`: temp file, fsync, rename), not an append log. The state is a few hundred bytes and the profile code already writes its files that way, so a crash leaves the old file or the new one; an append log pays off only for large state (many windows and long histories) and needs compaction and per-record checksums. A torn or foreign file is still checked on read: a `dweller-session 1` header, then the selected tab's index, then per tab `tab CURRENT COUNT`, its title line and COUNT URL lines, then `end`; any mismatch (missing `end`, an index out of range, a bad number) rejects the whole file. Titles have control characters replaced by spaces.
- when: the window's loop encodes its tabs each iteration and writes when the bytes changed and at least 500 ms passed since the last write (the idle wait is at most 1 s, so a change is on disk within about 1 s); on quit it writes at once. Entries restore as plain URLs loaded with GET: no form state, scroll offset, `history.state` or POST body (as the reference, which never resubmits). The selected tab loads at start; the others load when first shown (`TabSlot.unloaded`). A URL on the command line opens in a new tab after the restored ones.
- where: `browser/sessions/` (model-agnostic: `SavedWindow`/`SavedTab`, `encodeSession`, `decodeSession`, `openSessionFile`, `savedSession`, `saveSession`); the wiring is `ui/save-tabs.aye` and `ui/restore-tabs.aye`. Per window, not per Space: a Space is an agent's process without a profile of its own (it shares the window's jar), so only the person's tabs are saved.
- switch: on in the person's window when its profile is writable (a second window on a held profile neither restores nor saves); off in headless test windows unless `DWELLER_RESTORE=1`; `DWELLER_RESTORE=0` turns it off. `dweller open` now works without a page (the window restores or opens an empty tab); the usage reads `[FILE|URL]`.
- Left:
  - `DWELLER_PROCESS=tab` (PR #331) neither saves nor restores: it should build a `SavedWindow` from the browser's history model and fill the tabs from `decodeSession`.
  - A tab that was never shown since the restore shows its URL in the tab strip, not its saved title, and the next save writes that URL as its title.
