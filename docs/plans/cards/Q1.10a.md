# Q1.10a: fuzz harness and the HTML parser target

- goal: `dweller fuzz TARGET` runs a parser on mutated inputs in process, `browser/tools/fuzz.py run TARGET --minutes M` collects, de-duplicates and minimizes its crashes, and the HTML parser is the first target. Adding a target (Q1.10b–d) is one small file.
- cause: the shipped build is `--mode safe`, so an out-of-bounds access panics with a line, but nothing fed the parsers hostile bytes; there was no fuzzing in the repo.
- coverage: blind mutation. Aye has no coverage instrumentation or fuzzing story (`aye help`, the Aye docs); `--cflags` could pass `-fsanitize-coverage=trace-pc-guard`, but the callbacks and a corpus that grows on new edges are their own step, and Apple's clang ships no libFuzzer runtime. So the corpus does not grow; mutants are stacks of 1–8 mutations of the seed files.
- design:
  - `browser/fuzz/`: `fuzz-main.aye` (arguments; `--seconds` default 60, `--corpus` default `browser/tests/fuzz/TARGET`, `--seed` default the clock), `fuzz-loop.aye` (runs each corpus file once, then mutants until the time is up; writes each input to `target/fuzz/TARGET/current` before parsing it), `mutate.aye` (bit flip, random byte inserted, range deleted, splice with another corpus file, dictionary token inserted), `rng.aye` (splitmix64), `load-corpus.aye`, `target.aye` (`Target {name, dictionary, run}`), `targets.aye` (the registry), `html-target.aye` (the HTML dictionary and `fuzzHtml`: `html.parse`, then `html.parseWith("<body>" + input, false)` as `innerHTML` parses). `--seconds 0` only runs the corpus: the driver replays one input that way. `main.aye` only wires `fuzz`.
  - `browser/tools/fuzz.py run TARGET --minutes M [--binary target/dweller-fuzz]`: builds the binary when missing, restarts it after each crash, keys a crash by the panic's `file:line:col` (else the panic text, the signal, or `timeout`), keeps the first input of each key under `target/fuzz/TARGET/crashes/<hash>` with `<hash>.txt`, minimizes it by deleting byte ranges (delta debugging, at most 300 tries) into `<hash>.min`, prints one line per unique crash; exit 0 without a crash, 1 with one.
  - seed corpus `browser/tests/fuzz/html/`: 86 files, 16.6 KB: the 45 parser fixtures of `browser/tests/*.html` and 41 cases from html5lib `tree-construction` (`tests1`, `template`, `tests26`, `adoption01`, `tables01`, `svg`, `math`, `foreign-fragment`, ...).
- files: `browser/fuzz/*.aye` (new), `browser/fuzz/mutate_test.aye` (new), `browser/main.aye`, `browser/tools/fuzz.py` (new), `browser/tests/fuzz/html/` (new), `docs/browser.md` (section "Fuzzing"), `docs/plans/cards/Q1.10a.md` (new)
- verify:
  - `aye check browser` and `aye test browser` pass (159 passed, 16 modules; the new `fuzz` tests: the same seed mutates to the same bytes, and the seeds reach token inserts, splices and deletes).
  - planted crash (an out-of-bounds read on inputs containing `<plant>`, the token added to the dictionary; not committed): a 1 min driver run reported 1 unique crash at `browser/fuzz/html-target.aye:29:22` (1548 hits), saved the input and minimized it from 64 bytes to the 7 bytes `<plant>`; exit 1.
  - `fuzz.py run html --minutes 10` (safe build): 8,557,589 inputs, 14,262 inputs/s, 0 crashes, exit 0, peak 33 MB.
  - `python3 browser/tools/check_taste.py` exit 0.
- crashes: none found, none fixed, none filed.
- follow-ups: coverage guidance (`-fsanitize-coverage=trace-pc-guard` through `--cflags`, a growing corpus) if blind runs stay clean while bugs are found elsewhere; the fragment path covers the default (`<body>`) context only, not the table/select contexts of `engine/markup.aye` `parseFragment`.
