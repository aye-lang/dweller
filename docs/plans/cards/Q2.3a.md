# Q2.3a: mouse, wheel, keys and scrolling in the renderer

- goal: with `DWELLER_PROCESS=tab`, the page's input goes to the tab's renderer: mouse move, down, up (with click, hover, contextmenu, auxclick, dblclick), leave, the wheel, keys and typed text. The renderer scrolls the page and its inner scrollers, paints at the scroll offset and sends the damage. The window still keeps its own copy of the page (Q2.3c removes it), but it no longer acts on the input it forwards. The browser checks every new message from the renderer and kills it on a bad one. Without the flag nothing changes.
- design:
  - IPC messages added (type codes in order, all on the tab's frame id): 8 B→R `mouse{seq, kind, x, y, mx, my, button, buttons, mods, clicks}` (kind 0 move, 1 down, 2 up, 3 leave; `button` is the DOM button, `mods` the DOM modifier bits); 9 B→R `wheel{seq, x, y, dx, dy, precise}` (CSS px, after the window's `wheel` steps and its coalescing per loop iteration; x = y = -1 when the mouse is not over the page); 10 B→R `key{seq, down, key, code, repeat, location, mods}` (DOM `key` and `code`, so the renderer needs no SDL key table); 11 B→R `text{seq, text}`; 12 R→B `input_ack{seq}` (every input up to `seq` is handled and its frame sent). Coordinates are the tab's viewport, in CSS px.
  - the browser's checks (`rendererSent`; a failure logs `bad message: REASON PID` and kills, as Q2.2a): `input_ack` on the tab's frame id, its `seq` after the last acked and not past the last sent (`unexpected input_ack`); a `frame`'s `scroll_x`/`scroll_y` are now read: finite, 0 or more, under 1e9 (`ipc.badScroll`, `bad scroll`). The renderer exits on a `mouse` kind over 3, as on any message it does not know.
  - window (`ui/`): `forwardTab` (in `handle`, after the Spaces' `forwardInput`); `tabInput` (the active tab's renderer said hello and lives; no sign-in prompt, dropdown or chip menu open); `forwardMouse` (moves and downs over the page area; an up only for a button whose down was forwarded, `TabProcess.pressed`; left, middle and right buttons; back and forward stay the window's) and `sendMouse`; `forwardKey` (focus on the page and no Command or Control, which stay the window's shortcuts; Escape while the find bar is open stays the window's); `domKey` (the DOM key of a key, now also used by the window's `keyScripts`); text while the page has the focus; `forwardWheel` (in `flushWheel`). A forwarded event returns before the window's own handling; `pointerEvent` does nothing while a renderer takes the input, so the window's `pointerleave` and `pointercancel` reach only the renderer. `input_ack` does not mark the window dirty.
  - renderer (`renderer/`): `answerAll` handles the four input messages (`TabRenderer.took` keeps the seq and asks for a paint), then paints and sends `input_ack` (`ackInput`). `mouseInput`: hover (`engine.hoverAt`), pointer and mouse events (`pointerAt`, the window's `pageview.mouseEvent`), the press state, and on a left down the click (`clickAt`: the page's `click` listeners, layout, `engine.activate`, the caret in a text field, a click outside blurs). `wheelInput`: the page's `wheel` listeners, then an inner scroller (`wheelElement`, latched while a precise stream goes on, as the window's `wheelScrollElement`), a frame (`scrollFrameAt`), then the page (`scrollPage`: clamped, `setScriptScroll`). `keyInput`: `keydown`/`keyup` at `pageview.keyTarget`; a canceled `keydown` swallows its text; then text-field editing (`fieldKey`: Backspace, Delete, arrows, Home, End) or page scrolling (`scrollKey`: arrows, Page Up/Down, Space, Home, End). `textInput`: `beforeinput`, insert, `input`. `TabRenderer` keeps `scroll_x`/`scroll_y` and the largest offsets of its last display list; `paintFrame` scrolls the layout tree to the snapped offset (`layout.scrollTo`, `pageview.snappedScroll`) and paints with `TabRenderer.view()`; a scroll change makes the frame's damage whole; the `frame` carries the offsets.
  - test hooks: `--events` word `renderer:input` (waits until the renderer acked all input sent); `DWELLER_TEST_EVIL=ack` (the renderer acks one past the last input).
- Chromium read (idea only): `content/browser/renderer_host/render_widget_host_impl.cc` (`ForwardMouseEvent`, `ForwardWheelEvent`, `ForwardKeyboardEvent`: the browser turns native events into typed `WebInputEvent`s for the widget's renderer), `content/browser/renderer_host/input/` (wheel events coalesced in the browser, each event acked by the renderer), `third_party/blink/public/common/input/web_input_event.h` (type and modifiers; mouse button, position, movement, click count; wheel deltas; keyboard `dom_key`, `dom_code`, text). Dweller takes: typed input messages with the DOM key, code and modifier bits, the wheel coalesced in the browser, one cumulative ack per batch.
- files: `browser/ipc/{message,decode,put-payload,from-renderer,encode_test}.aye`, new `browser/ipc/{bad-scroll,bad-scroll_test}.aye`; `browser/renderer/{answer-all,tab-renderer,paint-frame,frame-damage,draw-damage,load}.aye`, new `browser/renderer/{mouse-at,mouse-input,pointer-at,click-at,element-of,inside,lay-out,wheel-input,wheel-element,scroll-page,key-input,field-key,scroll-key,text-input,ack-input}.aye`; `browser/ui/{window,tab-process,renderer-sent,take-messages,renderer-waits,tab-process-timeout}.aye`, `browser/ui/pageview/{key-target,mouse-event}.aye` (now `pub`), new `browser/ui/{tab-input,forward-tab,forward-mouse,send-mouse,forward-key,dom-key,forward-wheel}.aye`; new `browser/tests/ui/renderer_input.html`; `tests/browser.rs` (`window_renderer_input`); `docs/process-model.md` (the input row).
