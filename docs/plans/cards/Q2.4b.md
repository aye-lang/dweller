# Q2.4b: document.cookie and web storage live in the browser

- goal: with `DWELLER_PROCESS=tab`, `document.cookie` (get and set), `localStorage` and `sessionStorage` use stores in the browser, not in the renderer. The browser takes the document's URL and origin from its own record, never from the message, applies the same cookie rules as for HTTP, sends `storage` events to the other renderers of the origin, and kills a renderer that names a document it was not given. The sync APIs stay sync: each call is a blocking IPC round trip.
- design:
  - IPC messages added (type codes in order): 31 R→B `cookie_get{doc}`; 32 B→R `cookies{cookies}` (the reply); 33 R→B `cookie_set{doc, line}` (no reply: the socket is ordered, so a later `cookie_get` sees it); 34 R→B `storage{doc, context, session, op, index, key, value}` (op 0 getItem, 1 setItem, 2 removeItem, 3 clear, 4 key(index), 5 length; 6 copy the context's sessionStorage to context `index` (window.open), 7 drop the context's sessionStorage (a popup closed), both with no reply); 35 B→R `storage_reply{found, refused, changed, count, value}` (`value`: the item, the key, or the old value of a set or remove; `refused`: over the 5 MB quota); 36 B→R `storage_event{nulls, key, old, value, url}` (`nulls` bits 1, 2, 4: key, old, new value are null).
  - `doc` is the number the browser gave the document (Q2.4a): 0 the tab's top-level document (`tp.top`), n a frame's or popup's document (`tp.docs`). The renderer finds it with `docOf` from the page's origin (an `about:blank` frame's is its parent's).
  - the browser's checks: `cookie_*` with a `doc` above `docCount` (or on a frame id that is not the tab's) is `bad cookie`; `storage` with such a `doc`, `session` not 0 or 1, `op` above 7, or op 6/7 without `session`, is `bad storage`. Both kill the renderer (stderr `error: bad message: bad cookie PID`).
  - cookies: the browser runs `net.scriptCookies` / `net.setScriptCookie` (the jar with `script` true) with the document's URL from `fetchDoc` and the tab's top from `topOf`. So, as in the window's own process: no `HttpOnly` cookie is returned to script and none is stored from script, a `Secure` cookie is stored only from https, the context is third-party when the document is not of the top's site (none stored there), and the name/value size limit holds. In the renderer net calls hooks instead of its jar (`net.setRemoteCookies`).
  - storage: the store and its persistence stay `engine/storage.aye`'s (`<profile>/storage/<origin>`, saved by the window's loop); the browser calls `engine.applyStorage` on it, with the area key built from its own record: the origin of the document's URL for localStorage, `<tab>.<context> <origin>` for sessionStorage (`tab` is the slot's id, kept in `tp.tab`, so a tab's sessionStorage survives its navigations and a renderer crash, and goes when the tab closes: `dropTabStorage`). The renderer's own `akStorage` now asks `askStorage`, which goes through `engine.setStorageRemote`'s hook in a renderer and to `applyStorage` in-process, then fires the `storage` events of its own process (`storageResult`). The renderer refuses (QuotaExceededError) an item whose key and value pass 1 MiB − 8 KiB, which the IPC payload limit cannot carry.
  - events: after a localStorage change the browser sends `storage_event` (with the URL of the writing document from its record) to every other live tab process that holds a document of the origin (`hostsOrigin`; the list `tab_processes`); the renderer queues the event at its pages of that origin (`engine.storageEvent`). Pages in the writing renderer get theirs there, as before.
  - renderer fixes this needed: the renderer keeps one tab context for its pages (`r.context`, `setLoadingContext` before each load), so sessionStorage survives a navigation; it serves popups' load requests at once (`timerWait` is 0 while `hasContextRequests`), so `window.open` children load without a timer; replies are read by `awaitReply` (other messages stay in the inbox). At exit `engine.closeStorage` frees the stores.
  - test hooks: `DWELLER_TEST_EVIL=cookie` (every cookie message names doc 4096), `storage` (every storage message does).
- Chromium read: `services/network/restricted_cookie_manager.cc` (a cookie manager bound per frame to an origin, site for cookies and top-frame origin that the browser sets; a URL outside that origin is a bad message; `HttpOnly` excluded for script), `content/browser/dom_storage/dom_storage_context_wrapper.cc` and `storage_area_impl.cc` (one area per storage key in the browser, observers notified of changes), `content/browser/child_process_security_policy_impl.cc` (`CanAccessDataForOrigin`). Dweller takes: the renderer names only a document the browser gave it, the browser derives the origin, site and top from its own record and kills on a document it never gave; one area per origin (per tab and origin for sessionStorage) lives in the browser, and changes fan out from there.
- files: `browser/ipc/{message,decode,put-payload,from-renderer,message_test}.aye`; `browser/net/session.aye`, new `browser/net/set-remote-cookies.aye`; `browser/engine/storage.aye`, new `browser/engine/{storage-ask,storage-done,set-storage-remote,ask-storage,apply-storage,apply-storage_test,set-area-item,remove-area-item,clear-area,key-of-area,storage-result,storage-origin,copy-session-areas,drop-session-areas,storage-event,close-storage}.aye`; `browser/renderer/{tab-renderer,serve-on,answer-all,load,timer-wait}.aye`, new `browser/renderer/{store-through,store-doc,cookies-remote,storage-remote,await-reply,unless-null}.aye`; `browser/ui/{tab-process,start-tab-process,end-tab-process,renderer-sent,ask-renderer,ask-tab-renderer,poll-tab-processes,relay-agent-main,tabs}.aye`, new `browser/ui/{answer-browser-ask,answer-cookie,doc-cookies,answer-storage,tab-area,tab-session-changed,tell-storage,hosts-origin,tab-processes,drop-tab-storage}.aye`; `browser/main.aye`; new `browser/tests/storage/{listen,write,script-cookies,visits}.html`; `tests/browser.rs` (new `window_renderer_storage`).

## Status: done, 2026-11-08

Left:
- a cache of the areas and cookies in the renderer (each call is a blocking round trip now); with it, `storage_event` would also update the cache.
- a renderer is not locked to a site (stage `tab`): it may name any document the browser gave it, including a cross-site frame's (site locks: Q2.6). `docOf` picks a document by origin; a page whose origin has no document number (a `data:` frame) gets the top's.
- an area larger than the 1 MiB IPC payload (possible from a profile written by the window's own process, up to 5 MB) cannot be read back in one reply; values over 1 MiB − 8 KiB are refused under the flag.
- IndexedDB, and the proof that a renderer opens no profile file: Q2.4c.
- the window's own pages under the flag share the browser's store but do not get `storage_event`s from renderers (the window shows no page of its own there).
