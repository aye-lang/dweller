# Q4.27: GitHub's Turbo soft navigation completes

- goal: on https://github.com/rust-lang/rust, a click on `Issues` lands on `/rust-lang/rust/issues` (URL, title and body), as in Chrome: in `dweller agent` (the W2 task of github, `browser/tools/agent_tasks/github.jsonl`) with `DWELLER_PROCESS=site` and `single`, and in the window.
- failing step (live, `dweller agent`, 2026-11-24): Turbo cancels the click, fetches `/rust-lang/rust/issues` (200, `text/html`), and its response settles at the head of the body (Q5.8 streams bodies). Turbo then calls `response.clone().text()` twice. Neither promise settled: a probe that counted the stream's `enqueue`/`close` saw the first part and no close. In 1 run of 4 the whole body was in before the task ran: then `text()` settled, `DOMParser` parsed it and `turbo:before-frame-render` fired, and nothing came after it. With `{"cmd":"wait","ms":1000}` after the click, Turbo finished in the same session: `turbo:frame-render` at 58 ms page time, `turbo:render` and `turbo:load` at 74 ms, then the URL `/rust-lang/rust/issues` and the title `Issues · rust-lang/rust · GitHub`. So no web API was missing. The page needed time to pass after the click.
- cause: the agent's virtual clock. After an action the agent ran only the tasks due at once (`settleScripts`, `engine.runDueTimers`). Two steps of Turbo come later on that clock:
  1. the next part of a body is a task 10 ms later (`STREAM_POLL_MS`, `partTask`, Q5.8);
  2. `FrameRenderer.render` awaits `nextRepaint()` (an animation frame, a 16 ms timer on the virtual clock) three times before the swap.
  The click's response, and every `snapshot` after it, showed the old page until a `wait`. In a real browser these tasks follow the click by a few ms. Replay (whole bodies) still hit step 2, so the W2 task could not pass even with a new archive.
- fix: after an action that stays in the document (not `wait`, not `eval`, no document loaded), the agent runs the page while it has a task it waits for: a load's task (a fetch or XHR response, a part of its body, a module load; not an EventSource poll) or an animation frame (not while hidden). The virtual clock jumps to each one, and the timers due on the way run in order. The limit is 1 s of page time (`ACTION_AWAIT_MS`). The window's real clock is not changed. Code: `engine.runAwaitedTasks` (`browser/engine/run-awaited-tasks.aye`, `has-awaited-task.aye`), called from `settleScripts` (`browser/agent/scripts.aye`) when `awaitsTasks(act)` (`browser/agent/awaits-tasks.aye`). `docs/agent-protocol.md` (Time is the page's own) says it.
- test: `agent::agent_click_soft_navigation` (`tests/browser/agent.rs`, pages `browser/tests/agent/site/soft_nav.html` and `soft_nav_next.html`, test server). The page does what Turbo does: on the click it calls `preventDefault`, fetches the next page from `/parts/` (the test server sends the second part only after `/parts-go`, so the body comes in two parts), reads `response.clone().text()`, parses it with `DOMParser`, awaits `requestAnimationFrame`, then calls `pushState`, sets the title and replaces `#content` with an imported node. The test expects the click's response to have the new URL, the title `Issues`, and both parts in the diff. It runs in default mode and with `DWELLER_PROCESS=single`. Before the fix it failed (url `soft_nav.html`, title `Code`). After the fix it passes.
- live (2026-11-24, this Mac): the click's response is `https://github.com/rust-lang/rust/issues`, `Issues · rust-lang/rust · GitHub`, in default (site) mode and in `single` mode.
- github W2 (recaptured 2026-11-24 with this build; the old archive was deleted after both checks passed): `page_load.py capture --site github` exit 0. `check --site github` exit 0 (result pass, visual defects:2, as before). `check --agent --site github` exit 0 (task pass; reported, not judged: `archive fallback: https://collector.github.com/github/collect (+1 more)`).
- window (`--agent-socket`, a Space): the renderer was killed at Turbo's `pushState` (`bad same_document`): the browser kept no history entry for a page the agent loaded. Fixed in Q4.27b.
