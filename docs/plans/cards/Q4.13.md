# Q4.13: DOM query indexes and a parsed-selector cache

- goal: `querySelector(All)`, `getElementById` and the window's named properties stop walking the whole document and re-parsing the selector on every call (Blink's `SelectorQueryCache` and `TreeOrderedMap`).
- cause: Q4.1 (PERF.md, "Q4.1"): on zol `querySelectorAll` was ~2700 ms of a slow scroll frame (14496 calls, 0.78 ms each) and `isWindowNamed` ~700 ms (`getOwnPropertyDescriptor` on `window`, 70 µs each). A probe build that printed each selector showed that 14292 of the 14594 zol queries were `iframe[name], frame[name]` and `[id], [name]` from `window-named.js`: each global name lookup that missed (`typeof foo`) ran both queries. The rest: `img` (275), `.side-nav_list li.active` (27).
- design:
  - `dom`: `Document.ids` and `Document.names` (`StrMap(List(NodeId))`, the elements that have that `id` or `name` value, in any tree). `createElement`, `setAttr` and `removeAttr` keep them (`indexAttr`, `unindexAttr`). `releaseIfUnused` removes freed elements (`forgetIndexed`). Insert and remove change nothing in the index: lookups filter the candidates by tree root (`treeRoot`), so every tree scope is right without upkeep (the document, a shadow root, a fragment, a detached subtree).
  - `elementById(doc, scope, id)`: the one candidate whose tree root is `scope`. With two or more, it walks `scope` and the first in tree order wins (`firstById`). `Document.getElementById` uses it. A new native `getElementById` on `DocumentFragment.prototype` (`ShadowRoot` inherits it) replaces the two prelude loops over `querySelectorAll('[id]')`.
  - Selector cache: `Script.selectors`, from selector text to the parsed `Selector`, at most 256 (when full, all are dropped). `querySelector`, `querySelectorAll`, `matches` and `closest` use it. Invalid selectors are not cached.
  - Fast paths (`selectFast`), only for a list of one selector that selects elements (no pseudo-element):
    - an `#id` in the rightmost compound: the id index candidates under the root (not the root). One candidate: it is matched with the whole selector. Two or more: the general walk.
    - a single `tag`, `.class` or `*`: a walk with a direct test (no selector matcher). Blink walks for these too.
    - anything else: the general walk, with the cached selector.
  - Window named access: `windowNamedHas` checks the id and name index candidates that are in the document (`anyWindowNamed`, with the same `isWindowNamed` rules: `id` on any element, `name` on embed, form, img, object, iframe, frame). The `get` trap of `window-named.js` asks `Reflect.has(target, key)` (that check) first, so a miss costs no query.
- files: `browser/dom/dom.aye`, `browser/dom/{index-attr,unindex-attr,forget-indexed,free-index,element-by-id,first-by-id}.aye`, `browser/dom/element_index_test.aye`, `browser/engine/{cached-selector,drop-selectors,select-fast,select-by-id,select-simple,matches-simple,fragment-get-element-by-id,any-window-named}.aye`, `browser/engine/{dom_api,script,window-named-has}.aye`, `browser/engine/prelude.aye`, `browser/engine/window-named.js`.
- verify: `aye test browser` (5 index tests: attribute change, insert and remove, duplicates in tree order, shadow scope, name index), `aye check browser`; `cargo test` filtered `jsdom dom js_conformance window_`; WPT `dom/nodes` and `css/selectors`; zol before/after with `DWELLER_JS_NATIVES=1` and the W7 row; `check_taste.py`.
