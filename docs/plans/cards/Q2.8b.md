# Q2.8b: renderers run in a Landlock + seccomp-bpf sandbox on Linux

- goal: on Linux a renderer (`dweller --renderer FD`, started for `DWELLER_PROCESS=tab` and for every site's process) enters a sandbox at the same point as Q2.8a's seatbelt: in `serveOn`, after `serve` has its IPC socket (fd 3), the kept working directory and the system fonts, and before the `hello` and the first `navigate`. It can then no longer open the profile or any file outside `/usr` and the executable's directory, open any file for writing, make a socket, connect, fork or exec, or signal another process. A failure to enter ends the renderer (exit 3, the sad tab). `DWELLER_NO_SANDBOX=1` turns it off with the same warning as on macOS.
- design (`enterSandbox` → `enterLinuxSandbox`, gated by `@targetOs() is .linux` like the seatbelt by `.macos`; all libc through `extern fn`: `prctl`, `syscall`, `uname`):
  1. `prctl(PR_SET_NO_NEW_PRIVS)`; failure ends the renderer.
  2. Landlock (`restrictPaths`, `allowReads`): a ruleset that handles every filesystem right of the kernel's ABI (1–7; size and rights picked from tables by ABI), TCP bind and connect (ABI ≥ 4) and the abstract-socket and signal scopes (ABI ≥ 6), with read-file and read-dir rights beneath `/usr` (system libraries and `/usr/share/fonts`) and the executable's directory (`/proc/self/exe`, for ANGLE as on macOS); then `landlock_restrict_self`. Nothing is writable. Gives `false` when the kernel has no Landlock.
  3. seccomp-bpf (`installSeccomp`, `seccompProgram`, x86_64 only, checked with `uname`): the program is a `List(u64)` of `sock_filter` words built from data tables (`x86-64-syscalls.aye`, `allowed-syscalls.aye`) with one-line encoders (`bpf-insn.aye`), installed with `seccomp(SECCOMP_SET_MODE_FILTER, SECCOMP_FILTER_FLAG_TSYNC)`:
     - a foreign architecture (i386 `int 0x80`) kills the process; x32 numbers match nothing and get EPERM;
     - an allowlist of 59 syscalls (memory incl. `mprotect`/`mmap` with `PROT_EXEC` for wasmtime, `futex`, reads and writes on held fds, `recvmsg`/`sendmsg`, clocks and sleeps, signals on itself, `getrandom`, `membarrier`, `rseq`, epoll, exit);
     - `open`/`openat` only without write flags (`O_WRONLY|O_RDWR|O_CREAT|O_TRUNC|O_APPEND|O_TMPFILE`), and only when Landlock is on: without Landlock every open is refused (seccomp alone still keeps the profile out);
     - `clone` only with glibc's thread flags (`CLONE_VM|FS|FILES|SIGHAND|THREAD|SYSVSEM`, optionally TLS/TID flags), so threads start and `fork` fails; `clone3` gives ENOSYS so glibc falls back to `clone` (its argument is a pointer BPF cannot read);
     - `tgkill` only to its own pid (abort), `prlimit64` only on itself, `ioctl` only `TCGETS`;
     - everything else (`socket`, `connect`, `execve`, `fork`, `ptrace`, `kill`, `unlink`, `mkdir`, `prctl`, `unshare`, `seccomp`, stat by path, …) gives EPERM.
  - why Landlock and not namespaces for layer 2: the file opens after entry are FreeType's fallback faces and the canvas's system faces, by path (strace: about 100 opens under `/usr/share/fonts` for a page with CJK, Arabic, Hebrew and emoji text; a worker thread opens `/proc/sys/vm/overcommit_memory`, refused and harmless). Chromium answers those with a broker process (`syscall_broker/`) behind a SIGSYS trap, and confines the process with a user/pid/net namespace and a chroot (`credentials.cc`). Landlock gives the same path confinement unprivileged, inside the process, with no broker: and Ubuntu 23.10+ (CI runs 24.04) forbids unprivileged user namespaces to unconfined binaries through AppArmor, so namespaces would fall back on the very platform of the test; a pid namespace also needs a fork. Network namespaces add nothing once `socket` is refused.
  - threads: entry happens before any thread (decode pool, workers, regexp threads all start later and inherit both layers); TSYNC covers seccomp anyway. Landlock's `restrict_self` is per thread (ABI 7), which is why it must stay first in `serveOn`.
- test hook: Q2.8a's `DWELLER_TEST_SANDBOX_PROBE=1` (behind `DWELLER_TEST=1`). On Linux it prints `sandbox-probe home=13 tmp=1 tcp=1 fork=1`: the profile is refused by Landlock (EACCES), the write by seccomp (EPERM), `socket` and `fork` by seccomp (EPERM). Without Landlock (seccomp alone) `home=1`.
- files: new `browser/renderer/{enter-linux-sandbox,restrict-paths,allow-reads,install-seccomp,seccomp-program,allow-syscall-if,bpf-insn,allowed-syscalls,x86-64-syscalls}.aye`; `browser/renderer/enter-sandbox.aye` (the Linux branch); `tests/browser/window_renderer.rs` (`window_renderer_sandbox` runs on Linux too); `docs/process-model.md` §6 (the Linux design as built).
- Chromium read: `sandbox/linux/seccomp-bpf-helpers/baseline_policy.cc` (clone restricted to thread flags, `clone3` → ENOSYS, kill/tgkill to its own pid, prlimit on itself, ioctl restricted, filesystem syscalls denied with an errno instead of a crash), `sandbox/policy/linux/bpf_renderer_policy_linux.cc` (the renderer additions: `clock_getres`, `mremap`, `sysinfo`, `times`, `uname`, prlimit), `sandbox/linux/seccomp-bpf-helpers/syscall_parameters_restrictions.cc`, `sandbox/linux/services/credentials.cc` and `sandbox/linux/syscall_broker/` (namespaces and the broker, replaced by Landlock). Dweller takes the baseline's allowlist shape and its argument checks, as a flat table, with EPERM as the default instead of SIGSYS.
- verify (2026-11-09, Linux x86_64 6.18, Landlock ABI 7, Ubuntu 24.04 userland, glibc 2.39):
  - `python3 browser/tools/check_taste.py`: exit 0. `python3 browser/tools/check_layers.py`: exit 0. `aye check browser`, `aye check browser --target aarch64-macos`, `--target x86_64-macos`, `--target aarch64-linux`: exit 0. `aye test browser`: 264 passed, 0 failed, 20 modules.
  - `browser/build.sh`: exit 0.
  - `cargo test --release --test browser -- window_renderer_lifecycle window_renderer_frames window_renderer_input window_renderer_net window_renderer_sandbox`: 6 passed, 0 failed (the filter also selects `window_renderer_input_actions`). Wider: `cargo test --release --test browser -- window_renderer_ window_login_in_renderer agent_sessions_in_renderer`: 22 passed, 0 failed.
  - `window_renderer_sandbox` on Linux: sandboxed probe `sandbox-probe home=13 tmp=1 tcp=1 fork=1`, PNG byte-equal to the in-process window's; with `DWELLER_NO_SANDBOX=1` the warning and `home=0 tmp=0 tcp=111 fork=0`.
  - by hand under `strace -ff`: a page with CJK, Korean, Arabic, Hebrew, symbols and emoji, serif bold italic, a PNG, a 2D canvas with CJK text, `Date`, `crypto.getRandomValues`, `Intl.NumberFormat`, a backtracking regexp and a Worker (`worker 42`): the sandboxed renderer's PNG is byte-equal to the in-process window's and to the unsandboxed renderer's; after entry the only refused calls are `clone3` (ENOSYS, glibc falls back to `clone`) and the worker's `/proc/sys/vm/overcommit_memory` (EACCES).
  - seccomp alone (Landlock forced off in a scratch build): the probe gives `home=1 tmp=1 tcp=1 fork=1`; the page renders but the lazily opened fallback faces and the canvas's system faces are missing (tofu, no canvas text).
  - No golden re-blessed; every window run headless (`SDL_VIDEODRIVER=dummy`).

## Status: done, 2026-11-09

Left:
- seccomp on aarch64 Linux: only Landlock is applied there (the filter's numbers are x86_64's; `uname` picks); an `aarch64-syscalls.aye` table would add it.
- seccomp without Landlock refuses every open, so fallback faces and the canvas's lazily loaded system faces are missing on kernels without Landlock (< 5.13 or Landlock off): opening the fallback faces before entry, or a broker, would fix it.
- `newfstatat`/`statx` by path, `kill` and `prctl` are refused; no library in the tests needed them. wasmtime (not installed here) and WebGL in a sandboxed renderer are untested on Linux (ANGLE's GPU drivers would need `/dev/dri` and `/etc`).
- Landlock TCP rules and the signal scope need ABI 4 and 6; older kernels rely on seccomp alone for those.
