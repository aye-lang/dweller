# Q2.11: out-of-process iframes 3 (cross-process window proxies)

- goal: with `DWELLER_PROCESS=site`, a page and its out-of-process iframes see each other through window proxies, as in-process frames do: `postMessage` both ways with a structured clone, `event.origin` and an `event.source` that can answer, the `targetOrigin` checked in the browser; `parent`, `top`, `frames`, `window.length`, `frames[i]`, `name`, `closed`; `location` set on a remote window navigates it through the browser with the sandbox and navigation checks; `focus()` on an iframe's window; cross-origin access to anything else throws `SecurityError`. The iframe's `load` event fires when the child's own load event did (before, when the empty placeholder loaded), and the parent's load waits for it, as in-process. A renderer that lies about a message's source origin is killed. Without the flag (and with `tab`) nothing changes.
- design:
  - IPC (type codes 51–56, after Q2.4e's 50; Q2.3f takes 60 and up):
    - 51 R→B `post_message{key, frame, page, source_page, source_origin, target_origin, data, buffers}`: to remote frame `key` of the sender (an iframe placeholder of its own), or, with key 0, to page `page` (0: the root page) of the renderer of browser frame `frame` (a proxy the browser told it about: its `parent`, `top`, or an `event.source`). `source_page` is the sender's page (0: its root). `target_origin` is `*` or a serialized origin (`/` is resolved to the sender's own by the sender). `data` is the JSON of the workers' structured clone (`engine/workers/wire.js` `send`, the serializer `Worker.postMessage` uses: undefined, NaN, BigInt, Date, RegExp, Map, Set, Error, wrappers, typed arrays, cycles); `buffers` its ArrayBuffers, each a u32 length and the bytes. At most 960 KiB, else `DataCloneError`.
    - 52 B→R `message{page, from_key, from_frame, from_page, origin, target_origin, data, buffers}`: queued as a task at page `page` of the receiver, a trusted `MessageEvent` (`wire.receive`, `messageerror` when it cannot be decoded) with `origin` the browser checked; `event.source` is the `contentWindow` of the receiver's iframe `from_key` when the sender is that child's root page, else the proxy `(from_frame, from_page)`. The receiver drops it when its page's own origin is not `target_origin`.
    - 53 B→R `frame_owner{parent_frame, parent_page, top_frame, sandbox, name}`: sent to a child before each navigation the browser starts in it (`sendFrameOwner`, from `serviceChildren`). `parent_page` is the page of the embedder that holds the iframe (0: its root). `sandbox` is the iframe's sandbox flags (its `sandbox` attribute and those of the page that holds it): the child's root page gets them at load (`loadShared`), so a sandboxed cross-site iframe is sandboxed in its own renderer too (opaque origin, no scripts, no top navigation...); Q2.9 dropped them. `name` is the iframe's `name` (the child's `window.name`).
    - 54 B→R `frame_loaded{key}`: the child of remote frame `key` finished loading (or its renderer is gone, or could not start, before it did).
    - 55 R→B `proxy_navigate{key, frame, page, url}`: `location` set (`href`, `assign`, `replace`, the setter) on a remote window, the URL resolved by the sender.
    - 56 R→B `load_stopped`: a child renderer's root page fired its load event (`reportLoadStopped`, after each batch, once per page).
    - IPC 43's `subframes` record gains `holder` (the page that holds the iframe, 0 for the root), `sandbox` and `name`; `badSubframe` also refuses flags past the 18 sandbox bits and a name over 4096 bytes.
  - renderer engine (`engine/`): a remote window is a host object of a new tag `TAG_REMOTE_WINDOW` (index the browser frame, generation the page), one per `(frame, page)` and script (`remoteWindowValue`, `Script.remote_windows`), with the same prototype as other windows. An iframe placeholder's window (Q2.9's opaque, scriptless page) is remote too: `routeOf` gives its key. `frameOwnerOf(p)`: the `frame_owner` of the renderer when `p` is in its tab context (`owner_context`, from `loadShared`). The prelude's `WindowP.postMessage` sends to a remote window with `ak.remotePost` (`engine/remote-windows.js`: `wire.send`, staged buffers, `akPostRemote`: target origin parsed, `SyntaxError` when it is not a URL); `focus()` on an iframe's remote window focuses that iframe (Q2.10 then moves the keyboard focus into the child); `blur()` does nothing (as Chromium). The embedded root's `parent` and every page's `top` are the remote proxies from `frame_owner`; a remote window's `parent` and `top` are the tab's top (exact for one level of nesting); `name` is the iframe's; `closed` is false; `length` 0; `document` and `location.href` throw `SecurityError` (`remoteCrossOrigin`), as `contentWindow.document` of a placeholder already did. `location` set on a remote window: `remoteNavigationAllowed` (the sandbox check of Q3.9 for an ancestor: `SB_TOP_NAVIGATION` for the top, `SB_NAVIGATION` otherwise; a frame below is always allowed) else `SecurityError`, then `proxy_navigate`.
  - load: a remote placeholder is loaded (`pageLoaded`) only once `frame_loaded` came (`Page.remote_loaded`); `remoteFrameLoaded` sets it, marks the frame's load pending again (a later navigation of the child fires the iframe's `load` again, as in-process), and settles the loads of the pages above (`settleLoad`: the iframe's `load`, then the window's when nothing else delays it). A remote frame that gets no box (`display: none`, zero size) has no renderer (Q2.9 starts children from laid-out rects only), so `settleBoxlessFrames` (after each `subframes` report) counts it as loaded rather than delay the parent's load for ever.
  - browser (`ui/`): `routePostMessage` (`childSent` and `rendererSent`): the source origin must be `null` or a serialized http(s) origin in the sender's site lock (`originHosted`: `inSiteLock`, Chromium's `HostsOrigin`), the target origin `*` or a serialized origin, the buffers well formed, else kill `bad post_message`; the target (`postTarget`) is the sender's started child of that key, or a live frame of the sender's own tab (`findFrame` from `topProcess`), else the message is dropped; `targetOriginMatches` (else dropped): `*`, or the target's committed origin for its root page (never for a child whose iframe is sandboxed without `allow-same-origin`, whose origin is opaque), or the target's site lock for a page below its root (the receiving renderer compares the exact origin). `navigateProxy`: URL ≤ 2 MiB, the target as above (dropped otherwise), `proxyNavigationAllowed` (the target below the sender: allowed; the top: the sender's frame sandbox from `frame_owner` must allow top navigation; another frame: navigation) else kill `bad proxy_navigate` (an honest renderer threw already), `initiatorMayLoad` from the sender's committed URL (no `file:` from the web); a child is navigated in place (`navigateChild`, the sender's URL as referrer: Q2.9's swap takes a cross-site response to a new renderer), the top through `beginNavigation` from the next poll (`takeNavRequest`, which also refuses a top-level `data:`). `load_stopped` of a child while no navigation is open, once per commit, tells its embedder `frame_loaded` (`tellLoaded`); a gone child, or one whose renderer could not start, sends it once (`frameDone`) so the parent's load does not hang.
  - test hooks: `--events` word `renderer:title:END` (the shown tab's top title ends with END, `_` a space; `titleEndsAs`, shared with `renderer:child-title:`); `DWELLER_TEST_EVIL=post-message` (with `DWELLER_TEST=1`): the renderer claims `http://evil.example` as every message's source origin.
  - WPT in the window: `wpt.py run --process tab|site` runs each testharness test in a headless window with `DWELLER_PROCESS` set (`browser/tools/wpt_window.py`) instead of `dweller wpt` (which loads in process and cannot use renderers): the renderer echoes its console to stderr with `DWELLER_CONSOLE` (it did not before), and with `DWELLER_TEST=1` and `DWELLER_WPT_TIMEOUT_MS` it calls the harness's `timeout()` after the test's timeout in real time (`wptTimeout`), as `dweller wpt` does on its virtual clock; the result is the `DWELLER_WPT` console line. Reftests and crashtests stay in process.
- Chromium read: `third_party/blink/renderer/core/frame/remote_dom_window.cc` (`SchedulePostMessage`/`ForwardPostMessage`: a remote window's `postMessage` goes to the remote frame, which forwards it to the browser with the source frame, source origin and target origin), `third_party/blink/renderer/core/frame/remote_frame.cc` (`Navigate`: a remote frame's navigation is sent to the browser; `DidStopLoading`: the parent checks whether it completed; `DidFocus`), `content/browser/renderer_host/render_frame_proxy_host.cc` (`RouteMessageEvent`: the target's last committed origin against `target_origin` (drop), `HostsOrigin(source_origin)` (kill `RFPH_POST_MESSAGE_INVALID_SOURCE_ORIGIN`), same browsing instance (drop), the source translated to the proxy in the target's process). Dweller takes: the browser routes by frame, checks the claimed origin against the sender's lock and the target origin against what it committed, and names the source as a proxy the receiver already has; the renderer keeps proxy objects per (frame, page) so `event.source === parent` holds.

## Status: done, 2026-11-09

Left:
- `opener` across renderers: a popup opened from a child renderer, and an opener in another renderer, have no proxy (Q3.10's left list: popups live in their opener's renderer); `window.open(url, name)` does not find a remote frame by name; a remote window's `close()` does nothing.
- the replica of the frame tree is one level deep: a remote window's `length` is 0 and `w[i]` undefined (so the child's `parent.length` and `parent.frames[i]` miss the parent's frames), a remote window's `parent` is the tab's top (wrong for a middle frame of three cross-process levels), and a remote proxy's `closed` stays false after its frame went (no `proxy_delete`).
- `event.source` of a message from an in-process frame below the sender's root is a proxy `(frame, page)` that answers, but is not `===` the receiver's `frames[i][j]`; `location` set on such a page (page != 0) is dropped.
- `postMessage` to a remote window is sent at once, not after the current script (Chromium's `SchedulePostMessage`); `MessagePort`s and `OffscreenCanvas` cannot be transferred across processes (a `DataCloneError`); in process, window `postMessage` still clones by JSON (Map, Date, typed arrays are lost there), so the two modes differ for such data.
- remote navigation: no upgrade of insecure requests by the sender's policy, no navigation rate limit, the referrer is the sender's URL whatever its referrer policy, and `location.replace` adds a history entry where the child's history exists at all (Q2.9).
- the browser knows the sandbox flags of a renderer's root frame only (from `frame_owner`): in-process frames below it with stricter flags rely on the renderer's own check, and the top's CSP `sandbox` is unknown to the browser.
- `focus()` on a remote `parent`/`top` does nothing; `blur()` does nothing anywhere (as Chromium).
- a cross-site iframe without a box (`display: none`, zero size) still has no renderer (Q2.9): its `load` fires when the parent lays it out, and it has no document to message.
- process reuse (Q2.9's left list): a grandchild of the top's own origin runs in a renderer of its own, so `top.document` throws for it, where in process it is same-origin.
- `wpt.py run --process` loses the partial results of a test that never reports in the window (two files above); reftests and crashtests stay in process; `dweller wpt` itself has no process mode (the window does that work).
