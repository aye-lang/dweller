# Q3.14b: referrerpolicy attributes, noreferrer, redirect policy, Origin after 303

- goal: links, forms and frames apply their own referrer policy (`referrerpolicy` on `a`, `area`, `iframe`, `script`; `rel=noreferrer` on `a`, `area` and forms, which also means `noopener`), and so does `fetch(url, {referrerPolicy})`. Under `DWELLER_PROCESS=tab` a navigation uses the policy the renderer worked out for its element and document. A `Referrer-Policy` header on a redirect response sets the policy of the next hop. A 301/302 POST or a 303 that turns the request into a GET sends no `Origin` on the GET. Source: Q3.14's left list.
- chain: on Q3.14 (#313, which contains #311, #310, #307).
- design:
  - Navigation hint: `nav_policy: ?ReferrerPolicy`, a module variable of `net` (not a `Session` field: the renderer has no session, `setRemote` stops it), cleared by `noteNavigation`, set by `noteNavigationPolicy` (`net/note-navigation-policy.aye`). `requestLive` gives it to the navigation request that takes the hint's referrer, unless the request has its own policy. The engine notes it after `Page.follow` for an `a`/`area` (`engine/link-referrer-policy.aye`: `rel=noreferrer` → no-referrer, else the `referrerpolicy` attribute; in `activate` and `ui/forms.aye`'s frame click), after `submitForm` for a form with `rel=noreferrer`, and after `noteNavigation` for an `iframe`'s `referrerpolicy`. `noreferrer` already meant `noopener` (`targetContext`).
  - Tab process: the renderer sends `navigationReferrerPolicy(page)` (`net/navigation-referrer-policy.aye`: the element's policy, else the policy noted for the page's document, else strict-origin-when-cross-origin) as a code in `BeginNavigation.referrer_policy` (`net/referrer-policy-code.aye`). The browser range-checks it (`net/referrer-policy-at.aye`; `bad begin_navigation` otherwise), keeps it in `TabProcess.nav_policy`, and `answerFetch` sets it on the navigation it began. The referrer URL is still the browser's own (`nav_initiator`).
  - `fetch()`: `startFetch` passes `Request.referrerPolicy` to `ak.fetchStart` as argument 7 (after the callback, so no index moves); `fetchWith` parses it into `Request.referrer_policy` (`""` → none, the page's policy).
  - Redirects: `transfer` (`net/http.aye`), `finishRequest` and `finishLoad` (`net/loader.aye`) parse the redirect response's `Referrer-Policy` and keep the last valid one for the next hops.
  - `img` and `link rel=stylesheet`: an element with a `referrerpolicy` attribute is left out of the prefetch and background loads (`prefetchImages`, `loadElementImage`, `sheetHrefs`, as `crossorigin` ones are), and its own request carries the parsed policy (`ImageCache.bitmapOf`'s `policy`, `linkedSheet`'s `policy`). The image cache stays keyed by URL, mode and credentials.
  - Origin after a method change: `transfer` sets the request's `method` to GET when it rewrites the hop, and `startHop` sends the hop's method (`Ask.verb`), so `originHeader` sees a GET; same-origin or no-cors GETs then send no `Origin`. The body headers were already dropped (`requestHeaders`' `dropped`).
- references:
  - spec: https://w3c.github.io/webappsec-referrer-policy/ (set request's referrer policy on redirect), https://fetch.spec.whatwg.org/#http-redirect-fetch , https://html.spec.whatwg.org/multipage/links.html#following-hyperlinks-2 .
  - Chromium `third_party/blink/renderer/core/html/html_anchor_element.cc` (`HandleReferrerPolicyAttribute`, `noreferrer` → no-referrer and no opener), `net/url_request/redirect_util.cc` (`UpdateHttpRequest` drops `Origin` when the method changes to GET), `services/network/url_loader.cc` (the redirect's `Referrer-Policy`). Dweller takes: the anchor's policy rule and the "method changed → GET → no Origin" order; the redirect policy comes from the hop's raw headers, with no separate parsed-headers object.
