# Q4.16d: list items and operand decode inline in the VM's hot paths

- goal: no call for `List(T).items()` in `Heap.obj`, `Interp.slot`, `Ast.node`, `vmPushFrame`, and none for `vmImm`/`vmIdx` in the hot ops of `vmLoop` (Q4.16a: on bbc `<deduplicated_symbol>` 28% of Dweller's self samples, `vmImm` + `vmIdx` 9%).
- cause:
  - `<deduplicated_symbol>` is ld64's identical-code folding (on by default): the instances of `List(T).items()`, `len()`, `append()` and the other small generic std methods whose machine code is the same for many `T` fold into one symbol each, and `sample` names every folded body `<deduplicated_symbol>`.
  - They stay calls because the compiler splits a big program into up to 8 translation units (`aye/src/driver.rs:1299`, `Parts::split` at `aye/src/cgen.rs:1753`), each a contiguous run of function bodies, without LTO. The generic std instances are emitted first and land in unit 0; `Heap.obj`, `Interp.slot`, `Ast.node` are in unit 4 and `vmLoop`, `vmPushFrame` in unit 5 (`aye emit-c browser --mode safe`, the unit of each definition by the `split` rule). In a split build `AYE_FN` is `visibility("hidden")`, not `static` (`aye/src/cgen.rs:1718`), and clang cannot inline across units. The safe-mode bounds check is not the blocker: it is two compares that clang keeps inline.
  - `vmImm`/`vmIdx` are in the same unit as `vmLoop` but were not inlined by clang's cost model: each carried the 1-, 2- and 4-byte decode with their bounds checks (82 and 61 call sites left out-of-line in `vmLoop` on origin/main, `otool -tV`).
- design:
  - The hot callers read the list's fields directly: `list.buf[..list.count][i]` (the same bounds check as `items()[i]`, no call) in `Heap.obj`, `Interp.slot`, `Interp.setSlot`, `Ast.node`, the `this` slot of `vmPushFrame` and the 96 `regs` reloads of `vmLoop`; `list.count` for `len()` in `vmPushFrame`; `list.buf[list.count - 1]` for the last frame and saved caller in `vmPopFrame` and `Return` (the index is below `count`, so the capacity check is as strict).
  - `vmImm`/`vmIdx` keep only the 1-byte operand (`((b as i64) ^ 128) -% 128` sign-extends without the overflow check), and call the new out-of-line `vmWide` for the Wide/ExtraWide scales. After: 33 + 29 out-of-line call sites in `vmLoop`, in the jump ops and rare ops (`atos`); Ldar, Star, Mov, LdaSmi, LdaConstant, the property and call ops decode inline.
  - The first try sent Wide operands to the generic `bcGet` loop: `bcGet` rose from 27 to 64 samples on bbc (node indices `[n]` are often Wide), so `vmWide` keeps the direct 2- and 4-byte decode.
- files: `browser/js/heap.aye` (`obj`), `browser/js/interp.aye` (`slot`, `setSlot`), `browser/js/ast.aye` (`node`), `browser/js/vm.aye` (`vmImm`, `vmPushFrame`, `vmPopFrame`, the `regs` reloads and `Return` in `vmLoop`), `browser/js/vm-idx.aye`, `browser/js/vm-wide.aye` (new)
- V8 ref: `src/interpreter/bytecode-decoder.cc` (`DecodeSignedOperand`, `DecodeUnsignedOperand`): the operand is read in place at its scale by the handler, with no generic loop over bytes.
- verify (M2 Pro, `scripts/capped.sh`, safe builds from `browser/build.sh`; base = origin/main fc38b4b9 as `target/dweller-base`):
  - `check_layers.py`, `check_taste.py`, `aye check browser`: exit 0. `aye test browser`: 219 passed. `cargo test --release --test browser -- js_conformance aye_unit_tests`: 2 passed. No golden changed.
  - jsbench (`BENCH_BIN=target/dweller BENCH_BASELINE=target/dweller-base BENCH_REF=none`, interleaved, median of 3): geometric mean speedup 1.133 (calls 1.21, closures 1.22, raytrace 1.26, richards 1.20, navier-stokes 1.20, three 1.18; dom 0.92, see left).
  - bbc W7 (`window_perf.py report --replay --site bbc`, 3 runs each): longest loop 338/340/346 ms before, 324/307/306 ms after; scroll p95 265.4/267.0/269.3 ms before, 239.3/240.9/241.1 ms after.
  - `sample PID 30` of one bbc replay run (3 `frame`, 40 `wheel:-3 frame`) each, share of Dweller's self samples (top of stack, >= 5): `<deduplicated_symbol>` 246 of 1123 (21.9%) before, 174 of 1032 (16.9%) after; `vmImm` 70 + `vmIdx` 51 + `bcGet` 27 (13.2%) before, `vmImm`/`vmIdx` gone, `vmWide` 57 (5.5%) after; `vmLoop` 247 before, 297 after (the decode now inline). The callers of `<deduplicated_symbol>` left are `List.append` from `vmPushFrame` (`Interp.push`, `frames.append`), `vmLoop`, `StrMap.get` and a long tail: the compiler follow-up below.
  - Script time of the one sampled run is not a number here: its `timers` swung 1297 to 2539 ms between runs of the same binary under `sample`, so the card uses W7 and jsbench.

## aye follow-up (aye card, not in this card)

Small std generic methods (`List(T).items`, `len`, `append`, `pop`, `StrMap.get`) are called out-of-line from every other unit of a split build. Repro (scratch `main.aye`): 250 small functions `g0`..`g249` called from `main` (so the program is split, `SPLIT_MIN_FUNCS` = 200), then `fn hot(l: *List(u32), i: usize) u32 { return l.items()[i] }`; `aye build main.aye --mode safe`, `otool -tV repro -p _aye_f_hot` shows `bl _aye_m_330std_3a_3alist_3a_3aList_28u32_29_items`. Proposed change, in order of preference:

1. `aye/src/cgen.rs` (`Parts::split`, :1753, and the emit of function definitions): emit a function whose body is small (no loop, a few OIR instructions, as the generic accessors are) as `static inline` in the header instead of in one unit, so every unit has its own copy and clang can inline it. Measure: `nm` on `target/dweller` loses the `items` symbols; bbc `<deduplicated_symbol>` share.
2. Or `aye/src/driver.rs` (`compile_parts`, :1315, `clang_flags` :37): `-flto=thin` for safe and fast when the program is split (costs link time).

Then the `buf[..count]` reads of this card can go back to `items()`.
