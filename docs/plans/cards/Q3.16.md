# Q3.16: `javascript:` URLs in a named top-level browsing context

- goal: `html/browsers/sandboxing` to its X2 target (Q3.15b left it one subtest under: 20/32, target 64). Its `sandbox-javascript-window-open` needs `window.open("javascript:...", name)` to run in the named popup and show the string it returns as the popup's document.
- before: Dweller never ran a `javascript:` URL as a navigation. A context request for one was loaded as a URL, and nothing ran.
- change, one slice: the top-level context requests that `loadInTab` serves (`dump`, `wpt`, and a window with renderers, where `javascript_url.html` prints the same lines):
  - `loadInTab` (`engine/contexts.aye`), which serves every request to navigate or open a top-level context, hands a `javascript:` URL to `navigateToJavascript`. A context with no page yet gets its initial `about:blank` first, as the spec's new browsing context does.
  - `runJavascriptUrl` runs the URL's percent-decoded source in the page shown, but only when the request's initiator is of the page's origin (spec: "navigate to a javascript: URL", same origin-domain). `javascriptResult` evaluates it and reports an exception as any script's. A result that is not a string changes nothing.
  - `showJavascriptResult`: a string result becomes a new document from that markup, with the old document's URL, origin, CSP and sandbox flags. It runs its scripts in the context (`attachLoading`, `runDocument`) and replaces the current history entry.
  - an `about:blank` document that a context request loads takes the origin of the request's initiator (`Page.creator`, `inheritCreator`), as the spec's "determining the origin" gives it its creator's. `sameOrigin` and `self.origin` read it (`sameCreatorOrigin`, `appendCreatorOrigin`). Without it, an `about:blank` popup counted as cross-origin with its opener (Q3.15b's "Known gap of popups"), and the origin check above would refuse its own opener.
  - a request carries whether its initiator's origin is opaque (`ContextRequest.opaque_initiator`, from the source's sandbox flags). An opaque initiator gives an `about:blank` no creator and reaches no page. Without that, a sandboxed frame without `allow-same-origin`, loaded from a URL of the popup's origin, ran its `javascript:` URL in that popup (shown with a build that skips the check: the test page printed `opaque frame:`).
  - `window.open` checks the opener's CSP before it asks for a `javascript:` URL (`javascriptUrlRefused`: `script-src-elem` with the inline check of type navigation, so a hash needs `'unsafe-hashes'`). It reports the violation (console and `securitypolicyviolation`). A refused URL navigates nothing; a new popup still opens, with `about:blank`.
- tests: `sandbox::javascript_url_in_named_popup` (`browser/tests/sandbox/javascript_url.html`):
  - same-origin popup: the script runs, and the written document has the popup's URL and the opener's origin;
  - popup of another origin (`localhost`): nothing runs;
  - sandboxed frame without `allow-same-origin` (`javascript_url_frame.html`, loaded from the popup's origin): nothing runs;
  - a number result: the document is kept.

  `sandbox::javascript_url_refused_by_csp` (`javascript_url_csp.html`): under `script-src 'nonce-a'` the popup runs nothing, and the opener gets `script-src-elem` `inline`.
