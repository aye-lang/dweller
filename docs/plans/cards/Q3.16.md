# Q3.16: `javascript:` URLs in a named top-level browsing context

- goal: `html/browsers/sandboxing` to its X2 target (Q3.15b left it one subtest under: 20/32, target 64). Its `sandbox-javascript-window-open` needs `window.open("javascript:...", name)` to run in the named popup and show the string it returns as the popup's document.
- before: Dweller never ran a `javascript:` URL as a navigation. A context request for one was loaded as a URL, and nothing ran.
- change, one slice: the top-level context requests that `loadInTab` serves (`dump`, `wpt`, and a window with renderers, where `javascript_url.html` prints the same lines):
  - `loadInTab` (`engine/contexts.aye`), which serves every request to navigate or open a top-level context, hands a `javascript:` URL to `navigateToJavascript`. A context with no page yet gets its initial `about:blank` first, as the spec's new browsing context does.
  - `runJavascriptUrl` runs the URL's percent-decoded source in the page shown, but only when the request's initiator is of the page's origin (spec: "navigate to a javascript: URL", same origin-domain). `javascriptResult` evaluates it and reports an exception as any script's. A result that is not a string changes nothing.
  - `showJavascriptResult`: a string result becomes a new document from that markup, with the old document's URL, origin, CSP and sandbox flags. It runs its scripts in the context (`attachLoading`, `runDocument`) and replaces the current history entry.
  - an `about:blank` document that a context request loads takes the origin of the request's initiator (`Page.creator`, `inheritCreator`), as the spec's "determining the origin" gives it its creator's. `sameOrigin` and `self.origin` read it (`sameCreatorOrigin`, `appendCreatorOrigin`). Without it, an `about:blank` popup counted as cross-origin with its opener (Q3.15b's "Known gap of popups"), and the origin check above would refuse its own opener.
  - a request carries whether its initiator's origin is opaque (`ContextRequest.opaque_initiator`, from the source's sandbox flags). An opaque initiator gives an `about:blank` no creator and reaches no page. Without that, a sandboxed frame without `allow-same-origin`, loaded from a URL of the popup's origin, ran its `javascript:` URL in that popup (shown with a build that skips the check: the test page printed `opaque frame:`).
  - `window.open` checks the opener's CSP before it asks for a `javascript:` URL (`javascriptUrlRefused`: `script-src-elem` with the inline check of type navigation, so a hash needs `'unsafe-hashes'`). It reports the violation (console and `securitypolicyviolation`). A refused URL navigates nothing; a new popup still opens, with `about:blank`.
- tests: `sandbox::javascript_url_in_named_popup` (`browser/tests/sandbox/javascript_url.html`):
  - same-origin popup: the script runs, and the written document has the popup's URL and the opener's origin;
  - popup of another origin (`localhost`): nothing runs;
  - sandboxed frame without `allow-same-origin` (`javascript_url_frame.html`, loaded from the popup's origin): nothing runs;
  - a number result: the document is kept.

  `sandbox::javascript_url_refused_by_csp` (`javascript_url_csp.html`): under `script-src 'nonce-a'` the popup runs nothing, and the opener gets `script-src-elem` `inline`.

## Slice 2, 2026-11-22: `about:blank`, frames and a page's own `location`

- `about:blank` was not a document Dweller could load: a top-level `about:blank` was the error page "this kind of URL is not supported yet", with its URL. In `dump` the written document of slice 1 replaced it, but the window with one process showed it, and an opener could not read its `about:blank` popup (`SecurityError`, a build of `main` of 2026-11-21). A document request for `about:blank` now answers an empty `text/html` response (`requestLive`, `net/is-about-blank.aye`; spec: fetch's scheme fetch). Test `sandbox::blank_popup_is_an_empty_document`: the window with one process shows `url about:blank` and no error page, and the opener reads `popup body ""`.
- a frame whose `src` is a `javascript:` URL (`frameSourceJavascript`, from `loadFrame` and `reloadFrame`): the parent's CSP is checked as for `window.open`, and the violation goes to the parent. When the frame's initial `about:blank` is of the parent's origin, the URL runs in it (`runFrameJavascript`); a string result is the frame's written document (`Page.opened_doc`, shown as Q3.15b's written frames are).
- a page that sets its own `location` (`href`, `assign`, `replace`) to a `javascript:` URL: the setter dropped it. It now checks the page's CSP and queues a task (`queueJavascriptUrl`, a `Timer` with `javascript_url`) that runs the URL in the page (`runQueuedJavascriptUrl`). A frame's string result is its written document. A top-level page's is kept in its `opened_doc`, and the tab shows it (`showOwnJavascriptResult`, as slice 1's `showJavascriptResult`) where the engine holds the tab: a popup in `pumpContexts`, the window with one process in `afterScripts`. A navigation of a frame that another page asked for (`followFrameNavigation`) and a popup's (`pumpContexts`, the window's `afterScripts` with one process) run it the same way.
- a link whose `href` is a `javascript:` URL, with no target or `_self` (`followJavascriptLink`, from `activate`, so for a click in the window, in a renderer, by an agent or by a script): it queues the same task in the link's page. The click did nothing before. Test `sandbox::javascript_url_link_runs` (`javascript_url_link.html`, `dump` and the window with renderers).
- tests: `sandbox::javascript_url_of_frames_and_location` (`javascript_url_frames.html`, `javascript_url_self.html`; the window with one process): `src frame: from the src`, `self frame: navigated itself`, a popup that sets its own `location` runs it, and one whose URL returns a string shows it (`javascript_url_self_string.html`: `popup: its own string`). `javascript_url_refused_by_csp` also has a frame whose `src` is refused: the page gets its violation and the frame stays empty.
- files: new `browser/net/is-about-blank.aye`, `browser/engine/{frame-source-javascript,run-frame-javascript,queue-javascript-url,run-queued-javascript-url,follow-javascript-navigation,initiator-href,is-javascript-url}.aye`, `browser/engine/follow-javascript-link.aye`, `browser/engine/show-own-javascript-result.aye`, `browser/tests/sandbox/{blank_popup,javascript_url_frames,javascript_url_self,javascript_url_self_string,javascript_url_link}.html`; changed `browser/net/net.aye`, `browser/engine/{frames,forms,script,window_api,contexts}.aye`, `browser/ui/window.aye`, `browser/ui/window.aye`.
