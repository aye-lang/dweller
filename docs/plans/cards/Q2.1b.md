# Q2.1b: split `ui/window.aye` into the window and a page view

- goal: the page state of the shown tab and the code that works on it leave `ui/window.aye` for a page view in its own module, `browser/ui/pageview/`, along the boundary that the IPC of `docs/process-model.md` §2 cuts in Q2.2/Q2.3. Still one process, no IPC, no threads. Behavior, test output and goldens stay the same.
- cause: `window.aye` (2299 lines) held the window (SDL, chrome, tabs, loop) and the page view (display list, layer promotion, scroll, find, script input) in one struct `Ui`. Q2.2 needs the page half as one piece it can move into a renderer.
- design:
  - The directory is `pageview` because an Aye module path is identifiers (`import ui.pageview`). A module cannot import the module that imports it (spec §12), so the page view does not know `Ui`: it gets coordinates in the page's viewport (window y minus the toolbar and tab strip), the find query, and `from_timers` as arguments.
  - `pageview.PageView` owns what `Ui` had for the page: `tab` (the shown tab), `list`, `sigs` (moved from `PageDraw`), `relist`, `list_scroll`, `laid_version`, `matches`, `current`, `promote`, `anim`, `anim_els`, `anim_seq`, `relayout_ms`, `images_at`, and the viewport (`width`, `layout_height`, `view_height`, `scale`). It sets its own `dirty` and `repaint`; the window takes them after each call (`takeDamage`, `Ui.noteDamage`).
  - `Ui.view()` sends `resize` with the window's viewport before each call, so the page view never sees an old size. The `Ui` methods that other `ui/` files call (`relayout`, `maxScroll`, `scrollTo`, `buildList`, `dropList`, `linkAt`) stay and only forward.
  - Code moved, not rewritten. The splits: `keyScripts` keeps the key name and detail line in the window and the target and dispatch in `inputKey`; `pointerEvent` keeps the window's checks (dropdown, sign-in sheet, viewport, lock) and the detail line, and `inputPointer` returns null when it dispatched nothing (then no `afterScripts`, as before); `clickScripts` keeps the dropdown check and the relayout and title after a dispatch.
- entry functions and the IPC group each becomes:

  | Function | Today | Group (message) |
  |---|---|---|
  | `PageView.init`, `shutdown` | `Ui.init`, `Ui.deinit` | lifecycle (`init`, `shutdown`) |
  | `visible(view, tab)` | `showTab` sets `ui.tab` | lifecycle (`visible`) |
  | `hostState(view, what)` | `Ui.hostState` (lock, fullscreen) | lifecycle (`visible`) and input |
  | `stepScripts`, `imagesIn` | `Ui.stepScripts`, `Ui.imagesIn` | navigation (`body_data`, `loading`); renderer-internal after Q2.2 |
  | `resize(view, w, layout_h, view_h, scale)` | the window's size, read each time | frames (`resize`) |
  | `relayout`, `needsLayout`, `buildList`, `dropList` | `Ui.relayout` and its parts | frames; renderer-internal after Q2.2 (it lays out on its own) |
  | `frame(view)`, `hasFrame`, `paintMatches` | the page part of `Ui.draw` | frames (`frame`) |
  | `takeDamage(view)` | `Ui.dirty`, `Ui.repaint` set by page code | frames (`frame{damage[]}`) |
  | `maxScroll`, `scrollBy`, `scrollTo`, `scrollSideways`, `scrollFrame` | the `Ui` scroll methods | input (`input`, `input_ack{dx, dy}`) |
  | `inputClick`, `inputWheel`, `inputKey`, `inputPointer`, `inputPress`, `inputHover` | `clickScripts`, `wheelScripts`, `keyScripts`, `pointerEvent`, `press`, `hoverAt` | input (`input{word}`) |
  | `linkAt(view, x, y)` | `Ui.linkAt` | input (`hit_test`) |
  | `find(view, query, jump)`, `findNext(view, backwards)` | `findAll`, `nextMatch`, `showMatch` | input (`find`, `find_reply`) |
  | `snappedScroll` | `ui/snapped-scroll.aye` | helper of `frame`, also used by the window's compositing |

- left for Q2.2/Q2.3 (the window still reaches the page through `ui.tab.page`): the loop's timers and wake times (the renderer's own loop, Q2.2); navigation and history (`go`, `goBy`, `advanceLoad`, `navigated`, `afterScripts`' `takeNavigation` and `takeScriptScroll`; Q2.6a); the link under the mouse for the status line and cursor (`mouseMoved`, which needs `forms.aye`'s `overTextField`; `status_url`, `cursor`, Q2.3); pointer lock and fullscreen requests (`hostRequests`, Q2.3); the window title (`title`, Q2.3). `pagedraw.aye` (the page's pixels) and `forms.aye` are still in `ui/` and read `ui.page_view` fields; they move with Q2.2/Q2.3. `agents.aye`, `chrome.aye`, `script.aye`, `show-early.aye` and `draw-ringed.aye` read `ui.page_view` fields too.
