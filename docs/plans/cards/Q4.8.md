# Q4.8: finish the matched-properties cache

## Status: done, 2026-11-16

- goal: elements with the same matched rules and the same inherited parent values share computed values (P4.75w) wherever they can. P4.75w left the elements that could not use the cache (inline styles and hints, since keyed by `inlineKey`) and a table whose misses it read as "different rules or parents, not evictions".
- found (a throwaway build that counted, per element, why the cache was not used and what a miss replaced; not committed):

  | page (`dump --style --js`) | not cacheable (root / container units / centring parent / `inherit` / over 48 rules) | shared with a sibling | hits | misses | of them a miss that replaced another key |
  | --- | --- | ---: | ---: | ---: | ---: |
  | `tests/perf/feed.html` | 2 / 0 / 0 / 0 / 0 | 117 | 224 | 225 | 219 |
  | `tests/perf/paint_heavy.html` | 2 / 0 / 0 / 0 / 0 | 0 | 276 | 8 | 0 |
  | `tests/jsdom/class_sets.html` | 1 / 0 / 0 / 0 / 0 | 195 | 3029 | 26 | 6 |
  | `tests/jsdom/shadow_restyle.html` | 1 / 0 / 0 / 0 / 0 | 398 | 2234 | 58 | 10 |

  Nothing on these pages is uncacheable but the root. What was lost was the table: the slot was `hash % 256`, and the hash's low bits come from the low bits of the key words (the cascade level and the specificity), which the rule and sheet numbers in the high halves never reach through a multiply. Feed's 7 keys shared slots and replaced each other on every other element. A first fix (a mixed hash, still one slot per key) fixed feed and broke `class_sets.html` (402 of 433 misses were two keys taking turns in one slot), so one slot per key is not enough either.
- design (Blink's `MatchedPropertiesCache` is a hash map; here a fixed table, as P4.75w chose):
  - `matchedSlot`: the slot comes from the hash after a 64-bit finalizer (xor-shift, multiply, xor-shift).
  - two places per key (`matchedSlot(h)` and `matchedSlot(h ^ 0x9E37…)`); a miss replaces the unused one, else the one used longer ago (`MatchedEntry.stamp`, `MatchedCache.clock`, `matchedVictim`). The table stays 256 entries.
  - `sameEntry` is the hit test, for both places.
  - `noteMatchedCache`: each cascade and subtree restyle ends with a `DWELLER_TIMING` record `matched_cache` whose label is the styles' hits and misses so far, so the rate is read without a special build.
- files: new `browser/css/matched-slot.aye`, `matched-victim.aye`, `same-entry.aye`, `note-matched-cache.aye`, `write-counts.aye`; `css/matched-values.aye` (the lookup), `css/matched-cache.aye` (`stamp`, `clock`), `css/cascade.aye` (2 lines). Test `matched_cache_keeps_feed_keys` (tests/browser/jsdom.rs).
- blink: `core/css/resolver/matched_properties_cache.cc` (`Find`, `Add`), `core/css/resolver/style_resolver.cc` (`ApplyMatchedCache`).
