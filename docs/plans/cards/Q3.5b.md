# Q3.5b: WPT over https; mixed-content and upgrade-insecure-requests measured

- goal: the WPT runner serves https with WPT's own certificate, and Dweller trusts WPT's test CA only in those runs. `.https.` tests in the existing areas stop being skipped. The new areas `mixed-content` and `upgrade-insecure-requests` are measured and get thresholds. `upgrade-insecure-requests` also upgrades the page's same-host navigations, and its frames inherit it.
- design:
  - test CA: `net/test-ca.aye` `testCa` gives `DWELLER_TEST_CA` only when `DWELLER_TEST=1` is set too. `setTls` uses it for `CURLOPT_CAINFO`. Without the flag, the default CA store is used and nothing else changes. The Rust tests that used `DWELLER_TEST_CA` (`tls_errors`, `cert_bypass`, `hsts`, `mixed_content`) now set both variables.
  - runner (`browser/tools/wpt.py`): `SKIP_NAME` no longer skips `.https.`. `discover` marks a test `https` when its name has `.https.`. `run_area` loads it from the server's `https_base`. `trust_test_ca` sets `DWELLER_TEST=1` and `DWELLER_TEST_CA=<wpt>/tools/certs/cacert.pem` for the run. The static `Server` adds a second listener with an `ssl` context from `tools/certs/web-platform.test.{pem,key}` (DNS `web-platform.test` and its subdomains). Its `https_base` is `https://web-platform.test:PORT`, and `DWELLER_RESOLVE` maps that host to 127.0.0.1. Upstream `wpt serve` (`wpt_upstream.py`) already serves https on 8443 and 8444 with the same pregenerated certificates. The config now names those ports, `DWELLER_RESOLVE` covers them for every host, and start-up waits for both the http and the https port.
  - areas: `wpt_areas.json` has `mixed-content` and `upgrade-insecure-requests` (`upstream`: they need `.sub.` substitution and `common/security-features` handlers). Each threshold is the measured score rounded down to a multiple of 5 points, as for the other areas.
  - navigations: `net/upgrades-navigation.aye` `upgradesNavigation`. A top-level document request (`Kind.Document`, no `top`) from a page that has `upgrade-insecure-requests` goes to https when the target's host equals the page's host and is not potentially trustworthy. The port is not compared: Blink's insecure navigations set holds hosts only, and the WPT tests use `http://HOST:HTTPS_PORT`. `secureHref` checks it next to HSTS, so links, forms, `location` and redirect hops all get it. Frame navigations started by such a page were already upgraded by `mixedContent`.
  - frames: `engine/inherit-upgrades.aye` `inheritUpgrades`, called from `placeFrame`. A frame placed in a page whose `originPage` upgrades is added to `Session.upgrading` itself, so its own subresources and navigations are upgraded. `about:` frames are skipped: their requests already use the creator's URL as initiator (`originPage`). `upgradesInsecure` is now `pub`.
  - audio and video: Dweller loads no media (no `<audio>`/`<video>` fetch, no media `Kind`), so there is nothing to upgrade instead of block. This is left.
- files: new `browser/net/{test-ca,upgrades-navigation}.aye`, `browser/engine/inherit-upgrades.aye`, `browser/tests/hsts/{uir-nav,uir-frame,uir-inner}.html`, `browser/tools/conformance/{mixed-content,upgrade-insecure-requests}.json`. Changed: `browser/net/{set-tls,secure-href,upgrades-insecure}.aye`, `browser/engine/frames.aye`, `browser/tools/{wpt.py,wpt_upstream.py,wpt_areas.json}`, `browser/tools/conformance/{fetch_api.json,history.csv}`, `docs/conformance.md` (generated by `conformance.py table`), `tests/browser.rs` (`tls_errors`, `mixed_content`, and the `DWELLER_TEST` flag).
- Chromium files read: `third_party/blink/renderer/core/loader/mixed_content_checker.cc` (`UpgradeInsecureRequest`: a top-level navigation is upgraded only when its host is in the document's insecure navigations set, which holds the document's own host; potentially trustworthy URLs are not upgraded; a nested frame's document gets its parent's insecure request policy).
