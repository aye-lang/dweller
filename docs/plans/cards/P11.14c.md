# P11.14c: WebGL texture uploads from DOM sources and second contexts

- goal: P11.14b's goals (2) and (3), its failure groups 1, 3, 4 and 5: (1) `texImage2D/3D` and `texSubImage2D/3D` from DOM sources give the right texels for every combination of the WebGL 2 TexImageSource table, honouring the unpack state; (2) a second context and a WebGL canvas as a source; (3) `createImageBitmap(Blob)` and exact `ImageData` texels.
- design:
  - Blink's conversion pipeline (unpack → alpha op → pack), on the straight RGBA8 pixels of the source. `packTexel` premultiplies (bytes truncated as Blink's `uint8` path, floats as `c/255 * a/255`), then packs: bytes (also the `*_INTEGER` formats), `HALF_FLOAT` (truncated), `FLOAT`, the packed 16-bit types, `UNSIGNED_INT_10F_11F_11F_REV` (from the half-float bits) and `UNSIGNED_INT_2_10_10_10_REV`. `domChannels` picks the components of each format (`LUMINANCE_ALPHA` is r, a; `ALPHA` is a).
  - `domPixelSize` takes the whole table: integer formats only with `UNSIGNED_BYTE`; anything else is `INVALID_OPERATION`, as before.
  - Sub-rectangles: `UNPACK_SKIP_PIXELS`/`SKIP_ROWS` select the source rectangle (`DomRect`) of the flipped source, as the suite expects; 3D uploads take `depth` slices `UNPACK_IMAGE_HEIGHT` rows apart. A rectangle outside the source is `INVALID_VALUE` (the existing golden). The packed rows are tight; GL's unpack state (now with `UNPACK_IMAGE_HEIGHT`) is reset around the call and restored.
  - `texImage3D`/`texSubImage3D` from DOM sources: `webgl-tex-dom-3d.js` wraps `_texImage3D` and sends DOM sources to `webglTex`, whose spec gains `zoffset`, `depth` and `image height` (depth 0 is 2D).
  - Second contexts already worked; the 78 "Unable to fetch WebGL rendering context" pages were `OffscreenCanvas.getContext('webgl'|'webgl2')`, which returned null. It now makes a context on the OffscreenCanvas's backing canvas (registered for snapshots), so the WebGL-canvas pages run their OffscreenCanvas cases.
  - The 34 `createImageBitmap(Blob)` failures were `XMLHttpRequest` with `responseType = 'blob'` (the 3D pages); `response` now gives a `Blob` or an `ArrayBuffer` of the fetched bytes.
  - `browser/tests/webgl/textures.html`: "ImageData as FLOAT" used `RGBA32F`/`RGBA`/`FLOAT`, which the WebGL 2 table allows; it now uses `RGBA8`/`RGBA`/`FLOAT` (still `INVALID_OPERATION`), so the golden is unchanged.
