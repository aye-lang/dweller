# Q5.3: `alert`, `confirm` and `prompt` as real dialogs

- goal: the three calls stop the script, show a dialog on the tab, and return what the person chose: `alert` nothing, `confirm` true or false, `prompt` the text or null. Row Q5.3 of `foundations.md` (Chromium `core/frame/local_dom_window.cc`, `chrome/browser/ui/javascript_dialogs/`). Measured by window tests in one process and with `DWELLER_PROCESS=site`.
- facts found first (2026-11-16):
  - Today the three are console messages: `ak.alert(kind, message)` (`engine/window_api.aye` `akAlert`) adds `[alert] text` to the console, and the prelude returns `false` for `confirm` and `null` for `prompt`. A sandboxed frame without `allow-modals` gets nothing (kept).
  - The window already stops a script for a question: the "page is not responding" bar (`ui/ask-stuck.aye`): the engine calls a hook (`engine.setHangHook`), the UI draws and runs a loop of its own (`SDL_WaitEventTimeout`, `ui.handle`, `resumeScript` for the test's `--events` words) until answered, and a headless run (`--frames` or `--until-idle`) answers by itself. The sign-in sheet (`ui/auth.aye`, `chrome.aye` `drawSheet`) is a modal with text fields (`Field`), keys, clicks, and lines in `--state`.
  - With a renderer per tab or site the browser process owns dialogs (`docs/process-model.md`: R→B (s) `dialog{frame, kind, text, default}`; the origin is taken from the browser's tree, never from the message). A renderer already asks the browser and waits for storage and cookies (`engine.setStorageRemote`).
  - `dump --js` and `dweller wpt` have no window.
- slices:
  1. The engine's dialog hook: `engine.setDialogHook`; `ak.dialog(kind, message, default)` returns the answer; without a hook (dump, wpt, a worker's page) the calls answer as today (nothing, false, null) and the console line stays. Verify: the goldens that hold `[alert]` lines do not change; a dump test of the return values.
  2. The dialog in the window, in one process: a sheet on the tab with the message, OK and Cancel, and a text field for `prompt`; Return accepts, Escape cancels; the script waits in a loop of the UI as the stuck bar does; `--state` prints the open dialog; a headless run whose event script has ended dismisses it. Verify: a window test: accept and cancel of each kind, a typed prompt.
  3. With `DWELLER_PROCESS=site`/`tab`: the renderer asks the browser (IPC 130 `Dialog`, 131 `DialogReply`) and waits; the browser shows the sheet of slice 2 on that renderer's tab and answers; a renderer waiting for an answer is not "hung". Verify: slice 2's test with `DWELLER_PROCESS=site`.
  4. Whose dialog: the title names the origin ("example.org says", "An embedded page at … says" for a frame of another origin); a dialog of a tab in the background; an agent's tab (no person to answer). Verify: window tests of each.
- defaults taken (nobody to ask): a headless run dismisses a dialog nobody answers (Cancel) instead of waiting; a dialog of a background tab brings its tab to the front; Chromium's "prevent this page from creating additional dialogs" check box is not built.

## Done (slices 1 to 3 and the title of slice 4, 2026-11-16)

- slice 1: `engine.setDialogHook` (`engine/dialog-hook.aye`: `DialogAsk { kind, message, preset, href, top }`, the hook answers accepted or not and writes the typed text); `ak.dialog(kind, message, default)` (`ak-dialog.aye`) returns the text of an accepted `prompt`, else a boolean, and undefined without a hook or in a sandboxed frame without `allow-modals`. The prelude's `alert`, `confirm`, `prompt` keep the console line and take the answer; without a hook they answer as before (nothing, false, null), so `dump --js`, `dweller wpt` and the goldens with `[alert]` lines are unchanged.
- slice 2: the sheet (`ui/js-dialog.aye` the state, `dialog-sheet.aye` the rectangles, `draw-dialog.aye`: the title, up to 4 lines of the message, the text field of a prompt, Cancel and OK). `Ui.handle` gives every event to `dialogInput` while it is open (Return or OK accepts, Escape or Cancel dismisses, text and editing keys go to the field, a quit dismisses). In one process the hook runs `awaitDialog`, a loop of the UI inside the script's call, as `askStuck` does; `--state` prints `dialog <kind> [<title>] <message> input <text>`. A headless run (`--frames`, `--until-idle`) dismisses a dialog once its `--events` words are used up.
- slice 3: IPC kinds **130 `Dialog { kind, message, preset }`** (renderer to browser) and **131 `DialogReply { accepted, typed }`**. The renderer's hook sends and waits (`renderer/dialog-remote.aye`, `awaitReply`; a `Shutdown` that arrives meanwhile ends the wait). The browser keeps the question on the process (`TabProcess.asked`, `take-dialog.aye`: one at a time, kind 0 to 2, at most 64 KiB each), shows it from `pollTabSlot` (`settle-asked.aye`, also for a child frame's process) and answers when the sheet closes; the dialog closes if its process goes. A process with an open question is not pinged into "not responding" (`watch-hang.aye`). Event words for tests: `renderer:dialog` waits until a dialog is open, `dialog:keep` leaves a renderer's dialog open at the end of a headless run.
- slice 4 (part): the title is "<host> says", "An embedded page at <host> says" when the document's origin differs from the top one, "This page says" without an http origin (`dialog-title.aye`). With a renderer per site both URLs come from the browser's own records (`committed`), not from the message. A Space (an agent's window) gets no sheet: the call is dismissed at once.
- fix on the way: after the wave merge a renderer's pending fetch is found by `load_id`, not by the wire id; `ready-remote.aye`/`take-remote.aye` of Q5.8 looked it up by the wire id, so an `EventSource` stream with `DWELLER_PROCESS=site` delivered nothing until the response ended (`eventsource_open_stream` failed). They use `pendingByLoad` now.
- shared numbers: IPC 130 and 131 (range 130–139); `ipc/from-renderer.aye` lists both. No host object tag, no CSS property.
- verify (2026-11-16, cloud Linux): `cargo test --release --test browser`: 267 passed, 0 failed (298 s), with the new `window_dialogs_answers` (one process: accept and cancel of each kind, a typed prompt, an unanswered one dismissed), `window_dialogs_site` (the same answers with `DWELLER_PROCESS=site`), `window_dialogs_open_sheet` (the `--state` line and the picture `browser/tests/ui/dialogs_prompt.png` of an open prompt; the golden is new, read by eye: title, message, field with the typed "Bo", Cancel, OK). `DWELLER_PROCESS=tab` checked by hand. `aye test browser`: 318 passed. `check_taste.py`, `check_layers.py`, `gen_property_ids.py --check`, `aye check browser`: exit 0.
