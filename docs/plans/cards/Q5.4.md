# Q5.4: IME composition events and the candidate window at the caret

- goal: text typed through an input method (Chinese, Japanese, Korean, dead keys) shows in the field while it is composed, underlined, with `compositionstart`, `compositionupdate`, `compositionend` and the `beforeinput`/`input` events of `insertCompositionText` for the page's scripts, and the system's candidate window opens at the caret; in the page's text fields and in the address bar, in all three process modes. Row Q5.4 of `foundations.md` (F1; Chromium `core/editing/ime/input_method_controller.cc`, `ui/base/ime/`).
- facts found first (2026-11-16):
  - The window handles `SDL_TEXTINPUT` only (`ui/window.aye`): what an input method composes (`SDL_TEXTEDITING`, 0x302) is dropped, so a person sees nothing until they commit, and scripts see one plain `input`.
  - `SDL_SetTextInputRect` is never called: the candidate window opens wherever the system puts it (on macOS at the bottom left of the screen).
  - `CompositionEvent` exists in the prelude; `InputEvent` takes `isComposing` and `inputType`; `hostEvent` makes every `input` an `insertText`.
  - `SDL_TEXTEDITING` carries at most 31 bytes; `SDL_HINT_IME_SUPPORT_EXTENDED_TEXT` gives `SDL_TEXTEDITING_EXT` (0x305, SDL 2.0.22) with a heap string.
  - `contenteditable` editing is another lane's card (Q5.10): this card is `input` and `textarea`.
- slices (each with its verify):
  1. The engine: the composition of a document (the field, the byte range of the composed text in its value), `engine.composeText` (an update: start if none, replace the range, the events; an empty text cancels), `engine.commitText` (the committed text replaces the range, `compositionend`), `engine.finishComposition` (the focus left: the composed text stays, `compositionend`), `engine.compositionRects` for the underline. Verify: slice 2's window tests.
  2. The window, one process: `SDL_TEXTEDITING` and `SDL_TEXTEDITING_EXT` go to the page's focused field or to the window's own focused field (address bar, find bar, sign-in), the underline is drawn, `SDL_SetTextInputRect` follows the caret (page fields, with zoom, and the address bar). Test hooks: the `--events` word `compose:TEXT` is an `SDL_TEXTEDITING`; `--state` prints `composing TEXT` and, once an input method was used, `ime-rect X Y W H`. Verify: `tests/browser/window_ime.rs`: the events and their order and data seen by a page for compose, update, commit and cancel; the value while composing; the underline's pixels; the rect at the caret, moving with the text; the address bar composing and committing.
  3. `DWELLER_PROCESS=tab|site`: IPC kinds 198 `CaretRect{on, x, y, w, h}` (R→B, when it changes), 199 `Compose{seq, typed}` (B→R); a commit is the existing `Text`. Verify: the same tests with `DWELLER_PROCESS=site`, the same PNG as one process.
- decisions (nobody to ask; the plan's defaults):
  - Event order on an update: `compositionstart` (first only), `beforeinput`, `compositionupdate`, the value changes, `input`; on a commit: `beforeinput`, `compositionupdate` (when the text differs), the value, `input`, `compositionend` (UI Events §5.7.5; Chromium's order).
  - `keydown` during a composition is not rewritten to `key: "Process"`, `keyCode` 229: SDL's cocoa backend gives the keys to the input method first and the window sees none of them. Left to check on the Mac.
  - The composed text is in the field's value while it is composed (as in Chromium and Firefox), so a script reading `value` on `input` sees it.
  - The caret's place inside the composed text (`SDL_TextEditingEvent.start`) is not shown: the caret stays at its end.
- references: UI Events (https://www.w3.org/TR/uievents/#events-compositionevents), Input Events 2 (`insertCompositionText`); Chromium `third_party/blink/renderer/core/editing/ime/input_method_controller.cc` (`SetComposition`, `CommitText`, `FinishComposingText`), SDL `SDL_events.h`, `SDL_keyboard.h`.

## Status: done, 2026-11-17

Done note. Built whole for the three process modes.
- The engine (12 files): `Controls.composing`, `compose_start`, `compose_len`; `composeText`, `commitText`, `finishComposition`, `settleComposition` (a composition whose field lost the focus or left the document ends), `leaveComposition` in `setFocus` (so `compositionend` comes before `blur`), `rangeRects` (taken out of `selectionRects`, which now calls it) and `compositionRects` for the underline; four lines of `hostEvent` in the prelude make `CompositionEvent`s and the `insertCompositionText` `InputEvent`s.
