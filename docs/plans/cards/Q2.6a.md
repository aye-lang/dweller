# Q2.6a: navigation and session history live in the browser

- goal: with `DWELLER_PROCESS=tab`, the browser owns the top-level navigations and the joint session history of a tab. Every navigation a renderer starts (links, forms, `location.href=`/`assign`, `location.reload()`, `history.back/forward/go` to another document, `form.submit()`) is a request the browser decides; the browser commits each document in its history, records the renderer's same-document navigations (fragments, `pushState`/`replaceState`) after checking them, and decides back, forward and reload: a back or forward within the shown document goes to the renderer as a same-document traversal (popstate, hashchange), not as a load. A report that does not match what the browser asked for kills the renderer. Without the flag nothing changes.
- design:
  - the history: the tab's `engine.SessionHistory` in the window process (`slot.session.tab.history`, the one `--state` prints as `history N of M`) is the only history of the tab. Each committed document gets a number of the browser's (`tp.doc_seq`), kept in the entry's `doc`; an entry pushed by the renderer has the `doc` of the current entry. Entries keep the URL, the serialized state and the scroll offset (from the renderer's `frame` messages while nothing loads). Titles stay per tab (`tp.title`), not per entry.
  - IPC messages added (type codes in order, all on the tab's frame id): 39 B→R `session_history{index, length, scroll, nulls, state}` (sent right before every `navigate`: the place the next document takes, the length of the history then, and the entry's scroll and state, `nulls` 1 for no state); 40 R→B `history_go{index}` (a script's traversal to an entry of another document, and `location.reload()` as the current index); 41 B→R `traverse{index}` (a back or forward within the shown document). `same_document` (18) now carries `{url, index, nulls, state}`: the renderer's current index and the entry's state after the change.
  - the browser's decisions (`ui/`): `beginNavigation` (links, forms, script navigations) checks the scheme rule (`net.initiatorMayLoad`) and now refuses a top-level `data:` URL from a page (`error: Not allowed to navigate top frame to data URL: URL`, no `navigate`, no kill: a page may try), then sends `session_history` for the entry after the current one and `navigate`. `queueNavigate` (address bar, back, forward, reload) sends `session_history` for the current entry. `loaded` of a pending navigation commits it (`commitEntry`): a renderer-started one pushes a new entry, a browser-started one gives its entry the final URL and the new document number. `goByInRenderer` (the window's back, forward, reload) and `history_go` go through `goToEntry`: an entry of the shown document sends `traverse`, any other entry (or reload) sends a fresh `navigate`. The document is fetched through the browser's net: the renderer's document request is answered only for the navigation the browser sent (Q2.4a's `fetchNavigates`).
  - the browser's checks (a failure logs `bad message: REASON PID` and kills): `same_document` with another origin than the committed document (`commitMatches`, `bad url`, as in Q2.3d), with `nulls` over 1, or whose index is neither the current entry (replace), the next one (push), nor an entry of the same document with the same URL (the renderer's own `history.back()` within its document), or, while a `traverse` is pending, not the index the browser asked for (`bad same_document`); `history_go` with an index past the end (`bad history_go`); `loaded` keeps Q2.3d's `commitMatches` check against the URL the browser navigated to. A second back or forward while a traversal is pending is dropped, and `renderer:loaded` waits for the pending traversal too.
  - renderer (`renderer/`): the renderer keeps a mirror of the browser's history (`r.history`) so that `history.length`, `history.state` and same-document traversals work in the page: `mirrorHistory` builds it from `session_history` before the load (placeholders with `doc` 0 for the other documents' entries), `engine.loadShared` (new, the `loadState` shape) puts the new document's entry at the current index before the scripts run (`adoptAt`, with the entry's state), and `sharedHistory` restores the entry's scroll offset. `scriptNavigation` (from `reportPage`, after every task) takes what a script asked (`engine.takeNavigation`): `To` → `begin_navigation`, `History` → `history_go`, `Reload` → `history_go` with the current index, `Submit` → the form's submission as `begin_navigation` (`sendSubmission`, shared with `submitAt`). `reportHistory` sends `same_document` when the URL, the current index or the entry's state changed. `traverseTo` runs a `traverse` as `engine.traverseInDocument` (popstate, then hashchange as a task).
  - test hook: `DWELLER_TEST_EVIL=pushstate` (the renderer reports every same-document change as `https://evil.example/`).
- Chromium read: `content/browser/renderer_host/navigation_request.cc` (the browser starts and commits every navigation; `CommitNavigationParams` carries `current_history_list_offset` and `current_history_list_length` to the renderer; renderer-initiated top-level `data:` is blocked), `content/browser/renderer_host/navigation_controller_impl.cc` (`GoToIndex`/`NavigateToEntry`: a traversal to an entry of the same document is a same-document navigation sent to the renderer, else a new navigation; `RendererDidNavigate` classifies a commit as a new or an existing entry), `content/browser/renderer_host/render_frame_host_impl.cc` (`DidCommitSameDocumentNavigation`: the URL is checked against the frame's origin, `CanCommitOriginAndUrl`, and a mismatch is a bad message). Dweller takes: the browser's controller holds the entries and the renderer only gets their count and its offset; a same-document change is a report the browser checks and records; a traversal in the document is sent to the renderer, not reloaded.
- files: `browser/ipc/{message,decode,put-payload,from-renderer,message_test,encode_test}.aye`; new `browser/engine/load-shared.aye`; `browser/renderer/{tab-renderer,serve-on,answer-all,adopt-page,load,report-page,submit-at}.aye`, new `browser/renderer/{take-session-history,mirror-history,shared-history,note-state,report-history,script-navigation,send-submission,traverse-to}.aye`; `browser/ui/{tab-process,begin-navigation,queue-navigate,renderer-sent,renderer-waits,window}.aye`, new `browser/ui/{send-session-history,commit-entry,same-document-entry,go-to-entry,go-by-in-renderer}.aye`; new `browser/tests/ui/renderer_history.html`; `tests/browser.rs` (new `window_renderer_history`, `window_history_api_in_renderer`; `window_login_in_renderer` checks `history 2 of 2`; `window_renderer_focus` expects the `url` and `history` lines to follow the renderer's pushState).

## Status: done, 2026-11-08

Left:
- iframes: navigations in frames (links, forms, `location` of a frame, `history` entries a frame adds) stay inside the renderer's engine and are not in the browser's history; they become browser decisions with the OOPIF steps (Q2.9+).
- the document is still read by the renderer's fetch (answered by the browser's net only for the navigation it sent); a `commit_navigation` that hands the renderer a response the browser already fetched, with `body_data`/`body_done`, comes with the process swap (Q2.6b), where the browser must see the response before it picks the process.
- `location.replace()` to another document pushes an entry in both processes (the engine's `Navigation` has no replace flag); meta refresh is not implemented in the engine; `window.open` into the same tab (`_self`) and named targets go through the engine's contexts, not `begin_navigation`.
- per-entry titles (no history menu needs them yet); the entries of a document that the browser loaded again on a back are not given back to the new document (a later traversal to them loads again, Chromium would treat them as same-document); a second back or forward pressed while a traversal is pending is dropped, not queued.
- a pushState during the load of a page is reported after `loaded` and recorded as a push after the committed entry; `same_document` that crosses a `navigate` the browser just sent still kills (Q2.3d's rule: no same-document report while loading).
- scroll restoration is sent with `session_history` and set before the first frame, but no test covers it with the flag (`window_history_steps` reads the window's own `scroll` line and loop records).
- agent navigations in a renderer (`agent_acts`) commit without a history entry, as before.
