# Q2.2b: a tab's frames from its renderer process through shared memory

- goal: behind `DWELLER_PROCESS=tab` the renderer of Q2.2a paints its tab, and the window shows those pixels. The browser makes two shared-memory buffers per tab, passes their fds to the renderer over the IPC socket (`SCM_RIGHTS`), the renderer paints the page into a free buffer and sends `frame`, and the window copies that buffer into the page area. The window's PNG of a page is the same as the one painted in the window's own process. Without the flag nothing changes.
- design:
  - `browser/ipc/` (both sides): `sendFds` / `recvFds` (`sendmsg` / `recvmsg` with one `SCM_RIGHTS` control message; `MsgHdr`, `IoVec`; `putRights` builds the control bytes, `takeRights` reads them: macOS `cmsghdr` is 12 bytes, Linux 16), `makeShared` (Linux `memfd_create`; macOS `shm_open` with `O_EXCL`, `shm_unlink` at once; then `ftruncate`), `mapShared` / `unmapShared` (`mmap MAP_SHARED`, read-only in the browser, read-write in the renderer), `Buffers` (the browser's ids: two new ids per size, the size, the buffer shown), `checkFrame`.
  - IPC messages added (type codes in order): 5 B→R `resize{width, height, scale, buffer}` with 2 fds (device px; `buffer` is the id of the first fd, the second is `buffer + 1`), 6 R→B `frame{buffer, width, height, scroll_x, scroll_y, damage}` (damage: u32 rects `x0 y0 x1 y1`, empty = whole), 7 B→R `frame_ack{buffer}`. All on the tab's frame id.
  - browser (`ui/`): `giveBuffers` (each poll, once `hello` came and the out buffer is empty) gives new buffers when the page area's device size is not the buffers' size; the `resize` bytes go in the same `sendmsg` as the fds, what the socket did not take goes to the out buffer. `showTabFrame`: the frame is shown, and the buffer shown before is acked (`frame_ack`), so the renderer never writes a buffer the window reads. `drawTabFrame` copies the shown buffer into the page area after the window's own page (and `pageOverlays` makes such draws whole). `unmapBuffers` when buffers change and when the tab ends.
  - renderer (`renderer/`): `TabRenderer` keeps the page, the fds received, the two mappings and which are free. `recvFds` replaces the plain reads; `resize` takes the two oldest fds (`takeBuffers`), `navigate` keeps the page (`load`), `frame_ack` frees a buffer; after each batch `paintFrame` lays out at `width / scale` x `height / scale`, paints with the system font (the fixed one when there is none, as the window does by default), copies into a free buffer and sends `frame`. Test hook `DWELLER_TEST_EVIL=frame`: the frame says one px too wide.
  - test hooks: `--events` word `renderer:frame` (waits for the first frame shown); `--state` line `renderer-frame W H`.
- the browser's checks (`checkFrame`, from `rendererSent`; any failure logs `bad message: REASON PID` and kills, as Q2.2a): `frame` comes on the tab's frame id (`unexpected frame`); its buffer is one the browser gave (`unknown buffer`); not the one the window shows (`buffer in use`); its size is the buffers' size (`wrong size`); the damage is whole rects (`bad damage`) inside the buffer (`damage outside`). A frame for a buffer of an earlier size passes and is dropped (it crossed a `resize`). The renderer never sends an fd or a size the browser has to trust: the browser makes the buffers and keeps their size.
- Chromium read (idea only): `content/renderer/render_thread_impl.cc` (one renderer thread per process that owns the compositor and talks to the browser over one channel; Dweller: one socket, frames on the tab's frame id); `components/viz/service/surfaces/surface.{h,cc}` (a new active frame returns the previous frame's resources to the client, `UnrefFrameResourcesAndRunCallbacks`; Dweller: `frame_ack` of the buffer shown before).
- files: `browser/ipc/{message,decode,put-payload,put-u32,reader,from-renderer,encode_test}.aye`, new `browser/ipc/{buffers,check-frame,check-frame_test,msg-hdr,put-rights,put-rights_test,take-rights,send-fds,recv-fds,make-shared,make-shared_test,open-shared,map-shared,unmap-shared}.aye`; `browser/renderer/{serve,serve-on,answer-all,load}.aye`, new `browser/renderer/{tab-renderer,take-buffers,drop-buffers,paint-frame}.aye`; `browser/ui/{tab-process,poll-tab-processes,renderer-sent,renderer-waits,tab-process-timeout,end-tab-process,write-tab-process,pagedraw,window}.aye`, new `browser/ui/{give-buffers,show-tab-frame,draw-tab-frame,unmap-buffers}.aye`; `tests/browser.rs` (`window_renderer_frames`).
- verify (2026-11-08, macOS):
  - `aye check browser`: exit 0.
  - `aye test browser`: 189 passed, 0 failed, 17 modules (ipc: every message round-trips, the frame checks, fds through the control bytes, a shared buffer seen through two mappings).
  - `python3 browser/tools/check_taste.py`: exit 0.
  - `scripts/capped.sh cargo test --release --test browser -- window_renderer_frames window_renderer_lifecycle aye_unit_tests`: 3 passed. `window_renderer_frames`: `form.html` in a renderer gives the same PNG as in the window's process; `DWELLER_TEST_EVIL=frame` → `gone wrong size` and the `bad message` line. A page whose script paints the body red differs (the renderer runs no scripts), so the window shows the renderer's pixels.

## Status: done, 2026-11-08

Left:
- input, UI and agent routing to the renderer (Q2.3, Q2.3b); the window still loads and lays out the page itself and paints its own pixels under the renderer's.
- scroll: the renderer paints at scroll 0; `scroll_x`/`scroll_y` are sent as 0 and not read.
- damage: the renderer always paints and sends the whole buffer (empty damage), and the window copies all of it; partial damage, and painting straight into the buffer instead of a canvas copy.
- the font choice (`--font`) and scripts are not sent to the renderer (`init` of process-model §2); the test page has no script and uses the default font.
- `recvFds` reads one control message per read; several `resize`s in one read (fast window resizes) would lose fds.
- the IO thread and SDL wake event (the loop still polls at `POLL_MS`).
