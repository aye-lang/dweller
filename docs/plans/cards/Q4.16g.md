# Q4.16g: spec-correct `replace` with named groups, so core-js keeps the native

- goal: on bbc, core-js (`cdn.privacy-mgmt.com/unified/wrapperMessagingWithoutDetection.js`, `fix-regexp-well-known-symbol-logic`) replaces `String.prototype.{match,replace,search,split}` and `RegExp.prototype[@@match/@@replace/@@split]` with JavaScript wrappers because the native fails its feature tests. Make the native follow ECMA-262 and keep a native fast path for a plain RegExp.
- the failing checks (from the bbc archive's script, run in `target/dweller js` before the change; node passes all):
  - `g` for each of match, replace, search, split: `var t = {}; t[Symbol[KEY]] = function () { return 7 }; return 7 != ''[KEY](t)` must be false. `String.prototype` methods never looked up `@@match`/`@@replace`/`@@search`/`@@split` on the argument.
  - `s` (replace only): `var e = /./; e.exec = function () { var r = []; r.groups = { a: '7' }; return r }; return '7' !== ''.replace(e, '$<a>')` must be false. A RegExp argument always took the native path, which ignores an own `exec`.
  - Passed already: `REPLACE_KEEPS_$0`, `REGEXP_REPLACE_SUBSTITUTES_UNDEFINED_CAPTURE` (false), the split `exec` check, `es.regexp.exec`'s `lastIndex`, NPCG, `UNSUPPORTED_Y` and `BROKEN_CARET` checks. `m` depends on `g`; `RegExp.prototype[@@...]` were already the spec JavaScript in `regexp-spec.js` (they call `exec` through RegExpExec).
- design:
  - `regexpDispatch` (`browser/js/regexp-dispatch.aye`) runs first in `stringMatch`, `stringMatchAll`, `stringReplace`, `stringReplaceAll`, `stringSearch`, `stringSplit`: RequireObjectCoercible(this); when the argument is an object and not a plain RegExp, GetMethod(argument, @@KEY) and call it with (O) or (O, second argument). Primitives never look up the symbol (test262 `cstm-replace-on-*-primitive`). For `replaceAll`/`matchAll`, `requireGlobalFlag` runs IsRegExp and the `flags` check before anything else (a plain RegExp reads its compiled `global` flag).
  - `plainRegExp`: class RegExp, prototype `RegExp.prototype`, one own property (`lastIndex`), and `regexpProtoIntact`: the keys the spec methods read (`exec`, `flags`, the 8 flag getters, `constructor`, the 5 symbols) still hold the values `snapshotRegExpProto` recorded after `regexp-spec.js` ran (key, slot index, value, setter, in a rooted array). Then the old native code runs unchanged.
  - New `Interp` fields: `sym_match`, `sym_match_all`, `sym_replace`, `sym_search`, `sym_split`, `regexp_snapshot`.
- files: `browser/js/builtins_string.aye`, `interp.aye`, `symbol.aye`, `install-spec-scripts.aye`; new `regexp-dispatch.aye`, `plain-regexp.aye`, `regexp-proto-intact.aye`, `snapshot-regexp-proto.aye`, `snapshot-regexp-prop.aye`, `is-regexp.aye`, `require-global-flag.aye`; test `browser/tests/js/282_string_regexp_dispatch.{js,out}` (the core-js checks print `native is fine`; named groups, `replaceAll` with a regexp, own `exec`, a patched `RegExp.prototype.exec`, a custom `@@replace` object, a `toString` object; `.out` from node 22).
- references: ECMA-262 https://tc39.es/ecma262/#sec-string.prototype.replace , https://tc39.es/ecma262/#sec-getsubstitution , https://tc39.es/ecma262/#sec-regexp.prototype-@@replace ; v8 `src/builtins/builtins-regexp-gen.cc` (`BranchIfFastRegExp`, `IsFastRegExpNoPrototype`), `src/builtins/string-replace.tq`. Dweller takes V8's split: a native path behind a fast-RegExp check (initial shape, unchanged prototype; checked per call, as Dweller has no protector cells), the spec methods for everything else.
