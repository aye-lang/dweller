# P11.14: WebGL conformance runner and baseline

- goal: docs/webgl.md §7. Run the Khronos WebGL conformance suite in Dweller, pinned and fetched like WPT. Put "WebGL 2: <dir>" rows in `docs/conformance.md` through `conformance.py`'s table code. Add a weekly CI job. List the largest failure groups so that the next WebGL cards are chosen from data.
- design:
  - `browser/tools/webgl_cts.rev` pins KhronosGroup/WebGL `193020cd37c3ad6aa068805ef7fb7eca187734b5` (main, 2026-10-17). `webgl_conformance.py fetch` makes a sparse, depth-1 checkout of `sdk/tests` into `target/webgl` (43 MB), as `wpt.py fetch` does. CI caches it, keyed by the rev.
  - `webgl_conformance.py run [conformance2|conformance|DIR...] [-j N]` reads each `00_test_list.txt` recursively. It skips entries whose `--min-version`/`--max-version` excludes 2.0.1 (they count as skipped). The suite is served with `wpt.Server` (the P10.1 static server). Each page runs as `dweller dump --text --js --no-scroll URL` with `DWELLER_GL=swiftshader` and `DWELLER_WEBGL_HARNESS=1`, with a 30 s wall-clock timeout per page and `-j` workers.
  - The hook: when `DWELLER_WEBGL_HARNESS` is set, `script.aye` runs `webgl-harness.js` (embedded by `webgl-harness-prelude.aye`) after the WebGL preludes. It defines `window.webglTestHarness`, which `js-test-pre.js` reaches as `window.parent.webglTestHarness` (`reportTestResultsToHarness`, `notifyFinishedToHarness`). `reportResults` counts passes, logs each failure as `DWELLER_WEBGL fail <msg>` and ignores skipped results. `notifyFinished` logs `DWELLER_WEBGL done <passes>`. The hook is off by default.
  - Scoring:
    - A finished page counts passes plus failures, and passes only with no failure.
    - A page with no `done` line (timeout, crash) is its failures plus one, with no passes.
    - Each page record keeps the first failure (`message`) and the first `[error]` console line (`error`).
  - Results go to `target/webgl-results/webgl2_<dir>.json` (`webgl1_<dir>` for `conformance/`), one file per top directory, in the WPT result shape. `conformance.py` learns the WebGL areas:
    - `webgl_areas()` lists them from the baselines and results present.
    - `file_key` maps "WebGL 2: buffers" to `webgl2_buffers`, and `results_path` replaces `available`'s path logic.
    - `wpt_measure` reads them with the result's own threshold (0, so the status is baseline).
    - The header names the WebGL rev.
    - `conformance.py run` with no arguments still runs only WPT and test262.
  - `conformance.py table` writes the rows, the baselines under `browser/tools/conformance/` and the `history.csv` rows. `webgl_conformance.py check` runs `conformance.check_area` for the WebGL areas only.
  - `history.csv` had a second header line (line 22, from a merge), which made `conformance.py table` fail. That line is removed.
  - CI: a `webgl` job in `.github/workflows/conformance.yml` (weekly schedule + `workflow_dispatch`, Ubuntu 24.04). It caches ANGLE and the suite, builds, runs `conformance2 conformance` and `check`, and uploads `target/webgl-results`.
