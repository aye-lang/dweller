# Q2.3d: focus, caret, selection, title and URL from the renderer

- goal: with `DWELLER_PROCESS=tab`, the renderer owns the page's focus (Tab and Shift+Tab, focus by click, the focus ring), the text caret (it blinks on the renderer's timers, and only the caret rect is damaged), the selection in text fields (mouse drag and Shift+arrows, painted by the renderer), and it reports the document's title and URL. The window tells the renderer when the window or the toolbar takes or gives back the focus. The browser checks each reported URL against the URL it navigated to and shows the title and URL in the toolbar. Without the flag nothing changes, except the in-process window now also selects text in a field with a mouse drag (so both modes look the same).
- design:
  - IPC messages added (type codes in order, all on the tab's frame id): 16 B→R `focus{on}` (1 when the window has the system focus and the page has the window's focus; 0 when the window lost it or the toolbar, find bar or sign-in prompt took it); 17 R→B `title{title}`; 18 R→B `same_document{url}` (pushState, replaceState, fragments). R→B `loaded{title, url}` now carries the committed URL that the browser checks.
  - the browser's checks (`rendererSent`; a failure logs `bad message: REASON PID` and kills): `loaded` and `same_document` URLs must be the URL the browser navigated to (`tp.committed`) without its fragment, or the same origin as it (`net.sameOrigin`), or for `file:` the same path (as the engine's `canRewrite` for pushState): `commitMatches`, else `bad url`. `same_document` while a load is pending is `bad url` too. `title` on another frame id or over 4096 bytes is `bad title`. An accepted message sets `tp.title` and `tp.committed` (`showCommitted`) and `tp.shown_new`.
  - window (`ui/`): `Ui.inactive` follows `SDL_WINDOWEVENT_FOCUS_LOST`/`FOCUS_GAINED`; `tellFocus` (from `pollTabProcesses`) sends `focus` when `active && !inactive && focus == Page` changes (`TabProcess.focused`). `showToolbar` puts the reported URL into the address bar (unless the person is typing there) and the title into the window title (`setTitle` now uses `slotTitle`, which prefers the renderer's title). The window's own pushState follow-up (`setAddress` in `afterScripts`) is skipped while the tab has a renderer, so it does not overwrite the renderer's URL. `dragSelectPage`: a mouse move with the left button down extends the focused field's selection (in-process, for parity). `start-tab-process` passes `--steady-caret` when `DWELLER_STEADY_CARET` is set (the caret then never blinks; the tests use it to compare PNGs).
  - renderer (`renderer/`): `tabKey` (`keyInput`, before `focusKey`, no Command/Control): `engine.nextFocus` and `engine.keyFocus` (the focus ring is the page's `:focus-visible` outline, so it is in the display list), then it scrolls the focused box into view. Clicks focus as before (`clickAt`), and a click in a text field starts a drag (`TabRenderer.select_el`); moves with the left button extend the selection (`dragSelect`, `dom.extendCaret`); Shift+arrows already go through `fieldKey`. `fieldMarks` builds the caret and selection rects of the focused text field (`engine.caretRect`, `engine.selectionRects`) with the window's colors; no caret when `focused` is off or the blink is in its off phase. `paintFrame` adds the old and new mark rects to the damage when they changed (`sameMarks`, `addMarks`), and `drawDamage` fills the marks over each damage rect. Blink: `BLINK_MS` 500; every input and `focus` message shows the caret and restarts the blink (`TabRenderer.wake`); `timerWait` wakes for the next blink while a text field has the focus (`caretBlinks`); `runTimers` flips the phase. `reportPage` (after each message batch and timer run) sends `title` and `same_document` when the page's title or URL changed. `load` sends the committed URL in `loaded`; when the load was redirected to another origin, it does not commit and asks the browser again with `begin_navigation` for the final URL (the browser checks it as any other navigation).
  - test hooks: `DWELLER_TEST_EVIL=url` (the renderer reports `https://evil.example/` in `loaded`); `DWELLER_STEADY_CARET`.
- Chromium read (idea only): `content/browser/renderer_host/render_widget_host_impl.cc` (`Focus`/`Blur` → `SetPageFocus`: the browser tells the widget when the page has the focus), `third_party/blink/renderer/core/page/focus_controller.cc` (`SetFocused` stops the caret, `AdvanceFocus` walks the Tab order in the renderer), `content/browser/renderer_host/render_frame_host_impl.cc` (`UpdateTitle` rejects a title over `kMaxTitleChars` as a bad message; `CanCommitOriginAndUrl` rejects a same-document commit that changes the origin). Dweller takes: page focus is one browser→renderer bit; Tab, caret and selection live in the renderer; the browser only trusts a reported URL that is its own navigation or same-origin, and kills otherwise.
- files: `browser/ipc/{message,decode,put-payload,from-renderer,encode_test}.aye`, new `browser/ipc/message_test.aye`; new `browser/dom/extend-caret.aye`; `browser/renderer/{answer-all,click-at,draw-damage,key-input,load,mouse-input,paint-frame,run-timers,serve,serve-on,tab-renderer,timer-wait}.aye`, new `browser/renderer/{mark,field-marks,same-marks,add-marks,caret-blinks,tab-key,drag-select,report-page}.aye`; `browser/ui/{poll-tab-processes,renderer-sent,sdl,start-tab-process,tab-process,window}.aye`, new `browser/ui/{commit-matches,show-committed,show-toolbar,tell-focus,drag-select-page}.aye`; new `browser/tests/ui/renderer_focus.html`; `tests/browser.rs` (new `window_renderer_focus`; `window_renderer_input` now expects the caret too); `docs/process-model.md` (input and navigation rows).

After `window:blur` the renderer's frame differs from the in-process one only in the caret's column (the caret hid). Without `DWELLER_STEADY_CARET` the last frame after a click into a field is the blink, with damage only the caret rect (≤ 3 px wide). A button's `history.pushState(null, '', '?pushed')` and `document.title = 'Pushed'` give `address …/renderer_focus.html?pushed` and `title Pushed` while the window's own copy stays at `renderer_focus.html`. `DWELLER_TEST_EVIL=url` → `gone bad url` and the `bad message: bad url PID` line. `window_renderer_input`'s typing case now matches the in-process PNG exactly (the caret is drawn). Verify: check_layers, check_taste, `aye check browser` exit 0; `window_ agent_sessions`: 75 passed, `window_webgl` fails locally only (ANGLE not fetched).

Left:
- selection of the document's text (not in a field): the engine has no document `Selection`/range painting yet, in either mode; Shift+arrow page selection waits for it. Double and triple click word/line selection in fields.
- clipboard (Command/Control + A, C, X, V), find, cursor shape, status line, long-task chip: later cards; removing the window's copy of the page: Q2.3e.
- `focus` does not fire `blur`/`focus` events at the page's window or element when the browser window loses the focus (Blink's `SetFocused` does); the focus ring stays drawn.
- Tab past the page's last focusable element does not hand the focus back to the toolbar (`advance_focus`, Chromium's `TakeFocus`).
- a cross-origin redirect costs a second fetch (the renderer asks again with `begin_navigation`) until Q2.6 moves the network to the browser; a redirect loop between two origins would ping-pong.
- the blink interval is fixed at 500 ms (no platform setting); the selection is drawn in the active color when the window is not focused.
