# Q0.1: the weekly `conformance` run is green again

- goal: the weekly `conformance` workflow is green, and a red run means a real drop. It failed three weeks in a row (runs 39226075471, 40295867844, 41434511127), always only in the `webgl` job at `webgl_conformance.py check`: `WebGL 2: wasm: 100.0 -> 84.2`, with all 18 `conformance2/wasm/*-{2gb-in-4gb,4gb,16gb}-wasm-memory.html` files listed.
- cause: not runner memory and not a code regression. The `webgl` job never fetched libwasmtime, so on CI `WebAssembly` is undefined (`browser/wasm/fetch_wasmtime.sh`: "without the library ... `WebAssembly` is undefined"). The results artifact of run 41434511127 shows it: the six 16gb pages fail with `Allocating 17179869184 threw: ReferenceError: WebAssembly is not defined`, and the 2gb/4gb pages pass only 2 of the 3 or 4 checks the baseline has (they skip the wasm half), so `regressions()` lists all 18. The baseline `browser/tools/conformance/webgl2_wasm.json` (cec72af, "wasm in the CTS run") was made locally with libwasmtime, 52/52. The job has failed since its first scheduled run (39226075471), so there was never a green run to regress from.
- design: the `webgl` job gets the same wasmtime cache and `browser/wasm/fetch_wasmtime.sh` step as `ci.yml`; `browser/build.sh` links libwasmtime by itself when `target/wasmtime` holds it. No test is skipped and no baseline changes: CI now measures what the baseline measured. The plan's "job allowed to fail" is not needed, as the job's red had one cause and it is gone.
- files: `.github/workflows/conformance.yml`, `docs/plans/cards/Q0.1.md` (new)
- verify: `ruby -ryaml -e 'YAML.load_file(".github/workflows/conformance.yml")'` and `python3 browser/tools/check_taste.py` pass. On CI: `gh workflow run conformance --ref q0-1-weekly-green`, and the `webgl` job is green (`WebGL 2: wasm` back at 100).
