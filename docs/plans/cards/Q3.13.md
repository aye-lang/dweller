# Q3.13: the HTTP cache is keyed by top-level site, frame site and credentials

- goal (foundations.md row Q3.13): the session's HTTP cache key has the network isolation key of the request's initiator context, (top-level site, frame site) with sites as scheme + eTLD+1 (`net/psl.aye`), and whether the request is credentialed. A response loaded under site A is never a hit for site B, and an uncredentialed request never gets a response fetched with cookies. Reused connections get the same partition. A top-level document's own key is (its site, its site). Not in this card: storage partitioning.
- source: Q3.3c's "left" list (the cache did not separate requests with and without cookies).
- design:
  - `networkPartition(alloc, req, href)` (`net/network-partition.aye`) is `C/_dk_TOP FRAME`. `C` is `1` when the request is credentialed (`net/credentialed.aye`: credentials `include`, or `same-origin` and the request is same-origin), else `0`. FRAME is the site of the request's origin (`requestOrigin`: the initiator page, else the referrer). TOP is `Request.top`, else the top-level page that `noteFrame` noted for FRAME's page, else FRAME. For a `Document` request, FRAME is the document's own URL and TOP is `Request.top` (a frame's document) or the URL (a top-level navigation: (its site, its site)). A site is `scheme://` + `siteOf(host)` (`net/append-site.aye`), without the port, as `SchemefulSite`.
  - `cacheKey(alloc, req, href)` (`net/cache-key.aye`) is the partition, a space and the URL without the fragment. `Cache` (`net/cache.aye`) keys its entries by this string (`key`, was `href`). `fetchHttp` (`net/http.aye`) looks up and keeps under it. A background load (`net/loader.aye`) computes its key in `startLoadAs`, joins a running load only with the same key (`net/find-keyed.aye`), skips the transfer when the key is cached, and keeps its response under the key (`keepLoad`). The sync fetch that follows computes the same key from the same `Request` fields, so it hits. `prefetch` (`net/multi.aye`) no longer checks the cache by URL: `startLoadAs` does it by key.
  - Connections: the session had one libcurl share handle (connections, DNS, TLS sessions) for every transfer. It now has one share per network partition (`Session.shares`, `net/partition-share.aye`), made on first use by `shareFor` (`net/share-for.aye`). `prepare` (`net/http.aye`) sets the hop's share on the easy handle, so the reused easy handle and the loader's multi-handle transfers reuse a connection only within one partition. Chromium's socket pools use the network anonymization key (top-level site and a cross-site bit) plus the privacy mode. Dweller uses the full partition (frame site too), which is stricter and needs no second key.
  - Documents are still not cached (`fetchHttp`'s `cacheable`), so the document rule matters for the connection partition. The frame site of a cross-site frame's subresources is the frame's site, so a script of `localhost` embedded by a `127.0.0.1` page and by a `localhost` frame of that page is two entries.
- changed goldens: none.
- files: new `browser/net/{network-partition,credentialed,append-site,cache-key,find-keyed,share-for,partition-share}.aye`, `browser/net/network-partition_test.aye`; changed `browser/net/{cache,free-entry,http,loader,multi,session}.aye`; tests `browser/tests/net/cache-partition.html`, `browser/tests/net/cache-partition/{frame.html,r.js}`, `tests/browser.rs` (`cache_partition`).
- references:
  - spec: https://fetch.spec.whatwg.org/#http-cache-partitions (network partition key: top-level site and the frame's site), https://fetch.spec.whatwg.org/#concept-http-network-or-cache-fetch (includeCredentials).
  - Chromium `net/http/http_cache.cc` (`GenerateCacheKey`: `credential_key/upload_id/_dk_` + `NetworkIsolationKey::ToCacheKeyString()` + ` ` + URL), `net/base/network_isolation_key.h` (top-frame site and frame site), `net/base/network_anonymization_key.h` (top-frame site and is-cross-site, used for sockets). Dweller takes the `_dk_` key layout with the NIK's two sites, and the credentials prefix that Chromium has behind `kSplitCacheByIncludeCredentials`, on by default here; connections are split by the same partition instead of by the NAK.
