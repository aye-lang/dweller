# Q2.5: a dead or hung renderer shows a sad tab; other tabs go on

- goal: with `DWELLER_PROCESS=tab`, a renderer that dies (exit, signal, end of file on its socket, or killed by the browser for a bad message) leaves its tab on a browser-drawn sad tab: "This page crashed" (end of file) or "This page was stopped" (the browser killed it), with a Reload button. Reload starts a fresh renderer that loads the tab's page; the other tabs and their renderers go on. A renderer that does not answer the browser's ping for 10 s gets the Q1.7 bar "This page is not responding" with Wait and Stop: Wait re-arms, Stop kills it (SIGKILL) and shows the sad tab. Headless runs answer Wait as Q1.7b does, unless the script word `stuck:stop` comes first. Q2.4c's leftover: the browser's plain file opens are close-on-exec.
- design:
  - messages (type codes 37, 38, both on frame 0): B→R `ping{n}`, R→B `pong{n}`. `rendererSent`: a `pong` on another frame, with no ping open, or with another `n` is `bad pong` (logged and killed as every bad message).
  - pings (`ui/watch-hang.aye`, from `serviceTabProcess`): after `hello`, one ping is open at a time; the next goes out `PING_MS` (1 s) after the last pong. A ping open for `hangMs()` (`HUNG_MS`, 10 s; `DWELLER_HANG_MS` for tests) sets `tp.hung`. A pong clears it (the bar goes away by itself when the page comes back). `tabProcessTimeout` polls at `POLL_MS` while a ping is open.
  - renderer: `answerAll` answers `ping` with `pong`; `awaitFetch` answers it too (`renderer/answer-ping.aye`), so a slow fetch, which the browser serves, is not a hang. A script that loops never reads the socket, so its pings stay open.
  - hang UI: the active tab's hung renderer (`hungProcess`) draws the Q1.7 bar (`drawStuckBar`, unchanged) and makes the page an overlay (`pageOverlays`). The bar is not modal as the in-process one is: `hungInput` takes only the clicks on the bar (Wait → `waitHang`: the open ping counts again from now; Stop → `stopHung`: `dropTabProcess(tp, "stopped")`), and other tabs, the toolbar and the strip work. `answerHang` (from `pollTabProcesses`) counts the hang in `ui.unresponsive` (`--state` `unresponsive N`) on the first poll; in a headless run (`stuck_headless`, Q1.7b) the next poll, after the scripted words had one turn, answers Wait and logs `stuck: renderer PID not answering, waiting`. `stuck:stop` now also stops a hung renderer of the active tab; the new wait word `renderer:hung` waits for the hang.
  - crash: unchanged detection (Q2.2a: end of file or a failed send → `dropTabProcess(tp, "crashed")`; a bad message → `dropTabProcess(tp, REASON)`), which already SIGKILLs and `waitpid`s the child, so no zombie stays. New is what the tab shows: `sadTabOf` (a gone renderer of the active tab; the heading is "This page crashed" for `crashed`, else "This page was stopped") and `drawSadTab` (white page area, the heading, a Reload button), drawn over the last frame inside the page clip. `sadTabInput` makes a click on Reload `ui.reload()`. `goInRenderer` (reload, back, forward, the address bar) ends a gone renderer (`endTabProcess`) and clears `slot.process`; `pollTabProcesses` then starts a fresh one, and `queueNavigate` sends the tab's current history entry (under the flag the window's history has only the entries it committed itself, Q2.3e). `--state` prints `sad-tab HEADING`.
  - close-on-exec: the profile's `lock` (`net/profile.aye` `createFlags`) already had `O_CLOEXEC` since P4.50; Q2.4c's note read it wrong. The browser's other plain `open`s now pass it too: `ui/write-token.aye`, `ui/send-token.aye`, `ui/map-frame-file.aye` (`ui/cloexec-flag.aye`) and the telemetry file (`perf/telemetry.aye` `openAppend`). They are all short-lived (open, use, close), so this closes the window between `open` and `close` while a Space is spawned.
- Chromium read: `chrome/browser/ui/sad_tab.cc` (the kinds: crashed, killed, OOM; the Reload action), `chrome/browser/ui/hung_renderer/` (the Wait / Stop choice per renderer), `content/browser/renderer_host/render_process_host_impl.cc` (`ProcessDied`: every frame of the process is told, the host can be reused for a reload), `content/browser/renderer_host/render_widget_host_impl.cc` (the input-event hang monitor, `kHungRendererDelay` 15 s). Dweller takes: the sad tab's two kinds and Reload into a fresh process, and a per-renderer Wait/Stop over a timeout; the signal is a ping (Dweller's renderer has one thread, so an unanswered ping is a busy main thread, which an input ack would show only while input is sent), and the delay is 10 s.
- files: `browser/ipc/{message,decode,put-payload,from-renderer,message_test}.aye`; `browser/renderer/{answer-all,await-fetch}.aye`, new `browser/renderer/answer-ping.aye`; `browser/ui/{tab-process,service-tab-process,renderer-sent,tab-process-timeout,poll-tab-processes,renderer-waits,script,write-tab-process,go-in-renderer,pagedraw,window,write-token,send-token,map-frame-file}.aye`, new `browser/ui/{hang-ms,watch-hang,wait-hang,answer-hang,hung-process,hung-input,stop-hung,sad-tab,draw-sad-tab,sad-tab-input,cloexec-flag}.aye`; `browser/perf/telemetry.aye`; new `browser/tests/ui/renderer_hang.html`; `tests/browser.rs` (new `window_renderer_sad_tab`, `window_renderer_hang`; `window_renderer_no_profile_files` also lists the Space's open files); `docs/process-model.md` (§2 lifecycle row, §7 what Q2.5 ships).
- verify (2026-11-08, macOS):
  - `aye check browser`, `python3 browser/tools/check_layers.py`, `python3 browser/tools/check_taste.py`: exit 0. `aye build browser`: exit 0. `aye test browser`: 228 passed, 0 failed, 18 modules (new: ping and pong round-trip and their direction).
  - `scripts/capped.sh cargo test --release --test browser -- window_renderer_ window_stuck window_out_of_memory aye_unit_tests`: 16 passed, 0 failed (no test matches `window_out_of_memory` in this tree). The first run of the new tests failed `window_renderer_hang`: after `stuck:stop` the dropped renderer still had `hung` set and the next poll logged an automatic Wait for it; `pollTabProcesses` now answers only a hang of a live renderer.
  - `window_renderer_sad_tab`: SIGKILL of the renderer (`renderer:kill`) → `renderer PID gone crashed` and `sad-tab This page crashed`. With a second tab (`stuck.html`): killing tab 1's renderer, then showing tab 2 gives `renderer PID title Stuck`, `tabs 2, showing 2` and no sad tab. Reload by a click on the sad tab's button and by cmd+R each give `renderer PID title Form` from a fresh renderer. Empty stderr in every run.
  - `window_renderer_hang` (`DWELLER_HANG_MS=1000`, `renderer_hang.html` loops in its first script): `renderer:hung stuck:stop renderer:gone` → `renderer PID gone stopped`, `sad-tab This page was stopped`, `unresponsive 1`, empty stderr; the test finds the renderer with `pgrep -P` and sees it leave the process table (`ps -o stat= -p PID` empty, not `Z`) while the window still runs. Without `stuck:stop` the run exits 0 with `stuck: renderer PID not answering, waiting` on stderr and the renderer alive.
  - `window_renderer_no_profile_files`: the agent's Space (a child of the window that is not a renderer) holds no `<profile>/lock`.
  - No golden re-blessed; every window run headless (`SDL_VIDEODRIVER=dummy`).

## Status: done, 2026-11-08

Left:
- Stop kills the renderer: the page is lost. Keeping it needs the interrupt word in shared memory of §7 (the VM's `goes_on` hook reads it), then SIGKILL only after 2 s.
- no input-ack hang signal of its own: input that is not acked shows as a hang only through the ping (at most 10 s later, the same delay).
- no "three crashes of one site within 30 s" rule (§7): Reload is always offered and never automatic.
- OOPIFs have no sad frame (no OOPIFs yet); agents' open requests on a dead renderer already fail ("the tab's renderer is gone", Q2.3b).
- `std.fs.open` (the Aye runtime's `aye_std_open`, used by `font/`, `net/archive.aye`, `perf/telemetry.aye`) opens without `O_CLOEXEC`; those files are read and closed at once, but the runtime should pass it (an Aye change, not Dweller's).
- the sad tab draws over the dead renderer's last frame; its shared buffers stay mapped until Reload or the tab closes.
