# Q4.16l: `cssRules` is not rebuilt on every read

- goal: Q4.16a's ranked step 11 (bbc: `ruleObject` 104 ms and `selectorText` 60 ms per run in Q4.21). The rule objects were already kept per index (`_objects`), but every read of `sheet.cssRules` and every `insertRule` or `deleteRule` spliced the whole live list again (`_syncRules`: a map over all rules and a spread into `splice`), so a CSS-in-JS library that inserts rules one by one and reads `cssRules.length` each time does work quadratic in the rules.
- design (Blink keeps the CSSOM wrappers of a sheet's child rules, `CSSStyleSheet::child_rule_cssom_wrappers_`, and changes the list in place):
  - the sheet remembers which rules array its live list was built from (`_listOf`). `cssRules` rebuilds the list only when that array was replaced (the first read, `replaceSync`).
  - `insertRule` and `deleteRule` change the list in place (`_listInserted` makes the one new rule object, `_listDeleted` removes one), and only when a list was built from the current array. A list a script holds still changes with the sheet.
- files: `browser/engine/prelude.aye` (`CSSStyleSheet`: `cssRules`, `_syncRules`, `_listInserted`, `_listDeleted`, `insertRule`, `deleteRule`).
- verify (2026-11-22, Linux x86_64, 4 cores):
  - a page that inserts 2000 rules, reading `cssRules.length` and the last rule's `selectorText` after each: 2524 -> 85 ms. The list held before an `insertRule` at 0 and a `deleteRule` is the same object, with the right length and rules at each index.
