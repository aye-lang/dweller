# Q6.13c: functions declared in blocks (Annex B.3.3)

- goal: the function-in-block cluster of `test262/annexB` (457 of the 613 failing tests: `eval-code` 278, `global-code` 90, `function-code` 89).
- cause: a function declared in a block of sloppy code had no binding in the block: its name was only a `var` of the function, assigned when the block was entered. So the block's binding and the var were one (`block-scoping`), the var was made even when an enclosing `let`, `const`, parameter or destructured catch parameter had the name (`skip-early-err-*`, `skip-param`), and a function as the clause of an `if` was never created.
- design:
  - `FuncDecl` has a third field `annex`: an `Ident` the resolver adds for a declaration that B.3.3 applies to, resolved in the function's (or script's) var scope with `Resolver.lookupBelow`. The block always declares the function's own binding; the compiler copies it to `annex` where the declaration stands (`compiler.aye`, the `FuncDecl` arm).
  - `annex-pass.aye` and the files it calls (`annex-collect`, `annex-list`, `annex-cases`, `annex-var`, `annex-name-taken`, `annex-block-names`, `annex-pattern-names`, `annex-catch-names`, `annex-function-name`, `annex-resolve`) walk a body once and keep the names that would make `var F` an early error: the `let`/`const`/`class` and function names of every enclosing block, `for` head and `switch`, and a destructured catch parameter (a plain `catch (f)` does not block). No var for a parameter name, for `arguments`, for a generator or an async function.
  - eval code: its body is one block; `annex-eval-root.aye` treats that block's functions as top-level functions of the eval (bound at entry in the caller's var scope, as before).
  - `parse-if-clause.aye`: `if (x) function f() {}` is the function in a block of its own (B.3.4), a SyntaxError in strict code and for a generator. `parseSubStatement` refuses a function or class declaration as the body of a loop, `with` or label (a labelled plain function stays legal in sloppy code).
  - found on the way: `/\8/` or `/(a)\2/` indexed the capture array out of bounds and aborted the process. A decimal escape past the number of groups is now a legacy octal or identity escape (`regexp-legacy-escape.aye`, `regexp-count-groups.aye`: V8's `ScanForCaptures`), a SyntaxError with the `u` flag.
- V8 and the spec differ twice here; test262 follows the spec and so does Dweller: `{ function arguments() {} }` does not replace the arguments object (V8 replaces it), and in `{ function f() {} { function f() {} } }` the inner function is not copied to the var (V8 copies it). Neither is in the Node golden.
- references: ECMA-262 B.3.3.1 to B.3.3.3, B.3.4; V8 `src/parsing/parser.cc` (`InsertSloppyBlockFunctionVarBindings`), `src/ast/scopes.cc` (`HoistSloppyBlockFunctions`).
- files: `browser/js/ast.aye`, `resolve.aye`, `compiler.aye`, `parser.aye`, `parse-sub-statement.aye`, `vm-hoist.aye`, `interp.aye`, `regexp.aye`; new `annex-*.aye` (12 files), `parse-if-clause.aye`, `regexp-legacy-escape.aye`, `regexp-count-groups.aye`; `browser/tests/js/287_annex_b_block_functions.js` and `.out` (Node 22's output).
