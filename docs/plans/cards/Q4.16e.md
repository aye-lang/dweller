# Q4.16e: `Function.prototype.call`/`apply` stay in the dispatch loop

- goal: a `CallProperty` whose callee is the original `Function.prototype.call` or `apply` and whose receiver is a bytecode function pushes the target's frame in `vmLoop`, without `callNative` → `functionCall`/`functionApply` → `callAt` → `invoke` → `vmRun` (Q4.16a: `.call`/`.apply` re-enter the VM from bbc's hot code).
- design:
  - `installFunction` keeps the two native objects in the new `Interp.function_call` and `Interp.function_apply`.
  - `CallProperty` (op 77): when `vmNativeCallee` finds a native, `vmCallsClosure` asks whether it is one of the two and the receiver (`regs[r + 1]`) is a `Closure`. If not, the native path runs as before (natives, bound functions, proxies as targets keep it).
  - If so, after `vmPushCall` copied `[call, f, a0, a1, ...]` to the stack top, `vmShiftCall` rewrites it in place to `[f, thisArg, args...]` and gives the new argc: `call` shifts the arguments down one slot (no arguments: `this` undefined); `apply` takes `thisArg = a0` and spreads `a1` with `pushArrayLike` (the existing CreateListFromArrayLike: null/undefined no arguments, a primitive throws `TypeError`, a generic array-like reads `length` and the indices).
  - The rewritten call then goes the way of any other `CallProperty`: `vmInlineCallee` pushes the frame of a compiled plain function in the loop; a generator, async function, class constructor or function the VM does not compile falls to `vmCallOp` → `callAt` with the same stack, which is what `functionCall`/`functionApply` did. So `new.target` (undefined), the class-constructor `TypeError`, the max call depth (`vmInlineCallee`'s `frames >= max_depth`), sloppy `this` (`vmPushFrame`) and exceptions are those of a plain call.
- files: `browser/js/vm.aye` (op 77 in `vmLoop`), `browser/js/builtins.aye` (`installFunction`), `browser/js/interp.aye` (two fields); new `browser/js/vm-calls-closure.aye`, `browser/js/vm-shift-call.aye`; test `browser/tests/js/282_call_apply_shift.{js,out}` (`.out` from node 22: call/apply with no arguments, strict and sloppy `this`, null and array-like and holey and `arguments` lists, a primitive list, a throw, `new.target`, a class, a generator, a bound target, native targets, deep recursion through `.call` to the `RangeError`, `call.call`).
- V8 ref: `src/builtins/arm64/builtins-arm64.cc` (`Generate_FunctionPrototypeCall`, `Generate_FunctionPrototypeApply`): the builtin shifts the receiver out of the argument list and tail-calls `Call` on the target, so no extra frame and no re-entry. Dweller does the shift in the `CallProperty` handler and reuses its frame push.
- verify (M2 Pro, `scripts/capped.sh`, `browser/build.sh` safe builds; before = origin/main 7a9cb2df as `target/dweller-base`):
  - `check_layers.py`, `check_taste.py`, `aye check browser` exit 0; `aye test browser` 226 passed.
  - `cargo test --release --test browser -- js_conformance aye_unit_tests`: 2 passed. No golden re-blessed (one new `.out`).
  - test262 `built-ins/Function/prototype/call` and `apply` (`test262.py run`, rev d53ebc8b19): 45/49 and 40/46 (2 skipped) before and after, the same tests per file.
  - jsbench (`BENCH_BIN=target/dweller BENCH_BASELINE=target/dweller-base BENCH_REF=none`, interleaved, median of 3): geometric mean 0.995 (calls 1.00; dom 0.93 and three 0.95 while other agents' tests ran; the first run, with the check before `vmNativeCallee` on every `CallProperty`, was 0.988 with dom 0.98). jsbench barely uses `.call`/`.apply`. A micro loop of 2M `add.call` + 2M `add.apply`: 786 → 694 ms.
  - bbc, one replay run each of `window_perf.py scroll` (3 `frame`, 40 `wheel:-3 frame`) with `DWELLER_JS_VM_STATS=t DWELLER_JS_NATIVES=1`: native `call` 214751 → 145806 calls, `apply` 110044 → 108607. A temporary build that printed one line per `functionCall`/`functionApply` with a `Closure` target (not committed) counted 0 `call` and 221 `apply` re-entries after; the ~70k native calls that went away are the re-entries before. The calls left have native or bound targets (core-js `uncurryThis`, `toString.call`, `hasOwnProperty.call`), which never ran `vmRun`. Script time did not move outside noise (`(bytecode)` 3097 → 3174 ms under the profiler).
  - The expected −250 ms assumed Q4.16a's 1.33M bbc `call` calls; this replay now makes 215k (Q4.16f/g took core-js polyfills off), of them ~70k into JS, so the saving is about 10 ms at ~150 ns each.
