## Slice 1: interpolation of transform lists

- cause: `interpolateText` had no model of a transform list.
- design (css-transforms-2, interpolation of transforms), in `browser/animation/`:
  - `parseTransformList` reads a list into `TransformFn` values (name, up to 16 numbers, their units; a number may have an exponent). A list it cannot read (`calc()`, other units) falls back to the old text path.
  - `mixTransforms`: the shorter list is padded with the identity of the other one's functions (`identityTransform`; `perspective()` has none). Then pair by pair (`mixTransformPair`): the same function mixes its arguments; functions of one family mix as their primitive (`translate`/`translate3d`, `scale`/`scale3d` through `primitiveTransform`; rotations about one axis through `mixRotations`, written `rotate3d`). From the first pair that has no common primitive, the two remainders are turned into 4x4 matrices (`transformsMatrix`), decomposed (`decompose`: translation, scale, skew, quaternion), mixed (`mixDecomposed`, `slerp`) and recomposed into one `matrix()` or `matrix3d()`. A singular matrix, a percentage in the remainder or a perspective component is not interpolated (the pair is discrete).
  - a 2D matrix pair goes through the same 4x4 decomposition, not the 2D one of css-transforms-1: the WPT expectations (`transform-interpolation-005.html`) are those of the 4x4 path. The 2D version was written first and gave 170 of 384 there against 272.
  - at progress 0 and 1 an interpolable pair keeps the text of its endpoint (unless that endpoint is `none`), since Dweller's computed `transform` is the function list, not a resolved matrix.
- tool: `browser/tools/wpt.py` fetches `web-animations/resources` (and so `web-animations/testcommon.js`), which two files of the area load; without it they failed on `createDiv is not defined`.
- references: https://drafts.csswg.org/css-transforms-2/#interpolation-of-transforms , `#decomposing-a-3d-matrix`, `#recomposing-to-a-3d-matrix`. No Chromium file read. The quaternion-to-matrix signs in `quaternionMatrix` are the transpose of the draft's pseudo-code, chosen so that `recompose(decompose(M))` is `M` with the draft's sign tests in `quaternionOf`.
- files: `browser/animation/interpolate-text.aye` (one branch), 34 new files in `browser/animation/` (`mix-transforms.aye` is the entry); `browser/tools/wpt.py`; new fixture `browser/tests/jsdom/transform_interpolation.html` and `.tree` (golden new, nine half-way values read, among them `translate(25px, 25px)`, `scale(1.5, 2.5)`, `translate(150px) rotate(360deg)`, `matrix(0.71, 0.71, -0.71, 0.71, 10, 0)`); `browser/tools/conformance/css_css-transforms.json`.

## Slice 2: `getComputedStyle().transform` is the resolved matrix

- cause: getComputedStyle gave the computed function list. The resolved value of `transform` is `none`, `matrix()` or `matrix3d()`, and the tests (and pages that parse it) compare matrices: `scaleX(2) scaleX(2.5)` and `scaleX(5)` are the same answer.
- design: `animation.resolvedTransform` turns a list into its matrix (`transformsMatrix`, now with the reference box: `sizedTransform` resolves the percentages of the translate family against the border box; `perspective()` has its matrix) and writes `matrix()` when it is flat, else `matrix3d()`. `ak.resolvedTransform` (new native) is called by the prelude's `styleOf` for `transform` only; it asks for the layout only when the list has a percentage. A list that cannot be resolved (no box, an unknown function) stays as it is. The Web Animations shim (`animation-values.js`, `computedWith`) reads the unresolved list through `ak.computedStyle`, since interpolation and composition work on lists. The endpoint rule of slice 1 is gone (`write-endpoint.aye` removed).
- files: `browser/animation/transforms-matrix.aye`, `transform-matrix.aye`, `mix-transform-matrices.aye`, `mix-transforms.aye`, new `resolved-transform.aye`, `sized-transform.aye`; `browser/engine/window_api.aye` (one `defMethod`), `prelude.aye` (`styleOf`, one line), `animation-values.js`, new `ak-resolved-transform.aye`.
- measured alone: 3233 -> 3458/5428.

## Slice 3: composition of transform lists

- cause: `add` and `accumulate` were one text operation that summed the numbers of the two lists.
- design (css-transforms-2, combining transform lists): `addTransforms`: `add` appends the keyframe's list to the underlying one; `accumulate` (`accumulateTransforms`) pads the shorter list and sums each pair of the same function argument by argument, less the identity (scale 2 and 3 accumulate to 4). A pair of different functions or of matrices is not accumulated (the keyframe value is used, as before). `ak.add` takes the mode as a fourth argument.
- files: `browser/animation/add-text.aye`, new `add-transforms.aye`, `accumulate-transforms.aye`; `browser/engine/ak-add.aye`, `window_api.aye`, `animation-values.js`.
- references for both slices: https://drafts.csswg.org/css-transforms-1/#serialization-of-the-computed-value , https://drafts.csswg.org/css-transforms-2/#combining-transform-lists . No Chromium file read.
- fixture: `browser/tests/jsdom/transform_interpolation.html` and `.tree`, extended and blessed again (the nine half-way values are now matrices, read: `matrix(1, 0, 0, 1, 25, 25)`, `matrix(1.5, 0, 0, 2.5, 0, 0)`, the 45 degree rotations; new lines `add` `matrix(2, 0, 0, 2, 100, 0)`, `accumulate` `matrix(4, 0, 0, 4, 0, 0)`, `translateX(50%)` of a 200px box `matrix(1, 0, 0, 1, 100, 0)`, `none`).
