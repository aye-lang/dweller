## Slice 1: interpolation of transform lists

- cause: `interpolateText` had no model of a transform list.
- design (css-transforms-2, interpolation of transforms), in `browser/animation/`:
  - `parseTransformList` reads a list into `TransformFn` values (name, up to 16 numbers, their units; a number may have an exponent). A list it cannot read (`calc()`, other units) falls back to the old text path.
  - `mixTransforms`: the shorter list is padded with the identity of the other one's functions (`identityTransform`; `perspective()` has none). Then pair by pair (`mixTransformPair`): the same function mixes its arguments; functions of one family mix as their primitive (`translate`/`translate3d`, `scale`/`scale3d` through `primitiveTransform`; rotations about one axis through `mixRotations`, written `rotate3d`). From the first pair that has no common primitive, the two remainders are turned into 4x4 matrices (`transformsMatrix`), decomposed (`decompose`: translation, scale, skew, quaternion), mixed (`mixDecomposed`, `slerp`) and recomposed into one `matrix()` or `matrix3d()`. A singular matrix, a percentage in the remainder or a perspective component is not interpolated (the pair is discrete).
  - a 2D matrix pair goes through the same 4x4 decomposition, not the 2D one of css-transforms-1: the WPT expectations (`transform-interpolation-005.html`) are those of the 4x4 path. The 2D version was written first and gave 170 of 384 there against 272.
  - at progress 0 and 1 an interpolable pair keeps the text of its endpoint (unless that endpoint is `none`), since Dweller's computed `transform` is the function list, not a resolved matrix.
- tool: `browser/tools/wpt.py` fetches `web-animations/resources` (and so `web-animations/testcommon.js`), which two files of the area load; without it they failed on `createDiv is not defined`.
- references: https://drafts.csswg.org/css-transforms-2/#interpolation-of-transforms , `#decomposing-a-3d-matrix`, `#recomposing-to-a-3d-matrix`. No Chromium file read. The quaternion-to-matrix signs in `quaternionMatrix` are the transpose of the draft's pseudo-code, chosen so that `recompose(decompose(M))` is `M` with the draft's sign tests in `quaternionOf`.
- files: `browser/animation/interpolate-text.aye` (one branch), 34 new files in `browser/animation/` (`mix-transforms.aye` is the entry); `browser/tools/wpt.py`; new fixture `browser/tests/jsdom/transform_interpolation.html` and `.tree` (golden new, nine half-way values read, among them `translate(25px, 25px)`, `scale(1.5, 2.5)`, `translate(150px) rotate(360deg)`, `matrix(0.71, 0.71, -0.71, 0.71, 10, 0)`); `browser/tools/conformance/css_css-transforms.json`.

## Slice 2: `getComputedStyle().transform` is the resolved matrix

- cause: getComputedStyle gave the computed function list. The resolved value of `transform` is `none`, `matrix()` or `matrix3d()`, and the tests (and pages that parse it) compare matrices: `scaleX(2) scaleX(2.5)` and `scaleX(5)` are the same answer.
- design: `animation.resolvedTransform` turns a list into its matrix (`transformsMatrix`, now with the reference box: `sizedTransform` resolves the percentages of the translate family against the border box; `perspective()` has its matrix) and writes `matrix()` when it is flat, else `matrix3d()`. `ak.resolvedTransform` (new native) is called by the prelude's `styleOf` for `transform` only; it asks for the layout only when the list has a percentage. A list that cannot be resolved (no box, an unknown function) stays as it is. The Web Animations shim (`animation-values.js`, `computedWith`) reads the unresolved list through `ak.computedStyle`, since interpolation and composition work on lists. The endpoint rule of slice 1 is gone (`write-endpoint.aye` removed).
- files: `browser/animation/transforms-matrix.aye`, `transform-matrix.aye`, `mix-transform-matrices.aye`, `mix-transforms.aye`, new `resolved-transform.aye`, `sized-transform.aye`; `browser/engine/window_api.aye` (one `defMethod`), `prelude.aye` (`styleOf`, one line), `animation-values.js`, new `ak-resolved-transform.aye`.
- measured alone: 3233 -> 3458/5428.

## Slice 3: composition of transform lists

- cause: `add` and `accumulate` were one text operation that summed the numbers of the two lists.
- design (css-transforms-2, combining transform lists): `addTransforms`: `add` appends the keyframe's list to the underlying one; `accumulate` (`accumulateTransforms`) pads the shorter list and sums each pair of the same function argument by argument, less the identity (scale 2 and 3 accumulate to 4). A pair of different functions or of matrices is not accumulated (the keyframe value is used, as before). `ak.add` takes the mode as a fourth argument.
- files: `browser/animation/add-text.aye`, new `add-transforms.aye`, `accumulate-transforms.aye`; `browser/engine/ak-add.aye`, `window_api.aye`, `animation-values.js`.

## Slice 4: `rotate`, `scale` and `translate`

- causes: the three individual properties were mixed as text. `rotate` was taken for a non-negative property, so every negative angle became `0deg`; two rotations about different axes mixed their axis numbers; the result of `scale` and `translate` kept three components where the shortest form is expected; composition summed numbers.
- design:
  - `interpolateText` is now a wrapper: `interpolateRaw` (the old body) and, for the three properties, `css.canonicalValue` (new, the css module's own writer), so the result has the canonical form (`2 1`, `0px`, `y -50deg`).
  - `mixRotate`: the value is read as a rotation (`rotateValueFn`, `rotateKeywordFn`); two plain angles mix as angles; the same axis (or a zero angle on one side) mixes the angle (`mixRotations`); different axes go through quaternions (`slerpRotations`, `axisQuaternion`) and come back as a normalised axis and an angle.
  - `nonNegative` is false for `rotate`.
  - `addText` is a wrapper in the same way (`addRaw`): `addScales` multiplies for `add` and sums less one for `accumulate`; `addRotates` sums the angles about one axis.
  - the Web Animations shim no longer returns a keyframe's own value at local progress 0 or 1 for `transform`, so `none` at an end of a running animation is the identity of the other list.
- files: `browser/animation/interpolate-text.aye`, `add-text.aye`, `non-negative.aye`, new `interpolate-raw.aye`, `add-raw.aye`, `mix-rotate.aye`, `rotate-value-fn.aye`, `rotate-keyword-fn.aye`, `slerp-rotations.aye`, `axis-quaternion.aye`, `write-rotate-value.aye`, `add-scales.aye`, `scale-triple.aye`, `add-rotates.aye`; `browser/css/canonical-value.aye` (new); `browser/engine/animation-values.js`; new fixture `browser/tests/jsdom/individual_transform_values.html` and `.tree` (golden new, eleven values read: `-50deg`, `15deg`, `y -50deg`, `y 5deg`, `2 1`, `0px`, `6 1` for add, `4 1` for accumulate, `x 100deg`).

## Slice 5: transform values are checked and written in canonical form

- cause: `transform` was raw text, so any text was a valid value (`none scale(2)`, `matrix(1, 2)`, `scaleX(2), scaleY(3)`, `perspective(1000)`), in style sheets and in the style attribute; `rotate`, `scale` and `translate` were not checked in the style attribute.
- design:
  - `transformValue` (css, one arm of `parseValue`): `none` or a list of functions, each checked against its argument pattern (`transformPattern`: lengths, length-percentages, numbers, angles; `writeTransformFunction`, `writeTransformArg`) and written back with `scale` percentages as numbers and a unitless zero as `0deg` or `0px`. A function with a nested function (`calc()`, `var()`, `min()`) is kept as written, so nothing a page uses is refused for being unknown to this checker.
  - `writeFineNumber` (css, pub): a number with up to six decimals and no exponent. The arguments of `transform` are written with it (they were cut to two decimals by the token writer), and so are the results of the animation module (`matrix(-2e-06, ...)` was the sign that an exponent got out).
  - the style attribute: `specifiedValue` sends `transform` through the canonical writer; `checksValue` lists `rotate`, `scale` and `translate`; `validatesInline` lists `scale` and `translate`. `rotate` is checked but written as given, because the css writer turns its angle into degrees (`400grad` must stay).
- files: `browser/css/values.aye` (one arm), `specified-value.aye`, `checks-value.aye`, `specified-longhand.aye`, new `transform-value.aye`, `has-nested-function.aye`, `write-transform-function.aye`, `transform-pattern.aye`, `write-transform-arg.aye`, `unit-text.aye`, `write-fine-number.aye`, `write-padded.aye`; `browser/animation/write-transform-fn.aye`, `write-rotate-value.aye`, `add-scales.aye`; new fixture `browser/tests/jsdom/style_transform_values.html` and `.tree` (golden new, sixteen values read); `transform_interpolation.tree` blessed again: three lines, `0.71` is now `0.707107` and `1.06` is `1.06066`.

## Slice 6: `transform-origin`

- causes: getComputedStyle gave the computed text (`50% 50%`, `left`), where the resolved value is in px of the reference box; a transition or animation between a percentage (or keyword) origin and a px one did not run, since the text mix needs equal units; composition summed the numbers of the text.
- design: `originOf` reads an origin into px and percentage parts for x and y and a px z (`nextTerm`, `originTerm`, `calcTerm`; keywords are 0%, 50%, 100%, a vertical keyword first swaps the two). `mixOrigins` interpolates or, for composition, sums the parts and `writeOrigin` writes each as px, a percentage or `calc(P% + Xpx)`, which layout's `parseOrigin` reads. `animation.resolvedOrigin` gives px against the border box; `ak.resolvedOrigin` (new native) is called by the prelude's `styleOf` for `transform-origin`. The Web Animations shim reads the unresolved value, as for `transform`.
- files: `browser/animation/interpolate-raw.aye`, `add-raw.aye`, new `origin-of.aye`, `origin-term.aye`, `calc-term.aye`, `next-term.aye`, `mix-origins.aye`, `write-origin.aye`, `write-length-percent.aye`, `resolved-origin.aye`; `browser/engine/window_api.aye` (one `defMethod`), `prelude.aye` (`styleOf`), `animation-values.js`, new `ak-resolved-origin.aye`; new fixture `browser/tests/jsdom/transform_origin_values.html` and `.tree` (golden new, eight values of a 200x100 box read: `100px 50px`, `0px 50px`, `200px 100px`, `20px 30px`, `100px 0px`, `0px 50px 6px`, `60px 35px` half way through an animation from `50% 50%` to `20px 20px`, `80px 60px` for add).
