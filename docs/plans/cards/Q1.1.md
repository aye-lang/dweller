# Q1.1: the shipped build is safe mode; CI smokes it

- goal: what a person runs keeps the bounds and overflow checks, so a bug on a real site is a panic that names the line, not silent memory damage. CI runs the shipped mode, so a panic in it fails the PR.
- cause: `browser/build.sh` built `--mode fast` (no checks) for real use, while the tests build `--mode safe --leak-check`. Q0.2 measured safe against fast: longest loop +9.5%, scroll p95 +1.9%, jsbench +17.6% (navier-stokes 0.66× safe/fast; `browser/engine/PERF.md`, Q0.2). The plan asked for ≤ 5%; the decision is to ship safe at this cost and win the speed back in the compiler.
- design:
  - `browser/build.sh`: default `--mode safe`; `--mode fast` and `--mode debug` unchanged. A safe or fast build writes `OUT.safe` or `OUT.fast` (the binary's sha256); both are removed before each build.
  - `browser/tools/fast_build.py`: `is_optimized` (was `is_fast`) accepts either marker when it matches the binary; a debug build (no marker) is still refused without `--allow-debug`. W7/W8 (`page_load.py`, `window_perf.py`, `perf_gate.py`, `game_check.py`, conformance tools) now take the shipped build.
  - `browser/tests/jsbench/run.sh` builds `--mode fast`: its `baseline.json` and the `--json` label are fast-mode numbers.
  - CI: step `Smoke the shipped build` in `browser-shard` (ubuntu, shard 1/4, before the tests): `browser/build.sh target/dweller-shipped` (the default mode), checks the `.safe` marker, `dump --tree browser/tests/article.html`, `dump --layout browser/tests/basic.html`, and a 30-frame window run of `article.html` under `SDL_VIDEODRIVER=dummy`. Any panic or non-zero exit fails the job.
  - docs: `browser/README.md`, `docs/practices/browser.md` (safe is the default).
- follow-up: bounds-check elimination in loops, https://github.com/aye-lang/aye/issues/25
- files: `browser/build.sh`, `browser/tools/fast_build.py`, `browser/tools/perf_gate.py`, `browser/tests/jsbench/run.sh`, `.github/workflows/ci.yml`, `browser/README.md`, `docs/practices/browser.md`, `docs/plans/cards/Q1.1.md` (new)
- verify: `sh -n browser/build.sh`; `ruby -ryaml -e 'YAML.load_file(".github/workflows/ci.yml")'`; `python3 browser/tools/check_taste.py` exit 0; `scripts/capped.sh browser/build.sh target/dweller-q11` prints `target/dweller-q11 (safe)` and writes `target/dweller-q11.safe`; `fast_build.require` accepts it. On CI: the PR's `ci` run is green, including the smoke step.
