# Q3.14: Fetch Metadata headers, Origin on POST navigations, referrer policy

- goal: every http(s) request to a potentially trustworthy URL (https, `localhost`, `127.x`, `[::1]`) sends `Sec-Fetch-Site`, `Sec-Fetch-Mode`, `Sec-Fetch-Dest`, and `Sec-Fetch-User: ?1` on a user-activated top-level navigation, in both processes. A navigation by POST sends `Origin`. net applies the page's referrer policy (the `Referrer-Policy` header, `<meta name=referrer>`, `referrerpolicy` on scripts) when it sets `Referer`; the default is strict-origin-when-cross-origin. Source: Q2.4f's left list.
- chain: on Q3.13 (#311). Also merges Q2.4f (#310, which contains Q2.4d #307), because the `DWELLER_PROCESS=tab` navigation cases need its `nav_initiator`.
- design:
  - Fetch Metadata (`net/sec-fetch-headers.aye`, added by `requestHeaders` in `net/http.aye`): nothing for a URL that is not trustworthy (`net/trustworthy-url.aye`). `Sec-Fetch-Site` (`net/fetch-site.aye`, `net/fetch-site-at.aye`): `none` when the request has no origin (`requestOrigin` is empty: a URL the user typed, a bookmark, history), else it starts as same-origin and each URL of the chain lowers it (same-origin → same-site → cross-site, schemeful sites by `siteOf`), so `transfer` recomputes it on every redirect hop. A loader job (`net/multi.aye`) computes it for its one URL. `Sec-Fetch-Mode` (`net/sec-fetch-mode.aye`): `navigate` for a `Kind.Document`, else `cors` / `no-cors` from `Request.mode`. `Sec-Fetch-Dest` (`net/sec-fetch-dest.aye`): `document`, `iframe` (a document with `top`), `style`, `image`, `script`, `empty` (`Kind.Other`). `Sec-Fetch-User: ?1` for a top-level document when `Request.user_activated` or the site is `none`.
  - User activation: `noteNavigation` takes `user`. Links (`Page.follow`) and form submissions pass true; `location` and frames pass false. `requestLive` copies it with the hint's referrer. In the tab process the browser's `answerFetch` sets it for the navigation it began (`begin_navigation`, only clicks and submissions) and for a typed URL.
  - `Origin` (`net/origin-header.aye`): also for a request whose method is not GET or HEAD (a body without a method counts as POST), so a form POST navigation sends it. When the mode is not CORS, `originHidden` (`net/origin-hidden.aye`) makes it `null` per the referrer policy (no-referrer; https to http for the strict policies; another origin for same-origin). After a CORS redirect that taints the origin, the next hops send `Origin: null` (`sent.initiator` becomes `Page { url: "null" }`).
  - Referrer policy: `ReferrerPolicy` (`net/referrer-policy.aye`), `parseReferrerPolicy` (the last known token of a comma list, ASCII case-insensitive), `referrerPolicyName`. `Request.referrer_policy: ?ReferrerPolicy`: an element's own policy. `referrerPolicyOf(req)`: that, else the page's policy (`noteReferrerPolicy(alloc, page, policy)` keyed by the page URL, a list outside the session so the renderer has it too; `stop` frees it), else strict-origin-when-cross-origin. `referrerOf` (moved to `net/referrer-of.aye`) implements all eight policies; "downgrade" uses trustworthy URLs, not only https. The engine notes a page's policy in `pageOf` (`engine/note-page-referrer-policy.aye`: the last valid `<meta name=referrer>`, else the header). `referrerpolicy` on a script (`scriptRequest`, `engine/inserted.aye`) sets the request's own policy, kept by background loads (`Load.referrer_policy`). The renderer sends the resolved policy name in `Message.Fetch.referrer_policy`; the browser parses it.

## Status: done, 2026-11-08

Left:
- WPT `fetch/metadata` and `referrer-policy` are not areas of the conformance runner yet (they need upstream `wpt serve` like `mixed-content`); not measured.
- `referrerpolicy` on `img`, `link`, `iframe`, `a`/`area`, `rel=noreferrer`, and `fetch(…, {referrerPolicy})` are not applied: images and sheets go through `startLoad(href, kind, referrer)` and frames and links through `noteNavigation`, which carry no policy; fetch's native args would need a new position. The page's policy still applies to all of them.
- In the tab process a navigation's referrer policy is the default: the browser takes the referrer from `nav_initiator`, and `begin_navigation` carries no policy.
- A `Referrer-Policy` header on a redirect response does not change the request's policy for the next hop. A 303 after a POST still sends `Origin` on the GET hop (the check uses the request, not the hop's method).
- Fonts are fetched as `Kind.Script`, so they send `Sec-Fetch-Dest: script`; workers and websockets have no kind (`worker`, `websocket` destinations/modes are not sent).
- `form.submit()` from a script counts as user-activated in the window process (forms do not tell a click from a script).
- The page policy list keeps one entry per page URL until `stop`.
