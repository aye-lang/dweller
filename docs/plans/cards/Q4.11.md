Where the pause goes (`js_gc_mark` and `js_gc_sweep`, new records): on
`splay` marking is 65 to 72 ms of the two largest pauses and sweeping 11
to 53 ms. Marking does not get faster by tracing through pointers
instead of copies (tried: no change; it is cache misses), so both phases
have to be cut into steps.

## Slice 1, 2026-11-19: incremental marking and stepped sweeping, off by default

Verified on the merged tree (wave branch restarted from main, aye
96623d1): whole suite 301 passed, 0 failed (`target/q411.log`);
`check_taste.py`, `check_layers.py`, `gen_property_ids.py --check`, `aye
check browser`: 0. The 297 files of `browser/tests/js/` give the same
output and exit status under `DWELLER_JS_GC=torture` as without it (safe
build), and splay, raytrace, closures, json and strings give their
checksums under `incremental` and `torture`.

What is in:
- `js_gc_mark` and `js_gc_sweep` timing records beside `js_gc`.
- Incremental marking (`DWELLER_JS_GC=incremental`):
  `gc-on-allocation.aye` (the allocation hook), `gc-incremental.aye`
  (`startMarking` at the allocation threshold), `mark-step.aye` (every
  64 allocations, up to 384 values traced), `finish-cycle.aye` (the
  atomic end: roots again, the rest, ephemerons, the host's trace, dead
  weak entries, dead host wrappers). New values are allocated shaded
  while marking. The write barrier shades the stored value (`Heap.shade`,
  `shadeObj`, `shadeEnv`; `Heap.wrote` rescans an object whose `data`
  was replaced): 42 store sites in `browser/js/` placed by script, plus
  `heap.aye` `addProp` and `setLength`, `vm-ic-store-hit`, `typed.aye`,
  `weak.aye`, `vm-gen-frame`, `interp.aye` `setHome`,
  `vm-create-object-literal`. Moves inside one object, constant stores
  and stores of the root prototypes have no barrier. `browser/engine/`
  writes no heap object directly (checked by grep).
- Stepped sweeping after an incremental marking (`start-sweep.aye`,
  `sweep-step.aye`: 2048 slots every 64 allocations, `finish-sweep.aye`,
  `sweep-objs.aye`, `sweep-strs.aye`, `sweep-envs.aye`, `end-sweep.aye`).
  A full collection (`collectGarbage`, the memory limit, `gc()`) sweeps
  at once, through the same functions. Dead host wrappers are finalized
  and freed at the end of marking (`finalize-hosts.aye`,
  `Heap.host_objs`): the engine's wrapper cache would otherwise hand a
  dead wrapper back before the sweep reached it. A value allocated in a
  slot the sweep has not reached is born marked (`Heap.unswept`).
- `DWELLER_JS_GC=verify` (after each incremental marking: clear the
  marks, mark from scratch, exit 70 if a reachable value had not been
  marked; `gc-verify.aye`, `remark.aye`) and `DWELLER_JS_GC=torture`
  (verify, a cycle every 256 allocations, a step at every allocation).
  With every barrier turned off the verifier reports missed values on
  splay; turning off only `addProp`'s or only the inline-cache store's
  barrier is not caught by splay.
- Shared files touched (lane js has the builtins): barrier lines only in
  `builtins.aye` (4), `builtins_array.aye` (18), `builtins_misc.aye` (2),
  `modules.aye`, `sort-keys.aye`, `define-class.aye`, `typed.aye`,
  `weak.aye`, `proxy.aye` (none). A new store of a value into an object,
  an array's elements or an environment needs `it.heap.shade(value)`
  before it; the torture mode finds a missing one only where a test
  moves an old value.

## Slice 2, 2026-11-19: incremental is the default

- `DWELLER_JS_GC=full` goes back to one pause per collection; `stress`
  (a threshold of 1, also set by tests) stays a full collection at every
  allocation; `verify` and `torture` as above.
- While marking, a plain object (no `data`) and an environment are
  allocated black with their prototype or parent shaded; other objects
  and ropes are allocated shaded and traced later.
- The barrier's test is inline at the hot stores (`vm.aye`,
  `vm-ic-store-hit`, `vm-sta-global`, `vm-define-named-own-property`,
  `interp.aye`), and allocation tests one flag (`Heap.collecting`).
