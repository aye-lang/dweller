Pages under `browser/tests/perf/` (`dump --text --js`): `host_ic.html` 23

`animated.html`, `staged_scripts.html` none. `browser/perf/` holds no
pages (it is the telemetry module).

So two workloads are over 16 ms: `splay` (a live tree of about a million
values: the last collection is 72 ms of marking and 53 ms of sweeping)
and `dom` (19 ms). The sites of PERF.md (youtube-search p95 87 ms, zol
28, youtube 26, bbc 20) are in the Mac queue.

Where the pause goes (`js_gc_mark` and `js_gc_sweep`, new records): on
`splay` marking is 65 to 72 ms of the two largest pauses and sweeping 11
to 53 ms. Marking does not get faster by tracing through pointers
instead of copies (tried: no change; it is cache misses), so both phases
have to be cut into steps.

## State at the pause of the wave (2026-11-17): work in progress, NOT verified by the suite

The code of this card is on `w16-native` as a work-in-progress commit.
It type-checks (`aye check browser`) and builds; the whole suite, the
taste check and jsbench have NOT been run on it. Do not merge it into
the wave branch as it is.

Done (built and exercised by hand):
- `js_gc_mark` and `js_gc_sweep` timing records beside `js_gc`.
- Incremental marking, off by default (`DWELLER_JS_GC=incremental`):
  `gc-incremental.aye` (`startMarking` at the allocation threshold,
  `markStep` every 64 allocations tracing up to 384 values,
  `finishCycle` for the atomic end: roots again, the rest, ephemerons,
  the host's trace, dead weak entries). New values are allocated shaded
  while marking. The write barrier shades the stored value
  (`Heap.shade`, `shadeObj`, `shadeEnv`; `Heap.wrote` rescans an object
  whose `data` was replaced): 43 store sites in `browser/js/` placed by
  script plus `heap.aye` `addProp` and `setLength`, `vm-ic-store-hit`,
  `typed.aye`, `weak.aye`, `vm-gen-frame`, `interp.aye` `setHome`,
  `vm-create-object-literal`. Moves inside one object and constant
  stores have no barrier. The engine (`browser/engine/`) writes no heap
  object directly (checked by grep).
- `DWELLER_JS_GC=verify` (after each incremental marking: clear the
  marks, mark from scratch, exit 70 if a reachable value had not been
  marked) and `DWELLER_JS_GC=torture` (verify, a cycle every 256
  allocations, a step at every allocation).
- Checked by hand with the marking slice alone, safe build: the 297
  files of `browser/tests/js/` give the same output and exit status
  under `torture` as without it, and the jsbench workloads splay,
  raytrace, closures, json and strings give their checksums under
  `incremental` and `torture`. With every barrier turned off the
  verifier reports missed values on splay (so it does find a missing
  barrier); turning off only `addProp`'s or only the inline-cache
  store's barrier is not caught by splay.

Half done:
- Stepped sweeping (`gc-sweep.aye`, `sweep-slots.aye`, `sweep-objs.aye`,
  `sweep-strs.aye`, `sweep-envs.aye`, `end-sweep.aye`,
  `finalize-hosts.aye`): written and type-checked, never run. It also
  replaces the body of the full collection's `sweep`, so it changes the
  default path. Dead host wrappers are finalized and freed at the end of
  marking (`Heap.host_objs`), because the engine's wrapper cache would
  otherwise hand a dead wrapper back before a lazy sweep reached it; a
  value allocated in a slot the sweep has not reached is born marked
  (`Heap.unswept`).
- test262 under `torture` against a plain run (`test/built-ins`,
  `test/language/statements`, `test/language/expressions`): started and
  stopped at the pause; no result.
