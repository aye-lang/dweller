# Q2.3e: the window keeps no copy of the page; cursor, status, busy chip from the renderer

- goal: with `DWELLER_PROCESS=tab`, the window no longer loads, lays out or keeps its own copy of the page: it records the URL in the tab's history, spawns the renderer, sends `navigate` and composites the renderer's frames. The renderer reports the cursor shape, the hover link (status line), long tasks (the "page busy" status), and Tab past the page's last element (the address bar takes the focus); window blur/focus fire `blur`/`focus` in the page; a cross-origin redirect commits in the renderer without a second fetch. Without the flag nothing changes.
- design:
  - IPC messages added (type codes in order, all R→B on the tab's frame id): 19 `cursor{shape}` (0 default, 1 pointer, 2 text; sent only when it changes); 20 `target_url{url}` (the resolved link under the mouse, "" for none; sent only when it changes); 21 `long_task{on, ms}` (on 1 when a task passed `HANG_MS`, 5 s, through the engine's hang hook; on 0 after the task ended, with `ms` the task's length when it was over the in-process long-task limit, 10 s, else 0); 22 `take_focus{reverse}` (Tab, or Shift+Tab, on the last, or first, focusable element); 23 `redirect{url}` (the load was redirected to another origin; sent before `loaded`).
  - the browser's checks (`rendererSent`; a failure logs `bad message: REASON PID` and kills): `cursor` shape over 2 → `bad cursor`; `target_url` over 2 MiB (Chromium's `kMaxURLChars`) → `bad target_url`; `long_task` with `on` over 1, a start while busy or an end while not busy → `bad long_task`; `take_focus` with `reverse` over 1 → `bad take_focus`; `redirect` when no load is pending, a second one in one navigation, or not from an http(s) URL to an http(s) URL (`redirectAllowed`) → `bad redirect`. Every message on another frame id fails with its reason too. An accepted `redirect` sets `tp.committed`, so `loaded` with the redirected URL passes `commitMatches`.
  - redirects: the renderer commits the redirected page and tells the browser (`redirect`), instead of asking again with `begin_navigation` for the final URL. The other choice was for the browser to hand the renderer a response it already fetched, but the browser does no fetching until Q2.6 moves the network there. Committing the page the renderer already has is the simpler choice that is correct: one fetch, and no ping-pong between two origins. The 20-redirect cap is net's `MAX_REDIRECTS` (20, the same as Chromium's `kMaxRedirects`) on that one fetch, and one navigation is now one fetch, so a navigation is capped at 20. Over 20 the renderer commits net's error page. The browser cannot count the hops itself while the renderer does the network (Q2.6).
  - window (`ui/`): `Ui.go` under the flag pushes the URL to `tab.history` (no page) and calls `goInRenderer` (it clears `tp.url` so that `queueNavigate` sends `navigate`, then sets the address, title and focus). `goBy` moves `history.current` and does the same. `tab.page` stays null under the flag: no fetch, parse, layout, script or timer runs in the window process. `showStatus` (from `pollTabProcesses`, for the active tab) puts "The page is busy" while busy, "A page task ran for N s" once after a task over 10 s, else the target URL, into the status line, and sets the cursor. `takeFocusBack` gives the address bar the focus, and `tellFocus` then sends `focus{0}`. The remote `select` dropdown no longer needs the window's page: `Dropdown.sel` is `?NodeId` (null for a remote one), and `drawPageState` draws a remote dropdown without a page. `--state` prints `renderer-cursor default|pointer|text`; the `--events` word `renderer:busy` waits for a `long_task` start.
  - renderer (`renderer/`): `hoverReport` (after `engine.hoverAt` on each move: link → pointer and its resolved URL, text field → text, else default) and `showHover` (sends what changed; a mouse leave resets both). `watchBusy` installs `busyHook` as the engine's hang hook (sends `long_task{1}` once and lets the task go on), and `endBusy` (at the start of `reportPage`) sends `long_task{0}`. `answerAll` now reports the page before it acks the input, so everything an input caused arrives before its `input_ack`. `focusPage` (on `focus`) fires `blur`/`focus` at the focused element and at the window when the page focus changes (prelude `hostState('blur'|'focus')`; `activeElement` stays). `tabKey` sends `take_focus` when `atFocusEdge`. `load` sends `redirect` for a cross-origin redirect and commits.
- Chromium read (idea only): `content/browser/renderer_host/render_widget_host_impl.cc` (`SetCursor`: the renderer sends a cursor and the browser shows it; `TakeFocus`), `content/browser/renderer_host/render_frame_host_impl.cc` (`UpdateTargetURL`: the hovered link's URL goes to the status bubble), `net/url_request/url_request.cc` (`kMaxRedirects` = 20, `ERR_TOO_MANY_REDIRECTS`), `content/browser/renderer_host/navigation_request.cc` (`OnRequestRedirected`: the browser follows and checks each redirect). Dweller takes: the cursor and the status text are plain checked data from the renderer, the browser draws them; a redirect is checked by the browser and capped at 20, but it is followed in the renderer's one fetch until the network moves to the browser.
- files: `browser/ipc/{message,decode,put-payload,from-renderer,message_test}.aye`; `browser/engine/prelude.aye` (`hostState` blur/focus); `browser/renderer/{answer-all,load,mouse-input,report-page,serve-on,tab-key,tab-renderer}.aye`, new `browser/renderer/{focus-page,hover-report,show-hover,busy-hook,end-busy,at-focus-edge}.aye`; `browser/ui/{window,tab-process,start-tab-process,end-tab-process,renderer-sent,poll-tab-processes,queue-navigate,begin-navigation,renderer-waits,write-tab-process,take-popup,choose-row,forms}.aye`, new `browser/ui/{go-in-renderer,show-status,take-focus-back,redirect-allowed}.aye`; new `browser/tests/ui/renderer_status.html`; `browser/tests/server.py` (`/hops/N`); `tests/browser.rs` (new `window_renderer_status`).

## Status: done, 2026-11-08

Left:
- `window_*` tests that still cannot run with `DWELLER_PROCESS=tab`: everything that reads the window's own page state in `--state` (`element … value`, `frames`, `frame_urls`, `matches`, `history` after link navigations, `scroll`), the `loaded`/`painted` wait words (they wait on the window's page), and the features that are not in the renderer yet: find (`window_find*`), clipboard, agents (`window_agent*`, `agent_sessions`, `window_spaces`: Q2.3b routing), pointer lock and fullscreen (`window_pointer_lock`), the stuck bar (`window_stuck_script`: the renderer's hang hook only reports busy, it has no Wait/Stop), iframes, `--text` dumps (`window_long_task`), auth prompts (`window_auth*`), `window_paints_early` (`DWELLER_TIMING` of the window's own load), WebGL and canvas readback.
- history: under the flag the window's history has only the entries the address bar, back and forward made; a renderer's link navigation, pushState and fragments add none (Q2.6). Back, forward and reload send `navigate` again (no bfcache, no in-document traversal); an address-bar fragment of the shown page reloads it.
- the hang hook lets a task run forever (no "Stop", no renderer kill on a hang); the in-process window's Wait/Stop bar is not offered for a renderer.
- the browser cannot count redirect hops until the network moves to it (Q2.6); the cap is net's per-fetch limit.
- a Tab from the address bar back into the page does not go to the page's first element (Chromium's `SetInitialFocus`); the focus ring stays drawn while the window is blurred.
- agents (`agent.Session` reads the tab's page, now null under the flag): Q2.3b.
