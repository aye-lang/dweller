# V4: terminal emulator spike

The card is in `docs/plans/vision.md`. This file holds its status, what
was built, the numbers and what is left. Two slices: the parser with its
recorded-stream tests (commit b4befc5), then the window.

## Status: done, 2026-11-16 (the acceptance programs by hand are in the Mac queue)

Done note:
- `apps/term/` (new, 2053 lines of Aye; `README.md` there): its
  `aye.toml` names the engine as a path dependency, as V2's example
  does, and it imports `dweller.paint`, `dweller.font` and `dweller.sdl`.
- Slice 1, `apps/term/vt/`: the parser is the state machine of
  vt100.net's DEC parser (`step.aye`; ground, escape, CSI entry, param,
  intermediate and ignore, OSC and the ignored DCS/SOS/PM/APC strings,
  CAN/SUB/ESC from anywhere) and takes any split of the bytes. Handled:
  UTF-8, wide characters (two cells), C0 controls, CUU/CUD/CUF/CUB/CNL/
  CPL/CHA/CUP/HVP/VPA, ED, EL, IL, DL, ICH, DCH, ECH, SU, SD, REP,
  DECSTBM, IND/RI/NEL, DECSC/DECRC, RIS, SGR (attributes, 16, 256 and
  true colors, `;` and `:` forms), DECSET/DECRST 1, 6, 7, 25, 47, 1047,
  1049, 2004, IRM, DSR 5 and 6, DA1 and DA2 (answers go to the pty), the
  DEC line-drawing set (G0/G1, SO/SI), OSC 0 and 2. The screen model has
  the primary and the alternate screen, scrollback of 10 000 rows, the
  title and a dirty flag per row.
- Slice 2, the window: `forkpty` with `$SHELL` (or `--exec COMMAND`),
  `poll` on the pty, the rows that changed drawn with
  `paint.TextPainter` and `Canvas.fillRect`, the cursor as an inverse
  cell, xterm's 256-color palette, keys encoded as xterm does
  (`key-bytes.aye`: Return, Backspace, Tab, Shift+Tab, Escape, Ctrl+key,
  arrows and Home/End in normal and application mode, Delete, PageUp,
  PageDown), scrollback with Shift+PageUp/PageDown and the wheel, window
  resize (`vt.resize`, TIOCSWINSZ per OS), HiDPI scale. The window
  closes when the command exits.
- Tests (`tests/browser/term.rs`): `term_vt_streams` (7 streams in
  `apps/term/tests/`: vim's start screen, vim with syntax colors and
  line numbers, vim after `:q!`, an htop frame, less, and the hand-made
  `colors` and `modes`; each `.bytes` must dump as its `.grid`),
  `term_shot` (3 streams drawn with the fixed font against PNG goldens),
  `term_pty_window` (a command on a real pty under SDL's dummy driver:
  its colored output, a typed line echoed and read, `stty size` 24 80),
  `term_unit_tests` (`aye test apps/term`: the key table).
- The goldens were checked before blessing: the screen text and cursor
  of vim-start, vim-edit, htop and less are equal to pyte's
  (`apps/term/tools/reference.py`), row for row. `colors` and `modes`
  differ from pyte only where pyte lacks the feature (colon SGR, the
  line-drawing set, DCS strings, REP, the alternate screen), and those
  rows were checked by hand against xterm's `ctlseqs`; the PNGs were
  looked at with the system font (htop's bars, colors and function-key
  row, the color table).
- Verify, cloud machine, proxy variables unset: the whole suite 258
  passed, 0 failed (`target/v4.log`); `term_` alone five times in a row;
  `check_taste.py`, `check_layers.py`, `gen_property_ids.py --check`,
  `aye check browser`: 0.
- Seam in existing files: key constants added to `browser/sdl/sdl.aye`
  (this lane's own file); one `mod term` line in `tests/browser.rs`.

Numbers (cloud machine, `--mode fast`, SDL dummy driver):
- binary: 1 075 424 bytes.
- idle (`--exec "sleep 13"`, 10 s): 30 ms of CPU, 15 MB resident. The
  loop polls the pty for 10 ms, then SDL's queue; nothing is drawn or
  presented while no row is dirty.
- `seq 1 200000` to the end: 1.0 s.
- `vim -u NONE -N README.md`, `htop` and `less README.md` start in the
  window, take `:q` / `q` typed into the pty and exit, and the window
  closes (exit 0).

Left:
- Not handled by the parser: combining marks (dropped; pyte shows `é`
  where this shows `e`), mouse reporting (1000, 1002, 1006), focus
  events, tab stops other than every 8 (HTS, TBC), DECALN, the cursor
  style (DECSCUSR), OSC 4/10/11/52/8, synchronized output (2026), the
  kitty keyboard protocol and modifyOtherKeys, bracketed paste is
  recorded but there is no paste, sixel.
- Keys: Alt as ESC prefix, function keys, modified arrows
  (`CSI 1;5C`), the keypad's application mode.
- No selection, copy or paste; no blinking; the cursor is a block only;
  bold is the bold face (no bright colors for bold); no ligature or
  shaping across cells (one `draw` per cell).
- Resize keeps the top-left of the screen and does not reflow lines;
  scrollback rows keep their old width.
- The loop wakes every 10 ms to poll (30 ms of CPU in 10 s). A reader
  thread that pushes an SDL event would let it block; `std` threads and
  SDL's user events are there.
- The whole texture is uploaded when any row changed; upload the dirty
  rows only (`SDL_UpdateTexture` with a rect).
- The shell (`browser/shell`) and the terminal each open the window, the
  renderer and the texture; one `surface` for both, with V2's Left item
  about `ui/pagedraw.aye`.
- `apps/term` is outside `browser/`, so `check_taste.py` does not check
  it; it follows the rules by hand (one function a file, no comments
  but reference links).
