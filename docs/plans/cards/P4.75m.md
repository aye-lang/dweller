#### P4.75m: mistral panics in css/cascade.aye
- goal: the mistral archive (recaptured 2026-10-17) loads without the panic `browser/css/cascade.aye:1619:44: panic: float to integer cast out of range`.
- cause: Tailwind's `.rounded-full{border-radius:3.40282e38px}`. The `border-radius` shorthand writes its longhands back as text (`Declarer.shorthand` → `borderRadius` → `writeComp` → `writeLength` → `writeNumber`), and `writeNumber` cast `round(n * 100)` to `i64`; any length from about 9.2e16 up (or NaN) is out of the `i64` range. The sheet is parsed lazily when a script first asks for a metric (`akMetric` → `layoutStyling` → `authorSheets`), so the crash came from the page's JS.
- fix: `writeNumber` moved out of `cascade.aye` into `browser/css/write-number.aye`; a number of magnitude 1e16 or more (or NaN) is written with `text.Builder.appendFloat` (6 significant digits with an exponent, as Blink's `String::Number`: `3.40282e+38px`); smaller numbers keep the two-decimal form.
- files: `browser/css/write-number.aye` (new), `browser/css/cascade.aye` (function and its `std.math` import removed), `browser/tests/style/huge_numbers.html` + `.style`
- blink: `third_party/blink/renderer/core/css/css_primitive_value.cc` (`FormatNumber`)
- verify: `scripts/capped.sh cargo test --release --test browser -- style_fixtures layout_fixtures jsdom_fixtures errors > target/p475m.log 2>&1; echo $?` → 0 (the new `huge_numbers` fixture panicked before the fix); `scripts/capped.sh python3 browser/tools/page_load.py check --site mistral` → no panic
