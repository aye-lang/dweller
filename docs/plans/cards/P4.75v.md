#### P4.75v: mistral forced layouts: partial restyle cost and relayout refusals

- goal: make mistral's forced layouts cheaper (`script_layout` 5.2 s over 8123–8143 forced layouts after P4.75t): (1) the fixed cost of one partial restyle (~0.37 ms), (2) the incremental relayouts refused for container queries (850) and floats (420), (3) a forced layout with nothing dirty must do no work. Identical output.
- measurements (mistral, P4.75d archive, `browser/build.sh` fast binary of `origin/p4-75t-layout-speed`, M2 Pro, capped; `DWELLER_TIMING=1 DWELLER_LAYOUT_WHY=1` and a 15 s macOS `sample` of the replay, split by call site inside `restyleSubtrees`):
  - `geometry` 1173 samples, of it partial restyles (`restyleSubtrees`) 528 and `treeSourceKey` (`sheetSourceKey`) 128.
  - in `restyleSubtrees`, `styleElement` was called from three places: the ancestor chain of each root 241 samples (46%), the full subtree of a root 208, the shallow walk 6. Each partial restyle matched and computed every ancestor of each root again (the chain to `<html>`), only to recover what the root inherits, the root's font size (`rem`, `rlh`) and the `<center>` alignment; the ancestors' values were already in `Styles`.
  - the iframe's refusals: after `relayout:queried` was allowed, the same 873 layouts were refused as `relayout:shadows` (the relayout root is above one of the iframe's 14 shadow hosts).
  - a forced read with nothing dirty: `geometry` returns at once when `layoutVersion` and the viewport are unchanged (no timer, no style or sheet work); nothing to do.
- design (Blink's algorithms, no code copied):
  - `inheritChain`: when no ancestor of a restyle root is itself a root and all have values, the chain is not styled again; the root font size and root line height come from the root element's values, and `<center>` alignment from the chain's values (`centers`, also used by `alignCenter`). Otherwise the chain is styled as before. Blink's `StyleEngine::RecalcStyle` visits only dirty subtrees and reads the parent's `ComputedStyle`.
  - `relayoutDirty` no longer refuses container queries in a layout that is not the page's (`!g.shared`): there nothing records container sizes (`settleContainers` and `layoutQueried` run only for the page's layout), so the query results cannot change between a full and an incremental layout; the full layout it replaced (`layOut`) did not settle them either. Blink re-evaluates container queries only when a container's size changes.
  - `aboveShadows` replaces `clearOfShadows` in `relayoutDirty`: a relayout root may be above a shadow host (boxes are built from the flat tree in both paths); roots inside a shadow tree or under a host (slotted children) still refuse.
- files: new `browser/css/inherit-chain.aye`, `browser/css/centers.aye`, `browser/engine/above-shadows.aye`; wiring in `browser/css/cascade.aye` (`restyleSubtrees`, `alignCenter`), `browser/engine/geometry.aye` (`relayoutDirty`); removed `browser/engine/clear-of-shadows.aye` (no other user).
- blink: `core/css/style_engine.cc` (`RecalcStyle`), `core/css/container_query_evaluator.cc`, `core/dom/document.cc` (`UpdateStyleAndLayout`).
- verify: `scripts/capped.sh cargo test --release --test browser -- layout style_fixtures layout_fixtures jsdom_fixtures window_ > target/t.log 2>&1; echo $?` → 0 (61 passed, `window_webgl` with ANGLE from `browser/gpu/fetch_angle.sh`); `page_load.py check` on every site but mistral (mistral's six-load budget went to timing and checks): only bbc and zol fail (known, as on main); `DWELLER_LAYOUT_CHECK=1` on mistral (after each of the three steps), github and react: 0 `LAYOUT CHECK` / `STYLE CHECK`; the Markdown of all three equals the base binary's; `check_taste.py`, `check_layers.py` pass.
