# V5: agents on native apps

The card is in `docs/plans/vision.md`. This file holds its status, what
was built and what is left.

## Status: done, 2026-11-16

Done note:
- `APP --agent` on a V2 app (`shell.run` reads the option): the JSON
  lines of `docs/agent-protocol.md` on stdio, without a window, text
  measured with the fixed font as `dweller agent` does. Commands:
  `snapshot`, `click`, `type`, `press`, `scroll` (by `ref` or `dy`);
  errors for an unknown command, an unknown ref, a missing argument,
  invalid JSON. The answers have `id`, `ok`, `result`, `url` (the app's
  address), `title`, and `diff` when the snapshot changed.
- The semantic tree is built in `browser/shell/` from the document, the
  computed `display` and the boxes (`build-sem.aye`, `walk-sem.aye`,
  `write-sem.aye`): heading, paragraph, button, textbox, list, listitem,
  text, and `generic` for an element with a click handler; refs in
  document order, kept per node; `[focused]`, `value="..."`,
  `[offscreen]`; text runs are split at block boundaries.
- `click` runs the handler the window's click runs (`click-node.aye`);
  a click now also focuses a button, as in the browser. A focus change
  is a shallow restyle (`mark-restyle.aye`), so it rebuilds boxes only
  when a value moved (V2's test caught the full layout it cost before).
- Verify: `native::native_counter_agent` sends the 19 requests of
  `examples/native/counter/expected/agent.jsonl` to `counter --agent`
  and, after a `navigate`, to `dweller agent` on `counter.html`: the
  answers are equal byte for byte once the page's `file:` URL is written
  as `app:counter` (golden: `expected/agent.out`, read before blessing).
  Whole suite, cloud machine, proxy variables unset: 253 passed, 0
  failed (`target/v5.log`); `check_taste.py`, `check_layers.py`,
  `gen_property_ids.py --check`, `aye check browser`: 0.
- Decision: the session is a second, small implementation of the
  snapshot and the actions, in the shell. `browser/agent/` is written
  against `engine.Page` and its `Session` (1325 lines of `a11y.aye`,
  1185 of `actions.aye`) and a platform module may not import it
  (`check_layers.py`). Moving it under the engine is the first Left item;
  the test that both give equal answers keeps the two from drifting
  until then.

Left:
- One semantic tree for pages and apps: `agent/a11y.aye` over (document,
  styles, layout tree) in the core, with `engine.Page` as one caller and
  the shell as the other; then the shell's `sem*.aye`, `describe.aye`
  and `diff-lines.aye` go. `a11y.aye` uses the page for `p.doc`
  (about 100 places), `p.styling` (4), `engine.framePage` and
  `engine.labelControl` (1 each), and `html.isIn`.
- Not served: `read`, `find`, `wait`, `select`, `screenshot`, `eval`,
  `run`, `snapshot` with `boxes` or `format: "json"`, the MCP server, and
  agents on a window a person uses (`--agent-socket`, Spaces).
- Roles the shell does not know: links, checkboxes, radios, selects,
  tables, landmarks, images, ARIA attributes, labels; names only from
  content.
- `press`: Tab, Enter and Escape do nothing in an app (no focus
  traversal, no default button).
