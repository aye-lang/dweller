# Q6.13b: RegExp Unicode property escapes, regular expression literals checked when parsed

- goal: the `regexp-unicode-property-escapes` cluster of `test262/built-ins` (676 of 681 tests failed).
- cause: `\p{...}` knew about twenty names with hand-written approximate ranges, accepted any other name as an empty set, and a regular expression literal was compiled only when it ran, so a wrong one was never an early error.
- design:
  - `browser/tools/gen_unicode_properties.py` writes `browser/js/unicode-property-table.aye` from the Unicode 17.0.0 character database (the version the test262 files are generated for): the 53 binary properties of ECMA-262 Table 68 with their aliases, every `General_Category` value and group, every `Script` and `Script_Extensions` value (441 sets, 23045 ranges, 866 names sorted for a binary search). Files read: `Scripts.txt`, `ScriptExtensions.txt`, `PropList.txt`, `DerivedCoreProperties.txt`, `extracted/DerivedGeneralCategory.txt`, `extracted/DerivedBinaryProperties.txt`, `DerivedNormalizationProps.txt`, `emoji/emoji-data.txt`, `PropertyValueAliases.txt`.
  - `unicode-property-lookup.aye` / `unicode-property-find.aye`: `Name`, `gc=Value`, `sc=Value`, `scx=Value` and their long forms; anything else is a SyntaxError. `\p` is a property escape only with the `u` flag; without it `\p` is the letter (Annex B, as V8).
  - Every character class is now sorted and merged when it is closed (`regexp-canonical-set.aye`, V8's `CharacterRange::Canonicalize`) and `inSet` is a binary search (`regexp-set-has.aye`): `\p{L}` has 680 ranges, the old linear scan was per character.
  - `regexp-parse.aye` holds the parse-and-compile step of `compileRegex`; the JS parser calls it for every regular expression literal (`regexp-literal-valid.aye`) and fails with a SyntaxError: a bad pattern or flag is an early error. Flags may not repeat (`regexp-set-flags.aye`).
- references: ECMA-262 "UnicodeMatchProperty", "UnicodeMatchPropertyValue", "Primary Expression: Regular Expression Literals: Early Errors"; V8 `src/regexp/regexp-parser.cc` (`AddPropertyClassRange`), `src/regexp/regexp-compiler-tonode.cc`.
- files: `browser/js/regexp.aye`, `parser.aye`; new `regexp-parse.aye`, `regexp-set-flags.aye`, `regexp-literal-valid.aye`, `regexp-canonical-set.aye`, `regexp-set-has.aye`, `regexp-property-ranges.aye`, `unicode-property-name.aye`, `unicode-property-find.aye`, `unicode-property-lookup.aye`, `unicode-property-table.aye` (generated), `browser/tools/gen_unicode_properties.py`; `browser/tools/check_taste.py` (the table joins `GENERATED_OR_VENDORED`); `browser/tests/js/286_regexp_property_escapes.js` and `.out` (Node 22's output).
- verify:
  - `test262.py run test/annexB test/language test/built-ins -j 4`: built-ins 13429 -> 14046/18373 (76.4%), language 17901 -> 18044/23210 (77.7%), annexB 432. Against the baseline of the row: 1012 + 618 + 1 gained, 0 lost.
  - `cargo test --release --test browser -- js_ jsbench`: 4 passed.
  - `jsbench.py` with `BENCH_BASELINE` the binary of `2662662`: geometric mean 1.001.
  - `check_taste.py` 0, `check_layers.py` 0, `gen_property_ids.py --check` 0, `aye check browser` 0.
  - the whole suite (`cargo test --release --test browser`) runs with Q6.13c: the container restarted during this slice's run.
