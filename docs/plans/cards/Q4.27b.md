# Q4.27b: a page an agent loaded keeps its renderer when it calls pushState

- goal: in the window with renderers (site mode, the default), a page that an agent loaded (a Space; `--agent-socket`) can call `history.pushState`, `history.back()` and `pushState` again. Its renderer stays alive, and `location.href`, `history.length` and `history.state` follow. The same in tab and single mode. Found on GitHub's Turbo navigation (Q4.27, Left).
- failing case (before, 2026-11-24, this Mac): a Space's agent navigates to `browser/tests/ui/agent_push_state.html` and clicks `push` (`history.pushState({}, '', '?b')`). The window logs `error: bad message: bad same_document PID` and kills the renderer. The agent's next request answers `renderer crashed`. This happened in site, tab and single mode.
- cause, with evidence: a temporary log in `sameDocumentEntry` printed `same_document len 0 current 0 index 0` at the pushState. So the browser had no entry in `slot.session.tab.history` for the agent's document, and the check `if h.len() == 0 { return false }` killed the renderer. There were two faults:
  1. The browser: for an agent's `loaded` (`by_agent` in `renderer-sent.aye`, a load the browser did not navigate), it did not call `commitEntry`.
  2. The renderer: the agent's page uses the agent tab's own history (`s.tab.history`), and `adoptPage` set `mirrored = false`. So `reportHistory` sent the stale `r.at` (0), not the page's index. After a cross-site navigation the carried agent (`carryAgent`, then `navigateSpeculative` sends `session_history{at, length}` and the agent's line) also loaded into an empty agent history. So the renderer said index 0 where the browser had pushed entry `at`.
- fix:
  - IPC: `loaded{title, url}` becomes `loaded{title, url, index}` (`ipc/message.aye`, `decode.aye`, `put-payload.aye`). `index` is the entry the document commits at. The renderer sends `r.at` after `sharedHistory` for a navigation, and the first entry of the adopted page (`SessionHistory.adopted_at`, set by `adoptPushed` and `adoptAt`) for an agent's load.
  - browser: `rendererSent` now calls `commitEntry` for both paths. For an agent's load, `agentEntry` (`ui/agent-entry.aye`) checks `index` against the browser's list and sets up the commit as the browser's own navigations do. The next entry is a push (`push_on_commit`). The current entry is a reload. An existing entry is a traversal (`h.current = index`). Any other index kills the renderer (`bad loaded`). A reload or traversal by the agent gives the new document all the entries of the old one (`share_doc_on_commit`, `ui/share-document.aye`), as `adoptAt` does in the agent's tab. Then an in-document back after an agent's `back` matches on both sides.
  - renderer: `answerAgent` calls `shareAgentHistory` (`renderer/share-agent-history.aye`) before it serves a request. The agent's tab then gets the shape of the browser's list. For a page the browser navigated (the mirror), the agent's tab copies the entries and the page uses the agent's list from then on. Before the first page (a carried agent), the agent's tab gets the `session_history` index of empty entries. After an agent's load, `agentCommitted` (`renderer/agent-committed.aye`) sets `mirrored = true` and `r.at`. So `reportHistory`, `HistoryGo` and `traverse` use the page's own index, which is the browser's index.
  - The `same_document` check did not change. A renderer that reports an index the browser does not have is still killed. `DWELLER_TEST_EVIL=history-index` (in `reportHistory`) adds 7 to the reported index.
  - docs: `docs/process-model.md` §2 (`loaded{title, url, index}`) and §4 (rows for `same_document` and `loaded`, the evil name).
- test: `window_spaces_history::window_spaces_history` (`tests/browser/window_spaces_history.rs`, page `browser/tests/ui/agent_push_state.html`, test server). This runs in site, tab and single mode. A Space's agent navigates to `127.0.0.1`. It clicks `push` (`?b`, length 2), `back` (no `?b`, length 2) and `again` (`?c`, length 2, state `n` 2). It navigates cross-site to `localhost` and clicks `push` (length 4). It navigates to `renderer_history.html`, sends the agent's `back` (into the document of two entries, `?b`, length 5) and clicks `back` (in the document, length 5). The window exits with an empty stderr. Then, with `DWELLER_TEST_EVIL=history-index`, the first pushState kills the renderer (`bad same_document`, the next request answers `renderer crashed`). Before the fix, the test failed at the first pushState (`renderer crashed`). After the fix it passes.
- verify: `cargo test --release --test browser -- window_renderer window_spaces agent history` (once); `check_taste.py`, `check_layers.py`, `gen_property_ids.py --check`, `check_plan.py`, `aye check browser`: exit 0.
