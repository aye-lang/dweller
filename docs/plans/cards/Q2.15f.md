# Q2.15f: `location.replace()` replaces the entry

- goal: readiness list for Q2.14, "What a person sees", third bullet [Q2.6a]. `location.replace(url)` to another document added a session history entry in every mode, because the engine's `Navigation` had no replace flag. So Back from a page reached through a replacing redirect page (logins, consent pages) went to the redirect page, which sent the person forward again.
- design:
  - engine: `Navigation.replace` (`Script.nav_replace`, set by `ak.navigate(url, replace)`, which the prelude's `location.replace` already called with `true`; cleared by `takeNavigation`).
  - one process: `Tab.replace_next`, set from the navigation by the three callers that follow a script's navigation of a tab's page (`ui/window.aye` `afterScripts`, `engine/contexts.aye` for a script-opened window, `agent/scripts.aye`). `Tab.push` adopts the new page at the current entry (`adoptNavigated` → `SessionHistory.adoptAt`, as a traversal's reload does) instead of after it; the entries forward of it stay. A frame's own `location.replace` takes the frame's current entry (`replaceInFrame`).
  - renderer modes: the renderer sends the new R→B `ReplaceNavigation{url, referrer_policy}` (IPC kind 103) instead of `BeginNavigation` (`send-script-navigation.aye`). The browser runs `beginNavigation` with `replace_on_commit`: the session history it sends the renderer is the current index and the present length, and `commitEntry` replaces the current entry (URL, a null state, the new document) instead of pushing. With no entry yet it pushes. The flags are carried to a speculative renderer, so a replace that crosses sites replaces too. A child frame's `ReplaceNavigation` navigates the child as its `BeginNavigation` does (a child's navigations add no entry, Q2.9 Left).
  - `beginNavigation`'s two refusals (a `file:` target from the web, a top-level `data:` URL) moved to `navigationRefused` with their messages unchanged.
- decision: a new message kind instead of a `replace` field on `BeginNavigation`, so the other lanes' senders of `BeginNavigation` need no change at the merge.
- checks: `ReplaceNavigation` is checked as `BeginNavigation` is (the frame id, the referrer policy code, `initiatorMayLoad`, no top-level `data:`); what it replaces is the browser's own current entry, never an index the renderer names.
- spec read: https://html.spec.whatwg.org/multipage/nav-history-apis.html#dom-location-replace , https://html.spec.whatwg.org/multipage/browsing-the-web.html#navigate (history handling "replace"). Chromium read: `content/browser/renderer_host/navigation_controller_impl.cc` (`RendererDidNavigateToExistingEntry` and `should_replace_current_entry`: the pending entry replaces the last committed one, forward entries stay).
- files: `browser/engine/{script,window_api,tab,frames,contexts}.aye`, new `browser/engine/{adopt-navigated,replace-in-frame}.aye`; `browser/agent/scripts.aye`; `browser/ui/window.aye`; `browser/ipc/{message,decode,put-payload,from-renderer}.aye`, new `browser/ipc/replace-navigation_test.aye`; `browser/renderer/script-navigation.aye`, new `browser/renderer/send-script-navigation.aye`; `browser/ui/{begin-navigation,commit-entry,renderer-sent,child-sent,tab-process,start-speculative}.aye`, new `browser/ui/navigation-refused.aye`; new `browser/tests/ui/replace.html`; `tests/browser/window_renderer_oopif_site.rs`; `docs/process-model.md`.

## Status: done, 2026-11-16

Left:
- `location.replace()` on another window (`otherWindow.location.replace(url)`, `ak.winNavigate`) and on a remote window (`proxy_navigate`) still push.
- `window.open(url, '_self')`, a `<meta http-equiv=refresh>` (not implemented) and a navigation before the document's load event (the spec replaces there too) are not replacing navigations.
- a child renderer's replace is a plain navigation of the child (no joint history for frames in the renderer modes).
- the replaced entry's scroll offset is kept from the old entry until the new page scrolls.
