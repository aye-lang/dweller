- goal: `page_load.py check --agent` failed on bbc, mistral and zol on origin/main 8a9d8825 (#432 Q4.28 and #433 Q4.28b), with archive misses. On 2026-11-24 all 20 judged sites passed. Find each miss's cause and restore W2 without hiding a regression.
- method: `browser/build.sh` (safe) of main 8a9d8825, of 888e5c91 (before #432) and of a4cf8da1 (Q4.28 alone; #432 and #433 are the only engine changes between 888e5c91 and main). The misses are those of `check` (the replayed `dump --md --js`); the agent's navigate (`check`'s console errors) missed nothing on the three sites. `DWELLER_JS_VM_STATS=t` for the VM's instruction counts per function. A record and replay is a live `dump --md --js` with `DWELLER_RECORD` into a new directory, then the same with `DWELLER_REPLAY`, compared by their `requests` records (the first 440 bytes of each URL: the record's label is cut near 475 bytes).

## The misses on main and their cause

The benchmark `Date.now()` is the epoch plus the page's virtual clock, and the virtual clock in `dump` counts VM steps (1 ms per 1,000,000, `STEPS_PER_MS`, `browser/engine/script.aye`). So when a page runs fewer steps, every later `Date.now()` is earlier. Every value that differs below is such a time, or follows from one. Three runs of main gave the same misses each time; 888e5c91 passed all three sites.

- On 888e5c91 the page's `dump` makes the same gtag hits with `random=1791331200065` (the recording's values) and never asks for `www.google.com/g/collect`; on main the hits carry `…001` and `www.google.com/g/collect` is asked for. On the old engine each of gtag's `Array.from` calls recursed through core-js's `isConstructor` and the prelude's `Reflect.construct` to the stack limit (Q4.28), 64 ms of the virtual clock before gtag's first hit (and 129 s of wall time for the `dump`, 60 s on main). gtag now runs as in Chrome, so its clock reads 1 ms and it takes the branch of a page that is not late.

### zol: class (a), #432, then a class (b) found while recapturing

| missed URL | recorded twin → main |
|---|---|
| `show-g.mediav.com/s?…&jsonp=SSP_AD_PMP_…` | `jsonp` `SSP_AD_PMP_17913312000191` → `…0171` |

- The callback name is `"SSP_AD_PMP_".concat(Date.now())` and a counter (`static.mediav.com/js/ssp_ad_sdk.js`): epoch + 19 ms recorded, + 17 ms on main.

- Cause: zol's mediav scripts build classes with Babel's `_callSuper` (`Reflect.construct(e, r || [], s(t).constructor)`, `qihoo_syh_ad_lib_exterLlqClickToCurl.iife.js`), and `ssp_ad_sdk.js` carries core-js (`forced: !checkCorrectnessOfIteration(function (t) { Array.from(t) })`). The prelude's `Reflect.construct` called the page's `Array.from` for each one; since Q4.28 it reads the list natively, so the page runs 2 ms of steps fewer before the ad request. The request order of main and a4cf8da1 is the same; against 888e5c91 only the mediav script and this URL moved.

Recapturing zol with main found the second problem: the new archive did not replay. The recording's `dump` made 937 requests, its replay 939: the replay asked for `pv.zol.com.cn/images/pvhit0001.gif?t=1791331200000369…` (an image that `zdw.w8.com.cn/p.ht`, written by `web_foot.js`, asks for) where the recording had no request, and then missed `pvnpc.zol.com.cn/i/e.gif?…type=inview…_pos=103` (`t` 1791331201000 → …0500).

- The image's URL is the same in both (the `t` is `Date.now()` and `Math.random()`, the `ip_ck` the cookie of the recorded `p.ht`). Its archive entry has `date: … 18:13:11 GMT`; the `dump` asked for it about 18:10:17 (the `p.ht` it came from is 18:10:16) and ended about 18:11:15. So it was recorded by the capture's screenshot, which replays and records only its misses, not by the `dump` that asked for it.
- `curl` of that host from this Mac: 2 of 6 connects timed out after 20 s.
- Cause, class (b): a script's image request is a background load of the loader (`net.startLoadAs`, `images.aye`). Under `DWELLER_REPLAY` the load is done at once and the request that reads it (`bitmapOf` → `net.request`) asks the archive. Under `DWELLER_RECORD` it ran live in the background, and when it failed, `finishLoad` kept it as failed and nothing was written to the archive. The recording's page got an error; the replay, finding the URL recorded later, got an image, and the page went on differently from there. Any background load that fails live (an image, a preload, a prefetched script) does this. A second record and replay of zol with main gave the same 937 requests in the same order: that time the `pvhit` load did not fail.

Their `Array.from` (`function(e){var t,n,l,p,f,d,g=o(e),m="function"==typeof this…`) 359K → 0, their collection constructor (`function(t,n){u(t,S,e);var r=g(new y,t,S);…`, the `Map`/`Set` wrapper for an engine that fails the same check) 584K → 0, and less in their helpers. No regression: on each site the requests differ from the old build's only in these clock values, the requests that follow from them (GPT's retry, gtag's branch), and their order where a script ran at another time.

## Change

- `net.startLoadAs` (`browser/net/loader.aye`) starts no live load under `DWELLER_RECORD`, as under `DWELLER_REPLAY`: the load is done at once, and the request that reads it fetches it, at the same place in the same task as the replay's read of the archive, and records what came, a failure too (`net.request` already records a failed fetch). The parser's prefetch (`net.prefetch`) starts nothing while recording either. This is Q0.3e's rule ("Record a request the way the replay answers it", `docs/practices/browser.md`) for the loader's background loads; Q0.3e did it for a script's fetch, XHR and inserted scripts (`net.liveRequest`). `browser/engine/PERF.md` ("Archive semantics") and the practice say so.
- Cost: a capture makes these loads one after the other. zol's live `dump` while recording, one run each: about 75 s before, about 125 s after (its replay made the same 937 requests in the same order, the same Markdown, no miss).
- The replay path did not change, so the other 17 archives replay as before.
