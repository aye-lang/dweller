# P10.50c: keyboard default actions, Tab focus, wheel and scrollend, history buttons

- goal: the keyboard, focus, wheel and history-button items of P10.50b's "left" list, through real input (the window and the `--events` feed), keeping the window's trackpad scrolling as it is.
- design:
  - keys (`feed-key.aye`, `feed-text.aye`, `ui/forms.aye`): a canceled `keydown` or `keypress` sets `key_canceled`, which drops the following `text:` word; text goes `beforeinput` (cancelable `InputEvent`) → edit → `input`, in the feed and in the window's `pageText`. Space presses remember `space_pressed`; on `keyup` of the same element `spaceClicks` elements get a keyboard click (`key-click.aye`: `__click` in `hostEvent` dispatches a trusted `PointerEvent` `click` with pointerId -1, then `activate`); Enter clicks `enterClicks` elements (buttons, links) on keydown. Shift+Alt or Ctrl+Alt with a key clicks the element whose `accesskey` matches (`access-key-target.aye`). A keyboard click has offsetX/Y 0 (`ui-events.js`).
  - Tab / Shift+Tab: `key-focus.aye` sends `__focus` with key `key`, so the prelude's `moveFocus` fires blur/focusout/focus/focusin with `relatedTarget`; `setFocus` keeps `focus_visible` true, so `:focus-visible` matches.
  - wheel: the feed's `wheel:X,Y,DX,DY` word (`feed-wheel.aye`) dispatches `wheel` then, when not canceled, `__wheel` scrolls the nearest scrollable ancestor or the window (`wheelScroll`). The testdriver vendor turns a `wheel` source's `scroll` actions into that word. `WheelEvent.cancelable` is true only when a non-passive wheel listener is on the path (`wheelCancelable`; window/document/root/body listeners are passive by default). The window's wheel path is unchanged.
  - scrollend: `scrolled()` (every programmatic, keyboard, wheel or window scroll) re-arms a 100 ms timer per target; when it fires, `scrollend` goes to the document (bubbling) for the viewport or to a still-connected element. `onscrollend` is a handler; a `scrollend` listener on the window or document watches scrolling like `scroll`.
  - window back/forward buttons: `pointerEvent` keeps whether the page canceled the last pointer/mouse event (`pointer_on`); an X1/X2 release that was not canceled runs `back()`/`forward()`.
- files: `browser/engine/` (new `key-click.aye`, `key-focus.aye`, `space-clicks.aye`, `enter-clicks.aye`, `access-key-target.aye`, `feed-wheel.aye`; wiring in `feed-key.aye`, `feed-text.aye`, `feed-words.aye`, `prelude.aye`, `ui-events.js`), `browser/ui/` (new `space-up.aye`; wiring in `forms.aye`, `window.aye`), `browser/tools/wpt/testdriver-vendor.js`, `tests/browser.rs`.
- reference: `third_party/blink/renderer/core/input/keyboard_event_manager.cc` (keypress, accesskey), `core/html/forms/` button Space-on-keyup, `core/editing/` (beforeinput before input), `core/input/scroll_manager.cc`, `core/page/focus_controller.cc`; algorithm only (LGPL). Spec https://w3c.github.io/uievents/#events-keyboard-event-order, https://w3c.github.io/uievents/#cancelability-of-wheel-events, https://drafts.csswg.org/cssom-view/#scrolling-events
