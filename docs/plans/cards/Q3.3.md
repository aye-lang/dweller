# Q3.3: crossorigin on script, link and img; ORB in net

- goal: the `crossorigin` attribute on `<script>`, `<link rel=stylesheet>` and `<img>` makes a CORS-mode request with the matching credentials mode, checked by the CORS code in `net/` (Q3.2a/b). A failure is a load error. A CORS image is readable by canvas; a no-cors cross-origin image taints it. ORB: a no-cors response that a page must not see (HTML, XML, JSON, never-sniffed types, and HTML/JSON/XML/text/plain with `nosniff`) is blocked in `net/`, keyed on the initiator, so a renderer never gets its body.
- design:
  - `engine/cors-request.aye` `corsRequest(crossorigin, req)` (HTML CORS settings attribute): no attribute keeps `NoCors`; `anonymous`, `""` or any other value is `Cors` with `SameOrigin` credentials; `use-credentials` is `Cors` with `Include`. Used by classic scripts (`script.aye` `runScriptElement`, `inserted.aye`), linked sheets (`sheets.aye` `linkedSheet` takes the link's attribute; `@import` passes none) and images (`ImageCache.imageRequest`).
  - A CORS-mode subresource is fetched on the synchronous path through `net.request`, so `corsChecked` (Q3.2a) checks it. The preload scan (`scriptHrefsOf`, `sheetHrefs`), the inserted script's background load and the image preload/background paths skip elements with `crossorigin`, so no credentialed no-cors request is sent for them first. `fetchHttp` does not read or fill the HTTP cache for a `Cors` request (the cache has one entry per URL, filled by no-cors loads).
  - `Origin` (`origin-header.aye`) is now sent for every `Cors` request, not only `Kind.Other`, so a server can echo it in `Access-Control-Allow-Origin`.
  - images: `CachedImage` keeps `mode` and `credentials`; `bitmapOf` and `pictureOf` take the element's `crossorigin` and match on it, `known` only on no-cors entries. A CORS image that passed the check is not tainted; `sourceTainted` (canvas_api) picks the entry of the element's mode. The old JS-side rule "a crossorigin attribute alone never grants pixels" is now a real CORS check: without ACAO such an image fails to load.
  - ORB (`net/orb-*.aye`, https://github.com/annevk/orb, as Chromium's ORB v0.1): `orbRefuses(req, at, res)` applies to a no-cors, non-navigation request from a page whose final URL is cross-origin to the initiator (`corsOrigin` with the mode set to `Cors`; a tainted initiator is `null`, so every origin is cross). `orbBlocks(mime, headers, body)`: opaque-safelisted types (`text/css`, `image/svg+xml`, audio/video, DASH/HLS, `text/vtt`) pass; never-sniffed types (`never-sniffed-mime.aye`: zip, gzip, protobuf, event-stream, PDF, Office, CSV, multipart/signed, multipart/byteranges) are blocked; HTML/JSON/XML/text/plain with `X-Content-Type-Options: nosniff` are blocked; an image signature (`image.sniff`) or no MIME type passes; else the first 1024 bytes are sniffed for HTML (`sniffs-html.aye`, comments skipped), `<?xml`, JSON (`sniffs-json.aye`: parser breakers and `{"key":`) and blocked on a match; everything else passes.
  - ORB runs in `net.request` after `corsChecked` (`orb-checked.aye`, a blocked response is freed and is `FetchError.Network`) and in the loader's `finishRequest` for a script's `fetch` (`no-cors` fetch of JSON rejects with TypeError). Background loads go to the cache, which now keeps the response headers (`Cached.headers`, also from `keepLoad`), so the later `net.request` sees `nosniff`.
  - `inserted.aye` keeps its JS-side rule for cross-origin `text/html` scripts (it also blocks a JSONP body served as HTML, which ORB lets through); the HTML that ORB sniffs never reaches it.
- not done: module scripts are not CORS-mode (`js/module-response.aye` sends no-cors); `<link rel=preload>` is not fetched by Dweller at all, so its `crossorigin` has nothing to change; the image cache key for CORS entries is mode and credentials, not the full Fetch cache key; ORB does not do the audio/video sniffing step or the range-request rules (Dweller sends no range requests).
