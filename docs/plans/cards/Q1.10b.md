# Q1.10b: fuzz targets for the CSS and URL parsers

- goal: two more `dweller fuzz` targets on the Q1.10a harness, `css` (the style sheet parser, declaration and selector parsing, and the CSSOM serializers) and `url` (the WHATWG URL parser in `browser/url/`, with a round-trip check), each with a small seed corpus, listed by `dweller fuzz --list` so the Q1.10e nightly job runs them with no workflow edit.
- design:
  - `browser/fuzz/css-target.aye`: the CSS dictionary (brackets, at-rule names, combinators, pseudo-classes, `var()`/`calc()`/color functions, units, CSS-wide keywords, property names) and `fuzzCss`: `css.parseSheet` of the input, `css.parseInline` of the input (a `style` attribute), then `serializeRules`.
  - `browser/fuzz/serialize-rules.aye`: serializes the input as the CSSOM does (`engine/prelude.aye` `ruleObject`, `engine/dom_api.aye` `setStyleDecl`): for each `...{...}` chunk, the text before `{` through `serializeSelector`, and each `prop: value` of the block through `css.specifiedValue`.
  - `browser/fuzz/serialize-selector.aye`: as `engine/dom_api.aye` `parseSelector` + `ak-selector-text.aye`: parses `src {}` and, when that gives exactly one rule, `css.selectorText(src)`.
  - `browser/fuzz/url-target.aye`: the URL dictionary (delimiters, percent escapes, dot segments, IPv4/IPv6 hosts, special and non-special schemes, Windows drive letters, ports, IDNA bytes) and `fuzzUrl`: `url.resolve` against the fixed base `http://user:pass@example.org:8080/a/b/c?q#f` (so the relative states run too; an invalid input returns), then `url.parse(href)` again; a failure to parse its own `href` or a different `href` is `unreachable`, a panic with its own `file:line:col`, so `fuzz.py` keys and files it like any other crash.
  - `browser/fuzz/targets.aye` lists `html`, `css`, `url`.
  - seeds: `browser/tests/fuzz/css/` 74 files, 27.1 KB: the `<style>` blocks of 48 `browser/tests/style/*.html` fixtures, the 15 repo `.css` fixtures under 4 KB (`fixture_*`; `ui/container_feed.css`, 18 KB, left out), and 11 WPT files (`wpt_*`): `css-nesting/block-skipping.css`, `css-namespaces/support/syntax-007.css`, `cssom/support/import-rule.css`, `support/delete-other-rule-crash.css` and the `<style>` blocks of the `css-syntax` tests `missing-semicolon`, `trailing-braces`, `var-with-blocks`, `cdc-vs-ident-tokens`, `escaped-eof`, `unicode-range-selector`, `invalid-nested-rules`. `browser/tests/fuzz/url/` 132 files, 2.4 KB: every 6th distinct single-line `input` of WPT `url/resources/urltestdata.json` (791 distinct).
  - fix: `browser/css/values.aye` `channel` returns 0 for NaN (a `lab()`/`oklch()` with an infinite axis converts to NaN, and NaN `as u8` panicked); test `browser/css/channel_test.aye`.
- files: `browser/fuzz/css-target.aye`, `serialize-rules.aye`, `serialize-selector.aye`, `url-target.aye` (new), `browser/fuzz/targets.aye`, `browser/tests/fuzz/css/`, `browser/tests/fuzz/url/` (new), `browser/tests/fuzz-crashes/css/` (new), `browser/css/values.aye`, `browser/css/channel_test.aye` (new), `docs/browser.md` (section "Fuzzing"), `docs/plans/cards/Q1.10b.md` (new)

- crashes:

After the fix the input replays clean.
  - recorded, not fixed: `browser/css/write-channel.aye:6:48: panic: float to integer cast out of range` (5 hits), minimized to `{color:oklch(1 1e36 2` (21 bytes), kept as `browser/tests/fuzz-crashes/css/5c97adcc9e282dcb.min` with its panic in `.txt` (outside `browser/tests/fuzz/css/` because the nightly job copies that directory's files flat). `css.specifiedValue` serializes a color channel through `round(n * 1e6) as i64`, which overflows for `|n| > 9.2e12` and for infinity; the fix is serializing such numbers as CSSOM does (`1e+36`, `calc(infinity)`), its own small card.
