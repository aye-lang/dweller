# Q3.8: CSP 2: `style-src`, `img-src`, `connect-src`, `frame-src`, `base-uri`, `form-action` and report-only

- goal: the fetch directives other than `script-src` block what they name and fire `securitypolicyviolation`, and `Content-Security-Policy-Report-Only` evaluates the same checks without blocking (event with `disposition: "report"`, console line marked `[Report Only]`; `report-uri` and `report-to` are parsed as unknown directives and ignored, no report is sent). Builds on Q3.7 (`directiveOf`, `sourceList`, `sourceMatchesUrl`, `nextWord`, `listAllowsInline`), Q3.7b (`Refusal`, the event) and Q3.6 (`Page.header_csp`).
- design:
  - `csp.fallbackDirective(policy, effective)` (`fallback-chain.aye`, `fallback-directive.aye`): the CSP3 fallback lists. `style-src-elem`/`-attr` -> `style-src` -> `default-src`; `frame-src` -> `child-src` -> `default-src`; `worker-src` -> `child-src` -> `script-src` -> `default-src`; `img-src`, `font-src`, `connect-src`, `media-src`, `object-src`, `manifest-src`, `child-src`, `script-src`, `style-src` -> `default-src`; `form-action`, `base-uri`, `frame-ancestors` have none. `csp.urlRefusal(policies, effective, target, page, nonce)` is the generic "should request be blocked" (`'self'`, scheme, host sources and a nonce, no `'strict-dynamic'`); `csp.styleInlineRefusal` is "should element's inline behavior be blocked" for `<style>` (`style-src-elem`, nonce, hash) and `style=` (`style-src-attr`, hash only with `'unsafe-hashes'`) through `listAllowsInline`. `directiveOf` now ignores a directive with a byte outside tab and 0x20..0x7e (WPT `parsing/invalid-bytes`).
  - Report-only: `Page.report_csp` (the `Content-Security-Policy-Report-Only` header values, inherited by srcdoc/about:blank frames). `Refusal.report` (default false) and `csp.orReport(enforced, reported)`: every check runs on `p.csp` and on `p.report_csp`; the enforced refusal wins, else the reported one is returned with `report` set, and the call site fires the event and continues. Script URL and inline checks (Q3.7b) use it; `violationJson` writes `disposition`.
  - Inline `<style>`, `style=` and `<link rel=stylesheet>` (`style-src-elem` with the element's nonce) and `<base href>` (`base-uri`) are decided by a scan of the document, not at each use (`engine/mark-styles.aye`): it walks the tree and marks the blocked ones in `Document.style_marks` (`dom/style-marks.aye`; a blocked-element mark, a blocked-attribute mark, a "reported" token per element so one change reports once, and the hash of each `style` attribute value the CSSOM wrote). `sheets.aye` and `css/match-element.aye` skip a marked element, `findBase` skips a marked `<base>`, `document.styleSheets` / `.sheet` leave out a blocked `<style>` (a blocked `<link>` keeps its sheet, as Chromium) through `ak.styleBlocked`, and the CSSOM reads a blocked `style` attribute as empty. A `style` attribute whose value the CSSOM wrote (`putStyleDecl`, `cssText`; any value that was) is allowed, so `el.style.x = ...` works under `style-src 'self'` and a clone keeps its styles. The scan runs before every style computation and `document.baseURI` / `Page.currentBase` (marks only), and at every microtask checkpoint with reporting (`runMicrotasks`): during parsing only up to the script that just ran (`parserStop`, the page is parsed whole before its scripts run, so an event for an element after the running script must not fire yet). Violations fire `securitypolicyviolation` at the element and an `error` event at a blocked `<style>`/`<link>`.
  - Requests (`engine/request-refusal.aye`, `request-refused.aye`): `requestRefusal(p, effective, target)` is the pure check; `requestRefused` also queues the violation (`Page.violations`, one per effective directive, URL and element, `reported_requests`), fired at the document by `flushViolations` at the next checkpoint and only once the parser passed the element (`parserPassed`). `blockedURI` is `data`/`blob`/`filesystem` for those schemes else the URL without fragment. Wired to: `<img>` and `<picture>` (`loadElementImage`, `img-src`; the prefetch loops skip blocked URLs; CSS images fetched by `fillImages`; `ImageCache.page` set by `newImageCache`), `fetch()`/XHR (`fetchWith`, `connect-src`, also the landing URL of a redirect `redirectBlocked`, sync and async), `navigator.sendBeacon` (`ak.cspRefused`), iframes and frames (`framedDocument`, `frame-src` -> `child-src`; a refused frame shows the error page, its `load` event fires, `startFrameLoads` does not prefetch it), `form-action` (`submitForm`) and `<base>`. Frames in `DWELLER_PROCESS=site` (Q2.9 remote frames) are checked too, since `framedDocument` of the embedding page decides before `remoteFrame`.
  - `refuseRequest(p, el, r, blocked)` builds the console line from the effective directive (`requestVerb`); `Page.currentBase`, `resolve`, `follow` take `*mut Self` (they run the scan).
- references: https://w3c.github.io/webappsec-csp/#directive-fallback-list , #effective-directive-for-request , #should-block-request , #should-block-inline , #report-violation , #securitypolicy-base-uri . Chromium read: `services/network/public/cpp/content_security_policy/content_security_policy.cc` (`CSPFallbackDirective`: the chains above, `child-src` for frames, `default-src` last) and `third_party/blink/renderer/core/frame/csp/content_security_policy.cc` (`AllowInline`: style attributes and CSSOM; `ReportViolation` with `disposition`; report-only evaluated beside the enforced list). ## Status: done, 2026-11-09

Left:
- `font-src` (`@font-face` loads in `fonts.aye` take no page; `<link rel=preload as=font>` does not exist), `media-src`, `object-src`, `manifest-src`, `prefetch-src`, `worker-src` for `importScripts`, `EventSource`, `WebSocket`, `WebTransport`, shared workers and `<link rel=icon>` do not exist or have no request to gate; `@import` inside a sheet is not checked; `connect-src` for JSON/CSS/text module imports and `sendBeacon` redirects; workers use no policy of their own (their `fetch`/XHR are not checked).
- Redirects: `frame-src`/`form-action`/`img-src` check the first URL (and `connect-src` the landing URL of `fetch`), not each hop, and `blockedURI` after a cross-origin redirect is not cut to the origin.
- `form-action` blocks in `submitForm` but the violation reaches the page at the next checkpoint (`form.submit()` runs from the window loop, not in `dump`); `form-action` on `javascript:` actions and `target=_blank`/redirect cases are not covered.
- Reports: no `report-uri`/`report-to` request, no `Reporting-Endpoints`, `CSPViolationReportBody`; `lineNumber`, `sourceFile`, `statusCode` stay empty; the event fires from the next checkpoint, not in a queued task of its own; when an enforced policy and a report-only one both refuse, only the enforced event fires; report-only `eval`, module imports, event handlers and workers are enforced-only still.
- Inline: `getAttribute('style')` of a blocked attribute still returns the text.
- `frame-src` for same-document navigations, `object`/`embed`, and `'self'` for unique-origin (sandboxed) frames; a remote (out-of-process) frame navigated by the browser later is not rechecked there.
- `media-src` (audio/video `src`), `CSS filter`/`<use>` image blocks, favicon `rel=icon` (WPT `img-src/icon-blocked`, `svg-use-blocked`, `css-filter-blocked`), `img-src` via CSS `background-image` raised only when a layout fetches it.
