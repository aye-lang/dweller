# Q2.8a: renderers run in a macOS seatbelt sandbox

- goal: on macOS a renderer (`DWELLER_PROCESS=tab`) enters a seatbelt sandbox right after startup, before it reads any page: it can no longer open the profile or any file outside the system libraries and fonts, write any file, use the network, or fork and exec. A failure to enter the sandbox ends the renderer (exit 3, the tab shows the sad tab). `DWELLER_NO_SANDBOX=1` turns it off for debugging and prints `warning: DWELLER_NO_SANDBOX=1, the renderer runs without a sandbox`.
- the profile (`browser/renderer/sandbox.sb`, embedded with `@embedFile`, applied with `sandbox_init_with_parameters`, declared with Aye's `extern fn`):
  - `(deny default)`; `signal` and `process-info*` on itself only.
  - read: `EXECUTABLE_DIR` (the realpath of `_NSGetExecutablePath`'s directory); `/usr/lib`, `/System/Library/Frameworks`, `/System/Library/PrivateFrameworks`, `/Library/Apple/System/Library/{Frameworks,PrivateFrameworks}`, the OS cryptexes; the fonts: `/System/Library/Fonts`, `/Library/Fonts`, `HOME_DIR/Library/Fonts`; `/dev/urandom`, `/dev/random`, `/dev/null`; the time zone files (`/private/etc/localtime`, `/private/var/db/timezone`, `/usr/share/zoneinfo`).
  - write: `/dev/null` only.
  - basic `sysctl-read` (`hw.ncpu`, `hw.activecpu`, `hw.optional.*`, `kern.osversion`, ...).
  - no `mach-lookup` at all, no `network*`, no `process-fork`, no `process-exec`, no `ipc-posix-shm` (the frame buffers arrive as fds over the socket and are mapped from the fd), nothing else under `~`.
- what had to move before sandbox entry:
  - the entry point: `renderer.serveOn` enters the sandbox first, after `serve` has opened the IPC socket (fd 3) and the fonts (`font.System.init`: the twelve system faces and `DWELLER_FONT_DIRS` are read into memory), and before the `hello` and the first `navigate`. Fallback faces and variable instances that FreeType opens later come from the font directories the profile lets it read; no font server is needed (FreeType, not CoreText).
  - the working directory: `getcwd` fails in the sandbox (it reads every directory up to `/`), so an agent's relative `navigate browser/tests/...` resolved to `file:///browser/...`. `engine.keepCwd` (called in `serve`) keeps the directory before the sandbox, and `engine.fileUrl` uses it (`cwdInto`).
- test hook: `DWELLER_TEST_SANDBOX_PROBE=1` (always compiled in, acts only with the variable): after the sandbox the renderer tries to open `$HOME/.dweller`, to create `/tmp/dweller-sandbox-probe`, to connect a TCP socket to 127.0.0.1:9 and to `fork`, and prints `sandbox-probe home=E tmp=E tcp=E fork=E` with each errno (0 = it worked).
- files: new `browser/renderer/{sandbox.sb,enter-sandbox,enter-seatbelt,probe-sandbox,probe-write,probe-connect,probe-fork,open-errno,errno}.aye` (`sandbox.sb` is the profile), new `browser/engine/keep-cwd.aye`; `browser/renderer/{serve,serve-on}.aye`, `browser/engine/engine.aye` (`fileUrl`); `tests/browser.rs` (new `window_renderer_sandbox`).
- Chromium read: `sandbox/mac/seatbelt.cc` (`sandbox_init_with_parameters` with a NULL-terminated key/value list and the error buffer freed with `sandbox_free_error`), `sandbox/mac/sandbox_compiler.cc`, `sandbox/policy/mac/sandbox_mac.mm`, `sandbox/policy/mac/common.sb`, `sandbox/policy/mac/renderer.sb`. Dweller takes the common + renderer shape (deny default, executable and system frameworks readable, the font directories, `/dev/urandom`, `/dev/null` writable, basic sysctls) and none of Chromium's mach services, IOKit, preferences or logging sockets.
- verify (2026-11-08, macOS):
  - `python3 browser/tools/check_layers.py`: exit 0. `python3 browser/tools/check_taste.py`: exit 0. `aye check browser`: exit 0. `aye test browser`: 228 passed, 0 failed, 18 modules.
  - `scripts/capped.sh browser/build.sh`: exit 0.
  - `scripts/capped.sh cargo test --release --test browser -- window_renderer_sandbox window_renderer_ window_login_in_renderer agent_sessions_in_renderer aye_unit_tests`: 17 passed, 0 failed. The first run (before `keepCwd`) failed `window_renderer_agent` and `agent_sessions_in_renderer` (`cannot fetch file:///browser/tests/agent/site/todo.html`, the sandboxed `getcwd`); with `keepCwd` both pass.
  - `window_renderer_sandbox`: `form.html` with a fresh `HOME` whose `.dweller` is the profile. Sandboxed with the probe: stderr is exactly `sandbox-probe home=1 tmp=1 tcp=1 fork=1` (all EPERM) and the PNG is byte-equal to the in-process window's. With `DWELLER_NO_SANDBOX=1`: the warning, `home=0 tmp=0 fork=0` and `tcp` not EPERM, so the probes fail because of the sandbox.
  - by hand (safe build): a page with CJK, Korean and symbol text (fallback faces opened after entry), serif bold and italic, a PNG image and a 2D canvas with text gives the same PNG in a renderer as in the window's process, with nothing on stderr.
  - No golden re-blessed; every window run headless (`SDL_VIDEODRIVER=dummy`); no perf gate run.
