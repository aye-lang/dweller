# P11.14f: WebGL conformance: the runners refuse slow builds, attachment/renderbuffer/sampler queries, WebGL in workers (not started)

- goal: (1) `webgl_conformance.py run` and `conformance.py run` (both have per-page timeouts) refuse a binary that `browser/build.sh` did not build, as P4.75p's timing tools do; (2) WebGL in dedicated workers per the P11.14e design; (3) the `getFramebufferAttachmentParameter` details of P11.14e group 3 and `pbo-texture-uploads`.
- design:
  - Runner guard: `browser/tools/fast_build.py` taken unchanged from P4.75p (`bbe756a`, with its `build.sh` hunk that writes `OUT.fast`, the binary's sha256). Both runners call `fast_build.require(target/dweller, --allow-debug)` before running; without the marker they exit 2. When P4.75p merges, the two copies are identical.
  - `getFramebufferAttachmentParameter` (`webgl-attachment-parameter.js`, replacing the P11.14e one in `webgl-more.js`):
    - user framebuffer: attachments other than COLOR_ATTACHMENTi, DEPTH, STENCIL and DEPTH_STENCIL are INVALID_ENUM (BACK on a user framebuffer); DEPTH_STENCIL with different depth and stencil objects, or with COMPONENT_TYPE, is INVALID_OPERATION; DEPTH_STENCIL queries GL through the depth attachment (stencil for STENCIL_SIZE), so a texture with depth and stencil on different layers still names its object.
    - OBJECT_TYPE is asked first; with no attachment (NONE) every pname but OBJECT_TYPE/OBJECT_NAME is INVALID_OPERATION (ANGLE answers INVALID_ENUM).
    - `framebuffer*` no longer records a DEPTH_STENCIL key; depth and stencil are compared instead.
    - WebGL 1: target FRAMEBUFFER only, attachments COLOR_ATTACHMENT0 (1-15 with WEBGL_draw_buffers), DEPTH, STENCIL, DEPTH_STENCIL; pnames OBJECT_TYPE, OBJECT_NAME, TEXTURE_LEVEL, TEXTURE_CUBE_MAP_FACE, plus COMPONENT_TYPE with EXT_color_buffer_half_float/WEBGL_color_buffer_float and COLOR_ENCODING with EXT_sRGB; INVALID_OPERATION on the default framebuffer.
  - Methods the CTS found missing (`webglMore` ops 6-10, five GL entry points): `getRenderbufferParameter` (SAMPLES in WebGL 2 only), `getSamplerParameter`, `getFragDataLocation`, `getActiveUniformBlockName` (INVALID_OPERATION before link).
  - `webgl1.js` copies the private `_` helpers non-enumerable: `for (i in gl)` found them as extra methods (`offscreencanvas/methods`).
  - `pbo-texture-uploads`: an HTMLVideoElement source (`webgl-video-source.js`) is INVALID_OPERATION with a PIXEL_UNPACK_BUFFER bound, else a no-op (no video frames yet).
  - WebGL in workers: not started. Two blockers found beyond the P11.14e design:
    - Worker scripts load only through `net.fetchLocal` (`load-bytes.aye`, `local_loads_only`); every `*-worker.html` page fails `Failed to load a worker script` over the CTS http server before any OffscreenCanvas code runs. The worker needs the page's network loader (http) first.
    - The worker scope has no `OffscreenCanvas` at all (`offscreencanvas-query`, `-sync`, `-timer-query` create one in a blob worker); the main-thread one is backed by `document.createElement('canvas')`, and `canvasBitmap` finds bitmaps through the page's `ImageCache`. The per-Interp bitmap table of P11.14e is needed before any worker WebGL.
    - Then, as designed in P11.14e: `transferControlToOffscreen`, wire.js `{t: 'C', id, w, h}`, per-thread EGL `current`, `commit()`/rAF frames posted to the placeholder, `transferToImageBitmap`.
