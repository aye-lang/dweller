# Q6.14: vertical writing modes and bidi, the area `css/css-writing-modes`

- goal: `writing-mode` exists in style and layout, so that the orthogonal tests of `css/css-grid` (Q6.2, about 1900 subtests) can pass, and the new area `css/css-writing-modes` has a baseline and a threshold.
- design (`docs/writing-modes.md` once slice c lands): layout stays physical-horizontal code. A box whose writing mode is orthogonal to its parent's is laid out in its own logical space (inline axis as x, block axis as y) and its subtree's geometry is then transposed into the parent's space:
  - style: each box in a vertical space reads a transposed copy of its computed style during layout (`width`/`height`, `min-*`/`max-*`, the margin, padding, border-width and inset sides, `overflow-x`/`-y` swapped: `vertical-lr` is a pure transposition, `vertical-rl` also mirrors the block axis); the physical style is put back before paint and script geometry read it. A document without a vertical box takes none of these paths (`Tree.vertical`).
  - an orthogonal box has two styles: the outer one in its parent's space (its margins and position) and the inner one in its own (its padding, borders, size and contents). Its inline size is shrink-to-fit in the available size: the containing block's block size when definite, else the viewport's (css-writing-modes-4, 7.3.1).
  - geometry: after the inner layout, boxes, lines, fragments and markers of the subtree are transposed (and mirrored in their container for `vertical-rl`). A nested orthogonal subtree is transposed once per level.
  - absolutely positioned boxes are laid out in physical space after placement, as now; a vertical one is an orthogonal root there.
  - paint: a text fragment of a vertical line is drawn rotated a quarter turn (sideways glyphs); upright glyphs (`text-orientation`) are left.
- references: https://drafts.csswg.org/css-writing-modes-4/ (2 `direction`/`unicode-bidi`, 3 `writing-mode`, 6 abstract box terminology and the mappings, 7.3 orthogonal flows, 8 principal writing mode). Chromium `third_party/blink/renderer/platform/text/writing_mode.h`, `core/layout/geometry/writing_mode_converter.h` (the logical to physical conversion: Dweller takes the idea of converting whole fragments at the boundary, not per property), `core/layout/block_node.cc` (orthogonal roots are sized with the fallback available inline size).

## Slices

Each has its own verify; order follows what Q6.2 needs first.

- a. the area `css/css-writing-modes` in `wpt_areas.json`, its baseline `browser/tools/conformance/css_css-writing-modes.json`, threshold 40. Verify: `wpt.py run css/css-writing-modes`.
- b. properties: `writing-mode` (with the SVG 1.1 values and `-webkit-writing-mode`), `text-orientation`, `text-combine-upright`, `unicode-bidi`: parsed, inherited, computed, serialized. Verify: `parsing/*`, `*-parsing-*`, `inheritance.html`.
- c. block layout: orthogonal roots by transposition (style and geometry), in block flow, atomic inlines and intrinsic sizes; the principal writing mode from `body` to the root and viewport. Verify: `sizing-orthog-*`, `orthogonal-parent-shrink-to-fit-*`, `block-flow-direction-*`, a layout fixture.
- d. abspos: a vertical absolutely positioned box, its static position and auto sizes. Verify: `abs-pos-non-replaced-v*`, `css/css-grid/abspos/orthogonal-positioned-grid-descendants-*`.
- e. grid (and flex): vertical containers and orthogonal items. Verify: `wpt.py run css/css-grid`.
- f. inline layout and paint: lines of a vertical box (line-relative `text-align`, `text-indent`, `vertical-align`), text drawn rotated. Verify: `line-box-direction-*`, `text-align-v*`, `text-indent-v*`, a screenshot fixture.
- g. logical properties (`inline-size`, `margin-block-start`, ...) and `getComputedStyle` follow the element's writing mode and direction.
