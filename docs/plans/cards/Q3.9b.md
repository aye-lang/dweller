# Q3.9b: sandbox gaps after Q3.9 (user navigations, popups, WPT)

- goal: in the in-process mode, a sandboxed frame's link and form targets follow "allowed by sandboxing to navigate", popups inherit the opener's flags unless `allow-popups-to-escape-sandbox` is set, and the failures of WPT `html/browsers/sandboxing` have known causes.
- design:
  - `sandboxAllowsTarget(p, el, activated)` (`browser/engine/sandbox-allows-target.aye`): the target of a link or form of `p`. A frame target goes through `sandboxAllowsNavigation`; `_top`, `_parent` without a frame and `_self` of a tab's page are a top navigation; an open context's name needs no sandboxed navigation flag; `_blank` and unknown names need `allow-popups`.
  - checked on every link and form path: `openElsewhere` and `submitElsewhere` (moved to their own files) return true when it is blocked, so `activate`, `ui/` and `agent/` do not fall back to the tab. `ui/forms.aye` (`clickFrame`, `submitInFrame`) and `agent/actions.aye` (`followLink`, `submitNow`) check before the frame branch with `activated = true` (the person's or the agent's click). The agent says "the sandbox of its frame blocks the navigation" or "the submission". `submitFormIntoFrame` (script submissions) checks with `activated = false`.
  - popups: `BrowsingContext.popup_sandbox` (spec "popup sandboxing flag set"). `openContext` takes the opener's flags and keeps them when `SB_PROPAGATES_TO_POPUPS` is set (no `allow-popups-to-escape-sandbox`). `attachLoading` gives each page of the context those flags through `setSandbox` (`set-sandbox.aye`, also used by `placeFrame`).
  - `Window.open` of another window (`frames[0].open(...)`, `ak.winOpen`) opens from that window's page: its flags decide, as in the window open steps. `openWindow` (`open-window.aye`) is the old body of `akOpenWindow` with the source page as a parameter.
  - small WPT fixes: `HTMLIFrameElement.sandbox` reflects the attribute as a `DOMTokenList` (before, `iframe.sandbox = '...'` was an expando and the frame was not sandboxed). `submitForm` no longer resolves `""` against an `about:srcdoc` URL first, which failed, so no form in a srcdoc document ever submitted. Script submissions of a frame go to the frame their target names (`syncFrames` asks `submitIntoFrame` of the frame page first).
- references: https://html.spec.whatwg.org/multipage/browsing-the-web.html#allowed-by-sandboxing-to-navigate , https://html.spec.whatwg.org/multipage/browsers.html#popup-sandboxing-flag-set , https://html.spec.whatwg.org/multipage/nav-history-apis.html#window-open-steps . Read: `third_party/blink/renderer/core/frame/local_frame.cc` (`CanNavigate`), `core/page/create_window.cc` (popup flags, `kPropagatesToAuxiliaryBrowsingContexts`); algorithm only.
- files: new `browser/engine/{sandbox-allows-target,set-sandbox,open-window,open-elsewhere,submit-elsewhere}.aye`, `browser/tests/jsdom/sandbox_popups.{html,tree,err}`, `browser/tests/jsdom/sandbox/popup.html`, `browser/tests/ui/sandbox_targets.html`, `browser/tests/agent/sessions/sandbox_targets.{jsonl,out}`; changed `browser/engine/{contexts,frames,forms,windows,prelude,submit-form-into-frame}.aye`, `browser/ui/forms.aye`, `browser/agent/actions.aye`, `tests/browser.rs` (`window_sandbox_targets`), `browser/tools/{wpt_areas.json,conformance/*}`, `docs/conformance.md`.
- tests: `sandbox_flags.html` already loads 16 frames, the most a page loads, so the popup cases are in `sandbox_popups.html`. `dump --js` has no user input, so the clicks a person makes are in `window_sandbox_targets` (headless window, dummy driver) and the agent session `sandbox_targets`.
  - `sandbox_popups`: a popup of an `allow-popups` frame has the frame's flags (its form does not submit); with `allow-popups-to-escape-sandbox` it does. A `_blank` link clicked by script opens nothing without `allow-popups` and opens with it. `frames[k].open()` of a frame without `allow-scripts` gives a popup whose scripts do not run; with the escape token they run.
  - `window_sandbox_targets` / `sandbox_targets`: a `_top` link without a flag is blocked, with `allow-top-navigation-by-user-activation` it loads in the tab. A `_top` form with `allow-forms` alone is blocked, with `allow-top-navigation` it submits.
  - each case checked once with its enforcement removed: `sandboxAllowsTarget` always true (the `_blank` link opened, both `_top` clicks and the form loaded in the window and the agent), `activated` passed as false (the by-activation link was blocked), no `setSandbox` in `attachLoading` (popups submitted, the script-less opener's popup ran), the flags always copied (the escaped popups did not submit or run).

## Status: done, 2026-11-08

Left:
- Tab mode (`DWELLER_PROCESS=tab`): the window's own navigation from a renderer's frame does not check the flags yet. The agent and `submit-at.aye` of the renderer run the engine checks, so `sandbox_targets` gives the same output there.
- A script's `a.click()` or `form.submit()` with `target=_top` or `_parent` in a frame navigates that frame itself, as before (no top escape, but also no navigation where the spec has one). Only submissions into a named frame now go there.
- Lock the sandbox flags when the iframe element is inserted, not when its document loads (`sandbox-navigation-timing`, `sandbox-new-execution-context`, `popup-from-initial-empty-sandboxed-document`).
- `document.domain` and the `SB_DOCUMENT_DOMAIN` flag (5 subtests), the iframe `csp` attribute (7), flags from the initiator (2).
- Script navigations still pass `activated = false` (transient activation is Q3.14c), so `allow-top-navigation-by-user-activation` only lets the person's or agent's clicks through.
- The "one permitted sandboxed navigator" of a popup is not kept: a sandboxed frame that navigates an open context by name is checked against its sandboxed navigation flag only, even for a popup it opened itself.
- From a frame without `allow-same-origin`, a popup or top navigation to a `file:` URL fails with "network error" in `dump` and the agent (opaque initiator); the tests use `allow-same-origin`.
- Tooling (#336, merged in this branch): one `wpt.py run --upstream` of a single file stopped with `PermissionError` from `os.killpg` in `signal_group` (macOS returns EPERM for a group with only zombies). The retry passed and nothing was left listening. `signal_group` should also ignore `PermissionError`.
