# Q6.13e: resizable ArrayBuffer, length-tracking views, DataView

- goal: `test262/built-ins` to 82 (2 points over the threshold). The feature `resizable-arraybuffer` failed whole (368 of 409), and DataView kept its state in plain data properties.
- slice 1 (this card, done): the buffer and the views.
  - engine: `ObjData.Bytes` has `max` (NONE: fixed length). `bufNew(o, n, max)`, `bufMax`, `bufResize` (`buf-max.aye`, `engine-buf-resize.aye`: a new block, the old bytes copied, the rest zero). A view whose `len` is NONE tracks its buffer: `view-length.aye` (`viewLength`, ECMA-262 TypedArrayLength) is what `typedLen`, `typedGet`, `typedSet`, `viewBytes` and the VM's keyed typed load use, so a view that is out of bounds after a shrink has length 0 and reads `undefined`.
  - prelude (`lib.aye`): `new ArrayBuffer(n, { maxByteLength })`, `resizable`, `maxByteLength`, `resize`, `transfer` keeps resizability, `transferToFixedLength` does not. A typed array made on a resizable buffer without a length tracks it; `byteOffset` is 0 when out of bounds. `DataView` keeps `_viewBuf` / `_viewOff` / `_viewLen` behind a `WeakSet` brand, `buffer` / `byteLength` / `byteOffset` are prototype getters that throw a TypeError when detached or out of bounds, the accessors use ToIndex and check the receiver, `Symbol.toStringTag`.
- references: ECMA-262 "ArrayBuffer Objects" (resize, maxByteLength), "TypedArrayLength", "IsTypedArrayOutOfBounds", "GetViewByteLength". V8: `src/builtins/builtins-arraybuffer.cc` (`ResizeHelper`), `src/objects/js-array-buffer.cc`.
- files: `browser/js/heap.aye`, `typed.aye`, `vm-keyed-typed-at.aye`, `lib.aye`; new `view-length.aye`, `buf-max.aye`, `engine-buf-resize.aye`; `browser/tests/js/292_resizable_arraybuffer.js` and `.out` (Node 22's output).
