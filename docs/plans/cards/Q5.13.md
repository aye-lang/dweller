# Q5.13: bookmarks and address-bar search with suggestions from history

- goal: what a person types in the address bar is a URL or a search (Chromium `components/omnibox/browser/autocomplete_input.cc`), the bar suggests pages from the browsing history and the bookmarks as they type (`history_url_provider.cc`, `bookmark_provider.cc`), and a page can be bookmarked (`components/bookmarks/`). Row Q5.13 of `foundations.md` (F1). All of it is the browser process's: the same code in all three process modes, no IPC kind.
- facts found first (2026-11-16):
  - The address bar takes a URL, a file path or a host (`engine.urlOfInput`); anything else became a `file:` URL of a file that does not exist. No search.
  - There is no browsing history: `engine/history.aye` is one tab's session history, the profile has `cookies`, `session`, the storage files (and `zoom`, Q5.1).
  - No bookmarks anywhere.
  - `Field` (the address bar) has a caret and "all selected", no range selection: inline autocompletion (Chromium selects the completed tail) has nothing to stand on.
- slices (each with its verify):
  1. `browser/places/`, pure: the visits (URL, title, count, last visit) and the bookmarks (URL, title) of the profile, their files `<profile>/history` and `<profile>/bookmarks` (atomic, by the holder of the profile lock, torn or foreign files read as empty), the match of a typed text against them and its rank, the search URL of a text. Verify: Aye unit tests (`aye test browser --module places`).
  2. The window records visits: a person's tab that committed a new `http(s):` or `file:` document adds a visit (not a back or forward, not a Space's or an agent's tab), and its title follows. Enter in the address bar searches when the text is not a URL, a host or a file. Verify: window tests in `tests/browser/window_places.rs` with a profile and `DWELLER_SEARCH` at the test server, in one process and with `DWELLER_PROCESS=site`.
  3. The suggestions: a list under the address bar while it has the focus and text, at most 6 rows (the typed text first: "go to" or "search", then bookmarks and history by rank); Down and Up choose a row and put its URL in the bar, Enter goes, Escape closes the list and leaves the bar (one press, as before this card), a click on a row goes. Verify: the window tests (`suggest` lines of `--state`, the keys, a click, the PNG has the list).
  4. Bookmarks: Cmd+D and the mark (a ribbon) at the right end of the address bar add and remove the page; a bookmark shows its mark in the suggestions and counts as one and a half fresh visits; the empty address bar with Down lists the bookmarks. Verify: the window tests (`bookmarked` in `--state`, the file, the list, kept across two runs).
- decisions (nobody to ask; the plan's defaults):
  - The default search engine is DuckDuckGo (`https://duckduckgo.com/?q=%s`): it answers a browser it does not know without a consent wall or a script challenge. `<profile>/search` (one line, a URL with `%s`) or `DWELLER_SEARCH` names another. Chromium's default is Google.
  - No suggestions from the search engine: nothing typed leaves the machine before Enter. Chromium asks its engine per keystroke (`search_provider.cc`).
  - Rank, simpler than Chromium's `ScoredHistoryMatch`: visits weighted by age (Firefox's frecency buckets: 4, 14, 31, 90 days), plus 150 for a bookmark, doubled when the text starts the host (after `www.`); equal ranks by the later visit. At most 4096 visits are kept (the oldest go).
  - No bookmarks bar and no manager page: the list of the empty address bar is the place to find them. A bar would change the page viewport's height for every window test.
  - The typed text keeps the first row, so Enter never goes somewhere the person did not type (no inline autocompletion, see the facts).
- references: Chromium `components/omnibox/browser/autocomplete_input.cc` (URL or query), `history_url_provider.cc`, `bookmark_provider.cc`, `components/bookmarks/browser/bookmark_model.cc`, `chrome/browser/ui/views/omnibox/` (the popup).

## Status: done, 2026-11-16

Done note. Built whole in the browser process; the three process modes run the same code, no IPC kind.
- `browser/places/` (37 files): one list of places (a visit count and time, a bookmark flag), `<profile>/history` (saved at most every 2 s and at close) and `<profile>/bookmarks` (saved at each change), `isSearch`, `searchUrl` (`DWELLER_SEARCH`, `<profile>/search`, else DuckDuckGo), `suggest` with its rank. 4 unit tests (`aye test browser --module places`: 4 passed).
- The window: `noteVisits` at the start of each loop iteration (a person's tab that finished loading a new document; a back or forward is told by an unchanged history length with another current entry), `addressTarget` in `submitAddress` (search, `localhost` as `http:`, else `engine.urlOfInput`), the list (`ui/suggestions.aye` and 14 small files; `Ui.suggest`), the ribbon and Cmd+D, `bookmarked` and `suggest` lines in `--state`. While the list is open the page gets no input (`tabInput`), so a click on a row never reaches a renderer.
- Verify, 2026-11-16: `cargo test --release --test browser -- window_places`: 3 passed, each in one process and with `DWELLER_PROCESS=site` (`window_places_search`: two words, a forced `?`, `localhost:PORT`; `window_places_suggest_history`: the rows and their order, Down, Up around the ends, Escape, Enter, a narrowed list, a click on a row, the visit counts in the file after seven runs on one profile; `window_places_bookmarks`: Cmd+D, the file, the list of the selected address bar, the mark in the rows, kept across runs, the ribbon filled and hollow in the PNG, the list drawn). The whole suite: 259 passed, 0 failed. `check_taste.py`, `check_layers.py`, `gen_property_ids.py --check`, `aye check browser`: clean.
- Tests of others changed, each for a reason: `tests/browser/input.rs` (the state of a typed address now has its `suggest` line), `tests/browser/window_login.rs` (a profile now has a `history` file), and three goldens blessed after measuring the difference: `browser/tests/ui/auth_prompt.png`, `spaces_chips.png`, `forms_html5.validation.png` differ from the old ones in 29 pixels, all inside the ribbon's 9 by 11 px box at the end of the address bar. Q5.1's zoom chip moved left of the ribbon.
- Shared files touched (small): `ui/window.aye` (about 25 lines), `ui/tabs.aye` (4 fields of `TabSlot`), `ui/tab-input.aye`, `ui/pagedraw.aye`, `ui/script.aye`, `tests/browser.rs` (the `mod` pair).

Left:
