# P4.75x: align the error-union payload (Aye compiler)

- goal: the `JsError!Value` result copies in the dispatch loop stop stalling (the top stall in `vmCallNativeAt`, about 75% of its samples, and 45% of `vmLdaGlobal` in P4.75s); navier-stokes and crypto at or above 1.00× vs base `c996cf8` (both 0.96× after P4.75u).
- finding: the Aye C backend emitted `struct { uint16_t err; T val; }`, so C already put a 16-byte `Value` (8-byte aligned) at offset 8, not 2. The stall is the copy: the 16-byte load of the result's first half covers the 2-byte `err` store, its 6 padding bytes and the `Value` tag, which no store forwards. Same for `?T` (`{ bool has; T val; }`).
- design (Aye, branch `align-error-union-payload`): Zig's layout. `E!T` is `struct { T val; uint16_t err; }` and `?T` (non-pointer) is `struct { T val; bool has; }`: the payload at offset 0, at its own alignment, the error or flag after it, padded to the payload's alignment. Sizes do not change for any payload (`E!u8` 4, `E!u64` 16, `E!Value` 24, `?u64` 16). `Some`/`Ok` literals use designated initializers. `@sizeOf` is C `sizeof`; neither type is C-compatible, so no ABI change. No Dweller code changes.
- files: aye `src/cgen.rs` (type definitions, `Some`/`Ok` rvalues, constant `Some`), `tests/cases/payload_layout.{aye,out}` (sizes and byte offsets of `?u8`, `?u64`, `?Pair`, `?Quad`), `tests/golden.rs` (`codegen/payload_layout`: `offsetof`/`sizeof` static asserts on the generated C for `E!u8`, `E!u64`, `E!Pair` (16 bytes), `E!Quad`, `?Pair`, `?u8`), `docs/spec.md` §16, `CHANGELOG.md`.
