# Q2.3b: agent commands answered by the tab's renderer

- goal: with `DWELLER_PROCESS=tab`, the agent commands that read or act on a page (snapshot, read, find, click, type, select, press, scroll, eval, screenshot, run, navigate, back, forward, reload) are sent to the tab's renderer over IPC and answered there, by the same agent code on the renderer's own page; the agent socket protocol stays byte for byte the same (same refs, same result text). The browser keeps the commands it owns (`tabs`, `tab_new`, `tab_select`, `tab_close`, `user_context`, `wait`, `spaces`, `space_close`), the refusals (paused by user, the user's tabs are look-only), the MCP handshake and the tool list. `dweller agent` and `dweller mcp` under the flag are a browser process too: they relay each line to a renderer process. Without the flag nothing changes.
- design:
  - IPC messages added (type codes in order): 24 B→R `agent{id, mcp, line}` (one request line, JSON lines or MCP; `id` is the browser's request number, one outstanding per renderer); 25 R→B `agent_reply{id, answer}` (the bytes the agent gets, "" for an MCP notification). Both on the tab's frame id in a window, frame 0 from the `dweller agent` relay.
  - the browser's checks (`rendererSent`; a failure logs `bad message: REASON PID` and kills): `agent_reply` on another frame id, with no request outstanding, or with an id that is not the one it was sent → `bad agent_reply`. The answer is bounded by the IPC payload limit (1 MiB, `MAX_PAYLOAD`: a longer message fails decoding and kills). A `loaded` while an acting agent request is outstanding (the agent navigated, clicked a link, submitted a form) is a commit the agent asked for: http(s) is accepted, `file:` only when the tab's committed URL is `file:` or empty (`agentCommitAllowed`), else `bad url`. The relay (`askRenderer`) applies the same id check and exits 1 after killing the renderer.
  - refs: a renderer keeps one agent `Session` for its tab, as the window kept one per tab, so refs are per tab and numbered exactly as before (`e1` up, never reused within the session). One renderer per tab for the tab's life (a renderer that is gone is not restarted), so no renumbering is needed: a renderer never sees another tab's elements and its refs only name its own page.
  - window (`ui/`): `serveLine` asks `askTabRenderer` first: a page command (`agent.pageCommand`) that is not refused goes to the slot's renderer (started on the spot when the agent's tab has none yet); the connection is `asked` until `answerAsked` (from `pollAgents`) writes `tp.answer` to it. A request is held (put back in the connection's pending bytes) until the renderer said hello, has its buffers and has no other request outstanding. A renderer that is gone while a request is outstanding answers `{"id":null,"ok":false,"error":"the tab's renderer is gone"}`. `tabs` reports the renderer's committed URL (`slotUrl`).
  - renderer (`renderer/`): `answerAgent` (on `agent`): in a window (`width > 0`) a window session (`newWindowSession` with the renderer's measurer and viewport), `RendererHost` as its `agent.Host` (shared mode, as in the window: `focused` field, the window's tool list; no window commands, no refusals), its tab showing the renderer's page (`syncSession`, new refs when the renderer loaded another document); when the agent's command showed a new document, the renderer adopts it (`adoptPage`, shared with `load`) and sends `loaded` before the answer. Without a window (the relay) a headless session (`agent.headlessSession`, 800x600, the virtual clock, as `dweller agent`).
  - `dweller agent|mcp` with the flag (`ui.relayAgentMain`, from `main.aye`): starts a renderer (`startTabProcess`, fixed font) and relays each line, waiting for its answer. `--no-js` is passed on; `--width`/`--height` are refused with a usage error under the flag.
  - test hook: `DWELLER_TEST_EVIL=agent` (the renderer answers request id + 1).
- Chromium read (idea only): `content/browser/devtools/render_frame_devtools_agent_host.cc` and `devtools_session.cc` (the browser owns the DevTools session and target list; page-level commands are dispatched to the renderer's agent over Mojo and answered by call id; `Target.*` and browser commands stay in the browser), `content/browser/bad_message.cc` (a bad message from a renderer kills it). Dweller takes: the browser owns the socket, tabs and refusals; the page commands run in the renderer and come back as one checked answer per request id.
- files: `browser/ipc/{message,decode,put-payload,from-renderer,message_test}.aye`; new `browser/agent/{answer-line,headless-session,page-command,page-command_test}.aye`; `browser/renderer/{answer-all,load,tab-renderer}.aye`, new `browser/renderer/{answer-agent,agent-session,adopt-page,renderer-host}.aye`; `browser/ui/{agents,renderer-sent,tab-process,start-tab-process,end-tab-process}.aye`, new `browser/ui/{ask-tab-renderer,answer-asked,agent-commit-allowed,slot-url,ask-renderer,relay-agent-main}.aye`; `browser/main.aye`; `tests/browser.rs` (`agent_sessions` split into `agent_sessions_with`; new `agent_sessions_in_renderer`, `agent_sessions_bad_reply`, `window_renderer_agent`).

Left:
- `wait` (a window command, in real time) still reads the window's own page, which is null under the flag: it answers "no page". It needs a renderer-side wait answered later (Q2.3b follow-up).
- what agents do does not show under the flag: no outline of the target element with its ref, no `agent: click …` status line (`agentActs` is a no-op in `RendererHost`); `user_context` and Cmd+Shift+K point at nothing (they read the window's page).
- an agent's `scroll` moves the session's scroll offset, not the renderer's shown scroll; an agent's history (back, forward, pushState) lives in the renderer's session, not in the window's history (Q2.6).
- the browser cannot verify an agent-driven navigation's target beyond its scheme until the network moves to the browser (Q2.4/Q2.6); a compromised renderer can claim any http(s) URL while an acting agent request is outstanding.
- answers over 1 MiB (a large full-page screenshot) kill the renderer; they need chunking or shared memory.
- one outstanding request per renderer: a second connection on the same tab waits for the first answer.
- `dweller agent|mcp --width/--height` under the flag; popups a page opened (window.open) in a renderer are not tabs of the window yet.
