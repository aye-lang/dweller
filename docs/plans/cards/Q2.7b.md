# Q2.7b: agent navigations swap renderers; test hooks need DWELLER_TEST=1

- goal: with `DWELLER_PROCESS=tab`, an agent's navigation (navigate, a click on a link, a submit, back, forward, reload) whose response is of another site than the renderer's lock commits in a new renderer, as the user's and the page's navigations do since Q2.6b; the agent's next commands reach the new renderer. Every compromise or test hook of the renderer works only with `DWELLER_TEST=1`. Without the flag nothing changes.
- design:
  - the decision is the Q2.6b one, on the final response: `answerFetch` asks `takesSwap` for every navigation fetch of a window tab, the browser's own (`tp.loading`) and the agent's (`fetchNavigates` with an acting agent request outstanding). An agent's first navigation in a fresh tab sets the lock (before this card an agent-only tab had none). The `dweller agent` relay (`tp.tab` 0, no window) does not swap (Left).
  - the swap: the old renderer waits inside its agent command on the kept response and never gets it. `startSpeculative` takes the final URL from `tp.swap_url` (set by `takesSwap`) and, for an agent's navigation (`!old.loading`), `carryAgent` moves the outstanding request to the new renderer (`agent_id`, `agent_conn`, `agent_mcp`) and gives it a `navigate` to the final URL with the request's id (`agent.navigateLine`: a JSON-lines `{"id":ID,"cmd":"navigate","url":URL}` or the MCP `browser_navigate` tool call). `navigateSpeculative` sends `session_history` and that `agent` request (after the frame buffers, so the renderer answers with its window session) instead of `navigate`; its document fetch is answered with the kept response (`sendPrimed`). Its `loaded` commits a new history entry (`push_on_commit`), the old renderer is killed and reaped, and the new one's `agent_reply` is the agent's answer. If the new renderer cannot start or dies first, the old renderer's fetch fails (`failSwap`) and its agent command answers that failure.
  - agent commands after a swap go to `slot.process`, the new renderer (Q2.3b's `askTabRenderer`); a second connection waits while the request is outstanding, as before.
  - the browser's checks: an agent's `loaded` (no navigation open, an acting request outstanding) is now checked against the site lock too (`commit outside site lock`), unless the browser failed that navigation's fetch (`tp.nav_failed`, cleared when an acting agent request is sent while nothing loads).
  - hooks: `renderer/evil-test.aye` `evilTest(name)` (`DWELLER_TEST=1` and `DWELLER_TEST_EVIL=name`) is the only reader of `DWELLER_TEST_EVIL`; `DWELLER_TEST_SANDBOX_PROBE` also needs `DWELLER_TEST=1`. The tests that use a hook set `DWELLER_TEST=1`.
