# P10.54: images toward its threshold

- goal: WPT area `images` (`html/semantics/embedded-content/the-img-element`, `css/css-images`, `png`, `gif`) to its 60% threshold, weighting what real sites use.
- before: on `train-2` (`conformance.py run images`) 1029/5146 (20.0%; the 1022 row in `history.csv` was measured on train-1).
- cause groups (failing subtests before):
  - gradient color interpolation and serialization (2037: `gradient-interpolation-method-computed` 932, `-valid` 813, `-invalid` 292): `in <space> [<hue> hue]` was neither validated nor moved after the line; defaults (`in srgb` for legacy colors, `in oklab` otherwise, `shorter hue`) were kept; `xyz` was not `xyz-d65`; computed colors stayed as written.
  - gradient validation (about 130: `color-stops-parsing` 60, `gradient-position-*`, `gradient-specified-values`): `background-image` took any `*-gradient(...)` (`isImage` checked the name only); hints at the ends, two hints in a row and stops with three positions were accepted.
  - `sizes` attribute parsing (716, four `parse-a-sizes-attribute-*` files): not done here.
  - animations (about 640: `object-position`, `image-slice`, `object-view-box` interpolation, `image-no-interpolation`): not done.
  - `image-set()` parsing (120), `object-position` parsing (36), `<img>` decode / lazy / environment changes (about 120): not done.
- design: `readGradient` (layers.aye) is the validator: `layersValue` keeps a `background-image`/`mask-image` layer only when `isValidImage` (a gradient must read). `splitInterpolation` splits the first argument into the line and the interpolation method (before or after the line, never inside it); `applyInterpolation` stores the space and hue method on `Gradient`. Lengths the paint side cannot size yet (`cqi`, `lh`, `vw`, mixed `calc()` in conic stops) still validate (`gradientLength`). `writeGradient` writes the canonical form: line, then ` in <space>` unless it is the default for the stops (`legacyStops`), then stops; the computed form (`writeComputedGradient`, from `writeComp`) first resolves lengths, then writes colors as computed, drops `to bottom`, `ellipse`, `farthest-corner` and a centered `at`, and writes `at` as two length-percentages (`writeGradientAt`). The specified form (`specifiedImages`, from `specifiedValue`) keeps colors and the line as written, dropping `ellipse` before a size. Paint (`spaceStops`) splits each stop pair into 256 stops mixed in the gradient's space with `mixStop` (the `color-mix()` code), from the stops' unclipped colors; gradients without `in` (or `in srgb`) are unchanged. Image values animate discretely: `interpolateText` no longer mixes numbers inside `background-image`/`mask-image`, which the new comparable computed form would otherwise allow.
- files: `browser/css/` (new: `interp-split`, `split-interpolation`, `apply-interpolation`, `legacy-stops`, `write-gradient`, `write-computed-gradient`, `write-gradient-line`, `write-gradient-at`, `write-interpolation`, `write-len-pct`, `write-stop-part`, `specified-images`, `is-gradient`, `is-valid-image`, `gradient-length`, `mix-stop`; wiring in `layers.aye`, `specified-value.aye`), `browser/paint/` (new: `space-stops`, `stop-css-color`; wiring in `background.aye`), `browser/animation/interpolate-text.aye`, `browser/tests/style/backgrounds.style`.
- golden: `backgrounds.style` (1): the computed `linear-gradient(to right, red, rgb(0 0 255) 20px)` is now `linear-gradient(to right, rgb(255, 0, 0), rgb(0, 0, 255) 20px)`; css-images-4 serializes a computed gradient's colors as computed colors.
- reference: https://drafts.csswg.org/css-images-4/#gradients, https://drafts.csswg.org/css-color-4/#color-interpolation-method, https://drafts.csswg.org/css-images-4/#coloring-gradient-line; chromium `third_party/blink/renderer/core/css/css_gradient_value.cc` (`CustomCSSText`, `ShouldSerializeColorSpace`), algorithm only.
