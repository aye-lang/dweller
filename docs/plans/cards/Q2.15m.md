# Q2.15m: a popup and its opener are kept across a renderer swap

- goal: readiness list for Q2.14, "Logins and popups", first bullet [Q2.6b]: "`window.open` children and frames are dropped with the old renderer when a navigation swaps it". When Q2.6b wrote it, a popup lived in its opener's engine and died with the renderer. Since Q2.3f a popup is a tab of the browser, and since Q2.12d a same-site popup shares its opener's renderer. What a swap still dropped was the relation: a popup that left for another site (a sign-in page) and came back committed in a fresh renderer with `opener` null and no name, and its opener saw it as `closed` from the moment it left. Now the relation follows the tab, not the renderer.
- design:
  - renderer (`leaveContext`): when a tab ends, the context of a popup (one with an opener) stays in the process's table without a page; any other context goes as before. The opener's reference keeps working (`closed` is false, a navigation of the named target goes to the browser, which finds the tab).
  - browser: a slot attached to its opener's process remembers its home (`TabSlot.home`: `PopupHome { serial, context }`; `serial` numbers the OS process on its `TabProcess` records, so a reused pid cannot be mistaken for it). `startSpeculative` first asks `rejoinHome`: when the navigation's URL is of the site the home process shows, that process lives, the tab is not in it, and the response has no Cross-Origin-Opener-Policy, the speculative renderer is a new connection to the home process (`attachTabProcess` with the remembered context) instead of a new process. The renderer accepts it as it accepts the first attach (`attachable`: a known context with an opener, no page, no tab), so the document loads into the context its opener made: `opener`, the name and the opener's reference are those from before.
  - IPC 90 `context_closed{context}` B→R (`closeAwayContext`, from `endSlot`): the tab of that popup is closed. It goes on another live connection of the home process, in order with that connection's input, so a script that runs after the close sees `closed` true. The renderer (`closeContext`) ends the tab that shows the context, if it is still there, and removes the context; a context that is some other live page's, or the sender's own, is left alone.
  - frames: a tab's out-of-process frames are the browser's records under its `TabProcess` (`children`); a swap of the top ends them with the old document, and the new document's `subframes` start its own. Nothing of a frame outlives its document, as in Chromium, so there is nothing to keep (checked by `window_renderer_oopif*`, unchanged).
- decisions: a first try sent a "detach" on the connection being closed; the renderer's own write to that closed connection can fail first and end the tab before it reads the message, so the default was turned round (keep a popup's context; the browser says when the tab is closed). Rejoining is refused under any COOP value, since COOP may have put the document in another browsing context group (Q3.10 decides the swap; a refused rejoin is only a missed reuse).
- Chromium read (over HTTPS from `main`): `content/browser/renderer_host/render_frame_host_manager.cc` (`GetFrameHostForNavigation`, `CommitPending`: the frame that leaves a process stays in it as a proxy, and a navigation back to a site of the browsing instance uses that site's existing SiteInstance and process), `content/browser/site_instance_impl.cc` (`GetRelatedSiteInstance`: one SiteInstance per site in a BrowsingInstance). Dweller takes: the popup's context stays in its opener's process while the popup is elsewhere, and the way back to the opener's site is the opener's process. Not taken: the proxy carries no cross-process `postMessage` or `location` yet (Q2.15n).
- files: new `browser/ui/{popup-home,attach-slot,home-process,rejoin-home,close-away-context}.aye`, `browser/renderer/{leave-context,close-context}.aye`, `browser/ipc/context-closed_test.aye`; changed `browser/ipc/{message,decode,put-payload,from-renderer}.aye`, `browser/renderer/{answer-all,serve-tabs,tab-renderer}.aye`, `browser/ui/{tab-process,tab-processes,tabs,start-tab-process,attach-tab-process,opened-slot,host-tab,start-speculative,end-slot}.aye`; tests `tests/browser/window_renderer_popup.rs`, pages `browser/tests/ui/popup_{opener,child}.html`.
- verify (2026-11-16, Linux x86_64, headless, ANGLE fetched, proxy variables unset):
  - `aye check browser`: exit 0. `aye test browser`: 312 passed, 0 failed (new `ipc/context-closed_test.aye`). `check_taste.py`, `check_layers.py`, `gen_property_ids.py --check`: exit 0.
  - whole suite: 257 passed, 0 failed (248 s).

## Status: done, 2026-11-16

Left:
- The opener side is not symmetric: an opener that leaves its process and returns gets a fresh context (the browser does not know the context id of a process's first tab), so its popup's `opener` stays null after the opener left. With Q2.15n's proxies.
- While a popup is away, its opener's reference is a context without a page: `closed` and navigating it work, `postMessage` to it and its `location` do not reach the other process (Q2.15n).
- A popup's context whose opener's process ended is gone with the process; the popup then has no home to return to and gets a renderer of its own.
- `rejoinHome` is refused under any COOP header, also `unsafe-none` written out with a report-to, and `same-origin-allow-popups` from the opener's side.
