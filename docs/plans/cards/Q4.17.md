# Q4.17: canvas 2D cost on mistral

- goal: cut the canvas 2D cost of mistral's idle (foundations.md, Q4 table, row Q4.17). Q4.15b: 99.3% idle CPU; per 10 s the rAF script 5692 ms (of it `canvas_draw` 1750 ms), the raster of one 482804 px damage rect each frame 3480 ms, relayout 1714 ms.
- profile: one capped idle run of a `browser/build.sh` build of main (5ff6f43) with `DWELLER_TIMING=1 DWELLER_LAYOUT_WHY=1 --log`, a macOS `sample` of 8 s of it, and two throwaway debug builds that logged the scaled images of the raster and a hash of the canvas pixels each frame (`target/q417-*`).
  - The 2D calls: two draws a frame on one 800×600 canvas of a widget iframe (`ml4-blog-widgets…/visual-intelligence`, `drawing-trace.js`): a rotated `drawImage` of a 1119×1185 sheet, clipped to a rounded rect (330×348 area, 8.0 ms), and a `source-in` fill of the whole canvas (1.9 ms). In the sample: `canvasPaint` image sampling 58%, `svg.render` of the rect and the clip 23%, `canvasComposite` 18%. No single slow path.
  - The raster: `ui_draw` 18 ms a frame. The damage rect is the canvas's box (802×602 with its 1 px antialias edge). 1416 of 1883 samples of `renderWith` are `Canvas.drawImage` of the page's 2880×1504 background image, scaled to 1394×728 (bilinear, `mix`, `premul`, `blendPremul`), redrawn under the canvas each frame; begin/end of a window layer 358 more.
  - The canvas pixels: the same hash in 265 of 300 frames. The widget draws every frame but its camera does not move, so the pixels do not change, yet every draw bumps `Bitmap.version` and the paint signature of the canvas's image item changes.
- cause: paint takes "the canvas was drawn" for "the canvas changed". Every frame raises damage over the whole canvas box and re-rasters what is under it, a big scaled background image.
- design:
  - `image.Bitmap` gets `look` (counts the changes of the pixels that paint has seen), `looked_at` (the `version` they were checked at) and `shown()`: `look` when the check is current, else `version` with the top bit set. Paint's image items take `ver: bmp.shown()` instead of `version`. A bitmap that is never checked (decoded images, worker canvases) behaves as before: its `shown()` changes with every draw.
  - `settleCanvases(cache)` runs at the end of each task (`afterTask`): for each canvas drawn since its last check (`looked_at != version`) it compares the pixels with the copy in `CanvasBitmap.seen` (`memcmp`). Same: `looked_at = version` and `look` does not change. Different: copy them to `seen` and `look += 1`. A canvas over 16 MB of pixels is not checked (no second copy). `resetCanvas` carries `look` over, so a reset never reuses an earlier number.
  - Safe by construction: a check that did not run gives a value with the top bit, never a stale `look`, so a missed check costs a repaint, never a stale frame.
  - Tried and dropped: an axis-aligned fast path for `drawImage` sampling (column and row taps). The mistral sheet is rotated (inverse matrix b = −c = 1.285), so the path was never taken.
- files: new `browser/engine/settle-canvases.aye`, `settle-canvases_test.aye`. Changed: `browser/image/image.aye` (`look`, `looked_at`, `shown`), `browser/paint/paint.aye` (two image items), `browser/engine/canvas_api.aye` (`CanvasBitmap.seen`, its free, `resetCanvas`), `images.aye` (free `seen`), `script.aye` (`afterTask` calls `settleCanvases`).
- Chromium files read: `third_party/blink/renderer/core/html/canvas/html_canvas_element.cc` (`DidDraw`, `ContentsCcLayer`, `SetNeedsCompositingUpdate`), `third_party/blink/renderer/modules/canvas/canvas2d/canvas_rendering_context_2d.cc`, `base_rendering_context_2d.cc` (`DidDraw(rect)` after each call). Blink invalidates only the canvas's own composited layer on `DidDraw`, so the page behind it is never re-rastered; Dweller has no canvas layer, so it takes the intent (no page raster for a canvas whose output did not change) and uses a pixel compare where Blink uses the layer.
- verify:
  - `python3 browser/tools/check_layers.py`, `python3 browser/tools/check_taste.py`, `aye check browser` exit 0. `aye test browser` 201 passed, 0 failed, 17 modules; new `engine: a canvas drawn again with the same pixels keeps the version paint shows`.
  - `scripts/capped.sh cargo test --release --test browser -- canvas window_canvas window_damage imagebitmap aye_unit_tests`: `aye_unit_tests`, `canvas_animation`, `canvas_origin_clean`, `window_damage`, `window_damage_rect_only` pass; `imagebitmap_sources` and `worker_canvas` fail locally only because ANGLE is not fetched in this worktree (CI runs them). No golden re-blessed.
  - Perf, `browser/build.sh` builds of main 5ff6f43 (before) and this branch (after), mistral only, all through `scripts/capped.sh`, before and after alternating.
    - `window_perf.py report --replay --site mistral`, 3 runs each, medians: loop 1590 → 1557 ms, scroll p95 348.0 → 350.1 ms, idle 99.4% → 99.3%. W7 still fails (loop, scroll, idle).
    - `window_perf.py idle` with `DWELLER_TIMING`, 3 runs each, medians per 10 s: frames 195 → 313; ms a frame 52.3 → 32.5; raster `ui_draw` 3535 → 257 ms (18.1 → 0.8 ms a frame; frames with page damage 195 → 5); `canvas_draw` 1739 → 2562 ms (8.9 → 8.2 ms a frame, more frames); rAF 5696 → 8970 ms; relayout 1710 → 2274 ms. Spread under 7%.
    - Idle CPU does not fall: the page asks for a frame every frame and its script takes 29 ms of each, so the loop stays busy and the 18 ms of raster saved become 60% more frames.

## Status: done, 2026-11-08

- left:
  - Mistral idle stays at 99%: per frame now the rAF script about 29 ms (of it `canvas_draw` 8.2 ms), relayout 7.3 ms, `paint_build` about 5 ms (7 builds a frame, the page's frames). The relayout and style (`set:anywhere`, `local:unnoted`, `STYLE_FULL` each frame in `DWELLER_LAYOUT_WHY`) are the next cause; a canvas draw also bumps the DOM version (`canvasChanged`), which may start a relayout of its own: measure that first.
  - The rotated `drawImage` (8.0 ms a draw): bilinear sampling of a 1119×1185 source at 0.27 scale, a rounded-rect clip coverage and the composite, about 58/23/18%. A downscaled (mipmap) copy of the source, as Skia uses for `imageSmoothingQuality = "high"`, and an incremental affine walk would cut the sampling.
  - The page raster under a changing canvas still rescales the 2880×1504 background each time (1416 samples of 1883): a scaled-image cache or a canvas layer (Q4.1 cause 9) for when the canvas does change.
  - The settle check runs only for canvases of the page whose task drew them; a canvas drawn by a script of another frame (`s.active != s.page`) is not checked and repaints as before.
