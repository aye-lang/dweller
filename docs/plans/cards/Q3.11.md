# Q3.11: small leaks (Authorization on redirects, window.name, top-level data:, private network access)

- goal (foundations.md row Q3.11), one test each:
  1. A cross-origin redirect removes `Authorization`, `Proxy-Authorization` and `Cookie` set by a script, and the URL's credentials (`user:pass@`) are not sent to the new origin.
  2. `window.name` is cleared when a top-level navigation commits a document of another origin and the browsing context has no opener.
  3. A page cannot navigate the top level to a `data:` URL (link, `location`, `window.open`, form): the navigation is dropped and the page's console gets an error. `data:` in iframes and images still loads, and a `data:` URL the person types loads.
  4. Private network access: a page served from a public address cannot fetch, XHR or load a subresource from a private (RFC 1918, link-local, `fc00::/7`, `fe80::/10`) or loopback address. Loopback and private pages may.
- design:
  - redirect headers: `net/cross-origin.aye` `crossOrigin(from, to)` and `net/without-credentials.aye` `withoutCredentials` (the header lines without `authorization`, `proxy-authorization`, `cookie`). `transfer` (http.aye, the synchronous path) keeps a `sent` request whose headers lose those lines at the first cross-origin hop, before the CORS redirect check and its preflight (so the dropped `Authorization` no longer asks for one). The loader's `finishRequest` (fetch, async XHR) does the same to `Ask.headers` through `net/drop-credentials.aye`. The jar's cookies and the session's auth realms are per origin already, so only the script's lines needed removing. URL credentials: each hop is a new libcurl request on the Location URL, which has no userinfo for another origin, so nothing of `user:pass@` goes with it; the test checks it.
  - window.name: `engine/reset-window-name.aye`, called by `attachLoading` (contexts.aye) when a top-level page is attached to its context, before its scripts run. The condition is the HTML spec's ("apply the history step"): the context is not an auxiliary one with an opener (`opener == 0`) and the new document's origin is not the old one's (`net.sameOrigin` of the two pages' URLs, after redirects). The spec says origin, not site, so `127.0.0.1` to `localhost` clears it too.
  - top-level `data:`: `engine/blocks-top-data.aye` `blocksTopData(page, target, initiator)`: true for a `data:` target with a `Page` initiator, and it adds `[error] Not allowed to navigate top frame to data URL: <url>` (Chromium's text) to the current page's console. Called first in `Tab.navigate`, `Tab.navigateEarly` (the window), `navigateTo` (forms, GET and POST) and `loadInTab` (window.open, in memory). The address bar navigates with `Initiator.Browser`, so it passes. Frames navigate through `frames.aye`, not `Tab`, so `data:` iframes load. Dweller has no downloads, so there is nothing to exempt.
  - private network access: the address class is decided from the IP libcurl connected to, not the host name. `net/watch-address.aye` (from `prepare`) sets `CURLOPT_PREREQFUNCTION` (`net/on-connected.aye`), which libcurl calls after it connects (or reuses a connection) and before it sends the request. It records whether the peer is public (`net/public-address.aye`, `ipv4-octet.aye`; IPv4-mapped IPv6 as IPv4) and aborts the request when the page is public and the peer is not, which becomes a network error. A document response from a public address adds its final URL to `Session.public_pages` (`note-public-page.aye`, `public-page.aye`, like `Session.upgrading`); every non-document request whose referrer is such a page is public-only. Each redirect hop and each connection is checked again. Test hook: `DWELLER_PUBLIC_ADDRESS=<ip>` makes that one IP public (the test uses `127.0.0.1`, because macOS has no `127.0.0.2` on `lo0`; the loopback target is `[::1]`).
- files: new `browser/net/{cross-origin,without-credentials,drop-credentials,public-address,ipv4-octet,on-connected,watch-address,public-page,note-public-page}.aye`, `browser/net/public-address_test.aye`, `browser/engine/{reset-window-name,blocks-top-data}.aye`; changed `browser/net/{http,loader,session}.aye`, `browser/engine/{contexts,tab,forms}.aye`; tests `browser/tests/net/{redirect-credentials,pna,name-set,name-show,data-nav}.html`, `browser/tests/server.py` (`/fetch-redirect-to?URL`, an optional host argument such as `::1`), `tests/browser.rs` (`server_on`, `redirect_credentials`, `private_network_access`, `window_name_and_top_data`).
- references:
  - specs: https://fetch.spec.whatwg.org/#http-redirect-fetch (step 13: remove `Authorization` on a cross-origin redirect), https://html.spec.whatwg.org/multipage/browsing-the-web.html#apply-the-history-step (navigable target name reset), https://wicg.github.io/private-network-access/ (address spaces, the check at connection time).
  - Chromium `net/url_request/redirect_util.cc`: Dweller takes removing the listed headers before the next hop is built (Chromium removes `Authorization` in Blink, step 13, and the body headers here). `content/browser/renderer_host/navigation_request.cc`: Dweller takes blocking renderer-initiated top-level `data:` navigations, allowing browser-initiated ones, and the console text. `services/network/private_network_access_checker.cc`: Dweller takes the check against the connected endpoint's address space, with the client's address space from the document response; it does not take the preflight, the warning-only mode or private-to-loopback blocking.

## Status: done, 2026-11-08

- left:
  - private network access: no `Access-Control-Request-Private-Network` preflight (the request is refused, not asked); a private page may still reach loopback (the spec orders public < private < local); frame and worker documents, and top-level navigations, are not checked; `Session.public_pages` keeps every public page URL until the session ends, keyed by URL, so a page with a `file:`, `data:` or `about:` URL is never public.
  - window.name is cleared only on new navigations; back/forward does not restore the old entry's name (the spec keeps it per document state).
  - top-level `data:` from a page is refused for every MIME type; a `data:` download exemption is needed once Dweller has downloads.
