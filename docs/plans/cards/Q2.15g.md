# Q2.15g: the Linux sandbox keeps the fonts that are opened late

- goal: readiness list for Q2.14, "What a person sees", fourth bullet [Q2.8b]. A Linux renderer opens some font files after it entered its sandbox: the fallback faces (at the first character no system face has), a variable face's weight instances, and the canvas's own `font.System`. Landlock allows those opens beneath `/usr`; on a kernel without Landlock (before 5.13, or Landlock off) seccomp refuses every open, and the page shows tofu and no canvas text (Q2.8b's Left).
- design:
  - `font.keepFontFiles` (`font/keep-font-files.aye`, `keep-font-file.aye`): every path of the system face lists and of the fallback list that exists is opened read-only, mapped (`mmap`, `PROT_READ`, private) and closed; the path and the mapping go into a fixed table of 64 (no allocation kept). A mapping costs address space only; its pages are the kernel's page cache of the file, shared by every renderer, and are read when a face is used.
  - `openFace` (`font/freetype.aye`), the one place a face is opened by path, makes the face from the mapping when the path is in the table (`FT_New_Memory_Face`) and from the file otherwise. So the late opens need no `open` at all.
  - the renderer calls it in `enterLinuxSandbox` before Landlock and seccomp, on every Linux, with or without Landlock: one path for both, and the suite's Linux runs cover it.
  - test hook `DWELLER_TEST_NO_LANDLOCK=1` (with `DWELLER_TEST=1`, `renderer/landlock-off-for-test.aye`): `restrictPaths` reports no Landlock, so only seccomp is on.
- decision: mapping before entry, not a `font_open` message to the browser (process-model §6 named both). The files are a fixed list known before entry, so no message, no fd passing and no check of a path a renderer names are needed. A broker would only be needed for font files the list does not have (a font found by name at run time), which Dweller does not do.
- Chromium read: `docs/linux/sandbox_ipc.md` and `content/browser/font_service.cc` (the renderer asks the browser for a font file's fd, because fontconfig finds files by name at run time), `sandbox/policy/linux/bpf_renderer_policy_linux.cc` (no `open` in the renderer).
- files: new `browser/font/{kept-file,keep-font-files,keep-font-file,kept-font-file}.aye`, `browser/font/freetype.aye` (`openFace`); `browser/renderer/{enter-linux-sandbox,restrict-paths}.aye`, new `browser/renderer/landlock-off-for-test.aye`; new `browser/tests/ui/late-fonts.html`; `tests/browser/window_renderer_oopif_site.rs`; `docs/process-model.md` (§6, fonts).
- verify (2026-11-16, Linux x86_64, kernel 6.18 with Landlock ABI 7; test commands run with `env -u HTTPS_PROXY -u https_proxy -u CURL_CA_BUNDLE -u SSL_CERT_FILE`):
  - `cargo test --release --test browser`: 266 passed, 0 failed (the whole suite).
  - `window_renderer_oopif_site_late_fonts`: `late-fonts.html` with the system fonts (Latin, Chinese, Japanese, Korean, Arabic, Hebrew, symbols; serif bold italic; a canvas with sans-serif and bold monospace text). With `DWELLER_PROCESS=site` and Landlock off for the test, the probe prints `sandbox-probe home=1 tmp=1 tcp=1 fork=1` (every refusal is seccomp's EPERM) and the PNG is byte-equal to the in-process window's; with Landlock on it is byte-equal too.
  - before the change, by hand with the hook: the seccomp-only PNG differed from the in-process one (11541 bytes against 17543: the late faces were missing); with Landlock it was equal.
  - `python3 browser/tools/check_taste.py` exit 0, `check_layers.py` exit 0, `gen_property_ids.py --check` exit 0, `aye check browser` exit 0.
