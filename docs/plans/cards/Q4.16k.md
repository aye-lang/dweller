# Q4.16k: `Array.prototype.sort` without a comparator converts each element to a string once

- goal: a sort with no comparator converts each element to its string once, not twice per compare (Q4.21 cost 6: mistral's `sortLess` → `toStringValue` → `formatNumber` → `snprintf`/`strtod` on each compare, 2.7 ms a frame). Order unchanged: stable, `undefined` last, holes after.
- reference: V8 `third_party/v8/builtins/array-sort.tq` (`SortCompareDefault`) calls `ToString` on each compare, with a Smi fast path and V8's number-to-string cache behind it. Spec https://tc39.es/ecma262/#sec-sortindexedproperties: the sequence of `SortCompare` calls is implementation-defined. Dweller precomputes the keys only when no element is an object (Symbols are objects in Dweller's heap): a primitive's `ToString` has no side effects, so the result and the observable behavior are the same. An array with an object keeps the per-compare `ToString`, as V8 does, so a user `toString` runs the same calls as before. An array of only strings and `undefined` needs no keys and sorts as before.
- design: `sortKeys` (`browser/js/sort-keys.aye`) returns the work array itself (comparator given, fewer than 2 elements, an object, or nothing to convert), or a new array of the elements' strings (`undefined` stays `undefined`). `arraySort` merges by the keys and moves the values with them. When the keys are the work array, each move writes once, as before (a version that called a `sortMove` helper, or wrote through a `from` index, was 30% slower on 100k strings).
- files: `browser/js/sort-keys.aye` (new), `browser/js/builtins_array.aye` (`arraySort`), `browser/tests/js/284_array_sort_keys.js`/`.out` (new; expected from node: mixed number/string/bool/null stability, -0/NaN/Infinity/1e21/1e-7, BigInt, 300 fractional numbers, an object with `toString`, one Symbol (no throw), a Symbol with a string (TypeError), holes), `docs/plans/cards/Q4.16k.md` (new).
