# Q1.10c: fuzz target for the JS parser and bytecode compiler

- goal: a `dweller fuzz js` target on the Q1.10a harness that parses hostile input as a classic script and as a module and compiles what parses to bytecode, with a seed corpus, listed by `dweller fuzz --list` so the Q1.10e nightly job runs it with no workflow edit.
- reference read: `v8/test/fuzzer/parser.cc` (one isolate; `ParseProgram` on the input; inputs over 2048 bytes or with unbalanced brackets are skipped; nothing runs) and `v8/test/fuzzer/fuzzer-support.cc` (isolate and context setup, `--fuzzing`). Dweller's parse step is `Interp.parseCode` (tokenize, parse, resolve), so it gets the resolver too; the compiler step is the lazy one V8 does on first call, done for every function at once.
- design:
  - `browser/fuzz/js-target.aye`: the JS dictionary (punctuators, `?.`/`??=`/`**`, template and escape pieces, line terminators incl. U+2028, keywords and contextual words, `import.meta`/`import(`/`new.target`/`super`, `"use strict"`, numeric literal forms, regexp literals with flags, small destructuring, class, arrow and tagged-template snippets) and `fuzzJs`: a fresh realm (`js.newRealm`, which needs the built-ins: `parseCode` throws its SyntaxError through `syntax_error_proto`, and `Interp.create` alone panics in `heap.aye` on the first syntax error), `markStackBase(5 MB)` as `engine/script.aye` does for a page (the parser and the resolver then throw a RangeError instead of overflowing the main thread's 8 MB stack), then `compileJs` as a script and as a module.
  - `browser/fuzz/compile-js.aye`: `compileJs(alloc, it, src, module)`: `it.parseCode(src, module, 0, &info)`; a thrown SyntaxError returns; else `js.compileScript` of the script root, and `js.compileFunction` of every AST function the parse added (the module body is one). Nothing runs.
  - no run with a step budget: the Q1.7 tick is on back-edges and calls only, so native work (`"x".repeat(1e9)`, a long `sort`, a regexp) is not interrupted and would show up as timeouts and OOMs that are not parser or compiler bugs; and the reference does not run either.
  - `browser/fuzz/targets.aye` lists `html`, `css`, `url`, `js`.
  - seeds: `browser/tests/fuzz/js/` 294 files, 327 KB: 200 test262 `test/language/` files (`t262_*`, revision `browser/tools/test262.rev`, every 94th of the 18,832 files ≤ 2.5 KB in path order: 91 `expressions`, 75 `statements`, 8 `module-code`, 5 `literals`, and 1–3 each of `arguments-object`, `asi`, `block-scope`, `computed-property-names`, `directive-prologue`, `eval-code`, `function-code`, `global-code`, `identifiers`, `import`, `line-terminators`, `statementList`, `types`; negative syntax tests included) and every 3rd `browser/tests/js/*.js` (`js_*`, 97, minus the three over 4 KB). The nightly job copies the folder flat (`cp browser/tests/fuzz/$TARGET/*`).
  - throughput: about 290 inputs/s, set by the realm (the built-ins and the spec scripts run for each input; about 3.4 ms per input in all). One realm serves both parses of an input. A realm kept across inputs would be faster but makes a crash depend on earlier inputs (and top-level `let`s collide), so the replay with `--seconds 0` would not reproduce it.
- files: `browser/fuzz/js-target.aye`, `browser/fuzz/compile-js.aye` (new), `browser/fuzz/targets.aye`, `browser/tests/fuzz/js/` (new), `docs/browser.md` (section "Fuzzing"), `docs/plans/cards/Q1.10c.md` (new). Contains Q1.10b (PR #330).
- verify:
  - `python3 browser/tools/check_layers.py` exit 0; `python3 browser/tools/check_taste.py` exit 0; `aye check browser` passes; `aye test browser` 230 passed, 18 modules.
  - `scripts/capped.sh browser/build.sh` passes; `./target/dweller fuzz --list` prints `html`, `css`, `url`, `js`.
  - planted crash (`unreachable` when a module function compiled to bytecode and the input contains `plantfn`; not committed): replaying `export function plantfn(a) { return a + 1 }` with `--seconds 0` panicked at `browser/fuzz/compile-js.aye:28:13`, so the module path reaches the compiler.
  - `capped.sh ./target/dweller fuzz js --seconds 120`: 34,545 inputs in 120 s, 0 crashes, exit 0, peak 41 MB.
  - `capped.sh python3 browser/tools/fuzz.py run js --minutes 2 --binary target/dweller` (another seed): 34,775 inputs, 289/s, 0 unique crashes, exit 0, peak 58 MB.
  - `cargo test --release --test browser -- js_conformance aye_unit_tests errors`: 7 passed. No golden re-blessed.
- crashes: none found in about 69,000 inputs, none fixed, none filed.

## Status: done, 2026-11-08

- left: throughput is about 50 times below the html target; a realm made once and copied per input (a snapshot) would lift it, but Dweller has no realm snapshot. The mutator is byte-blind, so most mutants are syntax errors that stop in the lexer or parser; a token-aware or AST mutator is the next step if blind runs stay clean. Direct `eval` code (`parseCode` with an `eval_site`) is not fuzzed.
