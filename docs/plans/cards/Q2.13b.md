# Q2.13b: each style sheet is parsed once, not on every author sheet rebuild

- goal: Q2.13 ("Mac, real sites") and Q2.13a found that youtube-search's renderer parses its 3.85 MB `kevlar_base` sheet 22 times during the load, and keeps up to 8 old author sheets, each with a whole parse. Parse each sheet once, as Chromium does (`StyleEngine` keeps a text → `StyleSheetContents` cache for inline sheets; a linked sheet's contents live with its resource), and keep the cascade's inputs and order as they are.

## Count (before, origin/main 1ae97ed6)

- method: this Mac (arm64, macOS 26.5), `browser/build.sh` (safe), the default process mode (site), the archives (`DWELLER_REPLAY`), Q2.13's `mem2.py` (`--width 1280 --height 800`, `SDL_VIDEODRIVER=dummy`, a fresh `DWELLER_PROFILE` and `DWELLER_RESTORE=0` per run, the renderer's `renderer:loaded`, one wheel notch, then 10 s, `phys_footprint`). One run at a time. A scratch trace (not committed; the session scratchpad, `q213b/instrument.patch`, `sheets.py`) writes one line per `css.parseSheet` (sheet id, source length, base URL) and per `Sheet.deinit`, so a log gives the parses per source and the sheets alive over time. The same trace is in both builds.
- youtube-search (2 runs): `kevlar_base` (3,842,755 B) parsed 22 times, 1013 and 1020 ms of `css_parse`; up to 5 sheets alive that hold a parse of it (2 at the end); `www-player.css` (562 KB) 2 times; small linked sheets 22 times each. All `css_parse`: 1412 records, 1052 and 1058 ms. Renderer footprint 1733 and 1722 MB.

- mistral (1 run, 6 renderers): `astro.css` (239 KB) 6 times in the biggest renderer, the widget sheets 3 to 5 times each in the others; up to 2 to 3 alive; all `css_parse` 4599 records, 106 ms; renderers 1652 MB together.
- W7 (`window_perf.py report --replay --process site --site youtube-search`): loop 14 ms, wheel-to-frame p50/p95 125.9/551.1 ms, idle 84.9%, longest task 1741 ms (FAIL on p95, as before). The sheet timer of Q0.3f's Left (730 ms then) is a 785 ms `timers` task with 12 `kevlar_base` parses (564 ms).

## Cause

- `engine/sheet_cache.aye` keys all the author sheets of a document with one fingerprint of every source (`sheetSourceKey`), and a rebuild (`styleFor`, `computedStyling`, `swapSheets`) parses every source again into one new `css.Sheet` (`authorSheets`). YouTube's components insert `style` elements one by one, so each insertion parses `kevlar_base` again.
- each old author sheet that `swapSheets` keeps (`MAX_KEPT_SHEETS`, for the computed values that point into its arena) holds a whole parse: tokens, strings and lists.

## Change

- css: a parsed sheet can be shared. `css.sharedSheet` makes one on the heap with a reference count (`Sheet.refs`); `css.appendSheet(dst, src)` copies the lists of `src` into `dst` with their indices moved (rules, selectors, declarations, `@keyframes`, `@container` conditions, cascade layers by name, `@property`, `@font-face`, `@import`, `@page`) and holds a reference (`Sheet.parts`); `Sheet.deinit` releases its parts, and `css.releaseSheet` frees a shared sheet with its last reference. The strings and tokens stay in the shared sheet's arena, which the computed values point into. `PageBox.sized` tells the merge that a sheet set `size` (`size: auto` resets it). The parser notes when a sheet's `@scope` read the scope root (`Sheet.scope_read`).
- engine: `ParsedSheets` (one per page, `Page.parsed_sheets`) keeps one parsed sheet per source: a `style` element's or a CSSOM sheet's text, a constructed sheet's text, or a linked sheet's response (its URL and CORS mode: `doc.fetched` keeps one response per URL and mode for the document's life), each with the document base URL, the viewport media, the device pixel ratio and print mode, and the style element's parent when its parse read it (`@scope` without a prelude). `authorSheets` looks each source up (`appendSource`), parses only a missing one, and appends it; after the build, the sources it did not use leave the cache (`sweepParsed`). A source whose `@import` failed is not kept, so it is parsed again on the next build, as before.
- the CSSOM never edits a parsed sheet: a script's rules are a sheet text of their own (`dom.ScriptSheets`), so a changed sheet is a new source with its own parse, and a shared parse of the old text stays as it was.
- unchanged: when a rebuild happens (`sheetSourceKey`), the order of the sheets and rules, the media and `noscript` checks, the fetches and their `load`/`error` results, and the kept old sheets (`swapSheets`).
- `browser/engine/PERF.md`: a paragraph on the shared parses.

- youtube: `kevlar_base` 3 times (150 ms); up to 2 alive; all `css_parse` 197 ms (from 1071).
- mistral: `astro.css` 3 times, the widget sheets 2 to 3 times; all `css_parse` 91 ms (from 106).
- W7 youtube-search: loop 13 ms, wheel-to-frame p50/p95 131.9/494.5 ms, idle 84.1%, longest task 1620 ms (FAIL on p95, as on main). The old sheet timer is now a 58 ms task with 0.3 ms of `css_parse` and no `kevlar_base` parse (785 ms before); the 1724 ms `scripts` task is 1619 ms, an 812 ms timer 649 ms.
- footprint, **not better**: youtube-search's renderer at load + 10 s 1733, 1722 → 2277, 2241 MB; youtube 1600 → 1716; mistral 1652 → 1706 (6 renderers). A second check on youtube-search, 40 s after the load, before / after / before / after (MB at +10, +20, +30, +40 s): 1582 1799 2376 2449; 2041 2369 2962 3059; 1607 1888 2494 2601; 2267 2343 2989 2642. Both builds still grow at 40 s.
- what `vmmap` shows at +40 s: the live bytes are lower after (main malloc zone allocated 2.3 and 2.5 GB before, 2.2 and 2.3 GB after; `MALLOC_LARGE` live 1.4 to 1.5 GB in both), but more of the free pages stay dirty: `MALLOC_SMALL` dirty 632 and 743 MB before (300 to 400 MB more resident but clean, given back for reuse), 956 and 988 MB after, nearly all dirty; `MALLOC_LARGE (empty)` 344 and 349 MB before, 656 and 226 MB after. The page also loads sooner after (more of its scripts run inside the window of the measure). So the rise is macOS malloc keeping freed pages dirty (as in Q2.13a), plus timing, not more data kept; it still counts in the footprint, which is the M1 number.

## Tests

- `perf::style_sheets_parsed_once_per_source` (new): a page next to a generated 3000-rule linked sheet inserts 20 `style` elements, each in a task of its own that reads `getComputedStyle`, and gives the first of two `style` elements with the same text a rule (`insertRule`). The large sheet must be parsed once (`css_parse` records of its URL), every computed style right, the twin untouched (`rgb(255, 0, 0)`, its sheet still 1 rule), in one process and with `DWELLER_PROCESS=site`. On main's sources it fails: 40 parses (single mode). With the change: 1 in both modes.
- `browser/parsed-sheets_test.aye` (new, `aye test browser`): two `style` elements with the same text share one parse (one cache entry, the same `css.Sheet`); after `insertRule` on one, it has a parse of its own (2 rules) and the other keeps the shared one (1 rule). A removed `style` element's parse leaves the cache at the next build, and only the old author sheet still holds it (`refs` 1), which frees it.
- `browser/css/append-sheet_test.aye` (new): three sheets with layers, `@import ... layer()`, nesting, `:is()`, `:has()`, `:nth-child(of)`, `@keyframes`, nested `@container`, `@property` twice, `@font-face` and `@page`, parsed in order into one sheet and parsed apart then appended: every list is the same.

## Status: done, 2026-11-26

Left:
- `kevlar_base` and the other linked sheets are parsed 3 times on youtube-search, all together: the cache is emptied 3 times, which fits a change of the build's media (viewport size, dark, device pixel ratio) during the load, since `@media` is evaluated as a sheet is parsed and the media is part of the key. Not measured which. The full fix is Chromium's: parse a sheet without the media and evaluate `@media` when the rule set is built (`RuleSet` per media from one `StyleSheetContents`).
- the footprint did not go down (above): the next step is Q2.13a's, giving freed pages back (`malloc_zone_pressure_relief`) after a rebuild, measured for footprint and time; and the author sheet that a rebuild makes still copies every list (decls, selectors), into an arena that grows them by doubling, so a kept old author sheet holds those copies (`MAX_KEPT_SHEETS`): a kept sheet needs only its parts' references.
- the UA sheet is parsed again for each new `Styling` (the many tiny `css_parse` records: 3688, 1840 and 1839 on youtube, about 38 ms); it can be one shared parse per media too.
