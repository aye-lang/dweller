# P1.S10: zol's `tck` is a FingerprintJS hash; the replay computes it the same way every time, but the recording got another value

- goal: `page_load.py check --site zol` fails on main with 2 archive misses, both from mediav's `tck`. The zol archive was re-recorded 2026-11-25 02:27–02:31 (+08) by P1.S7, and the replays right after it passed. Find where `tck` comes from and make the replay deterministic at the source.
- method: `browser/build.sh` (safe) of main 888e29b7, and of 3593a439 (P1.S7's branch tip, which made the recording). The shared archive `target/sites/zol` of the main checkout, with no `DWELLER_PROFILE`. To see the page's own values, the archive was copied and the copy's `ssp_ad_sdk.js` was changed to request `https://fpjs.log/?<components>`; the replay prints that request as a miss. Two `DYLD_INSERT_LIBRARIES` shims, built in the scratchpad and not committed: one moves the real clock (`time`, `gettimeofday`, `clock_gettime`), one logs each `open`, `stat` and `getenv`.

## The misses

Three runs of `check --site zol` on main gave the same misses each time:

| missed URL | recorded twin |
|---|---|
| `ckmap.mediav.com/m?tid=696&tck=f3db23805d94542d7a88fb37b14f8488` | `…&tck=edcfd0c80abc99f5375993faab6082d8` |
| `show-g.mediav.com/s?…&adverid=&jsonp=SSP_AD_PMP_17913312000171` | `…&adverid=&tck=edcfd0c80abc99f5375993faab6082d8&jsonp=SSP_AD_PMP_17913312000171` |

The `show-g` miss is a result of the first miss. The `jsonp` (`Date.now()`) is the same in both runs. Only `&tck=` is not there.

## Where `tck` comes from

`W6(tid)` in `static.mediav.com/js/ssp_ad_sdk.js` (archive file `4145801495931476190.response`):

```js
[4,h6.load()] … [4,s.sent().get()] … r=s.sent(), o=G4(r.visitorId+t)   // t = tid "696"
i = cookie("__ad_cookie_mapping_tck_" + t)
i===o ? e(o) : (setTimeout(()=>e(""),3e3), (c=new Image).src=`…//ckmap.mediav.com/m?tid=${t}&tck=${o}`, c.onload=…)
```

- `h6` is FingerprintJS v4 (open source). It is bundled in the SDK. `visitorId` is `x64hash128` of the 41 sorted components, `key:JSON(value)` separated by `|`. `G4` is MD5. So `tck = md5(visitorId + "696")`.
- `show-g`'s `&tck=` is `W6`'s result. On the replay, the `ckmap` image is a miss, so `W6` gives `""` and `show-g` is requested without `tck`.
- The replay's components, from the changed copy: `canvas` (the winding, geometry and text images), `math`, `architecture 127`, `audio error` (no `createOscillator`), `dateTimeLocale error`, `timezone "UTC"`, `screenResolution [800,1280]`, `screenFrame [null,0,0,null]`, `hardwareConcurrency 4`, `languages [["en-US"],["en-US","en"]]`, `fonts []`, `fontPreferences` all 0, `touchSupport {0,true,false}`, `vendorFlavors []`, and fixed values for the others. A Node copy of `x64hash128` and MD5 of these components gives `f3db2380…`, which is the replay's value.

## What the replay reads, and what does not change it

The replay's `tck` was `f3db2380…` in each of these cases:

- 3 runs of `check`, and 8 runs of `dump --md --js` directly.
- P1.S7's build (3593a439), and the older `target/dweller` of the main checkout.
- Another working directory and another binary path. 12 CPU-bound processes running at the same time.
- The real clock moved back to 02:34 +08 (the shim makes a `new Date()` without `DWELLER_BENCHMARK` print 18:34Z). Cookie expiry, HTTP cache freshness and HSTS read the real clock (`net.now()`). None of the recorded `Set-Cookie` headers expires between the recording and the failure.
- The open log of a replay lists only the archive, the fixed system font files of `font/freetype.aye`, and the binary. The engine reads only `DWELLER_*` variables. Homebrew's freetype, harfbuzz and sdl2 did not change after Nov 11, and the Mac did not restart (up 4 days).
- The canvas text image of FingerprintJS, drawn on a local page by itself and after other canvas text, has the same bytes as on zol (`6a68cc4/7982`). It does not depend on what the page drew first.

So the replay is deterministic, and its inputs are the archive (no file changed after 02:31:34), the fonts and the binary.

## Class

Not found. It is not (a): the real clock does not change `tck`, and nothing else from outside reaches the replay. It is not (b): runs with different load and order gave the same value. The recording's fingerprint is different from the fingerprint of every replay today, built from the same commit. About 2,000 single-component changes that could happen (each small component, vendor flavor sets up to 4, `screenFrame`, `touchSupport`, storage flags, a component dropped) do not give `edcfd0c8…`. So one or more components with a large range of values were different when recorded: a canvas image, the `fonts`/`fontPreferences` measurements, or an audio hash.

This step does not explain P1.S7's report that `check --site zol` passed on this archive right after the capture. Q0.3f also saw these 2 misses on 888e5c91 with the old archive, and P1.S7's build of the same commit passed it. So the value has changed before, between builds of the same commit made by different agents.

## Change

None. No archive was re-recorded: the cause has not been shown to be in the recording, and a live `dump` of zol today (100 s, 924 requests, into a scratch directory, then deleted) requests nothing from mediav. A new capture would remove the `tck` path, not explain it.
