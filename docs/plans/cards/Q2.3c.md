# Q2.3c: default actions in the renderer; navigations and popups asked of the browser

- goal: with `DWELLER_PROCESS=tab`, the renderer runs the default actions the in-process window runs: link clicks and form submission (asked of the browser, which checks them and sends `navigate` back to the same renderer), Space and Enter on buttons, Enter in a `textarea`, Escape to blur, key scrolling of the page and of the last clicked inner scroller, Command/Control + arrows in text fields, range dragging, the scroll offset clamped when the page gets shorter, and `select` dropdowns (the renderer asks the browser to show the popup; the browser sends the choice back). Without the flag nothing changes.
- design:
  - IPC messages added (type codes in order, all on the tab's frame id): 13 R→B `begin_navigation{url, post, content_type, body}`; 14 R→B `popup{items, disabled, selected, x, y, w, h}` (labels joined by `\n`, one `0`/`1` per item, the rect of the `select` in the tab's viewport, CSS px); 15 B→R `popup_choice{index}`. B→R `navigate` now carries `post, content_type, body` too (a POST body goes with the navigation).
  - the browser's checks: `begin_navigation` on the tab's frame id (`unexpected begin_navigation`, kill); its URL against the URL the browser last sent to that renderer (`tp.committed`) with Q3.1's `net.initiatorMayLoad` (`file:` only from `file:`): refused → `error: navigation refused: URL` and no `navigate` (a page may try, so no kill); allowed → `navigate{url, post, content_type, body}` to the same renderer (`beginNavigation`). `popup` on the tab's frame id with one flag per item and `selected` in range (`ipc.badPopup`, `bad popup`, kill); its rect finite, not negative and inside the tab's viewport (`takePopup`, `popup outside the tab`, kill). The browser sends `popup_choice` only for an index it showed and that is not disabled (`chooseRow`); the renderer checks it again against the `select`'s current options.
  - window (`ui/`): `TabProcess.committed` (the URL last sent in `navigate`), `popup`, `popup_off`, `popup_at`, `popup_selected`, `popup_new`. `takePopup` (from `pollTabProcesses`, once no forwarded button is down, so the release reaches the renderer) opens the window's `Dropdown` with `remote: true`; `drawDropdown` takes the rows from the message (`remoteRow`), a click or Enter on a row sends `popup_choice` (`chooseRow`). `forwardKey` forwards Command/Control + arrows (other Command/Control keys stay the window's). The window's copy of the page does not follow a renderer's navigation (its URL and title are Q2.3d).
  - renderer (`renderer/`): `runAct` does what `engine.activate` asks: `Changed` restyles, `Follow` sends `begin_navigation`, `Submit` validates, fires `submit` and sends the submission (`submitAt`), `OpenSelect` sends `popup` (`openPopup`); `choosePopup` selects the chosen option. `clickAt` runs `runAct` and starts a range drag (`pressRange`, `dragRange` on moves, `change` on release). `keyInput`: `focusKey` (in a text field `fieldKey`: Escape blurs, Enter adds a line in a `textarea` or submits implicitly, Command/Control + arrows move to the line or field ends; on a `select` Space/Enter opens the popup; Space on a button presses it and `releaseSpace` clicks on keyup; Enter clicks; Escape blurs), then `keyScroller` (the scroller of the last left press, `engine.scrollerAt`), then `scrollKey`; both share `keyDelta`. `load` takes a POST body (`engine.loadWith`). `paintFrame` clamps the offsets to the new page size and repaints at the clamped offset.
- Chromium read (idea only): `content/browser/renderer_host/render_frame_host_impl.cc` (`BeginNavigation`: the renderer asks, the browser checks the URL against what the process may request, `CanRequestURL`, then starts the navigation), `content/browser/renderer_host/popup_menu_helper_mac.mm` (the browser shows the `select` popup from the renderer's items, selected index and bounds, and returns the chosen index), `third_party/blink/renderer/core/html/forms/html_form_element.cc` (`submit` event, then a form submission that becomes a navigation request). Dweller takes: the renderer never navigates itself, it asks; the browser checks the scheme rule and answers with `navigate`; the popup is drawn by the browser from plain data and only an index comes back.
- files: `browser/ipc/{message,decode,put-payload,from-renderer,encode_test}.aye`, new `browser/ipc/{bad-popup,bad-popup_test}.aye`; `browser/renderer/{answer-all,click-at,field-key,key-input,load,mouse-input,paint-frame,scroll-key,tab-renderer}.aye`, new `browser/renderer/{run-act,submit-at,open-popup,choose-popup,press-range,drag-range,focus-key,release-space,key-delta,key-scroller}.aye`; `browser/ui/{forms,forward-key,tab-process,start-tab-process,end-tab-process,queue-navigate,renderer-sent,poll-tab-processes,compose-damage}.aye`, new `browser/ui/{begin-navigation,take-popup,remote-row,choose-row}.aye`; new `browser/tests/ui/renderer_actions.html`; `tests/browser.rs` (`window_renderer_input_actions`).

A `file:` link of an http page → `error: navigation refused: file://...` and the page stays. No golden re-blessed.
