# Q6.5b: WPT `css/css-fonts` toward its target

- goal: the Target column of `docs/conformance.md` for `css/css-fonts`: 89 (7472 of 8396). Q6.5 left it at 5071/8396 (60.4%); 5115/8396 (60.9%) measured on the tree merged with the wave branch at the start of this card. The largest one-cause cluster first.
- design (clusters in the order done; subtests are of the area's 8396):
  - `font-family` was not validated by the inline setter or by a rule's `cssText` (`test_font_family_parsing`: 651). `checksValue` now covers the `FontFamily` kind, and `fontFamily()` rejects a list item that is one reserved word alone (`inherit`, `initial`, `unset`, `default`, `revert`, `revert-layer`; `css/is-reserved-family.aye`). 5115 -> 5726.
  - a longhand set through `style` after a shorthand that covers it was written in place, before the shorthand, and lost to it (`el.style.font = ...; el.style.fontFamily = ...` read the old family). `putStyleDecl` now moves such a declaration to the end, and a shorthand that is set drops the longhands it covers (`engine/shadowed-by-shorthand.aye`). This is the inline style as text catching up with what a declaration block does; it applies to every shorthand, not only `font`.
  - the `font` shorthand was parsed loosely (duplicates allowed, no system fonts, `font-stretch` and `small-caps` read and dropped) and echoed by the setter. One strict parser (`css/parse-font-parts.aye`, `font-parts.aye`, `font-prefix.aye`, `font-prefix-kind.aye`, `take-font-prefix.aye`) now serves three users:
    - the cascade (`Declarer.font`, `font-part-value.aye`): sets `font-style`, `font-weight`, `font-size`, `line-height`, `font-family`, `font-stretch`, `font-variant-caps` and resets the other font longhands (`font-resets.aye`); a system font keyword sets them all to their initial values.
    - the specified value (`specified-font.aye`, `write-font-prefix.aye`, `write-font-tail.aye`): canonical order, `normal` left out, ` / ` before the line height.
    - `getComputedStyle().font` (`engine/write-computed-font.aye`, `css/font-prefix-word.aye`; a getter in `prelude.aye`).
    `font-valid` 9/315 -> 315/315, `font-computed` 6/315 -> 315/315, `font-invalid` 16/16, `system-fonts` 28/30, `font-shorthand-subproperties-reset` 12/12. 5726 -> 6441.
  - the shorthand does not serialize when a sub-property set after it cannot be expressed in it: a CSS-wide keyword, a non-initial value of a reset-only longhand, a `font-variant-caps` other than `normal`/`small-caps`, a `font-stretch` that is not a keyword (`css/blocks-font-shorthand.aye`, `engine/font-blocked.aye`, `computed-font-blocked.aye`). `font-shorthand-serialization-prevention` 109/216 -> 213/216. 6441 -> 6546.
  - `font-style` took three keywords only. It is now a layered text property with its own grammar (`css/valid-font-style.aye`, `font-style-value.aye`, `specified-font-style.aye`): `oblique <angle>` from -90deg to 90deg, a `calc()` angle clamped, `oblique 0deg` written `normal`. Two styles with angles interpolate by angle, `normal` as 0deg and `oblique` as 14deg (`animation/mix-font-style.aye`, `oblique-angle.aye`); `italic` stays discrete. `font-stretch` keywords transition as their percentages (`css/stretch-percent.aye`). 6546 -> 6765.
  - an `@font-face` rule had no `style`. `CSSFontFaceRule.style` is a descriptor block (`engine/cssom-descriptors.js`, read through `ak.descriptor`, `engine/ak-descriptor.aye`, `css/specified-descriptor.aye`): descriptors are validated and written canonically by `css/font-face-descriptor.aye`: `font-weight`, `font-stretch`/`font-width` (one descriptor) and `font-style` as one value or a range with `calc()` simplified (`write-descriptor-range.aye`, `write-descriptor-part.aye`, `write-descriptor-math.aye`, `descriptor-number.aye`, `font-face-style.aye`, `all-zero-angles.aye`), `src` as a list whose bad items are dropped (`font-face-src.aye`, `valid-src-item.aye`, `valid-local-src.aye`, `valid-src-format.aye`, `valid-src-tech.aye`, `write-src-item.aye`, `is-function-named.aye`), the metric overrides and `size-adjust`. Other descriptors are kept as written. The rule's `cssText` is written from the block. 6765 -> 7008.
  - `@font-feature-values` and `@font-palette-values` were plain rules of type 0. `CSSFontFeatureValuesRule` (type 14) serializes its value blocks, keeping the declarations that are valid for their block (`featureValuesText` in `cssom-descriptors.js`); `CSSFontPaletteValuesRule` has `name`, `fontFamily`, `basePalette`, `overrideColors` over the same descriptor block (`css/font-palette-descriptor.aye`, `override-colors.aye`). Invalid preludes make the rule invalid (`cssom-syntax.js`), and a rule's leading comments no longer hide its at-keyword (`ruleParts`): every rule of a sheet that followed a comment was read as a style rule. 7008 -> 7318.
  - the `font-synthesis` shorthand (`css/synthesis-shorthand.aye`, `synthesis-words.aye`, `synthesis-slot.aye`, `write-synthesis.aye`, `specified-synthesis.aye`, `write-computed-synthesis.aye`) and `font-width` as an alias of `font-stretch`. 7318 -> 7396.
  - `font-size-adjust` is written without the default metric: `ex-height 0.5` is `0.5` (`css/without-default-metric.aye`, `has-default-metric.aye`). 7396 -> 7469.
- decisions taken without asking (plan defaults):
  - a system font keyword (`caption`, `icon`, ...) is valid and means the initial font; no platform font is looked up.
  - `oblique <angle>` is not parsed inside the `font` shorthand (the longhand takes it).
  - writing to an `@font-face` rule's `style` changes what the rule reports, not the font that was loaded from it.
  - the angle of `font-style` reaches no glyph: text is slanted or not, as before.
