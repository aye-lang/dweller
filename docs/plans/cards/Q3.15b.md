Slice 1 (two causes):
- `document.domain` had a setter that did nothing, so no test could see that a document is sandboxed. `ak.setDocumentDomain` (`engine/ak-set-document-domain.aye`) throws `SecurityError` when the page has the sandboxed `document.domain` flag (`SB_DOCUMENT_DOMAIN`, every sandboxed frame), when its origin is opaque, and when the value is not the host or a registrable suffix of it (`net/registrable-suffix-of.aye`, the spec's "is a registrable domain suffix of or is equal to", with a unit test); otherwise it changes nothing (Dweller does not relax the same-origin check, as an origin-keyed agent cluster). The getter (`ak-document-domain.aye`) is the effective domain: the host of the page that gives the origin (`originPage`, so a srcdoc or blank frame has its creator's), empty for an opaque origin. Passes `popup-from-initial-empty-sandboxed-document`, `sandbox-inherited-from-initiator-frame`, `sandbox-inherited-from-initiator-response` (+3).
- `document.write` did nothing once the parser had ended, and a write to another frame's document went into the caller's parser. Now a write to a frame's document that is not being parsed (by the frame after its load, or by another page) is kept in `Page.opened_doc` (`write-opened.aye`); the next `syncFrames` shows it (`show-written.aye`, `written-page.aye`): a new page of the frame from the written text, with the old page's URL, CSP and sandbox flags, run in the frame's own engine. `runUntilConsole` (the WPT loop) syncs again before it moves the virtual clock when a load handler wrote (`frames-written.aye`). Passes `sandbox-document-open` (2) and keeps `sandbox-document-open-mutation` (which passed before only because the setter never threw) (+3 net of that one).
- test: `tests/browser/sandbox.rs` `sandbox_document_domain_and_written_documents` (`browser/tests/sandbox/document_domain.html`, headless window, `DWELLER_PROCESS` `single` and `site`): passed alone. `aye test browser` 323 passed at the first slice.
