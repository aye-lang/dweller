# Q3.3b: module scripts in CORS mode

- goal: module scripts (`<script type=module>`, static `import`, `import()`, module workers' imports) are always fetched in CORS mode, as HTML's "fetch a single module script" says. Credentials are `same-origin` by default and `include` with `crossorigin=use-credentials`. A failed fetch (network error, failed CORS check, bad status or MIME type) is a load error: an error event at an inserted element, a rejected promise for `import()`. Same-origin graphs keep working. The module map still keys on the URL (and type).
- source: Q3.3's "left" list (module scripts in CORS mode, `crossorigin` on `<script type=module>`; ORB audio/video and range rules).
- design:
  - `js/module-response.aye`: `ModuleLoader` takes the referrer and `net.Credentials`; the default request (the command-line runner) is `Mode.Cors`. Pages set `module_loader` to `engine/page-module-response.aye`, whose initiator is the page (`initiatorOf`), not the importing module: a cross-origin module's same-origin sibling is still cross-origin to the document. Before this card the initiator was the importing module's URL.
  - Credentials: `js.runModuleScript` takes `include` (`crossorigin` is `use-credentials`, `engine/run-module-element.aye`). The JS loader (`lib.aye`) keeps `m.include` on each record and passes it to `fetchModule` (argument 4) for the record's static imports, the background graph and `import()` from that module. `import()` from a classic script or an inline module uses `same-origin`.
  - Fetch failure vs. error to rethrow: a TypeError from `fetchModule` (a failed fetch, status or MIME type, an unsupported import type) goes into the loader's `fetchFailures`. `moduleScript` returns `null` when loading the graph hits one. `runModuleGraph` (`engine/run-module-graph.aye`) then logs `Failed to load module script: URL` and returns false, and `akScriptRun` fires `error` instead of `load`. Parse, resolve and link errors are still reported as uncaught, and the element gets `load`. `runModuleElement` moved out of `script.aye` into its own file and returns that bool.
  - No credentialed no-cors request goes out first for a cross-origin module. The preload scan (`scriptHrefsOf`) skips cross-origin module scripts and `modulepreload` links. The inserted script's background load (`akScriptFetch`) and `import()`'s background load (`moduleLoad`) skip cross-origin modules, so those are fetched on the synchronous path. A new `Interp.module_prefetch` hook (`engine/page-prefetch-modules.aye`) prefetches only the graph's same-origin URLs.
  - Cache: `fetchHttp` reads and fills the HTTP cache for any request that no CORS check applies to (`net/cors-applies.aye`: `corsOrigin` is empty), so a same-origin CORS request (every same-origin module) still uses the prefetched entries. Q3.3 kept the cache for `NoCors` only, and that would have fetched every same-origin module twice.
  - Module workers: their imports ask the page with `FETCH_MODULE` (6). `wkFetch` takes a third argument, and with it the request is `Cors` with `same-origin` credentials. `importScripts` stays no-cors (`FETCH`).
  - ORB is for no-cors requests only, so it does not apply to modules.
  - ORB audio/video sniffing and range rules: not done. `<audio>` and `<video>` fetch nothing in Dweller (`prelude.aye`: the media elements play nothing and have no loader), so no media response goes through `net/`.
- changed goldens:
  - `browser/tests/jsdom/module_scripts.err`: `<script type=module src=module_scripts/absent.mjs>` used to log `Uncaught TypeError: Failed to fetch module`, as an uncaught exception at the window. HTML's "execute the script element" says that a module script with a null result fires `error` at the element and reports no exception. It now logs `[error] Failed to load module script: file://$ROOT/.../absent.mjs`, as a classic script's failed load does. Only this one line changed.
  - New golden: `browser/tests/net/module-cors.txt`. No existing fixture used a cross-origin module without ACAO.
- files: new `browser/engine/{page-module-response,page-prefetch-modules,run-module-element,run-module-graph}.aye`, `browser/js/module-prefetch.aye`, `browser/net/cors-applies.aye`; changed `browser/js/{module-response,modules,interp,lib}.aye`, `browser/js/MODULES.md`, `browser/net/http.aye`, `browser/engine/{script,inserted,window_api,wk-fetch,worker-api}.aye`, `browser/engine/workers/{message,set-up-worker,worker-module-response}.aye`, `browser/engine/workers/worker-page.js`; tests `browser/tests/net/module-cors.{html,txt}`, `browser/tests/net/module-cors/{hit,dep,same,imports-plain,imports-acao}.js`, `browser/tests/server.py` (`/cookie-module?acao&acac`), `browser/tests/jsdom/module_scripts.err`, `tests/browser.rs` (`module_cors`).
- references:
  - spec: https://html.spec.whatwg.org/multipage/webappapis.html#fetch-a-single-module-script (mode `cors`, credentials from the fetch options, null on a bad status or MIME type) and https://html.spec.whatwg.org/multipage/scripting.html#execute-the-script-element (a null result fires `error`).
  - Chromium `third_party/blink/renderer/core/loader/modulescript/module_script_loader.cc` (mode `kCors`, `options_.CredentialsMode()`) and `module_script_fetcher.cc` `WasModuleLoadSuccessful`. Dweller takes CORS mode with the script's credentials mode for every module request, and takes failure on an error, a non-ok status or a non-JavaScript MIME type as a null result, not a thrown error.
  - `services/network/orb/orb_impl.cc`: the media sniffing and range state were read but not ported (no media loads in Dweller).

## Status: done, 2026-11-08

- left:
  - ORB's audio/video sniffing and range-request rules, once `<audio>`/`<video>` load media through `net/`.
  - Cross-origin modules load on the synchronous path (no preload scan, no background load, no prefetch). This changes when the cache keys on mode and credentials (the Fetch cache key), and the loader can then keep CORS responses.
  - Parser-inserted scripts, classic and module, fire no `load`/`error` events (as before). Only inserted module scripts get the error event.
  - `import()` from an inline module, or from a classic script with `crossorigin=use-credentials`, uses `same-origin` credentials, not the script's. The `credentials` option of `new Worker(..., {type: 'module'})` is ignored (always `same-origin`).
  - `<link rel=preload>` (not fetched by Dweller), and the WPT areas (`html/semantics/scripting-1/the-script-element/module`, `fetch/orb`), are not done.
