# Q4.2: shadow trees in subtree restyle

## Status: in progress, 2026-11-16 (slice 1 of 2 done)

- goal: a change beside, above or under a shadow host restyles what it reaches, as in a page without shadow trees. Before (`liftOutOfShadows`, P4.75k): a restyle root that was an inclusive ancestor of any host was made a full root (its whole subtree, shadow trees included), and a root under a host (a slotted child, or anything below one) was lifted to the topmost host as a full root. With one shadow tree in the page, a class on `body` restyled the document.

## Slice 1 (done): roots in the document tree stay as they are

- design (Blink: a tree scope's rules reach outside it only through `:host()`, `:host-context()` and `::slotted()`; `core/css/style_engine.cc`, `core/css/resolver/scoped_style_resolver.cc`):
  - `liftOutOfShadows` lifts a root only when it is inside a shadow tree (to the topmost host, a full root, as before). A root in the document tree keeps its place: full when it is itself a host (`:host(.x) .y` in the tree's sheet), else as `restyleRoots` gave it. A slotted child's own change is its own restyle: `::slotted()` has no combinator after it.
  - the old lifting stays whole for a sheet set where it is needed: a shadow tree's sheet with `:has()` (`RestyleDeps.scoped_has`: `:host(:has(.x))` sees the host's light descendants), and roots above a host when a shadow sheet uses `:host-context()` (`RestyleDeps.host_context`).
  - a shallow root pushes changed values into shadow trees: `restyleBelow` walks shadow-including (`dom.shadowIncludingFollowing`, the order of `computeStyles`: a host, its shadow tree, then its children, so a slot is styled before what is assigned to it), and a shallow root or pushed element that is a host with changed values styles all below it. Before, both walked light children only, which is why roots above a host could not be shallow.
  - `slot` joins `ALWAYS_DEEP`: an element assigned to another slot inherits from it, so it and its subtree are styled again.
- files: `browser/engine/lift-out-of-shadows.aye` (rewritten, takes the deps), new `browser/css/scoped-looks-at.aye`; wiring in `css/invalidation.aye` (2 fields, 2 lines in `build`, `slot`), `css/cascade.aye` (`restyleBelow`, the shallow walk: 4 lines), `engine/geometry.aye` (1 line). Fixture `browser/tests/jsdom/shadow_restyle.html` (`.tree`), test `jsdom_shadow_restyle_keeps_roots_shallow`.

## Slice 2 (left): shallow roots inside a shadow tree stay there

Not started. What it needs, found while doing slice 1:

- `RestyleDeps.build` reads only the document's sheet for `deep`, the key sets and `:has()`: the shadow trees' sheets (`Sheet.scoped`) must be read too (union: `HasUse.keys` are indices into one sheet's `simples`, so `:has()` in a shadow sheet keeps the lifting).
- `simpleKeys` answers "not known" for `:host()`, `:host-context()`, `::slotted()`, `::part()` and `:defined`, which sets `deep_any` for `:host([disabled]) button`. In a compound that is not the subject, `:host()` and `:host-context()` name an element at or above the tree's boundary: a change there is already a full root (the host) or the `host_context` rule, so they add no key for changes inside the tree.
- a root inside a tree can stay only while it is shallow and styles nothing that a slot passes on: a `slot` whose values change (its assigned nodes are the host's children, not below it), a custom property or container change (`restyleBelow`), a children change, or a full root go to the topmost host as now (a slot passed through to an inner host can carry the change outward, so the tree's own host is not enough).
- github has about 41 shadow roots (P4.75k); whether its restyle roots are inside them or around them needs the archive: Mac queue.
