# P10.51b: CSS animations are visible in the window

- goal: a page with only CSS (`.spinner { animation: spin 1s linear infinite }`) animates from load in the window and in screenshots, without a script reading the element (P10.51's "left": discovery, painting); frames only while an animation runs.
- design:
  - Discovery: after each task (`afterTask` → `runAnimationHook`, once the load event fired, when the layout version or geometry moved), the prelude's hook `cssAnimations.discover` asks `ak.animatedElements()` for the elements whose layout-computed `animation-name` is not `none` (none when the styling has no `@keyframes`), adds the tracked ones, and calls `sync` only for those whose `animation-*`/`display` values changed (`seen`): syncing every element each task re-armed its event timer and never went idle. `ak.animatedElements` uses the page's styling, or computes one only when the document links no sheet (`stylingWithoutFetch`): computing it during a load fetched the linked sheets synchronously (`window_history_steps` waited 300 ms).
  - Painting: animated values already reach the inline style through P10.47's fill machinery, so the existing incremental paths apply: a transform/opacity change composites (`keepRestyled`, `paint_boxes`), others relayout the dirty subtree (`relayoutDirty`). The running elements resync on the rAF-flagged 16 ms timer (vsync in the window), which stops when nothing runs.
  - Interpolation fixes found by the screenshot: a unitless `0` mixes with a length (`translateX(0)` → `translateX(200px)`, `unitEnd` in `mixNumbers`); `transform: none` against a function list becomes that list's identity (`transformIdentity`: numbers 0, `scale*` 1), so `@keyframes spin { to { transform: rotate(360deg) } }` interpolates instead of flipping at 50%.
- files: `browser/engine/` (`ak-animated-elements.aye`, `ak-set-animation-hook.aye`, `run-animation-hook.aye`, `styling-without-fetch.aye`; wiring in `script.aye`, `window_api.aye`, `prelude.aye`, `css-animations.js`), `browser/animation/` (`transform-identity.aye`, `unit-end.aye`; wiring in `interpolate-text.aye`, `mix-numbers.aye`), tests: `browser/tests/paint/css_animation.html` (+ golden), `browser/tests/ui/css_spinner.html`, `tests/browser.rs` (`window_css_animation`).
- reference: blink `core/animation/css/css_animations.cc` (CalculateAnimationUpdate during style recalc), `core/animation/document_animations.cc`; algorithm only. https://drafts.csswg.org/css-animations-1/#animations, https://drafts.csswg.org/css-transforms-1/#interpolation-of-transforms.
- verify: `cargo test --release --test browser -- window_ webgl_screenshot` and `-- screenshot_ paint scroll style_fixtures layout_fixtures jsdom_fixtures` (ANGLE fetched); `check_taste.py`, `check_layers.py` → 0.
- status: done for CSS animations 2026-10-17.
  - `css_animation.html` (screenshot, paused at a negative delay): box at translateX(100px), opacity 0.5; bar at 75% width and colour.
  - `window_css_animation`: a 2 × 300 ms move+fade with no script: 32 composited frames, each damaging ~1848 px (the box's old+new rect, not the 104000 px window), `DWELLER_DAMAGE_CHECK` clean, no rAF and zero damage after it ended (37 animation frames, then idle).
  - tests: `window_` 55/56 + `webgl_screenshot` ok (only `window_spaces` `takeover.jsonl`, the known race fixed by PR #182); `screenshot_ paint scroll style_fixtures layout_fixtures jsdom_fixtures` 15/15. One golden added, none changed.
- left:
  - transitions are still not painted (their values live in `animation.Transitions` snapshots for `getComputedStyle` only) and start only for elements a script read: needs before-change styles kept by restyle for elements with `transition-*`.
  - a page with linked sheets is discovered at the first task after the window laid it out (the page's styling); a static page with linked sheets and no later task starts only when a script reads it. The window should call the hook after its own layout.
  - cost: ~7 ms of `ui_raf` per frame for one box (sync re-reads 9 computed values and `_valuesAt` resolves each keyframe through `getComputedStyle`); cache the resolved keyframes per animation.
  - an infinite animation on a small page restyles all every `RESTYLE_ROUNDS` frames (a `layout_full` every ~10 frames).
  - the screenshot painter does not draw `rotate()`/`scale()` (static ones neither).
