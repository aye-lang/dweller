# P10.50b: uievents and real input

- goal: P10.50's "left" list, real-site input feel first: pointer buttons (auxclick, contextmenu, dblclick, back/forward, `buttons` during a move, click as a PointerEvent), focus order and `FocusEvent.relatedTarget`, keyboard default actions, wheel and scrollend; `uievents` over its 70% threshold.
- cause groups (from `/tmp/wpt-base`, the P10.50 build):
  - `--events` and the testdriver knew only the left button: `pointerDown({button})` was sent as a left press, so no `auxclick`, `contextmenu`, back/forward `mouseup` or non-zero `button`; no click count, so no `dblclick` and `detail` was always 1 (`auxclick_event` 3, `contextmenu_event`, `dblclick_event_mouse`, `dblclick_event_on_text_control_inputs`, `mouse_buttons_back_forward`, `mouseevent_move_button`);
  - `click` (from input and from `element.click()`) was a `MouseEvent`, not a `PointerEvent` (`click-event.htm`);
  - a press never moved the focus (focus is `mousedown`'s default action), and `focus()`/`blur()` fired `focus`/`blur` with no `relatedTarget` (`focus.html`, `focus-contained`, `click-order`, `blur-relatedTarget`, dom/events `no-focus-events-at-clicking-editable-content-in-link` 2).
- design: the testdriver vendor sends `click:X,Y,BUTTON` / `release:X,Y,BUTTON` (`left middle right back forward`, the WebDriver button order); the window's `--events` parser maps `back`/`forward` to `SDL_BUTTON_X1/X2`. `feed-pointer.aye` keeps the pressed `buttons` mask (`pointer-button.aye`: DOM button index and bit), the click count (`next-click-count.aye`: same button within 500 ms of the page clock, as Blink's mouse_event_manager) and passes `button\nbuttons\nmods\ncount` to `hostEvent`; after a right `mousedown` it fires `contextmenu` (Linux order); on release `feed-click.aye` fires `click` (+ activation) and `dblclick` on the second click for the primary button, else `auxclick`. `click`/`auxclick`/`dblclick` go to the press/release common ancestor (`press-release-target.aye`). `hostEvent` builds `click`, `auxclick`, `contextmenu` as `PointerEvent` (pointerId 1, `mouse`) with `detail` = click count; `element.click()` builds a `PointerEvent` with pointerId -1, detail 0. Focus: the prelude's `moveFocus(next)` sets the focus, then fires `blur`, `focusout` at the old element and `focus`, `focusin` at the new one, each with the other as `relatedTarget`; `focus()`/`blur()` use it, and a not-canceled `mousedown` dispatches `__focus`, which moves the focus to the nearest click-focusable inclusive ancestor (or clears it). The window does the same through `pointerEvent`: `__focus` after `mousedown`, `contextmenu` on a right press, `auxclick` on a non-left release, `dblclick` when SDL reports `clicks == 2`; it now names X1/X2 as buttons 3/4 (bits 8/16).
- files: `browser/engine/` (`feed-pointer.aye`, new `feed-click.aye`, `next-click-count.aye`, `pointer-button.aye`; `press-release-target.aye`, `prelude.aye`, `dom-events.js`), `browser/ui/` (`window.aye`, `script.aye`, `sdl.aye`), `browser/tools/wpt/testdriver-vendor.js`.
- reference: `third_party/blink/renderer/core/input/mouse_event_manager.cc` (click count, `auxclick`, focus on mousedown), `core/page/focus_controller.cc` (blur/focusout then focus/focusin with relatedTarget); algorithm only (LGPL).
