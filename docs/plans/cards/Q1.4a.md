# Q1.4a: renderer window tests wait for the renderer's frame, not a frame count

- flaky test: `window_renderer_input` failed on Ubuntu CI (PR #300, green on the re-run): `inner scroller: no change in /tmp/dweller-out-8443/renderer_input_tab.png`; the PNG through the renderer (`DWELLER_PROCESS=tab`) was still the frame before the input.
- cause (three ways the PNG could be taken before the input's frame):
  - the runs used `--frames 60`: the window saves its PNG after 60 drawn frames whether or not the script finished, so on a slow runner the renderer's start, first frame, input and frame for it did not all fit in 60 frames (the practice in `docs/practices/browser.md`: tests must not depend on how many frames fit in wall time);
  - `input_ack` is documented as "every input up to `seq` handled and its frame sent" (Q2.3a), but `answerAll` sent it after `paintFrame` even when the paint was skipped because neither shared buffer was free (the window still held one and the other was in flight), so `renderer:input` could pass before the frame for that input; the title and URL report (`reportPage`) also came after the ack;
  - a wheel is coalesced and sent in `flushWheel` at the end of `resumeScript`, so `wheel:-3 renderer:input` checked the ack before the wheel was sent and passed at once.
- fix:
  - `browser/renderer/ack-input.aye`: the ack waits while the page has a paint due (`r.due`); `answerAll` acks after the next paint, when the window's `frame_ack` frees a buffer. `browser/renderer/answer-all.aye`: `reportPage` before `ackInput`.
  - `browser/ui/script.aye`: `renderer:input` first sends a pending coalesced wheel (`flushWheel`).
  - `tests/browser.rs`: `window_renderer_input`, `window_renderer_focus` and `window_renderer_input_actions` run `--frames 1000 --until-idle` (the run ends three settled iterations after the script's last wait, 1000 is only a cap); the focus test's `window:blur` case waits `renderer:next` for the blur's frame. What the tests check is unchanged. `window_renderer_lifecycle` and `window_renderer_frames` take no PNG after input and keep `--frames 300`; there is no `window_renderer_status`, `_agent` or `_net`.
- files: `browser/renderer/{ack-input,answer-all}.aye`, `browser/ui/script.aye`, `tests/browser.rs`, `docs/plans/cards/Q1.4a.md` (new).
- verify:
  - `python3 browser/tools/check_layers.py`, `python3 browser/tools/check_taste.py`, `aye check browser`: exit 0.
  - under load, as Q1.3: 6 `yes > /dev/null` hogs inside one `scripts/capped.sh sh -c`, then `cargo test --release --test browser -- window_renderer_` 5 times: not run yet (the run was stopped while it waited in the `capped.sh` queue); CI runs the five tests.
