# Q1.9b: session restore for DWELLER_PROCESS=tab

- goal: with `DWELLER_PROCESS=tab` the window saves its tabs and restores them after a quit or a SIGKILL, with each tab's back/forward entries intact. One encode/decode path for both modes.
- design: Q2.6a made the tab's `engine.SessionHistory` in the window process the only history of the tab (the renderer holds a mirror), so `saveTabs` already reads the browser's history model in both modes; the only thing keeping the flag out were two guards (`ui.tab_processes`) in `ui/save-tabs.aye` and `ui/restore-tabs.aye`. Both are removed. On restore the entries are pushed into the slot's history from `decodeSession` and the slot is `unloaded`; showing the tab calls `ui.reload()`, which in tab mode goes through `queueNavigate`: it sends `session_history` for the current entry and `navigate`, so the tab's renderer is spawned and committed on the current entry, and a later back or forward is a browser decision (`go_to_entry`) as usual. The tab's title in the file is `tp.title` when the tab has a renderer (`slotTitle`).
- references: `components/sessions/core/session_service_commands.cc` (as Q1.9: the navigation entries are the browser's `NavigationController` entries, restored by `RestoreFromSession`, each tab then navigates to its selected entry). Dweller takes: the saved state is read from the browser's controller, not from the renderer.
- files: `browser/ui/save-tabs.aye`, `browser/ui/restore-tabs.aye` (guards removed); `tests/browser/history.rs` (`session_run`/`session_restored` take an env; `session_restore_after_kill` helper; new `window_session_restore_after_kill_tab`).
