# Q4.9: a shape cache by word

- goal: layout does not shape the same word in the same font again. Q4.1: on zol, `shapeText` was 3821 of the 7784 `layOut` samples (~2300 ms of the p95 frame), and every layout shaped every text piece again through HarfBuzz or FreeType, with no cache.
- cause: `System.width` (the `Measurer` that layout calls) called `shapeText` on every call.
- design:
  - Layout already measures by word: `inline.aye` cuts text into pieces at spaces, at line-break opportunities between CJK characters, at hyphens and at bidi changes, and measures each piece (a run of spaces is a piece of its own). So `System.width` caches the width of the exact string it is asked for. A cached width is the value `shapeText` returned for that string, so it is equal by construction for every script, with no splitting inside `width` and no kerning or ligature across a space to check.
  - Key: the whole `Font` (size, weight, bold, italic, mono, serif, rtl, letter- and word-spacing, `font-family` list), then the text. `WidthCache` keeps one `StrMap(f64)` per font (`FontWidths`), found by comparing with the last font used, else by a scan of the fonts. A first version built one string key (font fields plus text) per call: building and hashing it cost as much as the shaping it saved (zol: 995 + ~1800 of 4487 samples).
  - Bound: 32768 entries for all fonts (Blink `FrameShapeCache` `kMaximumShapeCacheEntries`); when it is full the whole cache is cleared. Strings over 64 bytes are not cached (Blink's old `ShapeCache` cached only short words). Cleared when a web font is added (`addWebFont`, next to `clearChains`).
  - `Fixed` (layout tests) is not cached; paint (`glyphs.aye`) still shapes its runs for glyphs.
- files: `browser/font/width-cache.aye`, `font-widths.aye`, `widths-of.aye`, `put-width.aye`, `clear-width-cache.aye`, `cached-width.aye`, `width-cache_test.aye` (new); `browser/font/freetype.aye` (field, init, deinit, `width`, `addWebFont`).
- verify: `aye test browser` 159/159 (the cache tests: cached widths equal `shapeText` for ten strings, Latin, CJK, a combining mark, Arabic, Hebrew and one with a space, in a sans 16 px font and a bold italic serif 13.5 px font with letter-spacing; 32769 entries leave one); `aye check browser` 0; `cargo test --release --test browser -- layout font text dump window_`: 70 passed, no golden changed; the 3 failures are `webgl_context`, `webgl_textures`, `window_webgl` ("ANGLE not found", ANGLE is not fetched in this worktree); `check_taste.py` 0.
