# P10.47: property interpolation and element.animate

- goal: the `css/support/interpolation-testcommon.js` tests (every `*-interpolation.html` under the CSS `animation(s)/` directories) drive each case through CSS Transitions, Transitions with `transition-behavior: allow-discrete`, CSS Animations and Web Animations, then read `getComputedStyle` at progress -0.3 … 1.5. (1) A typed interpolation core over computed values, (2) the Web Animations API the harness needs (`Element.animate`, `Animation.pause`/`currentTime`, keyframe offsets and easing, the computed style at the current time), (3) CSS Animations only after (1) and (2).
- cause: four separate faults. (a) A transition took its before-change style only from an element whose `transition-*` already gave a duration when `getComputedStyle` read it; the harness reads the element *before* setting `transition-*`, so no transition started. (b) `css.listItem`/`listLength` split on every `, `, also inside `cubic-bezier(…)`/`steps(…)`, so every `transition-timing-function` that is not a keyword became linear (`createEasing` maps each progress to a bezier or `steps(1, …)`). (c) A class change followed by `offsetWidth` restyled the page but not the snapshots, so `properties-value-*` (P10.33's "left") saw no change. (d) `Element.animate` kept time but applied keyframe values only outside the active interval (fills), with no interpolation and no effect easing.
- design:
  - Transitions: `styleChange` keeps a snapshot of every element `getComputedStyle` reads (`Snapshot.wanted` says whether its `transition-*` ask for transitions; only wanted ones keep the frame loop running, `anyWanted`). `engine.geometry` wraps the page layout (`layoutGeometry`) and, when the layout version moved, restyles the snapshotted elements (`restyleTransitioning`), so a style change seen only by layout starts transitions. `listItem` tracks parenthesis depth.
  - Interpolation core (`browser/animation/`): `interpolateText(name, from, to, p)` parses both computed values for the property (`parsedValue`); single lengths, percentages, numbers and colours go through the typed `interpolate` (premultiplied sRGB: P10.44's colour spaces are not on main, so no oklab yet); anything else whose two serializations have the same shape mixes number by number (`mixNumbers`, `numberEnd`): lists of lengths, positions, shadows and transform lists with the same functions. Integer properties round (`isInteger`), and results are clamped to the property's range (`clampToRange`: `*opacity` to [0, 1], lengths to ≥ 0 when the property's parser rejects `-1px`/`-1`, `nonNegative`). No common shape: discrete, flipping at 0.5 (Web Animations) — the caller decides. Transitions' current value is clamped the same way.
  - Web Animations (`engine/animation-values.js`, wired by two lines at the end of the prelude's Web Animations block): `_progress` applies the effect's `easing` (`ak.ease` → `animation.easeText`); `KeyframeEffect._valuesAt` builds property-specific keyframes, adds neutral keyframes at 0/1 (the underlying value: the inline value before the animation), picks the interval, applies the keyframe easing, resolves both ends in the element's context (inline value set, `getComputedStyle` read, restored) and calls `ak.interpolate`; the fill machinery now applies in the active phase too, so a paused animation's `currentTime` shows in the computed style.
  - CSS Animations: not done. There are no `animation-*` longhands or `@keyframes` rules in the cascade, and this step may not add properties (property ids are being reworked); the `CSS Animations` quarter of every interpolation file still fails.
- files: `browser/animation/` (`interpolate-text.aye`, `parsed-value.aye`, `mix-numbers.aye`, `number-end.aye`, `is-integer.aye`, `clamp-to-range.aye`, `non-negative.aye`, `ease-text.aye`, `any-wanted.aye`; wiring in `style-change.aye`, `snapshot.aye`, `transitions.aye`, `current-value.aye`, `value-of-parts.aye`), `browser/css/` (`list-item.aye`, `list-length.aye`), `browser/engine/` (`ak-interpolate.aye`, `ak-ease.aye`, `animation-values.js`, `animation-values-prelude.aye`, `geometry-fn.aye` (the wrapper `geometry`; `geometry.aye` is the old file's name); wiring in `geometry.aye`, `window_api.aye`, `script.aye`, `prelude.aye`).
- references: blink `third_party/blink/renderer/core/animation/` (`css_interpolation_types_map.cc`, `interpolable_value.cc`, `css_length_interpolation_type.cc`, `css_color_interpolation_type.cc`, `element_animation.cc`, `keyframe_effect.cc`), algorithm only. Specs: https://drafts.csswg.org/web-animations-1/ (effect value of a keyframe effect, transformed progress), https://drafts.csswg.org/css-values-4/#combining-values, https://drafts.csswg.org/css-transitions-1/#starting.
