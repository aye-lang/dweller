# Q2.13: process limits (code part): a cap on renderers, reuse over it, hidden child frames throttled

## Status: done for the code part, 2026-11-19 (the budget waits for the Mac)

- goal: the code part of Q2.13. A soft cap on renderer processes with Chromium's formula; over the cap a new tab of a site that already has a renderer joins it; a cross-site frame out of its embedder's view is throttled. Memory per tab measured here goes into this card; the Chromium comparison and the M1 budget go to the Mac queue.

Done (tested):
- the cap and reuse, with `DWELLER_PROCESS=site`: `ui/max-renderers.aye` (`DWELLER_MAX_RENDERERS=N`, else half the physical RAM divided by 48 MB a process, clamped to 3..82, as `GetMaxRendererProcessCount`; 48 MB is a renderer's resident size measured below), `ui/renderer-count.aye` (live renderers counted by pid), `ui/reused-process.aye` (at the cap, a new tab whose URL's site has a live tab renderer of the same partition is attached to it with `attachTabProcess` and context 0; else a new renderer, the cap is soft), called from `ui/poll-tab-slot.aye`. The renderer accepts `attach_tab` with context 0 as a tab with a context of its own (`renderer/attachable.aye`).
- `window_renderer_limits::window_renderer_limits_cap` passed once (`cargo test --release --test browser -- window_renderer_limits`): with `DWELLER_MAX_RENDERERS=1` a second same-site tab has the first tab's pid and loads (`title Child 127.0.0.1?two`); a `localhost` tab gets another pid; without the variable two same-site tabs have two pids.

Memory per tab on this machine (2026-11-19, Linux x86_64 cloud container, safe build, `--font fixed`, 1000x800, dummy video driver, a fresh profile and `DWELLER_RESTORE=0` per run, 5 s after start, from `/proc/PID/smaps_rollup`, in MB):

|---|---|---|---|---|
| `browser/tests/ui/form.html` | 62.3 / 64.2 | 31.7 / 41.7 | 37.2 / 47.1 | 68.9 |

- `tab` mode gives the same numbers as `site` within 0.5 MB.
- so one tab costs about 7 MB more with a renderer than in one process, and a renderer is about 37 to 38 MB proportional, 47 to 48 MB resident, for a small page. In runs where the profile restored earlier tabs (2 to 10 renderers of such pages at once), each renderer was 29 to 34 MB proportional: about 30 MB for each further tab.
- these are small test pages; a real site's renderer is larger by its DOM, images and script heap, which this machine cannot load (no site archives). The cap's 48 MB is therefore a floor for the cost and gives a high cap (16 GB: 82, the clamp).
