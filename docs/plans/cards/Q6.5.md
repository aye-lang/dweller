# Q6.5: WPT `css/css-fonts` to its floor

- goal: the area reaches its floor of 50 plus 2 points (32.7 in the table; 2764/8356, 33.1%, measured at the start of this card).
- cause: one. Only four font longhands existed (`font-size`, `font-weight`, `font-style`, `font-family`). 2212 of the failing subtests said "'from' value should be supported": every interpolation, composition and discrete test of a missing property, and their parsing files.
- design:
  - eighteen longhands appended to `PROPERTIES` (ids 192 to 209 after `object-position`; all inherited):
    - keywords (`PKind.Keywords`): `font-kerning`, `font-optical-sizing`, `font-synthesis-weight`, `-style` (with `oblique-only`), `-small-caps`, `-position`, `font-variant-caps`, `font-variant-position`, `font-variant-emoji`.
    - with a grammar (`PKind.Layers`, kept as canonical text, so the existing text interpolation and `allow-discrete` apply): `font-stretch`, `font-size-adjust`, `font-variation-settings`, `font-feature-settings`, `font-variant-ligatures`, `font-variant-numeric`, `font-variant-east-asian`, `font-variant-alternates`, `font-palette`.
  - validation hangs on the layered-value hook (`hasLayerGrammar`, `validLayer`): `valid-font-layer.aye` dispatches to `valid-size-adjust.aye` (`none`, `from-font`, a number, a metric with either), `valid-font-setting.aye` (a 4-character string with a number, or `on`/`off`/an integer for features), `valid-keyword-groups.aye` with `font-variant-groups.aye` and `keyword-group.aye` (at most one keyword of each group, `normal`/`none` alone), `valid-alternates.aye` with `alternate-index.aye`, `non-negative-percent.aye`; `font-list-allowed.aye` rejects a comma list except for the two settings properties.
  - computed `font-stretch` is a percentage (`write-font-stretch.aye`, from `writeComputed`).
- what this is not: the properties are parsed, cascaded, inherited, serialized and animated. Font matching, shaping and synthesis do not read them: `font-feature-settings`, `font-variation-settings`, `font-stretch`, `font-kerning` and the variants change no glyph. So the telemetry of unsupported CSS no longer lists them as dropped; `browser/unit_tests.aye` ("telemetry: supported and unsupported css properties") expected `font-feature-settings` to be unknown and now uses `font-language-override`. This is a changed expectation, not a loosened test: say so at the merge if the telemetry list is read as "what rendering lacks".
- references: https://drafts.csswg.org/css-fonts-4/ (#font-rend-props, #font-stretch-prop, #font-feature-settings-prop, #font-variant-props, #font-variant-alternates-prop), https://drafts.csswg.org/css-fonts-5/#font-size-adjust-prop . No Chromium source was read.
- files: new `browser/css/{valid-font-layer,valid-size-adjust,valid-font-setting,font-variant-groups,valid-keyword-groups,keyword-group,valid-alternates,alternate-index,non-negative-percent,font-list-allowed,write-font-stretch}.aye`; changed `browser/css/{css,property-ids,valid-layers,valid-layer,write-computed}.aye`, `browser/unit_tests.aye`, `browser/tools/conformance/css_css-fonts.json`.
- shared tables: eighteen CSS properties appended (ids 192 to 209; `NPROPS` 192 -> 210, with Q6.7's `object-position` at 191). The integrator renumbers at the merge. No IPC kind, no host tag.
- verify (2026-11-16, WPT `e58225abb9`, proxy variables unset):
