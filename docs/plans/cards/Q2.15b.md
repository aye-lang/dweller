# Q2.15b: `blob:` documents have a site

- goal: readiness list for Q2.14, "Security (X1)", second bullet [Q2.7]. `writeSite` gave a `blob:` URL no site, so a commit at `blob:https://other.example/...` passed every site-lock check (`inSiteLock`: a siteless URL passes), and the storage of every `blob:` document of every site was one area, `blob://`. A `blob:` URL now has the site of its inner origin, as in Chromium and in process-model §3.
- design:
  - `ui/write-site.aye`: a URL whose parsed scheme is `blob` has the site of the rest of its serialization (`blob:https://www.a.example:8443/ID` → `https://a.example`; `blob:null/ID` → none). The check is on the parsed scheme, so `BLOB:` is the same. Every user of `writeSite` follows: `inSiteLock` (commit, cookies, storage, `post_message` origins), `takesSwap` and the speculative renderer (a `blob:` navigation belongs to its inner site's process), `frameLeaves`.
  - `ui/child-cross-site.aye`: a remote frame's URL must itself be http(s); a `blob:` URL of another site is not a frame a renderer may name in `subframes` (its site alone would now pass).
  - `engine/storage-origin.aye`: the storage area of a `blob:` document is its inner origin's (URL Standard, origin of a blob URL), not `blob://`.
  - test hook `DWELLER_TEST_EVIL=blob` (`renderer/load.aye`, with `DWELLER_TEST=1`): the renderer answers a navigation to a `blob:` URL with `loaded` at that URL without asking the browser for the document.
- decision: Dweller cannot show a `blob:` document yet in any mode (the blob store is the creating page's script; a navigation to a `blob:` URL ends in "Cannot load page"). That is a feature, not this card: here the browser's checks stop a renderer from claiming such a document for another site.
- Chromium read: `content/browser/site_info.cc` (`GetSiteForURLInternal`: "If the url has a blob scheme, use its inner origin"), `content/browser/child_process_security_policy_impl.cc` (`CanCommitURL` for `blob:` and `filesystem:` checks the inner origin).
- files: `browser/ui/{write-site,child-cross-site}.aye`, new `browser/ui/write-site_test.aye`; `browser/engine/storage-origin.aye`, new `browser/engine/storage-origin_test.aye`; `browser/renderer/load.aye`; new `browser/tests/ui/blob-away.html`; `tests/browser/window_renderer_oopif_site.rs`.
- verify (2026-11-16, Linux x86_64):
  - `cargo test --release --test browser -- window_renderer_oopif_site aye_unit_tests window_renderer_oopif_process window_renderer_storage window_renderer::window_renderer_lifecycle`: 6 passed, 0 failed.
    - `window_renderer_oopif_site_blob`, with `DWELLER_PROCESS=site`: `blob-away.html` on `127.0.0.1` sets `location` to `blob:http://localhost:PORT/ID`. Honest renderer: `url blob:http://localhost:...`, `renderer PID title Cannot load page`, lock `http://127.0.0.1`, empty stderr. `DWELLER_TEST_EVIL=blob`: `renderer PID gone commit outside site lock`, stderr `error: bad message: commit outside site lock PID`, and the shown URL stays the page's. Before the change the forged commit passed (a siteless URL).
    - `aye_unit_tests`: new `write-site_test.aye` (http, `blob:` with a subdomain and port, `BLOB:`, `blob:null`, `data:`, `file:`) and `storage-origin_test.aye` (`blob:http://a.example:8000/ID` → `http://a.example:8000`).
  - `python3 browser/tools/check_taste.py`, `check_layers.py`, `gen_property_ids.py --check`, `aye check browser`: exit 0.
