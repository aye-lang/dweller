# Q3.10b: the WPT runner waits in real time while another browsing context is live

- goal: `dweller wpt` ran the opener on the virtual clock (`runUntilConsole` jumps from timer to timer) while a popup polled the `common/dispatcher` long-poll server; the first message got through and the second round trip never answered, so 72 of the 116 `html/cross-origin-opener-policy` files ended in TIMEOUT (Q3.10). Single-context tests stay on the virtual clock.
- finding (how the popup's loop is driven): in `dweller wpt` the popup is loaded and its timers run by `pumpContexts` (in memory, no window), which calls `runDueTimers(popup)` after every opener task. The popup's page has its own virtual clock that moves only with the steps it ran, so a timer of 10 to 100 ms (`randomDelay` in `dispatcher.js`, between two `not ready` polls) was never due: the popup's `receive` loop stopped after its first poll round. The opener's fetches are not the problem: on the virtual clock a fetch task blocks in `runTimer` until the load ends.
- rule: a context is live when it owns a tab with a loaded page (any context the test opened that has not closed: `window.open`, a link with `target`, a context the popup opened in turn). Idle pages and iframes do not count (their loads are the opener's own tasks). While any context is live, `runUntilConsole` (`wait-live.aye`) does not jump: it runs the opener's timers that are due now; when none is due it sleeps 2 ms of real time, moves the opener's clock forward by the real time that passed (`setPageClock`) and moves the clock of every live context to the same instant (`syncContextClocks`, `live-contexts.aye`), then `pumpContexts` runs what became due in the popups. The wait is bounded by the same `--timeout` (the clock is now real time, so it reaches `end`); it does not count against `MAX_TASKS`. When the last context closes, the loop goes back to the jump. The window, `dump` and the agent do not call `runUntilConsole`.
- why not just share the clock and keep jumping: a jump gives the poll timers no real time for the server state they wait for (the stash entry another context posts, a pending request of the popup's own); with real time a timer that is due after 50 ms is run after 50 ms.
- files: new `browser/engine/{live-contexts,wait-live}.aye`; changed `browser/engine/script.aye` (`runUntilConsole`), `browser/tools/wpt_areas.json` (threshold of the area only), `browser/tools/conformance/{history.csv,html_cross-origin-opener-policy.json}`, `docs/conformance.md` (row of the area only).
