# Q1.4b: the three tests flaky under load in the wave of 2026-11-16

- flaky tests (`docs/plans/waves/2026-11-16.md`, "State at the close"; each passed alone): `websocket::websocket_echo_in_renderers`, `media_element::media_element_sound`, `window_renderer_oopif_input::window_renderer_oopif_input_tab`.
- method: each page run directly (`target/dweller`, the test's arguments and events, the test server of `tests/browser.rs`) 20 times with 4 busy loops (`sh -c 'while :; do :; done'`) beside it on a 4-core machine, with `main`'s build (5530df87) and with this card's.
- cause, one for all three: `--until-idle` ends a run after three loop iterations in which the renderer is settled, and the browser read that from the renderer's last `settled`. Between the browser handing a renderer work (the media resource's data, a socket's message, the focus that Tab moves into a cross-site frame) and the renderer's next `settled`, the browser took the old 1 as true; and a frame's renderer never said `settled` at all, so `--until-idle` did not wait for work a frame had. Q2.14h row 31 has the change: the browser counts a renderer as not settled from the moment it sends it bytes or has bytes queued for it, a renderer says `settled` after every batch of messages it handled, frames say it too, and `--until-idle` waits for every frame's renderer.
- measured (runs that failed of 20, under the load above):
