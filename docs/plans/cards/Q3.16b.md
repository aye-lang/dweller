# Q3.16b: the `javascript:` URL gaps of Q3.16, with renderers

- goal: in site mode (the default), the `javascript:` URL cases Q3.16 left (its Left list) work as with one process:
  - (a) a top-level page that sets its own `location` to a `javascript:` URL whose result is a string shows that string as its new document; the browser process commits the new document;
  - (b) `javascript:` URLs of links with a target (another frame or tab) and of `window.open` into a frame's name run in the target, with Chromium's same-origin rule (`LocalFrame::CanNavigate`, `third_party/blink/renderer/core/frame/local_frame.cc`: a `javascript:` URL needs the source's origin to access the target's, else the console error "The frame attempting navigation must be same-origin with the target if navigating to a javascript: url").
- not done, by decision:
  - a `javascript:` URL typed into the address bar: Chromium does not run it either, and it is safer.
  - a frame's written document showing at the renderer's next layout: as `document.write` into a frame does; no site is known to break.
  - `sandbox-new-execution-context` and `sandbox-navigation-timing.tentative` (they need replaced pages kept alive): `html/browsers/sandboxing` is already at its target.

## Slice (a), as built

- IPC: R→B `written_document{title, url}` (222, the next number after 221 `host_state`; `ipc/message.aye`, `decode.aye`, `put-payload.aye`, `from-renderer.aye`, `written-document_test.aye`).
- renderer: after a batch (`reportPage`), `showWrittenDocument` (`renderer/show-written-document.aye`) takes the top-level page's `opened_doc` (the string that `runQueuedJavascriptUrl` kept) and makes the new page with `engine.ownJavascriptPage` (`engine/own-javascript-page.aye`: `writtenPage`, the old page's sandbox flags and creator, the renderer's shared history with the new document at the current entry, the renderer's context, `runDocument`). It drops the old page, adopts the new one and sends `written_document`. A frame's renderer (`embedded`) does not.
- browser: `rendererSentNavigation` checks the frame and that the URL is the committed one (else `bad written_document`, the renderer is ended). While a navigation is in flight it ignores the message. Otherwise `commitWritten` (`ui/commit-written.aye`; chromium: `NavigationRequest::CreateForSynchronousRendererCommit`) gives the current entry a new document (`doc_seq`) with no state and shows the title.
- test: `sandbox::javascript_url_top_string_replaces_document` (`browser/tests/sandbox/javascript_url_top_string.html`), in the window with `DWELLER_PROCESS=site` and `single`: the written document's text, its script ran, its title, `history.length` 1, the page's URL and `history 1 of 1`, no old text. Passed on this Mac (2026-11-23).

## Slice (b), found so far (not built)

- `browser/tests/sandbox/javascript_url_targets.html` (no test uses it yet): links with `target` a same-origin frame, a cross-origin frame (`localhost`), a same-origin named tab and a cross-origin one, and `window.open` into the two frames. On `main`: `dump` runs none; the window with renderers runs only `window.open` into the same-origin frame; the window with one process runs `window.open` into both frames, the cross-origin one too (no origin check: `openWindow` sets the frame's navigation and `followFrameNavigation` runs it with the frame as its own initiator, and the CSP refusal `refused` is not used on that path).
- plan: split `queueJavascriptUrl` into the CSP check and `queueJavascriptTask`; in `openWindow` (a frame, `_parent`, `_top`) and in `followJavascriptLink` (a frame target or `_top`): the source's CSP, the target's sandbox rule, then `sameOrigin(source, target)` or the Chromium console error, then queue the URL in the target's script. A link to a tab goes through `targetContext` (`loadInTab` → `navigateToJavascript` checks the origin); a new context without an opener gets an opaque creator, so nothing runs in it. Check how a `javascript:` request to a tab of another renderer reaches the browser (`sendContexts`, `openTarget`) so that it never loads as a document there.
