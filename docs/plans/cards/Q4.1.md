# Q4.1: where the W7 time goes, ranked by ms

- goal: for each site that fails W7, the ms by cause, so that the Q4 steps run in the order of their real gain and each step names the sites it moves. Measure only; nothing is fixed here.
- cause: 11 of 20 sites fail W7 (Q0.2). zol and bbc were never profiled; the causes of github, mistral, youtube and youtube-search date from 2026-10-15; the re-recorded archives added 1–4.5 MB of scripts to wikipedia-en, wikipedia (ja) and go-docs (Q0.4), with no cost per frame known.
- design:
  - the shipped build (`browser/build.sh`, safe) of main f998dbf; every build and run through `scripts/capped.sh`, one at a time.
  - per site, `window_perf.py scroll` and `idle` on the archive with `DWELLER_TIMING=1 DWELLER_LAYOUT_WHY=1 --log`; a second scroll run with `DWELLER_JS_NATIVES=1`; a macOS `sample` of the zol and mistral scroll runs and of youtube-search idle.
  - each loop iteration split into script, network task, forced-layout overhead, style full / partial, layout full / partial, paint, raster, decode, GC, canvas, network wait and parse (the method is in `browser/engine/PERF.md`, "Q4.1").
  - PR #259 (Q0.4a) was still open: its diff was built separately to measure react and go-docs with it.
- files: `browser/engine/PERF.md` (section "Q4.1: where the W7 time goes (2026-11-04)"), `docs/plans/cards/Q4.1.md` (new)
- verify: the PERF.md tables; `python3 browser/tools/check_taste.py` exit 0.
