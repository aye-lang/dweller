# Q2.13a: the dead list buffers in the style sheet's arena

## Status: stopped, 2026-11-26 (the CSS live bytes halve, but youtube-search's renderer footprint rises 300 to 450 MB on macOS: malloc keeps the freed buffers)

- goal: Q2.13's "Mac, real sites" found that the lists of a `css.Sheet` grow inside its arena, which never frees the buffer a list grows out of. Build the growing lists outside the arena and put only final slices in it, so that the arena holds live bytes; youtube-search's renderer (1.7 GB footprint) should get smaller, CSS parse time not slower than 3 %.
- stopped by the stop rule: the footprint verify failed for the change and for two variants of it (below). The code is on the branch, green, and not for merging as it is.

## Measure

- this Mac (arm64, macOS 26.5), `main` 1c259ff9, `browser/build.sh` (safe), the default process mode (site), the archives (`DWELLER_REPLAY=target/sites/NAME`), `--width 1280 --height 800`, `SDL_VIDEODRIVER=dummy`, a fresh `DWELLER_PROFILE` and `DWELLER_RESTORE=0` per run, one run at a time. Q2.13's `mem.py` method: the page's `renderer:loaded`, one wheel notch, then 10 s, then `phys_footprint` per process and `vmmap --summary`.
- the CSS split: a scratch build whose renderer keeps `Malloc*` variables (not committed), `MallocStackLogging=1`, `malloc_history PID -allBySize` at load + 10 s, each live allocation summed by its innermost CSS frame; arena chunks counted apart (`aye_arena_alloc` in the stack).
- parse time: the `css_parse` records (`DWELLER_TIMING=1`) of the same runs, 3 runs of each build interleaved.
- the scripts and raw numbers are in the session scratchpad, `q213a/` (`run_pairs.sh`, `run_msl.sh`, `arena_sum.py`, `raw/`).

## Before (confirmed)

- youtube-search's renderer: footprint 1774, 1782, 1648, 1649, 1625 MB (5 runs).
- CSS holds 285 MB of live malloc blocks, 272 MB of them arena chunks. The arena chunks by site: the token list (`css::tokenize` < `tokens`) 96 MB, `decls` (`Declarer.add` and `addRaw`) 54, `simples`, `compounds` and `complexes` 25, the selector parser's own lists (`parseComplex`, `parseSelectorList`) 35, `components` 15, the rules 3, gradient checks 2.
- cause: `List` doubles with `resize`, which allocates the new buffer and frees the old, and an arena's free does nothing. So each list leaves every buffer it grew out of: about as many dead bytes as its last buffer. Lists that live only during a parse (a selector's simples, a declaration's components) stay too.
- youtube-search parses its 3.85 MB `kevlar_base` sheet 22 times during the load (the author sheet is rebuilt on each change, `engine/swap-sheets.aye`, and up to 8 old sheets are kept): 22 x 46 to 50 ms of `css_parse`.

## Change

- the tokens of a source grow in a list from `sheet.alloc` and are copied into the arena once, at their count (`settled.aye`).
- the lists of `Sheet` (`rules`, `complexes`, `compounds`, `simples`, `decls`, `imports`, `import_layers`, `font_faces`, `keyframes`, `layers`, `conditions`, `registered`, `scoped`) use `sheet.alloc` and are freed in `Sheet.deinit` (`free-sheet-lists.aye`).
- the selector parser's lists (`parseSelectorList`, `parseComplex`, `parseForgiving`, `:has()`) use `sheet.alloc` and are freed on return.
- `components` counts first (`component-count.aye`) and allocates its slice once, at its length.
- `isValidImage` reads a gradient in an arena of its own, freed on return (the result was thrown away in the sheet's arena).
- test: `sheet-bytes_test.aye` parses a generated sheet of 8000 rules (1.4 MB, 27.2 MB of source and tokens) and checks that the arena, without the sheet's lists, holds at most 1.2 x its source and tokens. Before: 148.4 MB (5.5 x), fails. After: 30.2 MB (1.11 x), passes.

## After

- the CSS live bytes on youtube-search (stack logging): 285 MB to 139 MB (arena 64, general allocator 75): tokens 96 to 31 MB (exact), `decls` 54 to 40, selector lists 25 to 19, the parser's own lists 35 to 0, `components` 15 to 2. All live malloc blocks: 2054 to 1938 MB.
- CSS parse time (the default malloc): `kevlar_base` 49.0, 50.5, 46.4 ms a parse before; 46.4, 49.6, 48.9 after (-0.6 %). All `css_parse` records: 1117, 1150, 1057 ms before; 1053, 1122, 1049 after.
- footprint, youtube: 1596 to 1491 MB; mistral (6 renderers): 1651 to 1562 MB (one run each).
- **footprint, youtube-search: 2067, 2105, 2063, 2113 MB (4 runs), up from 1625 to 1782.** `vmmap`: `MALLOC_LARGE` live 1.2 GB to 1.0 GB, but `MALLOC_LARGE (empty)` 7 MB to 494 MB in 22 blocks: the buffers the lists now free stay dirty in macOS malloc's cache of freed large blocks, which counts in the footprint. With stack logging (one run each): 1.6 GB to 2.0 GB, `MALLOC_LARGE (empty)` 162 to 410 MB.
- the variants: only the token copy, with the sheet's lists back in the arena: 2108, 2143 MB; only the sheet's lists, with the tokens back in the arena: 1980, 2263 MB. Both free big buffers, and both rise.
- with `MallocLargeCache=0` (passed to the renderer by the scratch build): before 1257 MB, after 1199 MB. So that cache holds 400 to 500 MB of youtube-search's footprint in both builds. But without it a `kevlar_base` parse takes 62.7 ms before and 83.7 ms after: the cache is not free to drop.

## Next

- the arena change only pays off on macOS if malloc gives back what it frees. The next step measures `malloc_zone_pressure_relief(NULL, 0)` (macOS; `malloc_trim(0)` on Linux) after a style rebuild, for the footprint and for the time it takes, with and without this change. If that does not hold, the fallback is a change that frees no big buffer during a parse: tokens collected in fixed small blocks and copied once into the arena, the sheet's lists kept in the arena.

Left:

- the 22 rebuilds of youtube-search's author sheet during the load, and the up to 8 kept old sheets (`MAX_KEPT_SHEETS`, `engine/swap-sheets.aye`), which keep all their lists: a kept sheet needs only its arena (strings and tokens that computed values point into).
- the same grow-in-arena pattern elsewhere, from the stack logging of youtube-search (arena chunks, MB): layout's `Tree.boxes` (`layout.aye`, `newBox`) 24 to 35; SVG's `Pen` verbs and points (`svg/path.aye` `cubicTo`, `svg/shapes.aye` `addRoundBox`) 5 to 19; the cascade's `Styles` arena: `substituteVars` lists (`vars.aye`) about 5, custom-property maps (`cascade.aye` `customLevel`) 1, `writeGradient` lists 2. DOM and JS showed no arena growth (JS has no Aye arena; its tables are in the general allocator).
- in the sheet's arena, not changed (each under 0.3 MB on youtube-search): the Builders of value strings (about 25 sites, whose `write*` helpers leave their own lists to the arena), the tokenizer's string Builders, the `@font-face` lists.
