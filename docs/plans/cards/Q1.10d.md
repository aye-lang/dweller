# Q1.10d: fuzz targets for the image decoders and web fonts

- goal: `dweller fuzz image` (PNG, JPEG, GIF, WebP, ICO) and `dweller fuzz font` (WOFF, WOFF 2, and TrueType/OpenType taken as they are) on the Q1.10a harness, each with a seed corpus, listed by `dweller fuzz --list` so the Q1.10e nightly job runs them with no workflow edit.
- reference read: `third_party/blink/renderer/platform/image-decoders/image_decoder_fuzzer_utils.cc` (`FuzzDecoder`: all data received, decode every frame until one fails) and the per-format `*_image_decoder_fuzzer.cc` (`png`, `jpeg`, `gif`, `webp`, `ico`: one decoder each); `third_party/woff2/src/convert_woff2ttf_fuzzer.cc` (`ConvertWOFF2ToTTF`, output capped at 30 MB), `woff2/src/woff2_dec.cc` (`kMaxPlausibleCompressionRatio` 100), `third_party/ots/fuzz/ots_fuzzer.cc` and `ots/src/ots.cc` `ProcessWOFF` (table offsets and lengths checked before anything is allocated).
- decoders: all Dweller's own Aye code (`browser/image/`, `browser/webfont/`); only Brotli (`libbrotlidec`, linked in the build) is C, called from `woff2.aye`. GIF and WebP decode the first frame only (`image.decode`), so there are no further frames to walk as `FuzzDecoder` does.
- design:
  - one sniffing target per family, not one per format: the page calls `image.decode` and `webfont.sfntOf`, which both pick the decoder by signature, so a target per format would fuzz the same entry with a different corpus; ICO (and CUR) come along, and a mutant whose signature changes still reaches a real decoder. A 2-minute run splits its time over the formats by seed count.
  - `browser/fuzz/image-target.aye`: the image dictionary (PNG signature and chunk names, zlib headers, JPEG markers incl. Exif and Adobe, GIF headers and extensions, RIFF/WebP chunk names, the VP8 start code and VP8L signature, ICO and BMP headers, 16-bit and 32-bit extremes) and `fuzzImage`: `image.headerSize` (the lazy-image path of `engine/images.aye`), then `image.decode` with the page's limits (`MAX_SIDE` 16384, `MAX_PIXELS` 40 million); a bitmap whose `pixels` is not `width * height * 4` bytes is `unreachable`, since paint indexes it that way.
  - `browser/fuzz/font-target.aye`: the font dictionary (signatures, table tags, WOFF 2 flag bytes, UIntBase128 and 255UInt16 forms, zlib headers) and `fuzzFont`: `webfont.sfntOf`, as `engine/fonts.aye` does for `@font-face`.
  - `browser/fuzz/targets.aye` lists `html`, `css`, `url`, `js`, `image`, `font`.
  - seeds: `browser/tests/fuzz/image/` 155 files, 198 KB: per format png 49 (41 = every 2nd `browser/tests/image/*.png`, `fixture_*`; 8 WPT `images/`: `apng`, `anim-gr`, `threecolors`, `wide-gamut-pattern`, `smiley`, `broken`, `undecodable`, `green-16x16`), jpg 43 (all 41 fixtures, WPT `arrow-oriented-upright`, `computer`), gif 16 (13 fixtures, WPT `anim-gr`, `anim-rgb`, `red-green-animated`), webp 35 (34 fixtures, WPT `webp-animated`), ico 11 and cur 1 (the fixtures up to 16 KB). `browser/tests/fuzz/font/` 26 files, 163 KB: `fixture_tiny.ttf`, `tinyvar.ttf`, `tiny.woff`, `tiny.woff2` (`browser/tests/fonts/`), 13 WPT WOFF (`css-values/resources/ExTest*`, `ChTest*`, `fonts/pass`, `fail`, `AD`, `Revalia`, `noto-sans-v8-latin-regular`, 4 of `fonts/math/`), 7 WPT WOFF 2 (`IcTest*`, `NotoSansNko-regular-webfont`, `FontStyleTest-slnt-VF`, `HasubiMono-Regular`, `NotoSansMongolian-regular`), and the two memory-bomb inputs below (`oom_huge.woff`, `oom_huge.woff2`). WPT revision `browser/tools/wpt.rev`.
  - fix (memory, not a crash): `browser/webfont/woff.aye` `unwoff` checked each table's offset and compressed length only after allocating the whole output, so an 84-byte WOFF claiming two 128 MB tables allocated 256 MB first (max RSS 280 MB); now the offsets are checked first and a compressed table may claim at most 1032 times its length (deflate's limit, as `image/inflate.aye` assumes). `browser/webfont/woff2.aye` `decodeWoff2` allocated the Brotli output (up to 512 MB) before Brotli saw a byte, so a 59-byte WOFF 2 reached a max RSS of 549 MB; now the table lengths may add up to at most 100 times the file (the reference's implausible compression ratio). Both inputs now stay at 12 MB. The seeds above measure at most 3.8 (`NotoSansMongolian`). No unit test: the result was already null before the fix and the Aye test allocator has no size limit, so a test could not tell the two apart; the inputs are seeds instead, and the RSS numbers are the check.

## Status: done, 2026-11-08

- left: the image peak of 705 MB comes from tiny files that claim a size just under the 40-million-pixel limit (a 160 MB bitmap, plus the JPEG coefficient planes or the PNG rows); a check of the declared size against the file length, like WOFF 2's ratio, would bound it, but legit PNGs and JPEGs of flat color compress far beyond 100 times, so it needs its own measurements. The `font` target stops at `sfntOf`: the sfnt then goes to FreeType and HarfBuzz unsanitized (Dweller has no OTS), so a target that loads the face and shapes a string is the next step for fonts. GIF and WebP animation frames past the first are not decoded by Dweller, so not fuzzed. The WOFF 2 path needs `libbrotlidec` at build time; without it the `woff2` seeds return null.
