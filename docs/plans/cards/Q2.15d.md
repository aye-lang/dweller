# Q2.15d: an out-of-process frame's clip honours overflow, transform and opacity

- goal: readiness list for Q2.14, "What a person sees", first bullet [Q2.9]. The parent's renderer reported a remote frame's content box from layout alone (`engine.frameRect`): the clip was the viewport and the frame boxes above it, so a cross-site frame in an `overflow: hidden` box drew over the box's edge, one in a scrolled container was drawn where it would be unscrolled, and an ancestor's `opacity` was ignored. Now the report is what the parent's paint does with the frame.
- design:
  - paint (`paint/frame-items.aye`, `frame-place.aye`): `DisplayList.frames` lists, for every frame whose items a list holds, the index of the frame's `Clip` item and the frame's layout tree (`FramePlace`); a nested list's places are carried over with their index moved. The `Clip` has passed `Builder.add`, so its rect has the ancestors' scroll offsets and transforms (a rotation or scale gives the bounding box).
  - `paint.shownFrame(list, tree)` (`shown-frame.aye`): that rect, the intersection of the `Clip`s open around it (`clipAround`, a walk back that skips closed groups), and the product of the `EndLayer` alphas that close around it (`alphaAround`, a walk forward). No allocation.
  - renderer (`put-remote-frames.aye`, `place-shown.aye`): position from the shown rect, size from layout (the child's buffer keeps the frame's own size), clip = shown clip ∩ viewport ∩ the frame's rect, and the new `Subframe.opacity` (0 to 255, default 255; the `subframes` record grows by one u32, `badSubframe` refuses more than 255). A remote frame with a box that paint did not place is reported with an empty clip, so its renderer stays.
  - window (`copy-child-frames.aye`, `blend-shown.aye`): a child whose opacity (times its embedders') is under 255 is blended instead of copied. The parent painted the placeholder white inside the same group, so the parent's pixel is `under·(1−a) + 255·a` and the child's pixel replaces the white: `out = parent − (255 − child)·a/255`, per channel. A change of opacity repaints the parent's area (`placeChild`).
  - the browser's hit test (`hitFrame`) reads the same clip, so a click on the part an `overflow` box hides now goes to the parent.
- Chromium read: `third_party/blink/renderer/core/frame/remote_frame_view.cc` (`UpdateCompositingRect`, `PropagateFrameRectsInternal`: the rect in the local root after clips), `components/viz/service/display/surface_aggregator.cc` (`EmitSurfaceContent`: the child surface's quads take the embedding quad's clip and opacity). Dweller takes the idea; it composites translation, clip and opacity only (process-model §5).
- files: new `browser/paint/{frame-place,frame-shown,shown-frame,clip-around,alpha-around,intersect-rects,shown-frame_test}.aye`, `browser/paint/{paint,frame-items}.aye`; `browser/renderer/{put-remote-frames,report-subframes,paint-frame}.aye`, new `browser/renderer/place-shown.aye`; `browser/ipc/{subframe,put-subframe,read-subframe,bad-subframe}.aye`; `browser/ui/{child-frame,place-child,copy-child-frames,copy-tab-frame}.aye`, new `browser/ui/blend-shown.aye`; new `browser/tests/ui/oopif-effects.html`; `tests/browser/window_renderer_oopif_site.rs`.
- verify (2026-11-16, Linux x86_64; test commands run with `env -u HTTPS_PROXY -u https_proxy -u CURL_CA_BUNDLE -u SSL_CERT_FILE`):
  - `cargo test --release --test browser`: 253 passed, 0 failed (the whole suite; 252 before this card).
  - `window_renderer_oopif_site_effects`, with `DWELLER_PROCESS=site` against the in-process window, `oopif-effects.html` (a 200x100 `localhost` frame in a 150x60 box of a `127.0.0.1` page): `?hidden` (`overflow: hidden`), `?scrolled` (`overflow: auto`, `scrollTop = 45`: the child is `at 20 -5`) and `?moved` (`transform: translate(30px, 20px)`: `at 50 60`) are byte-equal PNGs; `?faded` (`opacity: 0.5`) has no channel more than 1 away.
  - `aye_unit_tests`: new `shown-frame_test.aye` (a clip and a layer closed before the item do not count; two open layers of alpha 128 give 64).
