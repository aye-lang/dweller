# Q3.10: `X-Content-Type-Options: nosniff`, and COOP

- goal: (a) a `nosniff` script or stylesheet response of the wrong MIME type is blocked; (b) `Cross-Origin-Opener-Policy` on top-level documents switches the browsing context group when the policies do not match: the new document has no `window.opener`, and the opener's handle to it is `closed`. With `DWELLER_PROCESS=tab` the switch also forces a new renderer. WPT `fetch/nosniff` and `html/cross-origin-opener-policy` become measured areas.
- design (a, nosniff):
  - `net/nosniff.aye` `nosniff(headers)`: Fetch "determine nosniff": the first value of the first `X-Content-Type-Options` header, ASCII case-insensitively `nosniff` (shared with ORB's `orbBlocks`, which had its own copy).
  - `net/nosniff-blocked.aye` (Fetch "should response to request be blocked due to nosniff?"): with nosniff, a `Script` or `Worker` request needs a JavaScript MIME type essence (`net/javascript-mime.aye`, the list of the MIME Sniffing spec) and a `Style` request needs `text/css`; an empty MIME type fails both. `nosniffChecked` runs in `net.request` after `corsChecked` and `orbChecked`, so every script, module, sheet, worker script and `importScripts` goes through it, from the network, the archive and the cache alike; a blocked response is `FetchError.Network` (a script `error` event, a sheet not applied).
  - `importScripts` in a worker throws a `NetworkError` (`workers/worker-scope.js` `loadScript`) instead of a `TypeError`.
  - Dweller sniffs no document by MIME type (text/plain stays plain, XML types are listed, everything else parses as HTML), and images are sniffed by signature whatever the header says (as every browser's decoder does); there is nothing to switch off for `nosniff` there.
- design (b, COOP):
  - `net/coop.aye` (`Coop`: UnsafeNone, SameOriginAllowPopups, SameOrigin, NoopenerAllowPopups), `net/parse-coop.aye` + `coop-of-token.aye` + `is-structured-token.aye`: the header is a structured-header item whose token is the policy (parameters such as `report-to` ignored); a repeated header, a list, a quoted string, a wrong case or a non-token byte is `unsafe-none`. `net/coop-swaps.aye` (`allow-popups-swaps`, `noopener-swaps`) is Chromium's `ShouldSwapBrowsingInstanceForCrossOriginOpenerPolicy`: current policy, same origin, "navigating from the initial empty document", destination policy.
  - `Page.coop` is parsed from the response headers in `pageOf` (all pages; only top-level documents use it).
  - `engine/apply-coop.aye`, called by `attachLoading` before `resetWindowName`: the current policy is that of the context's page, or, for the first document of a popup (the initial empty document), that of its opener's page (Chromium's initial empty document inherits the opener's policy and origin). On a switch, `leaveGroup` clears the context's `opener`, the `opener` of every context it opened, its `window.name`, and raises `BrowsingContext.epoch`.
  - window objects of contexts (`windows.aye` `contextValue`) are made per epoch (`TAG_WINDOW` generation = epoch + 1, the stand-in cache is keyed with the epoch): after a switch, the opener's old handle is stale (`context-at.aye` `contextAt` is null for it): `closed` is true (`win-stand-in-closed.aye`), `postMessage`, `close` and the page lookups do nothing, and `popup.opener` of its own popups is null. `contextValue(id)` after the switch is a new object for the same tab.
  - tab mode: `ui/coop-swaps-tab.aye` makes `takesSwap` swap to a new renderer when the site is the same but the policies do not match (the tab's last committed top URL and `tp.coop`, set in `sendFetched`), as for a cross-site navigation.
- references: https://html.spec.whatwg.org/multipage/browsers.html#cross-origin-opener-policies , https://fetch.spec.whatwg.org/#should-response-to-request-be-blocked-due-to-nosniff? . - Tab mode: the switch forces a new renderer, but popups of the retired renderer live and die with it (Q2.6b's left list); the opener relation across renderers does not exist yet.
