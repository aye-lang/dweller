# Q3.4c: certificate exceptions pinned to the accepted key; no HSTS over a bypass

- goal: the certificate exception of Q3.4b is bound to the certificate the user accepted. A later handshake on that host that shows another key (same host, same kind of error) gets the interstitial again, and that check happens in the same handshake that carries the page. A `Strict-Transport-Security` header received over a bypassed connection is not stored. The certificate bar can be reached with Tab and pressed with Enter (or Space); page scripts still cannot reach it.
- design:
  - pin: `CertException` gets `pin`, the libcurl pin `sha256//BASE64` of the leaf certificate's SubjectPublicKeyInfo. Proceeding (`allowCert(at: *Url, kind)`, called by the bar with the page's URL) first runs `cert-pin.aye` `certPin`: its own easy handle with `CURLOPT_CONNECT_ONLY`, `CURLOPT_CERTINFO`, both checks off and `DWELLER_RESOLVE` applied, handshakes with the page's host and port and reads `CURLINFO_CERTINFO`. `leaf-pem.aye` takes the `Cert:` field of certificate 0 (`CurlList` now declares the `curl_slist` fields); `pin-of.aye` decodes the PEM (net's forgiving `base64Decode`), `spki-of.aye` walks the DER (`read-der.aye`, `DerItem`: certificate, tbsCertificate, optional `[0]` version, five fields, then the SPKI), hashes it with `std.crypto.sha256` and base64-encodes it. No pin (the server is gone, no certificate) means no exception and no reload. `addCert` keeps one entry per host, kind and pin, so a host can have several accepted keys.
  - applying it: `relaxTls` turns off the one check only when `cert-pins.aye` `certPins` finds pins for `(cert_host, kind)`, and sets `CURLOPT_PINNEDPUBLICKEY` to them (`;`-separated). libcurl checks the pin in the relaxed handshake itself, before any byte of the request or the body, also with `VERIFYPEER` 0 (checked with curl 8.7.1 and LibreSSL: `-k --pinnedpubkey` gives 0 for the right pin, 90 for another, and accepts a `;` list). On the second relaxation (another kind), only pins accepted for both kinds are kept (`also` is `Sink.cert_kind`, the kind relaxed before). A pin mismatch is CURLcode 90; `curlError` maps it by `pin-error.aye` `pinError` to the kind of the strict attempt (`Sink.cert_kind`), so the top-level page is the interstitial with the bar again, not the generic TLS error. Why not `CURLINFO_CERTINFO` on the strict attempt: libcurl fills it only after a handshake that passed verification (`curl -w '%{num_certs}'` gives 0 without `-k`), so the accepted key comes from the probe, and the handshake that carries data is pinned to it.
  - HSTS: `noteHsts` takes the `Sink` and returns when `cert_relaxed > 0` (Chromium's `ProcessStrictTransportSecurityHeader` returns when the certificate status has an error). The three callers (http.aye, two in loader.aye) pass the sink.
  - keyboard: `ui/cert-key.aye` `certKey`, first in `Ui.key` after the sheet: while the bar is shown and the page has the focus, Tab toggles `Ui.cert_focused` (reset with `cert_advanced`) and Enter, keypad Enter or Space on the focused bar presses it; the keys do not go to the page. `ui/press-cert.aye` `pressCert` is what the click and the key share (Advanced, then `allowCert` and reload). `drawCertBar` draws the focus ring around the button. The window's key handler takes only real key events; a script's `dispatchEvent` never reaches it, and the interstitial has no script.
- files: new `browser/net/{cert-pin,cert-pins,leaf-pem,pin-of,spki-of,read-der,der-item,pin-error}.aye`, `browser/net/pin-of_test.aye`, `browser/ui/{cert-key,press-cert}.aye`, `browser/tests/tls/self-signed-b.pem` (P-256, IP 127.0.0.1, its own issuer, 100 years, another key than `self-signed.pem`); changed `browser/net/{http,loader,note-hsts,relax-tls,allow-cert,add-cert,cert-allowed,cert-exception,cert-exceptions}.aye`, `browser/net/cert-allowed_test.aye`, `browser/ui/{cert-click,draw-cert-bar,show-early,window}.aye`, `browser/tests/tls_server.py` (a sixth port: `Switching` wraps each accepted socket with the current context; `/switch` swaps self-signed and self-signed-b), `tests/browser.rs` (`cert_bypass`, `tls_errors` expects six ports).
- Chromium files read:
  - `components/security_interstitials/content/stateful_ssl_host_state_delegate.cc` (`GetKey`: the error and the SHA-256 chain fingerprint, per host; the card named `chrome/browser/ssl/`, which now holds only its factory) and `net/url_request/url_request_http_job.cc` (`ProcessStrictTransportSecurityHeader`: no HSTS when `IsCertStatusError`; the card named `transport_security_state.cc`, which only stores): Dweller takes exceptions keyed by host, error and key, and no HSTS over a connection with a certificate error; it pins the leaf's SPKI hash instead of the chain fingerprint, because libcurl can check that inside the handshake.
  - https://curl.se/libcurl/c/CURLOPT_PINNEDPUBLICKEY.html, https://curl.se/libcurl/c/CURLINFO_CERTINFO.html.
- verify (2026-11-08):
  - `python3 browser/tools/check_layers.py`, `python3 browser/tools/check_taste.py`, `$AYE check browser`: exit 0. `$AYE test browser`: 205 passed, 0 failed (new: "net: a certificate's pin is the SHA-256 of its public key" (the pin of `self-signed.pem` equals `openssl x509 -pubkey | openssl pkey -pubin -outform der | openssl dgst -sha256 -binary | base64`; bad DER and no PEM give none), "net: the pins of a host and kind, also accepted for the kind relaxed before"; the exception test now checks the key too).
  - `scripts/capped.sh cargo test --release --test browser -- cert_bypass tls_errors hsts mixed_content aye_unit_tests`: 5 passed.
  - `cert_bypass` additions (headless window, SDL dummy driver): on the self-signed page, `key:tab key:return` gives `cert Proceed to 127.0.0.1 (unsafe)`, and one more `key:return` loads the page (fetch and XHR 200). On the switching server: proceed past key A, load `/switch` (served over the pinned A, then the server swaps to B), `cmd+r`: the interstitial with `cert Advanced` again. In a new process (server now on B): proceed past B, `/switch` (back to A), `cmd+r` shows the interstitial, proceeding again loads `secure page`. On `site.test` with a fresh profile: proceeding past its untrusted certificate to `/hsts` loads it, the profile's `hsts` file has no `site.test`, and in the same process `http://site.test:TLS/` is not upgraded ("Cannot load this page", not the interstitial).
  - mutation checks: without the `CURLOPT_PINNEDPUBLICKEY` line, `cert_bypass` fails at "an exception is for the key that was accepted"; without the `cert_relaxed` return in `noteHsts`, it fails at "no HSTS from a bypassed connection".
- left:
  - the accepted key is read by a probe handshake when the user proceeds, not from the failed strict handshake that made the interstitial (libcurl gives no certificate for a handshake that failed verification); a server that changes its key between the interstitial and the click gets the newer key accepted. Taking it from the strict handshake needs `CURLOPT_SSL_CTX_FUNCTION` and the TLS library's own verify callback.
  - the pin is of the leaf's SPKI, not of the whole chain (Chromium): a reissued certificate with the same key passes.
  - in the tab-process mode (`DWELLER_PROCESS=tab`) `allowCert` runs in the window's net session (as in Q3.4b); not checked here.
  - no window test across hosts (Q3.4b's left list).
