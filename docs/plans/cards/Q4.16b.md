# Q4.16b: geometry reads restyle only when something is dirty

- goal: a geometry read (getBoundingClientRect, offset*, client*, scroll*) runs style and layout only when something is dirty, and with nothing dirty returns from the current layout. Transitions advance once per rendering update, not per read; a read in a rAF sees the values of the current animation frame. Mistral's `metric` (152 µs a call in Q4.16a) under 10 µs when style is clean.
- profile (before, `browser/build.sh` safe of this branch's base: origin/main plus #303's off-by-default counter; replay archive, `--frames 210`, 200 `frame` events, `SDL_VIDEODRIVER=dummy`, `DWELLER_TIMING=1 DWELLER_JS_NATIVES=1`; idle = the 210-frame run minus a 12-frame run, 198 frames): `metric` 8714 calls, 1396 ms (160 µs a call, 7.1 ms a frame). `sample` of 6 s idle (`target/q416b-before.sample`): `akMetric` 528 samples, of them `restyleTransitioning` 508 (`animation.styleChange` → `changeStyle` 470) and `layoutGeometry` 17. Only 444 of the 9581 reads laid out (`script_layout`); each of those then walked every transitioned element.
- cause: `geometry` (`geometry-fn.aye`, P10.47) ran `restyleTransitioning` after every layout that moved the version: `computedValues` and `styleChange` for every element with a transition snapshot (`Transitions.before`), not only the ones restyled. GSAP on mistral writes a transform and reads `offsetWidth` per tick, so every such read paid the walk. P10.51d had since put `showTransitions` into each restyle path of the layout (`styledElements`: the restyled and moved elements of a local restyle, every snapshot after a full one), so the walk found nothing new.
- design (spec: https://drafts.csswg.org/css-transitions-1/#starting, https://html.spec.whatwg.org/multipage/webappapis.html#update-the-rendering):
  - `geometry` is the layout itself (`layoutGeometry` renamed, the wrapper file removed): it returns the current layout when the version and viewport are unchanged, and a dirty one restyles only the changed elements, whose style change starts transitions in `showTransitions`.
  - Transitions advance once per rendering update: `transitionFrame` (the prelude's 16 ms tick) still runs `restyleTransitioning`, `noteRunning` and `updateTransitions`; the first read after a tick lays out with the tick's values, the next reads reuse them.
  - Chromium (read-only): `core/dom/document.cc` (`UpdateStyleAndLayoutForNode` → `UpdateStyleAndLayout`, which recalcs only when `NeedsLayoutTreeUpdate`), `core/animation/document_animations.cc` (`UpdateAnimationTimingForAnimationFrame`). Dweller takes: a forced read recalcs only dirty elements and starts transitions for those (Blink computes the transition update per element in its style recalc), and animation time moves once per frame.
- files: `browser/engine/geometry-fn.aye` (removed), `browser/engine/geometry.aye` (`layoutGeometry` → `geometry`), `browser/tests/ui/transition_reads.html` (new), `tests/browser.rs` (`geometry_reads_restyle_once`), `docs/plans/cards/Q4.16b.md` (new).
- verify:
  - `check_layers.py`, `check_taste.py` → 0; `aye check browser` → 0; `aye test browser` → 210 passed; `browser/build.sh` → 0.
  - `geometry_reads_restyle_once`: in the 5th rAF of a running `width` transition, 100 getBoundingClientRect reads give one width, between the start and end, equal to getComputedStyle's; a width change between two reads of another element is seen (50 → 70); the run has as many `script_layout` records with 100 reads as with 1 (4).
  - `cargo test --release --test browser -- geometry_reads_restyle_once window_css_animation window_css_transition window_transition_kept css_ jsdom_fixtures js_conformance aye_unit_tests` → 8 passed (`target/q416b.log`). No golden re-blessed.
