# Q3.7b: the rest of CSP `script-src`

- goal: `script-src` behaves like Chromium's for module scripts, `'strict-dynamic'`, all three hash algorithms, inline event handlers and the `securitypolicyviolation` event, so WPT `content-security-policy/script-src` (and the generated `gen/` matrix) pass what they test about scripts. Builds on Q3.7 (`csp/`) and Q3.6 (`directiveOf`, `sourceList`, `Page.header_csp`).
- design:
  - `csp.Refusal { policy, directive, effective }` replaces the bare directive string that `scriptUrlRefusal`, `inlineRefusal`, `evalRefusal` returned, so the event can carry `originalPolicy` (the one policy of the list that refused), the directive text (console line) and the effective directive name. `csp.Inline { Script, Attribute, Navigation }` picks the effective directive of an inline check (`script-src-elem` or `script-src-attr`); `scriptDirective(policy, specific)` is the fallback list `specific` -> `script-src` -> `default-src`.
  - `'strict-dynamic'`: `listAllowsUrl` ignores host, scheme and `'self'` sources and allows a request only for a matching nonce or a script that is not parser-inserted; `listAllowsInline` allows a non-parser-inserted inline script. Parser-inserted is known by the call site (`runClassicElement`/`runModuleElement` from `runScriptElement` = parser, `akScriptPrepare`/`akScriptRun` = created by script).
  - Hashes: `sha256` (std), `sha384`, `sha512` (`csp/sha512.aye`, `sha512-block.aye`, constants generated from the primes); `hashBytes`, `digestOf`, `hashMatches` pick the algorithm by the source's prefix. Attributes (`Inline.Attribute`/`Navigation`) match a hash only when the list has `'unsafe-hashes'`.
  - Module scripts: `<script type=module>` inline goes through `inlineRefused`, external through `urlRefused`; static imports and `import()` go through `pageModuleResponse` -> `moduleUrlRefusal` (a refused import fails the load with `AccessDenied`, a TypeError in script; JSON modules are `connect-src`'s and skip it). `module_gate` (a global set by `runGatedGraph` for the synchronous graph load) gives the loader the entry URL (already checked by the element) and the element's nonce. The background prefetches (`pagePrefetchModules`, `moduleLoad`, the inserted-script `akScriptFetch`) skip refused URLs, so a blocked script is never requested.
  - Inline event handlers: `ak.compile(src, element)` calls `handlerRefused` (`Inline.Attribute`, `script-src-attr`) when the handler is first compiled; a refused handler is `null`.
  - `securitypolicyviolation`: `SecurityPolicyViolationEvent` (prelude `eventClass`) with `documentURI`, `blockedURI` (`inline`, `eval` or the URL), `effectiveDirective`, `violatedDirective` (= effective), `originalPolicy`, `disposition: "enforce"`, `sample` (first 40 bytes, only with `'report-sample'`), `statusCode` 0, `lineNumber` 0. `violationJson` builds it, `fireViolation` hands it to the dispatcher (`hostEvent` type `securitypolicyviolation`, JSON in `key`), bubbling from the element (or the document for eval, imports and workers). Eval/`Function`/string timers fire it through `Interp.eval_report` (`refuseStringCode(it, code)` now takes the code for the sample).
  - Nonce: the `nonce` attribute is trimmed of whitespace (`elementNonce`).
  - `<meta>` applies to later elements only: `policyAt(page, element)` is the prefix of `Page.csp` made of the header values and the `<meta>` elements before the element in tree order; only a `<meta>` that is a child of `<head>` counts (`isPolicyMeta`).
  - srcdoc and about:blank frames inherit the parent's policy (`sourcePolicy`, `Page.inherited_csp`).
  - Workers: `new Worker(url)` is checked on the page against `worker-src` -> `child-src` -> `script-src` -> `default-src` (`csp.workerUrlRefusal`, native `__workerHost.refused`); a refused worker fires `error` on the Worker object and the violation event on the document. A script that lands on a refused URL after a redirect is refused after the fetch (`redirectRefused`), the request itself having been made.
  - Count stability (the Q3.6 note, 215 -> 183): the `.https.` tests (10 files in `script-src`, 28 subtests in one of them) load `https://web-platform.test:8443`; with the cloud container's `HTTPS_PROXY` set Dweller connected through the agent proxy, the TLS handshake failed and each such file counted as one crash. The subtest total therefore depended on whether the environment had a proxy. `wpt.py run` now drops the proxy variables for the browser it starts (`drop_proxies`); `script-src` is 215 subtests with and without them (217 after this step, two files that used to time out now finish). The Q3.6 baselines of `fetch/api` (+55 subtests) and the others were measured with the proxy set; `conformance.py check` sees no fall.

## Status: done, 2026-11-09

Left:
- `javascript:` URLs are not navigated by the engine at all (`unsafe-hashes/javascript_src_*`, `navigation/*`, `script-src-strict_dynamic_javascript_uri`); the `Inline.Navigation` kind exists in `csp/` for them.
- Policies inside workers: `eval`, `importScripts`, `setTimeout(string)` and imports of a worker use no policy (WPT `worker-*.sub.html`, `inside-worker`, `gen/*worker-import*`); a data:/blob: worker must inherit its creator's policy and a URL worker takes its own response headers (workers fetch through the page, which does not see the response headers). SharedWorker and worklets do not exist.
- Script `integrity` hashes allowing a script (`script-src-sri_hash`, `tentative/script-url-allowed-by-hash`), `modulepreload` + `'strict-dynamic'`, `'unsafe-eval'` wasm (`wasm-unsafe-eval`), Trusted Types.
- `lineNumber`, `columnNumber`, `sourceFile`, `statusCode` of the event are 0 or empty (the parser keeps no source positions); `referrer` is empty; report-only policies and reports are Q3.8; the event fires synchronously, not in a queued task.
- A redirect is checked on the final URL after the request was made, not hop by hop (net follows redirects inside one request).
- The `nonce` IDL attribute and nonce hiding (`nonce-hiding/nonces.html`, 60+ subtests) are not implemented; a `<meta>` inserted after parse by script does not change the policy; ISO-8859-3/7/9 documents decode wrongly so `hash-always-converted-to-utf-8/*` fail.
