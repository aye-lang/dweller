# P10.51e: pointer state restyles locally: :hover and :active without lag

- goal: (1) a hover change restyles only what the `:hover` rules can affect, with the boxes kept and no full layout; a page with no `:hover` rules does no restyle on pointer moves; (2) `:active` matches the pressed element chain between mousedown and mouseup; (3) `:hover` inside iframes; (4) `Transitions.kept` stops growing per changed value. P10.51d's "left" list.
- design:
  - Invalidation features: `css.HOVER_CHANGED` and `css.ACTIVE_CHANGED` are style changes of their own (`what` 2 and 3; `nameKey` now stays clear of 0..3). `simpleKeys` gives `:hover`/`:active` their key, so `RestyleDeps.walkDeep` records them as deep only when the pseudo-class is in a compound left of the subject (`.card:hover .title`); a subject-only use (`a:hover`) is a shallow change: the element alone, its descendants only when its inherited values move. `RestyleDeps.deep` now keeps whether a `+`/`~` follows the compound (`siblingAfter`, nested selectors count as siblings); `reachesSiblings` false makes `restyleRoots` restyle the element's subtree without its following siblings (not for `of S`). `RestyleDeps.hover`/`active` (`looksAtKind`, scoped sheets too) say whether any selector uses the state (`seesState`).
  - Chains: `hoverAt` → `hoverElement` → `notePointerState`: when the layout's deps see the state, `noteLeftChain` notes the change at each element that left the old chain or entered the new one (below their common ancestor), and moves `Controls.pointer_styled`, which `styleInputs` hashes in place of the hovered node; otherwise nothing is noted and no version moves. `localChanges` accepts these changes (`isPointerState`), so `layoutGeometry` restyles them with `keep` and `keepRestyled` rebinds the boxes.
  - `:active`: `SelKind.Active` (was `Never`) matches `Controls.active` and its ancestors (`dom.inChain`); the window calls `engine.pressAt` on left mousedown (`click:` in `--events`) and mouseup (`release:`).
  - Frames: `hoverFrames` passes the point into the frame under it (`frameRect`, frame scroll) and clears the hover of the others, recursively.
  - `restyled_elements` timing record (`noteRestyled`): elements styled by each local restyle, with the ancestors styled for context.
- files: `browser/css/` (`looks-at-kind.aye`, `sibling-after.aye`, `sees-state.aye`, `is-pointer-state.aye`); `browser/engine/` (`hover-element.aye`, `hover-frames.aye`, `pointed-element.aye`, `press-at.aye`, `note-pointer-state.aye`, `note-left-chain.aye`, `note-restyled.aye`; `top-changed.aye`, `note-hover-change.aye` removed); wiring in `css/invalidation.aye`, `css/selector.aye`, `css/inputs.aye`, `dom/controls.aye`, `engine/geometry.aye`, `engine/hover-at.aye`, `ui/window.aye`. Tests: `browser/tests/ui/hover_local.html`, `hover_none.html`, `hover_frame.html`; `tests/browser.rs` `window_hover_local`.
- reference: blink `core/css/invalidation/rule_invalidation_data.cc` (pseudo-class features, descendant vs sibling sets), `core/dom/element.cc` (SetHovered/SetActive → PseudoStateChanged), `core/input/mouse_event_manager.cc`; algorithm only. https://drafts.csswg.org/selectors-4/#the-hover-pseudo, https://drafts.csswg.org/selectors-4/#the-active-pseudo.

- left:
  - `Transitions.kept`: its owned texts can still be referenced by the shown values interned into `Styles` (boxes kept by a local restyle point at them), so freeing on end/replace needs a reference sweep over running transitions, snapshots and shown values; not done.
  - A descendant-deep change restyles the whole subtree of the element (Blink restricts it to descendants matching the invalidation set's features, e.g. `.title`), and the element's own features are not used to skip elements (`a:hover` still restyles a `div` entering the chain).
  - `:focus-within`/`:focus-visible` still go through `STATE_CHANGED` (deep, full layout); hover in frames does a full layout of the frame (frames lay out through `layoutFrames`, not the shared geometry).
