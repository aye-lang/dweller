# P4.75s: JS speed on the WebGL conformance ogles pages

- goal: P11.14d group 1: 79 WebGL 1 CTS pages (`conformance/ogles/*`, `glsl`, `conformance2/rendering/vertex-id-large-count`) time out at 30 s; `ogles/GL/swizzlers/swizzlers_041_to_048.html` took 37 s in the JS interpreter (Chrome: well under a second).
- symptom here: not reproduced on this box (4-core Xeon 2.1 GHz, fast build, base `c996cf8`): the page takes 4.4 s alone, and `webgl_conformance.py run conformance/ogles -j 4` gives 141/141 pages, 0 timeouts (slowest page 5.4 s at -j 4). The 37 s was measured during the 25-minute full run (P11.14d), so machine load; the time is still JS.
- profile (`DWELLER_JS_NATIVES=1 DWELLER_JS_VM_STATS=1 DWELLER_TIMING=1`, swizzlers_041_to_048, base): bytecode 3799 ms, `webglPng` 327 ms (16), `Math.abs` 295 ms (6.0M calls), `webglReadPixels` 228 ms (16), `imageLoad` 93 ms; parse about 8 ms, compile under 1 ms, GC negligible. The bytecode is `compareImages` (`ogles/ogles-utils.js`): per pixel of every 500x500 readPixels comparison, one closure call (`isPixelSame`), 3 `Math.abs` calls, 6 `Uint8Array` loads through context variables and 4 `Uint8ClampedArray` stores; 8 comparisons, 2M pixels, 275M bytecodes (about 13 ns each).
- micro costs (fast build, per operation): a native call (`Math.abs`) 175 ns, a JS closure call 150 ns, a typed-array load from a context variable 95 ns. `perf` of `pixels.js`: `vmLoop` 46%, `List(Value).pop` 8.7% (`Interp.truncate` popped one value at a time after every call), `vmLdaGlobal` 6.5% (45% of it one 16-byte copy of the `JsError!Value` result: a store-forwarding stall, the Value sits at offset 2 of the error union), the typed-array keyed path (`vmKeyedLoadSlow`, `getIndex`, `setIndex`, `typedGet`, `toNumber`, ...) about 12%, the call path (`callAt`, `vmCallOp`, `vmInlineCallee`, `callNative`) about 15%. VM stats: 37 of 42 keyed sites generic (typed arrays had no IC element kind).
- root causes: (1) typed arrays had no keyed load/store handler in the VM: every `a[i]` on a typed array left the loop through `vmKeyedLoadSlow`/`getIndex` (V8 has TYPED_ARRAY elements kinds in its keyed IC); (2) the stack truncate after every call was linear; (3) global and context-slot loads returned `JsError!Value` through a stalling copy even on a cache hit.
- fix: `KIND_TYPED` keyed handlers (`vmKeyedTypedAt` finds the element: an index below the length, inside the buffer, not BigInt; `vmKeyedTypedLoad` reads it with `viewRead`, `vmKeyedTypedStore` writes a number with `viewWrite`; anything else takes the slow path as before), tried after the dense one in `GetKeyedProperty`/`SetKeyedProperty`; `Interp.truncate` sets the length; `vmGlobalCell` and `vmContextCell` give the slot (`?*mut Value`, as `vmKeyedDenseElem` does) so a hit never copies through the error union; `vmLdaGlobal` uses `vmGlobalCell`. VM stats now print the typed-array count.
- files: new `browser/js/typed-at.aye`, `vm-keyed-typed-at.aye`, `vm-keyed-typed-load.aye`, `vm-keyed-typed-store.aye`, `vm-global-cell.aye`, `vm-context-cell.aye`, `browser/tests/jsbench/pixels.{js,out,smoke.out}`; wiring in `vm.aye`, `interp.aye` (`truncate`), `vm-lda-global.aye`, `ic-element-kind.aye`, `vm-print-ic-stats.aye`.
- reference: v8 `src/ic/accessor-assembler.cc` (`EmitElementLoad`/`EmitElementStore` for TYPED_ARRAY elements, `LoadGlobalIC_TryPropertyCellCase`), `src/interpreter/interpreter-generator.cc` (LdaContextSlot).
- verify (fast build, this box):
  - `cargo test --release --test browser -- js_conformance js_command_line jsdom_fixtures jsdom_gc_stress` → 0 (6 passed); `jsbench.py --smoke` → 0; `check_taste.py`, `check_layers.py` → 0.
  - swizzlers_041_to_048 alone: 4.37/4.44 s → 3.59/3.51 s (bytecode 3799 → 2858 ms); `dump --text` output identical.
  - `conformance/ogles -j 4`: 141/141 pages, 0 timeouts before and after; sum of page times 440.5 → 363.0 s (−18%), slowest page 5.4 → 4.3 s.
  - jsbench `pixels` (new, median of 3): 2.49 → 1.90 s (1.31×). Whole suite, one run, base → this: geomean 1.089× (array 1.20, calls 1.17, closures 1.23, globals 1.27, three 1.20, methods 1.14, raytrace 1.12; crypto 0.98, dom 0.97, loop 0.93), all checksums equal.
- status: partial 2026-10-17. The three causes above are fixed; the 37 s did not reproduce here, so the timeout count could not move on this box (0 → 0).
