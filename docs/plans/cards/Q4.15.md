# Q4.15: no raster without damage, raster only the damaged rect

- goal: a frame with no damage rasters nothing and presents nothing new. A frame with damage rasters only the union of the damaged rects into the kept back buffer, clipped to them. This applies to the page and to the window composed over it.
- cause: Q4.1 (`browser/engine/PERF.md`, "Q4.1") counted raster in every frame: mistral 2193 ms of its 10 s idle, react 47 ms per p95 scroll frame. The page's own pixels were already damage-limited (P4.35, `ui/pagedraw.aye`: display-item signatures, `paint.diff`, scroll bands, `drawRinged` into the kept ring canvas). The window was not. When any overlay was over the page (a focused text field's caret or selection, the hover status line), every frame with page damage, and every frame of a `--frames` run, took the whole path in `Ui.draw`: blit the whole page into the window canvas, draw the chrome and the overlays again, and upload and present the whole window texture. A site with an autofocused search box and a rAF animation composes the whole window in each frame.
- design:
  - `ui/overlay-key.aye` `overlayKey(ui, v) ?u64` is a hash of everything the supported overlays draw: the view (scroll and scale), the window size, the hover text, the focused node, and its caret or selection rects. It is null when an overlay outside that set is up (find bar and matches, dropdown, validation bubble, agents, the stuck bar, the auth sheet). Those keep the whole path.
  - In `Ui.draw` (`ui/window.aye`), when the frame is not `dirty`, the window canvas is not stale (the last frame composed it), and the key equals the last composed frame's key, the overlays are unchanged and in the same place. Then `ui/compose-damage.aye` `composeDamage` composes only the page's damage rects. For each rect it blits the page pixels (ring-aware), redraws the caret, selection and status line clipped to the rect, and uploads only that rect to the window texture. No page damage means no compose and no present. Otherwise the whole path runs as before and stores the key.
  - A scroll changes the view, so the key changes and the window is composed whole. The page itself still draws only the band and the diff (P4.35). A partial window compose for scroll is left out of this card.
  - There is no caret blink in Dweller, so it adds no damage source. Resize, chrome and overlay state changes set `dirty` and take the whole path.
  - Counter: the `ui_window_px` DWELLER_TIMING record ("PIXELS RECTS", like `raster_px`) is written in each frame that composes window pixels: the whole window, or the damage rects.
- files: `browser/ui/overlay-key.aye` (new), `browser/ui/compose-damage.aye` (new), `browser/ui/window.aye` (field `overlay_key`, the branch in `draw`, the `ui_window_px` record), `browser/tests/ui/damage_window.html` and `damage_window_final.html` (new), `tests/browser.rs` (`window_idle_no_raster`, `window_damage_rect_only`, helpers `frame_records`, `rasters`, `damage_window_run`)
- Chromium files read:
  - `cc/trees/damage_tracker.cc`: Dweller takes damage as the union of the changed rects in target space, and draws nothing when that union is empty.
  - `cc/scheduler/scheduler_state_machine.cc` (`ShouldDraw`, `needs_redraw_`) and `cc/trees/layer_tree_host_impl.cc` (`HasDamage`): Dweller takes "no damage, no draw": the frame skips raster and present.
- verify:
  - `aye check browser`: exit 0.
  - `aye test browser`: 179 passed.
  - `python3 browser/tools/check_taste.py`: exit 0.
  - `cargo test --release --test browser -- window_idle_no_raster window_damage_rect_only`: 2 passed. With the partial branch turned off, both fail: every idle frame composes `120000 1` window pixels.
  - `cargo test --release --test browser -- window_`: 69 passed, 1 failed (`window_webgl`: "ANGLE not found … run browser/gpu/fetch_angle.sh", the local machine has no ANGLE; CI has it). No golden changed.
  - `window_damage_rect_only` checks that the window saved after the color change is byte-equal to a run that draws that color from the start, with `DWELLER_DAMAGE_CHECK=1`. The changed frame rasters `1344 1` (42x32: the 40x30 box with the one-pixel margin) in the page and in the window.
