# Q4.16m: `RegExp(re)` returns `re` and `test` calls `exec`, so core-js leaves RegExp alone

- goal: on bbc, core-js (privacy-mgmt wrapper `es.regexp.constructor`, echo-client `es.regexp.test`) replaced the `RegExp` constructor (which sets `RegExp.prototype.constructor`) and deleted and re-added `RegExp.prototype.test` (which moves the other prototype slots), because Dweller's natives failed its feature tests (Q4.16g "left"). Make both natives follow ECMA-262 and keep the native fast path.
- the core-js checks (read from the bbc archive, core-js 3.x minified):
  - `es.regexp.constructor`: `new RegExp(re1) !== re1`, UNSUPPORTED_Y, and `re2[Symbol.match] = false; RegExp(re1) != re1 || RegExp(re2) == re2 || '/a/i' != RegExp(re1, 'i')`. Failed on `RegExp(re1) != re1`: a call without `new` always made a copy.
  - `es.regexp.test`: `re.exec = function () { called = true; ... }; re.test('abc') === true && called`. Failed: `test` ran the matcher directly.
  - Passed already: `es.regexp.to-string` (`toString.call({ source: 'a', flags: 'b' })`, `name`), `es.regexp.flags` (`/./g.flags`), sticky.
- more found: `new RegExp(obj)` for an object with a truthy `@@match` (IsRegExp) used `String(obj)`, not `obj.source` and `obj.flags` (test262 `from-regexp-like*`, `S15.10.3.1_A1_*`).
- design:
  - `regexpCtor` (`regexp-ctor.aye`): IsRegExp only for objects; without `new`, a regexp-like pattern, undefined flags and `pattern.constructor === RegExp` (the callee) returns the pattern; a RegExp copies its source and flags (flags replaced when given); a regexp-like object reads `source` and `flags`; else ToString of each (undefined is empty).
  - `regexpTest` (`regexp-test.aye`): a non-object receiver throws; ToString(S); Get(R, "exec"). When it is the original `exec` (`Interp.regexp_exec`, rooted at install) or not callable, the old native match on a RegExp runs; else it calls `exec` and throws unless the result is an object or null.
  - New atom `A_EXEC`.
- files: `browser/js/regexp.aye` (old `regexpCtor`/`regexpTest` removed, `regexp_exec` stored), `atoms.aye`, `interp.aye`; new `regexp-ctor.aye`, `regexp-test.aye`; test `browser/tests/js/283_regexp_ctor_test.{js,out}` (the three core-js checks print "native ... is fine"; `RegExp(re)`, a changed `constructor`, regexp-like objects, a falsy `@@match`, own `exec` results, a non-callable `exec`, a generic receiver, `lastIndex` with `g`; `.out` from node 22).
- references: ECMA-262 https://tc39.es/ecma262/#sec-regexp-pattern-flags , https://tc39.es/ecma262/#sec-regexp.prototype.test , https://tc39.es/ecma262/#sec-regexpexec ; v8 `src/builtins/builtins-regexp-gen.cc` (`RegExpConstructor`), `src/builtins/regexp-test.tq` (`RegExpPrototypeTest`). Dweller takes V8's shape for `test`: the matcher without a result array when `exec` is the original, `RegExpExec` otherwise (Dweller checks the `exec` value, not V8's whole fast-RegExp map).
