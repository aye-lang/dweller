# Q4.3: invalidation sets for class, id and attribute changes

## Status: done, 2026-11-16

- goal: a change to a class, an id or an attribute that selectors look at on an ancestor or a preceding sibling (`.dark .title`, `.open + .panel`) styles again the elements those selectors can match, not the changed element's whole subtree and all its following siblings.
- before: `restyleRoots` (engine/geometry.aye) asked `RestyleDeps.isDeep`: a "deep" change made the element a full root (every descendant styled again), and for every class change (`reachesSiblings` is true for a class token) every following sibling a full root too. A class toggled on `body` was a restyle of the whole document, counted as partial.
- design (Blink's invalidation sets, algorithm only):
  - `RestyleDeps.sets` (`KeySets`): a `KeySet` per change key (`simpleKeys`: a class, "class", `[class]`, an attribute name, "id"). `walkKeySets` reads every selector of the author, UA and quirks sheets. For each compound that is not the subject, `compoundReach` says where the subject is from the compound's element: `Descendant` (the next combinator is a descendant or child one: every later compound is below the element), `Sibling` (only `+`/`~` up to the subject), `SiblingDescendant` (a run of `+`/`~`, then below), with the distance in siblings when the run is all `+` (`ANY_DISTANCE` for `~`). The subject's feature (`compoundFeature`: id, class, attribute name or type of the last compound) goes into the set's `descendants`, `siblings` or `sibling_descendants`; a subject without one sets `all_*`.
  - `:is()`, `:where()`, `:not()` and `&` carry the reach of their compound into their arguments (`.row:not(.dark .skip) .note`: `dark` reaches descendants with `.note`). Any other argument (`:nth-child(of S)`, `@scope` limits, `:host()`), `::slotted()`, `::part()` and the attributes of `ALWAYS_DEEP` make the set `whole`; `:has()` keeps its own path (`HasUse`, `whole_has`).
  - `setRoots` (engine): for a change with a set that is not `whole` (`css.followsSets`: not children, state or pointer changes, not `deep_any`), the element is a shallow root, the descendants with a feature of `descendants` are shallow roots (`addSetDescendants`, `css.inFeatures`), and the next `sibling_distance` element siblings are shallow roots when they have a feature of `siblings`, with their descendants that have one of `sibling_descendants`. A class token also takes the set of `[class]`. An `all_*` set gives the full root as before. The old path stays for `whole` sets, `of S`, and an element under a `:has()` anchor.
  - `restyleSubtrees` takes a root out of `root_set` once it is styled, so a root below it reads the values (`inheritChain`) and does not style the chain between them again.
  - decision: one set of sibling descendants per key, not one per sibling feature (`.a + .b .c` looks for `.c` under each sibling in reach, not only under `.b` ones): the walk is a hash lookup per element and styles nothing. Blink keeps the pair.

## Left

- A children change (`appendChild`, `remove`, text) still makes the parent a full root: every descendant of the parent is styled again. Blink styles the inserted subtree and the siblings that structural selectors reach. This is the larger part of what sites restyle (wikipedia's `deps_whole_children`, PERF.md Q4.1 cause 7) and is not a class, id or attribute change.
- A shallow root that is an inclusive ancestor of a shadow host becomes a full root (`liftOutOfShadows`, `aroundHost`): on a page with any shadow tree, a class on `body` still restyles the document. Q4.2.
- An element under a `:has()` anchor, a sheet with `:nth-child(of S)`, and the `ALWAYS_DEEP` attributes take the old path.
- Sibling descendants per sibling feature (the decision above); `max_direct_adjacent` is kept per key (`sibling_distance`), not per feature.
