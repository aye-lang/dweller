#### P4.75h: 2D canvas rasterization speed
- goal: mistral's `canvasDraw` (12661 ms in 13126 calls, 965 µs each) at least 4× faster.
- design: first measure which draws cost (canvas size, fill or stroke or text, path size; one stderr line per slow draw under `DWELLER_TIMING`); then skip work that cannot show (a draw fully outside the canvas or the clip, a canvas that is never painted) and port Skia's coverage scan conversion for the paths.

  Done (pixels unchanged: `screenshot_fixtures`, `jsdom_fixtures`, `canvasbench` against the old binary and a mistral screenshot hash are equal): a fill path that is a pixel-aligned axis rectangle gets its coverage without the rasterizer (`canvas-rect-cover.aye`, `cover-rect.aye`); `clearRect` of such a rectangle without a clip zeroes the bitmap rows directly (`clear-canvas-rect.aye`); color paint copies the precomputed pixel at full and zero coverage (`paint-color.aye`); an unbounded composite (copy, source-in, ...) without a clip writes 0,0,0,0 where the source is transparent without the float formula. clearRect 5806 → ~0 ms, source-in fills 1986 → 561 ms.
  Left: (1) the image draws, now 60–75% of what is left: bilinear sampling of large downscaled images per pixel; Chrome samples a mipmap level there (medium filter quality), which would also change pixels, so it needs a reason for the goldens. (2) "a canvas that is never painted": mistral clears each canvas every frame and nothing reads it back in `dump`, so a per-bitmap list of pending draws, dropped by a whole-canvas clear and flushed by any pixel read, paint or source use, would skip nearly all of it; it touches every reader of canvas pixels (images, webgl, readback), so it is its own card. (3) Skia's coverage scan conversion (`SkScan_AntiPath.cpp`) for the clip and stroke renders (~1.3 s).
