# Q3.12: the agent socket is 0600 behind a 0700 directory and needs a token

- goal: a process that is not the user's, or that has not read the token the window wrote, cannot drive the window. `dweller --agent-socket PATH` makes PATH's directory `0700` when it is missing and refuses to start when it is not a directory, belongs to another user, or has any group/other bit; the socket file is `0600`; a random 32-byte token (64 hex digits) goes to `PATH.token` (`0600`); the first line of every connection must be `{"token":"HEX"}` with it, else the connection gets one error line, is closed, and none of its requests runs.
- design:
  - `ui/socket-dir-refusal.aye` `socketDirRefusal(sock) ?[]u8`: `mkdir(dir, 0700)` (EEXIST is fine), then `lstat` the directory (`ui/owner-mode-of.aye`: `statx` on Linux, the runtime's `aye_std_statbuf` on macOS, the same layouts `std.fs` reads) and returns why it is refused, or null. A missing parent stays the old `cannot listen on PATH`.
  - `ui/write-token.aye` `writeToken`: `std.crypto.randomBytes` (`getentropy`: the OS CSPRNG on macOS, `getrandom` underneath on glibc) and `std.encoding.hexEncode`, written with `O_CREAT|O_EXCL` mode `0600` after removing a stale file. `startAgents` refuses the directory, writes the token, then listens, so the token is there before the socket is.
  - `listenAt` `chmod`s the socket `0600` right after `bind`, while it is still `PATH.l` and not listening; the directory is already `0700`, so there is no moment anyone else can reach it. `removeSocket` (now `ui/remove-socket.aye`) removes `PATH.token` too, which also cleans a crashed Space's directory.
  - `ui/admit-conn.aye` `admitConn`: before a connection is served or relayed, its first line is read and checked with `agent.hasToken` (`agent/has-token.aye`: JSON object member `token`, `std.crypto.constantTimeEqual`). No newline within 256 bytes, the end first, or a wrong token: `ui/refuse-conn.aye` sends `{"id":null,"ok":false,"error":"no token: ..."}` and drops it. `Agents.ever` (for `--exit-when-idle`) is set only by an admitted connection, so a refused one cannot end a test window.
  - `connectTo` sends the token line (`ui/send-token.aye`, from `PATH.token`) after it connects: `dweller connect` and the window's connection to each Space go through it, so Spaces (whose sockets sit in a `mkdtemp` `0700` directory) check the token too. The hello and everything after it are unchanged.
  - tests: the harness's raw connections (`AgentConn::open`, `window_agent_session`) send the token line first (`token_line`), and their sockets moved to `target/sockets/` (the window makes it `0700`; `target/` itself is `0755` and is refused). `window_agents_errors` uses `target/no-such-dir/sub/x.sock` for "cannot listen" (the window now makes one missing level).
  - docs: `docs/agent-protocol.md` ("Who may connect", the Spaces first line, `dweller connect`), `browser/README.md`; examples use `~/.dweller/agent.sock` instead of `/tmp/dweller.sock`.
- files: `browser/ui/{agents,socket,admit-conn,refuse-conn,owner-mode,owner-mode-of,socket-dir,socket-dir-refusal,token-file-path,write-token,send-token,remove-socket}.aye`, `browser/agent/{has-token,has-token_test}.aye`, `tests/browser.rs`, `docs/agent-protocol.md`, `browser/README.md`
- reference: chromium `chrome/browser/devtools/remote_debugging_server.cc`, `content/browser/devtools/devtools_http_handler.cc` (`RequestIsSafeToServe`). Dweller takes the rule "no remote control without an explicit opt-in, and check who asks before serving": the socket exists only with `--agent-socket`, and the token plus `0600`/`0700` stand in for DevTools' Host/Origin check (a Unix socket has no Host header).
- verify:
  - `python3 browser/tools/check_layers.py`, `python3 browser/tools/check_taste.py`, `aye check browser`: exit 0.
  - `scripts/capped.sh cargo test --release --test browser -- window_agent_socket_token window_agents_errors aye_unit_tests`: 3 passed (`aye_unit_tests` runs `aye test browser`, with `has-token_test.aye`).
  - `scripts/capped.sh cargo test --release --test browser -- agent_sessions window_spaces`: 10 passed (every `window_spaces*` test; with `window_agents_errors` and the new test these are all the tests that open the socket).
  - new test `window_agent_socket_token` (headless): directory `0700`, socket and token `0600`, token 64 hex; a raw connection without the token and one with a wrong token each get the error line and EOF, and their `tab_new` never ran (`tabs 1, showing 1` at exit); the normal client works; socket and token are gone after; a `0755` directory is refused with `cannot listen on DIR/x.sock: other users can open its directory (it must be 0700)`.
