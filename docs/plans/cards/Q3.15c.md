# Q3.15c: WPT `mixed-content` to its target

- goal: criterion X2 for `mixed-content`: 53.3% in the table, 1276/2281 (55.9%) measured here before the card; target 89 (2030 of 2281).

## Status: in progress, 2026-11-19 (slices 1 and 2 are green and pushed)

Score now: 1621/2281 (71.1%), floor 50, target 89. `conformance.py check`: no area fell.

How the area is built: 388 files, almost all generated (`mixed-content/gen/<source context>.<policy delivery>/<opt-in|unset>/<resource type>.https.html`): a resource type (30 of them) is requested from a source context (the top page, a same-origin or srcdoc or `data:` frame, a dedicated or shared worker) and the server says whether the request came, came upgraded, or did not come. A file's subtests run one after the other, so one request that never settles times out its file and the rest are "not run".

Slice 1 (three causes, 1276 -> 1465, +189):
- a media element that a script creates and inserts never started loading unless a script read one of its media properties (Q5.9a's Left: the observer was made with the first element a script touched). `media-element.js` now starts watching when `document.createElement` makes a media element, and a noticed element in `NO_SOURCE` selects again only when a `source` arrives (a late notice of the element itself ran the selection, and its error events, a second time). This is the media lane's file: three small edits.
- audio and video were fetched as a script's `fetch()` and so blocked on a secure page; Mixed Content makes them upgradeable like images. `net.Kind` has `Audio` and `Video` (request codes 7 and 8, `Sec-Fetch-Dest: audio|video`, `Accept: */*`, kept out of the HTTP cache like a script's fetch because the media loader asks byte ranges). `fetchStart` takes the destination as its tenth argument (`engine/fetch-destination.aye`); `net/upgradeable.aye` says which kinds a secure page upgrades. Q3.5's Left item "audio/video have no `Kind`" is closed.
- `<object type="text/html" data>` loaded nothing, so neither `load` nor `error` came. It is now a frame element (`engine/is-html-object.aye`, `frame-address-attr.aye`): a nested document with the frame rules (CSP `frame-src`, mixed content, X-Frame-Options, the frame cap), counted in `frames.length`, and its `load` fires. Other `object` types are unchanged.
- tests: `net/mixed-content_test.aye` (audio and video upgrade), `tests/browser/media_scripted.rs` (`browser/tests/media/scripted.html`: one `loadeddata` and one source `error`, without a touch), fixture `jsdom/object_html` (new golden: "load, frames: 1"; the `image/png` object beside it loads no document).
- found on the way: my first version passed the destination as argument 8 of `fetchStart`, which already means "stream the body": two media requests then got each other's results and the media lane's `media_element_wav` and `media_element_ranges` failed. Caught by the whole suite before the push.
- verify (2026-11-19, on the tree merged with the wave branch 492db3e0): `cargo test --release --test browser` 334 passed, 0 failed after the wave merge of e8898d3b (before that merge 323 passed; one earlier run: 322 and `websocket::websocket_echo_in_renderers` failed, feat-net's test, the second time today; it passes alone); `aye test browser` 343 passed; `aye check browser`, `check_taste.py`, `check_layers.py`, `gen_property_ids.py --check` exit 0. `wpt.py run mixed-content`: 1465/2281.

Slice 2 (three causes, 1465 -> 1621, +156):
- the workers of a frame's page were never pumped on the virtual clock: `waitWorkers` took only the top page's script, so a frame's worker never delivered its message or error. `pump-page-workers.aye` and `page-workers-busy.aye` walk the page and its frames.
- a module worker whose static import cannot load (missing, blocked as mixed content) ended silently: `runModuleScript` answers null for a failed fetch and the worker ignored it. `workers/run-worker-source.aye` throws a `TypeError`, which becomes the `error` event at the `Worker`.
- `self.origin` of a srcdoc or blank frame was `"null"` (the origin of its own `about:` URL): the window's `origin` getter now asks `ak.winOrigin`, the page's origin, which such a frame inherits. The worker's same-origin test compared with `location.origin`; it compares with `origin` (`workers/worker-page.js`), so a srcdoc frame can start its parent's-origin worker script.
- the media lane fixed its own Left item natively (`ak.mediaWatch`) while this card ran; the merge took its version and dropped this card's `createElement` wrapper. Kept from slice 1 in its file: `selectResource` again only when a `source` arrives, and the destination argument.
