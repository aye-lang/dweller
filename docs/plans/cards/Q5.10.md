# Q5.10: contenteditable, the core of `execCommand`, the async Clipboard API

- goal: a page can read and write the clipboard with `navigator.clipboard`; an element with `contenteditable` takes the caret, typing, deletion, Enter, and copy, cut and paste; `document.execCommand` does the core commands on the selection. Row Q5.10 of `foundations.md` (Chromium `core/editing/`, `modules/clipboard/`). Measured by window tests in one process and with `DWELLER_PROCESS=site`, and by WPT (`clipboard-apis`, `editing`, `selection`: none is fetched yet; each slice that uses one adds its area).
- facts found first (2026-11-16):
  - Nothing of the three exists: no `contenteditable` handling, no `execCommand`, no `navigator.clipboard` (grep of `browser/`).
  - `Range` and `Selection` are stubs in the prelude (`prelude.aye` about line 3758): boundary points and `collapse`, `selectNodeContents`, `insertNode`; no `deleteContents`/`extractContents`/`compareBoundaryPoints`, `getClientRects()` is empty, and the `Selection` object is not connected to anything the window draws or the mouse selects.
  - Text fields are edited on the Aye side (`dom.insertText`, `doc.controls`, `engine.caretRect`, `engine.selectionRects`); copy, cut and paste of a field go to the SDL clipboard from the UI (`ui/forms.aye` `copySelection`, `paste`), and with a renderer per site through `Edit { command, typed }` (browser to renderer) and `Clipboard { copied }` (renderer to browser, accepted only for a copy the browser asked for: `ui/take-clipboard.aye`).
  - User activation is tracked in the prelude (`hasActivation()`, 5 s after a click or key); `isSecureContext` is always true.
- slices:
  1. The async Clipboard API, text: `navigator.clipboard.writeText/readText`, `write/read` with `ClipboardItem` of `text/plain`; refused (`NotAllowedError`) without transient user activation. One process: the SDL clipboard through an engine hook. With a renderer per site: IPC 132 `ClipboardWrite`, 133 `ClipboardRead`, 134 `ClipboardText`; the browser serves only the process of the tab in front. Verify: a window test (click, write, read back) in one process and with `DWELLER_PROCESS=site`.
  2. A real `Range` and `Selection` for editing: `compareBoundaryPoints`, `deleteContents`, `extractContents`, `cloneContents`, `surroundContents`, `toString` across nodes, `Selection` with direction (`anchor`/`focus`, `extend`, `setBaseAndExtent`, `deleteFromDocument`, `containsNode`), live ranges that follow DOM mutations. Verify: `dom/ranges` (in the area `dom/api`) and a new area `selection`.
  3. `contenteditable` in the DOM: `contentEditable`, `isContentEditable`, `inputMode`, editing hosts are focusable, `:read-write`, and `document.execCommand` with `queryCommandSupported/Enabled/State/Value` for `insertText`, `delete`, `forwardDelete`, `insertLineBreak`, `insertParagraph`, `insertHTML`, `selectAll`, `bold`, `italic`, `underline`, each firing `beforeinput` and `input` with its `inputType`. Verify: a dump test of each command; a subset of WPT `editing/run`.
  4. The caret in page text: a point to a DOM position and back (hit testing in the line boxes), the caret and the selection of an editing host drawn by the window, the `Selection` object moved by clicks and arrow keys. Verify: window tests (click, type, `--state`, pixels of the caret).
  5. Typing: text, Backspace, Delete, Enter and the arrow keys in an editing host go through slice 3's commands; with a renderer per site the keys already reach the renderer. Verify: a window test in both modes.
  6. Clipboard events and keys: `copy`, `cut`, `paste` events with `clipboardData` (`DataTransfer`), Cmd+C/X/V on a page selection and in an editing host, `execCommand('copy'|'cut'|'paste')`. Verify: a window test in both modes.
  7. Undo and redo of edits (`execCommand('undo')`, Cmd+Z). Verify: a window test.
- defaults taken (nobody to ask): reading the clipboard asks no permission prompt (Q5.12 builds prompts in another lane); it needs transient user activation instead, as writing does; only `text/plain` is carried (no `text/html`, no images).

## Done: slice 4, the caret (2026-11-17)

- The map between a layout text box and its DOM text: `engine/aligned-text.aye` walks the node's text and the shown text together (white space collapsed or dropped), `utf16-to-byte.aye` and `byte-to-utf16.aye` convert script offsets. `engine.textCaretRect(page, node, offset)` gives the caret's rectangle from the line fragment that holds the offset; `engine.caretAtPoint(page, x, y)` gives the text node and offset nearest a point (the fragment on that line nearest in x, then the nearest character boundary).

## Done: slice 7, undo and redo (2026-11-17)

- `engine/editing-history.js`: per editing host, a stack of snapshots (the host's markup and the caret as a path of child indexes), at most 100; every command of `execCommand` records one before it runs. `undo` and `redo` put a snapshot back, with a cancelable `beforeinput` and an `input` of type `historyUndo` or `historyRedo`; a new edit empties what could be redone. `queryCommandEnabled('undo'|'redo')` answers by the stacks.
- Keys: Cmd+Z and Cmd+Shift+Z. One process: `ui/host-cmd-key.aye`. A renderer: the browser's `Edit` message carries commands 4 (undo) and 5 (redo) besides 0 to 3 (`ui/edit-command-of.aye`, `renderer/answer-all.aye` accepts up to 5, `renderer/edit-command.aye`); for a text field they do nothing, as before.
- decision: snapshots of markup, not Chromium's steps of commands: node identity inside the host is lost by an undo (a script holding a child node holds a detached one afterwards).
- verify: `cargo test --release --test browser`: 285 passed, 0 failed (302 s), with the new `editing_undo_redo_in_host` (two edits, three undos of which the third finds nothing, a redo, an edit, a redo that finds nothing; in one process and with `DWELLER_PROCESS=site`). `aye test browser`: 320 passed. `check_taste.py`, `check_layers.py`, `gen_property_ids.py --check`, `aye check browser`: exit 0.
