# P10.54d: lazy images in inner scrollers; the real device pixel ratio

- goal: (1) the regression of P10.54c (blocks merging it): lazy images in inner scroll containers and multicol never loaded; an image in the list of available images must load at once even when lazy; `loading` lazy → eager resumes the fetch; `currentSrc` of a deferred lazy image is the selected source; (2) the window's real DPR in `devicePixelRatio`, `resolution` media and srcset selection, `--dpr N` for dumps; (3) `viewport-change` re-selection.
- before: `images` 4071/5348 (76.1%), `intersection-observer` 168/355 (47.3%) on the P10.54c build.
- design: the lazy load observer gets the HTML lazy-load scroll margin: `IntersectionObserver` takes `scrollMargin` (the intersection-observer spec's option; each scroll container between target and root clips with its padding box grown by it, `scrollClip`), and `lazy-images.js` passes 1250px for both margins (Blink's 4G distance). Script scrolls of inner scrollers already count as geometry changes, so the layout hook re-runs the check at the next frame; no new per-frame work. `akImageLoad` decides deferral after the source selection (`deferredImage`): the selected URL comes back as a string (the prelude's request keeps it as `currentSrc`, marked `lazy`), unless the URL is in the page's decoded images (`imageAvailable`) and the img has no `crossorigin` (images are fetched no-cors), then it is revealed and loads now. A request that replaces a lazy one is `resumed`: its tasks do not delay the load event (`imageTask`'s third argument). A `loading` change on a lazy request runs `imageUpdate`; the observer skips targets whose request is no longer lazy. DPR: `css.devicePixelRatio()` (process-wide, 1 by default) feeds `resolution`/`pixel-ratio` media, srcset (smallest density ≥ DPR) and `window.devicePixelRatio` (`ak.devicePixelRatio`); the window sets it from its backing scale in `resize`, `dweller dump --dpr N` sets it, so goldens stay at 1.
- files: `browser/engine/` (new: `deferred-image.aye`, `image-available.aye`, `ak-device-pixel-ratio.aye`; wiring in `image_api.aye`, `prelude.aye`, `lazy-images.js`, `sources.aye`, `window_api.aye`), `browser/css/` (new: `device-pixel-ratio.aye`; `media.aye`), `browser/ui/window.aye`, `browser/main.aye`, `browser/tools/wpt_areas.json` (new area `intersection-observer`, threshold 0), fixture `browser/tests/net/lazy_scroller.html`, test `window_lazy_images_in_scroller` in `tests/browser.rs`.
- golden: none changed.
- reference: https://html.spec.whatwg.org/multipage/urls-and-fetching.html#lazy-loading-attributes, https://w3c.github.io/IntersectionObserver/#dom-intersectionobserverinit-scrollmargin; chromium `third_party/blink/renderer/core/html/lazy_load_image_observer.cc`, `core/intersection_observer/intersection_geometry.cc` (algorithm only).
- verify: `python3 browser/tools/conformance.py run images intersection-observer` before/after; `check_taste.py`, `check_layers.py` → 0; `cargo test --release --test browser -- window_ screenshot_ paint scroll style_fixtures layout_fixtures jsdom_fixtures` → 0 (66 passed, no golden changed). `window_lazy_images_in_scroller`: 30 lazy 200px inline images in a 400px horizontal scroller; the server's `/log` has 9 image requests after load and 18 after a key handler scrolls it 2000px. `window_lazy_images` (P10.54c's 100 images) still 16 / 101. `DWELLER_TIMING` over 40 page-downs of `lazy_images.html`: one `layout` per run and `ui_loop` 0.5–0.7 ms mean on both the P10.54c and this fast build.
