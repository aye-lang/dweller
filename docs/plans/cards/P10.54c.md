# P10.54c: lazy images

- goal: the `left` list of P10.54b for real-site feel: (1) `loading=lazy` (an image farther than the lazy-load margin from the viewport is not fetched until scrolling brings it near), (2) the window's real device pixel ratio (`devicePixelRatio`, `resolution` media, srcset/`image-set()` selection, `--dpr N`), (3) `viewport-change` re-selection and `sizes-auto` with layout widths.
- before: `images` 4052/5348 (75.8%) on the P10.54b build.
- design: HTML "will lazy load element steps": only with scripting on (`ImageCache.scripting`, set by `updateImages`/`preloadImages` from `scriptingEnabled()` and by the script bridge); without scripts every image stays eager, so dumps without `--js` do not change. `lazyDeferred` is true for an `img` with `loading=lazy` that is not in `ImageCache.revealed`; rendering (`fillImagesWith`, `prefetchImages`) skips it and the script request (`akImageLoad`) answers `false`, which leaves the request pending (not complete, no event, no task: it does not delay the load event). The prelude then hands it to the lazy load intersection observer (`lazy-images.js`, an internal `IntersectionObserver` with a 1250px root margin, Blink's 4G distance): when it intersects, `ak.imageReveal` adds it to `revealed` and the request starts again (`imageUpdate`), loading in the background as any other. The observer runs at the window's animation frames, so scrolling brings images in; a dump's scroll steps do too.
- files: `browser/engine/` (new: `lazy-deferred.aye`, `ak-image-reveal.aye`, `lazy-images.js`, `lazy-images-prelude.aye`; wiring in `images.aye`, `image_api.aye`, `prelude.aye`, `script.aye`), fixture `browser/tests/net/lazy_images.html`, test `window_lazy_images` in `tests/browser.rs`.
- golden: `jsdom/lazy_sections.{tree,a11y}` (its lazy image, 2000px down, loaded at once before; now it loads when the dump's scroll brings it near, after the sections above filled in: `image loaded at 2130` → `2162`), and `dump_scrolls_through` now expects it still loading with `--no-scroll`; the fixture's comment says so.
- reference: https://html.spec.whatwg.org/multipage/urls-and-fetching.html#lazy-loading-attributes; chromium `third_party/blink/renderer/core/html/lazy_load_image_observer.cc`, `core/loader/lazy_image_helper.cc` (algorithm only).
