# Q4.6b: an attribute change costs only what it changes

- goal: a change to an attribute other than `class` and `style` no longer ends incremental layout. One that no selector names and layout does not read lays out nothing; one that selectors or presentational hints see restyles the element (and what its selectors reach) and lays out again only the boxes whose values changed; one that layout reads from the element lays out that element's boxes again. The `local:attr` refusal of `localChanges` goes away.
- cause: Q4.1 (PR #264): `localChanges` refused every noted change that was not to children, to a class, to `style` or a pointer state. mistral idled with 110 `local:attr` refusals per 10 s, each a full layout; zol's scroll had 62 (a scroll-spy that sets attributes).
- design:
  - the style side was already there: every attribute change is noted (`changedAttr`, `css.attrChange`), `styleInputs` hashes every attribute but `class`, and `restyleRoots` restyles the element alone (`shallow`) when no selector looks at the attribute on an ancestor or a sibling (`RestyleDeps.isDeep`), its subtree and siblings when one does. Presentational hints (`css/hints.aye`: `width`/`height` of img, video, iframe, `bgcolor`, ...) and UA rules (`[hidden] { display: none }`, `dir`) are in the cascade, so their changes show up as values that layout reads (`Styles.moved`), and those elements' boxes are built again, as for a class.
  - what was missing is what layout reads from the DOM and not through styles. `layoutReadsAttr` (engine/layout-reads-attr.aye): a table of `element/attribute` pairs from a grep of `browser/layout` (`td/colspan`, `ol/start`, `li/value`, `details/open`, `svg/viewbox`, `canvas/width`, `canvas/height`, `*/lang`, `frameset/cols`, the form controls' `type`, `value`, `size`, `multiple`, `placeholder`, `rows`, `cols`, `option/label`, `selected`, `disabled`). Such a change puts the element in `dirty`; `relayoutDirty` already lifts it to the nearest box that can be built again (a table cell to the block around the table, a list item to its list, a control or canvas to its block).
  - `localChanges`: any change that is not to children nor a pointer state takes the path of class and `style` changes (`showsAttr` for `content: attr()`), plus `layoutReadsAttr`. Unmatched `data-*` and `aria-*` changes: one shallow restyle of the element, no values move, no relayout (Blink: no invalidation set, `core/css/invalidation/rule_invalidation_data.cc`).
  - `src`, `alt` and the other `STYLE_NEUTRAL_ATTRS` are unchanged (noted as a change to the element's children).
- `relayout:dropped` (not fixed, not local): zol's scroll-spy toggles `active` on `li`s of a side nav inside `div.guide-widget`, an out-of-flow box (fixed). `canRebuild` refuses boxes in or under out-of-flow boxes (`blockFlowUp`), so `relayoutDirty` climbs to `body` and builds the whole document again (7575 boxes) each time. The old boxes stay in `Tree.boxes` until a full layout, so the second such rebuild passes `2 * built + 1024` and refuses. Every dirty relayout there already costs a full layout. Follow-up: let an absolutely or fixed positioned box be built and laid out again alone (its containing block and static position are known from the last layout; Blink's relayout boundary, `core/layout/layout_object.cc` `MarkContainerChainForLayout`, stops at an out-of-flow positioned object). Compacting the box list would only hide the cost.
- files: `browser/engine/layout-reads-attr.aye` (new), `browser/engine/geometry.aye`, `browser/tests/ui/relayout_attr.html`, `browser/tests/ui/relayout_attr_unmatched.html` (new), `tests/browser.rs` (`window_relayout_attr`), `docs/plans/cards/Q4.6b.md` (new)
- verify: `window_relayout_attr` (40 ticks, `--frames 600 --until-idle`, `DWELLER_LAYOUT_CHECK`): a `[data-y]` toggle, an img `width`, `hidden`, `td colSpan`, a canvas `width` and `ol start` give no full layout after the first frame and 30 or more dirty relayouts, each equal to a full layout; `data-x` and `aria-label` alone give no layout at all. With `layoutReadsAttr` left out the check finds 31 differences (`td` place, the canvas's line). The `layout`, `window_` and `dump` tests in one capped run; mistral and zol `DWELLER_LAYOUT_WHY` and W7 before and after; `$AYE test browser`, `$AYE check browser`, `check_taste.py`.
