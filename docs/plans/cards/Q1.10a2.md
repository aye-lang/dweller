# Q1.10a2: coverage-guided fuzzing

- goal: `dweller fuzz TARGET` keeps the inputs that reach new code and mutates those too, so the corpus grows from new edges. Without the coverage build it behaves as before.
- cause: Q1.10a fuzzed blind because Aye had no edge counters. Aye's `--coverage` (aye-lang/aye#30, card O7.8) makes clang keep one byte per CFG edge and `std.coverage` reads them.
- design:
  - `fuzz-loop.aye`: `runOne` calls `coverage.reset()` before the target runs; afterwards `observeCoverage` ORs `coverage.counters()` into `Corpus.seen` (`coverage-merge.aye`, one bit per edge and hit-count bucket: 1, 2, 3, 4-7, 8-15, 16-31, 32-127, 128+, `bucket-bit.aye`). An input that sets a new bit is copied into the in-memory corpus and written to the corpus directory (`keep-input.aye`; file name the FNV-1a of the bytes, so a restart or a second run does not duplicate it). The seeds are run first and only mark `seen`.
  - parents: `Corpus.pick` (`pick-index.aye`) draws two indices and takes the larger when the build has coverage: uniform over the corpus, newest weighted up. Without coverage it is the uniform draw it was, with the same random numbers, so a blind run with a seed is unchanged.
  - corpus directory: `--corpus DIR` when given (the nightly job's cache dir), else `target/fuzz/TARGET/corpus`; the seeds in `browser/tests/fuzz/` are never written to.
  - output: with coverage, a line `coverage TARGET: N s, corpus C, edges E/T` every 20 s and at the end (E: edges hit so far, T: all edges of the binary). Nothing extra without it. `fuzz TARGET: N inputs in M ms` is unchanged, so `fuzz.py` parses it as before.
  - build: `browser/build.sh [OUT] --coverage` passes `--coverage` to `aye build`; `fuzz.py run TARGET --coverage` builds `target/dweller-fuzz-cov` with `--coverage --mode debug` when missing (the O7.8 card: at -O2 clang folds branches into selects, so a fuzz build keeps them as branches in `debug`). The nightly workflow's fuzz job builds with `browser/build.sh target/dweller-fuzz --coverage --mode debug`.
- references: `compiler-rt/lib/fuzzer/FuzzerLoop.cpp` (`RunOne`: reset the counters, run, merge the new features, `AddToCorpus` when there are any), `FuzzerCorpus.h` (`ChooseUnitIdxToMutate`, weights), `FuzzerTracePC.cpp` (the counter buckets). Dweller takes: the run-and-keep loop, the 8 hit-count buckets, and a corpus picked with a bias to the newest. Not taken: per-input weights by new-edge count and rarity, corpus minimization (`-merge`), value profile, `trace-cmp`.
- files: `browser/fuzz/{corpus,coverage-merge,coverage-merge_test,bucket-bit,pick-index,observe-coverage,keep-input,fnv1a,free-corpus,report-coverage,seen-count,mutant,run-one}.aye` (new), `browser/fuzz/{fuzz-loop,fuzz-main}.aye`, `browser/build.sh`, `browser/tools/fuzz.py`, `.github/workflows/fuzz.yml`, `docs/browser.md`.
- verify (2026-11-09, aye-81deafd = aye#30, seed 1; the coverage binary is a `debug` build and the plain one `safe`, run side by side on a shared 4-core box, so the input rates only give an order of magnitude):
  - `aye check browser` clean, `aye test browser` 286 passed (two new tests), `check_taste.py` and `check_layers.py` exit 0, `browser/build.sh` exit 0 (also with `--coverage --mode debug`).
  - html, 120 s, coverage build (seeds: 86 files):

## Status: done, 2026-11-09

Left:
- The fuzz CI job works only once `AYE_REV` includes aye#30 (the whole browser imports `std.coverage` now, so an older `aye` does not compile it either).
- The debug build prints `leak:` lines for the `css` target at exit (5187 lines from `std/text/text.aye:487`, `toOwned`; exit code 0): a leak of the css target's serializer that the safe build does not report, not of this step.
- The corpus grows by hit-count buckets, which is what libFuzzer's counters do; it is not minimized. There is no `-merge` step, so the nightly cache keeps every kept input.
- A debug build is about 4 times slower than the safe one; the hit edges are 1 to 4% of the binary's edges (the binary holds the whole browser, a target reaches its parser).
- `pc-table` to name the edges in a report, `trace-cmp` for comparison-guided mutation, rarity weights for the parent choice.
