# V3: one component API, two implementations

The card is in `docs/plans/vision.md`. This file holds the design note
the card asks for, the status, and what is left.

## Design note: the component API

A component is one Aye module with two exports and a few imported DOM
functions. It is what the framework's F4 island already is
(`framework/examples/pages/islands/counter/client.aye` in aye-lang/aye,
`web.islandsScript()`), with the functions an island did not need
because its markup came from the server.

Exports (C ABI, so the same on wasm32 and natively):

```
mount(root: i32, props: [*]u8, len: usize)   build or adopt the subtree of `root`
event(id: i32)                               a listener the component named fired
```

Imports. An element is an `i32` handle; `root` is handle 1; 0 is "none".
Strings are pointer and length, UTF-8.

```
dom_create(tag, len) -> el
dom_append(parent, child)
dom_set_attr(el, name, name_len, value, value_len)     class, id and style are attributes
dom_set_text(el, s, len)                               textContent              (F4)
dom_on(el, name, len, id)                              listen; `event(id)` runs (F4)
dom_query(root, selector, len) -> el                   first match under root   (F4)
dom_value(el, out, capacity) -> len                    a text field's value
dom_set_value(el, s, len)
```

Two implementations:

- wasm32, in any browser: JS glue over the page's DOM
  (`examples/native/counter/widget/glue.js`; the framework's
  `islands.js` has the three F4 functions).
- native: `browser/shell/dom-*.aye` define the same C symbols over
  `dom.Document` (`pub extern fn dom_create(...)`), so the component's
  body-less `extern fn` declarations link to them. `shell.mount(app,
  root, widget.mount, widget.event, props)` makes `app` the document the
  functions act on and `root` handle 1.

State and re-render: the component keeps its state in module variables
and the handles of the elements it changes, and writes the change with
`dom_set_text` or `dom_append` in `event`. No virtual DOM and no diff:
the counter and the list need neither. The engine side is already
incremental (V2): a changed element is restyled and its box rebuilt.

Not in the API yet, by decision: removing a child, reading an attribute,
event data (which key, which target), timers, and several components in
one program (the handles and the exported names `mount` and `event` are
per program natively, per module in wasm).

## Status: done, 2026-11-16 (without the framework's packaging, see Left)

Done note:
- The framework's F4 is in the pinned compiler (`AYE_REV`): islands with
  `dom_query`, `dom_set_text`, `dom_on`, `mount` and `event`. So the
  card did not have to stop at the native half.
- `examples/native/counter/widget/widget.aye` is the counter written
  once against the API above: the heading, the count, `+1`, `Reset`, the
  text field with `Add`, and 1000 rows. It imports nothing but the DOM
  functions (no `std`), so its wasm is small.
- Native: `browser/shell/` defines the eight DOM functions over
  `dom.Document` (`dom-create.aye`, `dom-append.aye`, `dom-set-attr.aye`,
  `dom-set-text.aye`, `dom-on.aye`, `dom-query.aye` with the `css`
  selector matcher, `dom-value.aye`) and `shell.mount`. The counter app
  (`examples/native/counter/main.aye`) is now 24 lines: it mounts the
  component on the body. V2's and V5's tests run on it unchanged and
  pass (the window, the incremental layout, the agent session).
- wasm32: `aye build examples/native/counter/widget --target
  wasm32-freestanding`, loaded by `widget/glue.js` (the JS
  implementation of the same functions).
- Verify: `native::native_counter_component` builds the wasm, puts it in
  a page with the glue, lets `dweller dump --tree --js` run it with five
  button clicks, a typed value and `Add`, and runs the native app with
  the same input: the two documents under the mount root are equal line
  for line (2 000 lines). Whole suite on the merged tree, cloud machine,
  proxy variables unset: 268 passed, 0 failed (`target/v3.log`);
  `check_taste.py`, `check_layers.py`, `gen_property_ids.py --check`,
  `aye check browser`: 0.
- A golden changed, read before blessing: the shell's `--dump` now writes
  what `dweller dump --tree` writes (the same quoting, no `value=`
  on text fields), so that the two can be compared; `expected/final.tree`
  lost `value=""` on one line.
- Decision: the native functions are C symbols (`pub extern fn`), not an
  Aye interface, because that is what makes one source file build for
  both targets with no conditional code: wasm imports them from `env`,
  the native linker finds them in the shell.

Left:
- The framework side: `web.islandsScript()` in aye-lang/aye has only the
  three F4 functions; the five new ones live in `glue.js` here. Move
  them there (a card in aye-lang/aye), and let `web.island` render a
  component that builds its own subtree (today an island adopts
  server-rendered markup).
- Server rendering of the same component (the third use: `render` to
  HTML) is not shown; the component only builds through the DOM
  functions.
- One component per native program (see the design note); `props` are
  passed but the counter does not read them; only `click` listeners are
  taken natively.
- No removal, no keyed list update: `Add` appends. A list that changes
  in the middle is the first thing that will ask for more than this API.
- The wasm half of the test needs `wasm-ld`; where it is missing the test
  says so and runs only the native half's build.
