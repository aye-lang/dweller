# Q4.23: an inline cache for DOM wrapper and primitive property loads

- goal: Q4.21 ranked step 7 (cost 7): on zol jQuery's Sizzle runs in bytecode and every load on a DOM wrapper leaves the inline cache (kind 6: `getAttribute` 903k, `ownerDocument` 751k, `inTemplate` 751k, `nodeType` 194k, `className` 186k); bbc has kind 0 (primitive receivers, `charCodeAt` 1.41M), kind 6 (`length` 524k on arrays) and kind 5. Give the VM's existing IC (`browser/js/vm-load-named.aye`, `vm-ic-*.aye`, `IcEntry`/`IcCase`, the stub cache) entries for host objects and primitive receivers, the way V8's LoadIC handlers do, without a new IC architecture.
- how host objects expose properties (found): a DOM wrapper is a `Class.Host` object (`newHostObject`, tag `TAG_NODE`) whose prototype chain is ordinary objects (`HTMLDivElement.prototype` → `HTMLElement.prototype` → `Element.prototype` → `Node.prototype`); `nodeType`, `className`, `parentNode` are native accessors (`accessor` in `engine/dom_api.aye`), `getAttribute` a native method, `ownerDocument` a prelude JS getter that calls `ak.inTemplate`. Only tags with `HOST_NAMED` (style, dataset, live lists, other windows) have host hooks (`getNamed`/`setNamed`/`hasNamed`, V8's interceptors). Three things kept them out of the IC: (a) `cacheable` refused every `Class.Host`; (b) the prelude deletes members from `HTMLElement.prototype` and `Node.prototype` (`moveMembers`, `moveTo`), and `removeProp` leaves an object shapeless for good, so every chain walk stopped there; (c) `ak` has more than `MAX_SHAPE_PROPS` (128) natives, so it is a dictionary and `ak.inTemplate` was always generic.
- design:
  - `cacheable` (moved to `cacheable.aye`, split into `ordinaryLookup`): a host object without `HOST_NAMED` is ordinary (V8: an API object without interceptors keeps its map); a `Class.String` object is ordinary except `length` and indices, like arrays (so `String.prototype`, itself a String object, can be a holder).
  - cases are keyed by (shape, prototype), as a V8 map includes the prototype: `icCaseFits` (find, record, stub probe, inline hit), own cases record the receiver's prototype, the stub index hashes it. All element wrappers have shape 0 but a different prototype per tag; with shape-only keys a site seeing `div` and `span` replaced its one case on every load.
  - `heapMakeFast` (V8 `JSObject::MakePrototypesFast`/`MigrateSlowToFast`): the load chain walk (`vmIcChainCase`, split out of `vmIcLoadCase`) gives a shapeless prototype a shape again from its property order (at most 8 times per object, `Obj.reshapes`, and under `MAX_SHAPE_PROPS`); its dictionary index is dropped (a shaped object has none). The walk then marks it `used_as_proto`, so later changes move `proto_epoch` as for any holder. This also covers `delete Function.prototype.x` (Q4.16a's `call` repro) for loads.
  - primitive receivers (`vmLoadPrimitive`, `vmIcHitPrimitive`, `vmPrimProto`): a string, number, boolean or bigint loads through a case with the pseudo shape `IC_SHAPE_PRIMITIVE` and the prototype of its wrapper (`String.prototype`, ...) as the case's prototype, validated by `proto_epoch` like every prototype case; the inline `GetNamedProperty` hit (`vmIcHitProp`) serves it. String `length` returns `len16` (V8 `LoadIC_StringLength`); index keys stay generic.
  - `vmLoadNormal` (V8 `LoadHandler::kNormal`, `kArrayLength`): an own property of a dictionary-mode receiver (`ak`, any receiver past 128 properties or after a delete) is read through `findProp` without `getProp`; array, arguments and typed array `length` return the length directly, in `getFrom`'s order.
  - accessor holders (all DOM getters) hit in `vmLoadNamed` and call the getter with `call0`, as before through the slow path; the inline hit stays data-only.
- references: V8 `src/ic/ic.cc` (`LoadIC::Load`: `MakePrototypesFast` before the lookup, primitive receivers looked up from their wrapper map; `LoadIC::ComputeHandler`: `LoadIC_StringLength`, `LoadHandler::LoadApiGetter`/`LoadAccessorFromPrototype` with the holder, `LoadNormal` for dictionary holders), `src/ic/handler-configuration.h` (`LoadHandler::Kind`: `kNormal`, `kApiGetter`, `kAccessorFromPrototype`, `kInterceptor`), `src/objects/map.h` (the prototype is part of the map), `src/objects/js-objects.cc` (`JSObject::MakePrototypesFast`). Dweller takes: host objects without interceptors are cacheable, (shape, prototype) keys, prototypes made fast again on an IC walk, primitive receivers through the wrapper's prototype, the string/array length handlers and the dictionary-receiver handler.
- files: new `browser/js/{cacheable,ic-case-fits,heap-make-fast,vm-ic-chain-case,vm-ic-hit-primitive,vm-load-normal,vm-load-primitive,vm-prim-proto}.aye`; changed `browser/js/{shapes,heap,ic-stub,vm-ic-find,vm-ic-record,vm-ic-hit-prop,vm-ic-load-case,vm-load-named,vm-store-named}.aye`; tests `browser/tests/jsdom/host_ic.{html,tree,err}`; benchmark `browser/tests/perf/host_ic.html`, `host_ic/run.js`.

## Status: done, 2026-11-09

Left:
- Accessor hits still call the getter through `call0`: a native getter costs a `callAt`, and the prelude's JS getters (`ownerDocument` → `ak.inTemplate` + `nativeOwnerDocument.call`) re-enter the VM. V8 calls API getters from the handler and JS getters without a runtime call; pushing a JS getter's frame in the dispatch loop (as Q4.16e did for `call`/`apply`) is the next step for zol's Sizzle.
- A megamorphic site (more than 4 (shape, prototype) pairs: a DOM walk over many element types) hits through the stub cache in `vmLoadNamed`, not in the inline `vmIcHitProp`.
- `proto_epoch` is one global counter: any change to any prototype, or freeing an object used as one, stales every prototype case (bbc's kind 5, 715k).
- Stores do not make prototypes fast (`vmIcAddCase` still stops at a shapeless prototype); `removeProp` still makes the receiver shapeless (Q4.16h).
- Seen in the jQuery part of the benchmark, not IC costs: native `apply` (`push.apply(results, qSA(...))`) 21 µs a call and a NodeList `length` 93 µs a call (`DWELLER_JS_NATIVES=1`); the jQuery part did not move.
