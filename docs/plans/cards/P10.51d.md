# P10.51d: CSS transitions paint in the window

- goal: (1) transitions start without a script read: restyle keeps the before-change style only for elements whose `transition-*` applies, and a class/attribute change, `:hover`/`:focus` or a media change starts a transition for each transitioned property whose value changed (reversing a running one, `transition-behavior: normal`); (2) running transitions' values reach painting the way P10.51b's animations do (transform/opacity composite, others relayout or repaint the element), sampled on the window's frame tick, which stops when none runs; (3) no `getComputedStyle` per frame. P10.51c's "left" list.
- design:
  - `:hover`: `dom.Controls.hover` (the element under the pointer), `dom.isHovered` (the hovered element and its ancestors) for `selector.aye`'s `.Hover`. The window calls `engine.hoverAt` on each pointer motion: when the hovered element changes, it notes a state change at the topmost element that left or entered the hover chain on each side (`topChanged`), and `css.styleInputs` includes the hovered element, so the styles are no longer current (the controls' fingerprint is left alone: the window keeps sharing the scripts' layout and restyles there instead of styling the page again).
  - Before-change styles: `showTransitions` runs wherever styles were just computed (the local restyle in `layoutGeometry`, before its full layout of restyled styles, after `computeStyles`, and in `Page.layoutPage` before `layoutQueried`). It calls `animation.styleChange` for the restyled elements (local) or every element (otherwise), but only for those with a snapshot, a shown overlay, or `transition-*` that asks for transitions (`transitionsWanted`): a page without transitions makes no snapshot.
  - Painting: for an element with running transitions, `shownValues` copies its computed values with each running property at its current value, `Styles.intern`s the copy in place of the computed array (now `pub`) and remembers it (`Transitions.shown`, with the sample time). `styleChange` skips an array it showed (`isShown`: same array and the same sampled values, since a non-local restyle reuses arrays in place). `keepRestyled` then rebinds the boxes to the shown values and composites when only transform/opacity moved; `paintOnly` changes repaint the box, layout changes go to `relayoutDirty`.
  - Frames: the prelude's animation hook also arms the transition timer (`watchTransitions`), and the hook's stamp counts started transitions (`Transitions.started`), so a transition started by the window's own layout gets a tick. Each tick (`akTransitionFrame` → `noteRunning`) notes a `style` change at each running element and moves `Controls.transition_frame` (a style input), so the next layout restyles just those elements and overlays the new values; the element whose transition ended is restyled once more and gets its computed values back. Snapshots made by discovery no longer keep the tick running: only those a script read (`Snapshot.read`, `markRead`).
  - Transform transitions: `transitionMix` falls back to P10.47's `interpolateText` mixer for keyword values of the transform properties (the typed `interpolate` handles only lengths, percentages, numbers and colours). Snapshot and transition ends are owned copies (`Transitions.kept`, `ownedValue`); per-frame mixed texts live in `Transitions.frames`, dropped when a transition starts with nothing running or shown. `animation.sameValue` compares keywords by text.

- left:
  - `:active` does not match yet (no pressed state in the DOM); `:hover` is not set inside frames, and a hover change restyles from the topmost changed element (a full layout of the scripts' geometry), not locally.
  - `transition-behavior: allow-discrete` and list values other than transforms (shadows, `background-size`) still do not transition from the window (the mixer could take them like transforms).
  - `Transitions.kept` grows by one owned text per changed transform value of a transitioned element until the page goes away.
  - `restyleTransitioning` still re-reads each snapshotted element on each tick (cheap now: the layout's styles), and the screenshot painter still does not draw `rotate()`/`scale()`.
