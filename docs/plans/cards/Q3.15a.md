# Q3.15a: WPT `x-frame-options` to its target

- goal: criterion X2 for `x-frame-options`: 38.9% (61/157), target 90.
- cause: one. Every failing subtest (94 of `multiple.html`, 2 of `invalid.html`) timed out because the engine loaded at most 16 frames per tab (`MAX_FRAMES`, Q3.6 Left) and these files make 110 and 18. The X-Frame-Options decisions were already right for the frames that loaded.
- change: `MAX_FRAMES` (`browser/engine/frames.aye`) is 1000, Blink's limit (`kMaxNumberOfFrames`, https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/core/page/page.cc). The depth limit (3) is unchanged, so a page that embeds itself still stops.
- where the check lives: unchanged. An in-process frame is checked where the engine commits it (`placeChecked`); a frame in another renderer is checked by the browser process on the navigation response (`framingRefusedBy`, Q2.9, Q2.15a).
- files: `browser/engine/frames.aye`, `browser/tests/jsdom/frames_many.{html,tree}` (new: 40 `srcdoc` frames all load; 16 of 40 before), `browser/tools/conformance/x-frame-options.json`, `docs/browser.md` (the frame limit it states).
- verify (2026-11-17, cloud):
  - WPT `e58225abb9`, `wpt.py run x-frame-options`: before 61/157 (38.9%), after 157/157 (100.0%), floor 35, target 90. With `--process site`: 157/157.
  - `cargo test --release --test browser`, `aye test browser`, `check_taste.py`, `check_layers.py`, `gen_property_ids.py --check`, `aye check browser`: see the commit message.
  - one golden added (`frames_many.tree`, read: "40 of 40 frames loaded"); none changed.
- decision: the plan names no value for the cap, so it is the reference implementation's. Measured cost of a frame here (`dump --tree --js` of N `srcdoc` frames, safe build): 0 frames 44 MB and 0.06 s, 8 frames 203 MB, 40 frames 845 MB and 1.95 s, 110 frames 2248 MB and 5.1 s: about 20 MB and 47 ms per frame, since each frame is a page with its own JS engine and prelude. The old cap hid that cost by leaving the 17th frame blank.
