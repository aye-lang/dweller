# Q0.5: bbc loads its privacy-mgmt script again under replay

- symptom (Q4.16g): on main, bbc under replay ran 64 scripts instead of 91 (b7f82258); `cdn.privacy-mgmt.com/unified/wrapperMessagingWithoutDetection.js` and core-js never loaded. The 64-script run never requested `https://www.bbc.co.uk/userinfo`, so `dotcom-bootstrap.js` never decided that ads and consent run.
- probe: `dweller agent` `navigate` on the replay printed the cause directly, so no bisect: `[error] Failed to load module script: https://gn-web-assets.api.bbc.com/ngas/latest/dotcom-bootstrap.js`.
- commit: 3145eaff (Q3.3b, module scripts in CORS mode), merged to main with #298 (394859a5). Module scripts are now `Kind.Script` with `Mode.Cors`, so a cross-origin module needs `Access-Control-Allow-Origin`.
- cause: replay, not the CORS check. Old archive entries (without a recorded header block) replay permissive CORS headers (P10.40, `browser/net/permissive-cors.aye`), but only for `Kind.Other` (fetch/XHR). A CORS-mode module script got no ACAO and failed the check. A live response from bbc has ACAO, so this only happened under replay.
- fix: `permissiveCors` also adds the headers when `req.mode == Mode.Cors`, the same condition `originHeader` uses. Test: `browser/net/permissive-cors_test.aye`.
- bbc probe (`target/dweller dump --md --js` with `DWELLER_REPLAY`, `DWELLER_TIMING=1`, counting `script` and `requests` lines): main 64 scripts / 80 requests, privacy-mgmt 0; with the fix 96 / 204, the privacy-mgmt wrapper and both bundles run, userinfo is requested. (91 in Q4.16g was a `window_perf.py scroll` run; the dump of b7f82258 gives 95 / 204.)
