# Q2.7c: agent refs, eval navigations and the relay across renderer swaps

- goal: with `DWELLER_PROCESS=tab`, an agent's ref from before a navigation is refused after it, as in a window without the flag, whether the navigation stayed in the renderer or swapped it; an agent request outstanding when the tab's renderer is swapped always gets an answer; `dweller agent` follows a navigation to another site into a new renderer. Without the flag nothing changes.
- design:
  - in-process refs (`agent/session.aye`): refs are numbered `e1` up and never reused in a session (`next_ref`); a new document starts at the next number (`newDocument` sets `ref_base`), so a ref of the old page is below `ref_base` and `findTarget` answers `unknown ref eN: take a new snapshot (refs belong to one document)`. A same-site navigation keeps its renderer and session, so it was already refused under the flag. A swap started a new session at `e1`, so an old ref could name an element of the new page.
  - the counter crosses renderers: `agent` (B→R) gains `ref_base`, `agent_reply` (R→B) gains `next_ref`. The browser keeps the last `next_ref` a renderer reported (`tp.next_ref`, starting at 1), carries it to the next renderer of the tab (`startSpeculative`, and `followSwap` for the relay) and sends it in every `agent` request; the renderer raises a session that has no refs yet to it (`agent.carryRefs`) before it syncs the page, so the new page's refs start after the old ones and the old ones hit the same refusal, with the same text, as without the flag. A `next_ref` lower than the one the browser holds is a `bad agent_reply` (the renderer is killed). Refs are only made while an agent request runs, so the last reply's counter is exact for user and page swaps too.
  - an agent command whose script navigates the tab (`eval` setting `location`, a click on a link) loads in the agent session with a page initiator; its document fetch was not marked as a navigation, so the browser fetched it as a plain document and then killed the renderer on its `loaded` (`commit outside site lock`): the agent got `the tab's renderer is gone` and the tab a sad tab. The renderer now marks a top-level document fetch as a navigation when it is for one of its tabs (`renderer/tab-loads.aye`: the loading context, `engine.loadingContext`, is the renderer's or the agent session's tab, never a popup's); the browser decides as for any agent navigation (`fetchNavigates`, `takesSwap`), so a cross-site one swaps and the request is carried to the new renderer (Q2.7b's `carryAgent`, answered as a `navigate` to the final URL).
  - any agent request still outstanding in the old renderer when another navigation's swap commits (a user's or the page's) is answered by the browser (`ui/carry-answer.aye`): the old renderer's answer if it came, else `the page navigated before the answer: take a new snapshot` with the request's id (`agent.failLine`, JSON lines or MCP).
  - the relay (`dweller agent|mcp` with the flag) now takes the site decision too (`answerFetch` asks `takesSwap` for every navigation fetch, so the relay's first navigation sets its lock). On a swap, `followSwap` (from `askRenderer`) starts a new renderer locked to the final site, gives it the kept response (`primed`), the ref counter and the request as a `navigate` to the final URL, relays its answer, and kills and reaps the old one; the relay goes on with the new renderer. If it cannot start, the old renderer's fetch fails. `askRenderer` takes `*mut *mut TabProcess` for this.

## Status: done, 2026-11-08

Left:
- `carryAnswer` (an agent request outstanding when a user's or page's swap commits) has no test: it needs the user's navigation and the agent's request in the same frame of the loop.
- a window's `--dump`-style text (`rendererText`, sync `askRenderer` on a window tab) does not follow a swap: a page that navigates to another site during its 5 s wait still blocks it, as before this card (`followSwap` is only for the relay, `tp.tab == 0`).
- `next_ref` has no upper bound: a compromised renderer can push its successor's counter to the u32 limit (its own tab's agent then fails); the browser only checks it never goes down.
- an eval or click that navigates across sites is answered as a `navigate` to the final URL (Q2.7b Left): the eval's own result is lost.
- a page-initiated top-level document fetch outside an agent command is still not a navigation (the renderer's page navigations go through `begin_navigation`); one in a `file:` page an agent drives is a navigation for the renderer but not for the browser (`agentCommitAllowed` refuses `file:` from the web).
