# Q3.5: HSTS, mixed content and upgrade-insecure-requests

- goal: a host that sent `Strict-Transport-Security` over https (or is on the preload list) is never fetched over http again: `http://` requests to it, and to its subdomains with `includeSubDomains`, become `https://` before they are sent. On an https page, active mixed content (scripts, styles, frames, fetch/XHR) over http is blocked and passive content (images) is upgraded to https. A page with `upgrade-insecure-requests` (CSP header or `<meta http-equiv>`) gets all its http subresources upgraded.
- design:
  - store: `net/hsts.aye` `Hsts` (a list of `HstsHost`: host, expiry in seconds, subdomains) in `Session.hsts`, next to the cookies. `net/parse-hsts.aye` `parseHsts` (RFC 6797 6.1: `max-age` required and once, `includeSubDomains` without a value, quoted values, names without case; `hsts-seconds.aye` caps max-age at one year like Chromium's `kMaxHSTSAgeSecs`). `net/note-hsts.aye` `noteHsts` takes the header only from https responses and not on IP hosts (`isIp`); it is called after `storeCookies` in `transfer` (http.aye) and in the loader's `finishRequest` and `finishLoad`. `net/hsts-store.aye` `hstsStore` replaces the host's entry; max-age=0 deletes it; it says whether anything changed, and only then the profile file is written.
  - profile: `<profile>/hsts`, one line per host: `host expiry [*]` (`hsts-text.aye`, `save-hsts.aye` through `writeAtomic`; `load-hsts.aye`, `load-profile-hsts.aye` from `openProfile`). Expired entries are dropped on save and load. No profile: the store lives for the session only.
  - preload: `net/hsts-preload.txt` (`@embedFile`, `hsts-preload.aye` `preloadedHsts`), 560 entries generated by `browser/tools/gen_hsts_preload.py` from Chromium's `net/http/transport_security_state_static.json` in the local checkout (last changed in Chromium 9ba674ebe7, 2026-03-21; generated 2026-11-08). Kept: the hand-reviewed policies (public-suffix, google, custom: TLDs such as .dev and .app, Google, Facebook, Twitter, PayPal) and a few top sites (github.com, wikipedia.org, reddit.com, ...). The full list is about 93,000 entries (10 MB).
  - `net/hsts-upgrades.aye` `hstsUpgrades`: exact host or a subdomain of an includeSubDomains entry, unexpired; else the preload list. `hsts-known.aye` uses the session's store, or only the preload list without a session.
  - mixed content: `net/mixed-content.aye` `mixedContent(req, url)` gives `Mixed.None`, `Upgrade` or `Block`. Not mixed: a non-http URL, a potentially trustworthy host (`trustworthy-host.aye`: localhost, *.localhost, 127.x, [::1]), a top-level navigation. A page that asked for `upgrade-insecure-requests` upgrades everything; otherwise, under an https page (the initiator's URL, or `req.top` for frames), `Kind.Image` is upgraded and every other kind is blocked.
  - one entry point: `net/secure-href.aye` `secureHref(req, href, out)` writes the URL to use (https for mixed upgrades and HSTS hosts) or returns false (blocked). Used by `request` (net.aye: a blocked request is a network error; an upgraded one re-enters `request` with the https URL through `upgraded-request.aye`), by every redirect hop in `transfer` (before the CORS redirect check), by the loader's `startLoad` (`secured-as-is.aye`: a subresource that would need a change is refused, the synchronous path does it) and by `multi.aye` `startJob` (prefetch). `blocked.aye` notes the failure in telemetry.
  - upgrade-insecure-requests: `net/upgrade-directive.aye` finds the directive in a CSP value; engine `pageOf` calls `notePageUpgrades` (`engine/note-page-upgrades.aye`), which checks the `Content-Security-Policy` response header and `meta-upgrades.aye` (`<meta http-equiv="Content-Security-Policy">`), and `net.noteUpgradeInsecure` adds the page URL to `Session.upgrading`.
  - certificate bypass for HSTS hosts: Q3.4 has no bypass at all (its interstitial has no "Proceed" link), so there is no check to wire the store into yet; `hstsKnown` is the function such a bypass must consult.
