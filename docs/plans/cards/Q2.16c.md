# Q2.16c: a renderer keeps its display list over frames that cannot change it

- goal: with `DWELLER_PROCESS=tab` or `site`, a renderer's frame no longer builds and signs its display list when nothing that feeds the list changed: a scroll of the page, a caret blink, a canvas draw (Q4.20 left: "the tab-process renderer rebuilds its list per due frame").
- source: the readiness list of Q2, "Speed with the flag", third bullet.
- design:
  - `TabRenderer` keeps `list` (the `paint.DisplayList`), `sigs` (its signatures; `drawn` is the last frame's copy for the damage diff), `shown` (the canvases' pixel versions) and what the list was built from: the tree pointer, `engine.treeVersion` (DOM mutations, layout version, images, frames: the window's own test for "needs a layout", `pageview.needsLayout`) and `engine.layoutGeneration` (new: `Page.layouts`, counted when an owned tree is freed, summed over the frames, so a tree rebuilt at the same address with the same version is seen).
  - `keepList` (from `paintFrame`, after the layout and `layout.scrollTo`) reuses the list when all three are the same, no fixed or sticky box moved with the scroll, and `relist` is not set; else it builds and signs as before. On reuse `canvasesDrawn` does what the window does since Q4.20: when a canvas's shown version moved, `paint.refreshImages` and a new signature, no build.
  - `relist` is set by what changes the list outside the page's scripts: every message except the ones in `keepsList` (frame acks, pings, fetch replies, wheel, scroll bubble, storage event, posted message, frame loaded, viewport intersection), so mouse, key, text, edit, focus, find, popup, resize, navigate, traverse and agent messages build; a wheel that scrolls an element or a frame instead of the page (`scrollChain`); an image that arrived or a decode that landed (`imagesIn`); a new page and a preview (`dropList`). What a script changes moves the tree version, as in the window.
- Chromium read: `third_party/blink/renderer/platform/graphics/paint/paint_controller.cc` (cached display items and subsequences are reused when the client is not invalidated), `cc/layers/picture_layer.cc` (a scroll changes no recording). Dweller takes: the recording is kept until something invalidates it, and a scroll is not such a thing.
- files: new `browser/engine/layout-generation.aye`, `browser/engine/engine.aye` (`Page.layouts`); new `browser/renderer/{keep-list,drop-list,canvases-drawn,same-shown-as,keeps-list}.aye`, `browser/renderer/{paint-frame,tab-renderer,new-tab-renderer,adopt-page,show-preview,images-in,answer-all,scroll-chain}.aye`; new `browser/tests/ui/kept_list.html`, `tests/browser/window_renderer_list.rs` (and its `mod` pair in `tests/browser.rs`).

  - new `window_renderer_list_kept`: `ui/kept_list.html` (10 canvas draws, then 6 wheels): 3 list builds with the flag, and the PNG after the scroll is byte-equal to the in-process window's.
