# Q2.12: Spaces become renderers (first slice: hosted Spaces behind `DWELLER_SPACES=renderer`)

- goal: an agent's Space is a group of renderer-backed tabs that the browser owns, under the same renderer processes, IPC and sandbox as tabs, and the second copy of the engine (`dweller space`, `ui/spaces.aye`'s process half) goes. Shared logins go through the browser's jar and storage (Q2.4b). Every user-visible and agent-visible behaviour stays.
- decision (in-process mode): Spaces always use renderers, in every `DWELLER_PROCESS` mode, also when the person's tabs are in the window's process (the default today). There is no in-process Space path: an agent request that runs on the window's thread breaks "the window never waits for a Space" (`window_spaces_responsive`), and Chromium has no in-process mode in production either. `DWELLER_SPACES=renderer` is the temporary switch of this slice; without it the window still starts a `dweller space` process per Space (the old path, unchanged).
- how a Space differs from a tab (kept): its tabs are not in the person's tab strip, are not shown unless the person watches the Space (its chip), have their own numbering from 1 (`tabs`, `tab_new`, `taken_over`), belong to one agent connection at a time, and stay (`done`) when the agent leaves; it has a name, a state (`working`, `waiting`, `idle`, `paused`, `done`), a last action, and is paused, stopped, closed and handed back per Space.
- design (this slice):
  - `Space` (ui/spaces.aye) gets `hosted`, `own_tabs` (its `TabSlot`s), `next_tab` and `last_tab`; `TabSlot` gets `in_space` (its number in the Space; 0: the person's tab). A hosted tab's `id` (its frame id and `sessionStorage` key) comes from its own counter at 2^29, below child frames' 2^30, so the person's tab ids do not change. `newSpace` is shared by both paths.
  - The window reads the hello as before (`openSpace`); a `shared` Space becomes hosted (`startHosted`: one tab, its renderer started at once), an `isolated` one still gets a Space process (the browser has one jar). From then on the connection is served on the window's thread as tab-mode agents are (Q2.3b): page commands and `wait` go to the tab's renderer (`askTabRenderer`, async, `answerAsked`); `tabs`, `tab_new`, `tab_select`, `tab_close`, `user_context` (the live context, without a layout), `spaces` and `space_close` are answered by the window from the Space (`hostedCommand`). A Space's tabs are polled with the person's (`pollTabSlot`, split out of `pollTabProcesses`), in every mode.
  - The Space's state is computed each round (`hostedState`); its last action comes from the renderer (`agent_acted`) or the window (`opened a tab`, `waiting`); `agents:N` counts every line sent to an agent (answers and events), as the relay counted the Space's lines, and the script resumes right after an answer goes out, so a scripted pause reaches the renderer before the agent's next request.
  - Pause, resume, stop, `space_close`, attach (`"space":N` acts on the last tab) and hand back act on the hosted Space directly (`pauseHosted` sends `agent_paused` to its renderers, which then refuse acting calls inside a `run` too; `stopHosted` ends the connection after `stopped`).
  - Watching draws the Space's first tab's renderer buffer in the page area (`drawHostedFrame`); while it is shown, `tabInput` is that renderer, so clicks, keys, text and the wheel go to it, and the first one takes the tab over (`takeHosted`, `taken_over`). The frame file and the `input` words go for hosted Spaces.
  - Popups an agent's page opens go to the Space (`openedSlot`); a renderer serving an agent request now hands its new contexts to the browser (`setTabHost`, `sendContexts` before the reply), and an acting agent request counts as the user gesture of `takeContext`. An agent's answer waits (at most 5 s, `opensPending`) until the tabs it opened have loaded, as the in-process engine loaded them in the click.
  - Inside a `run`, window commands (`tabs`, `tab_new`, `tab_select`, `tab_close`, `user_context`, `spaces`) are a sync call to the browser (`agent_window`, answered by `windowCommandOf` for the request's connection).
  - Renderer fixes found on the way (all `DWELLER_PROCESS=tab` too): a `run` counts as acting (its navigations commit, `fetchNavigates`); an agent's first navigation of a fresh tab may be a `data:` URL (`agentCommitAllowed`); the agent session takes the renderer's scroll before a request and gives it back after (a wheel the person gave is seen by `snapshot`, an agent's `scroll` shows in the frame); a session whose page the browser loaded gets its URL (`url` of answers in popups).
- IPC type codes (new, 70 up): 70 `agent_acted{what}` R→B (the renderer's `agentActs` text, before `agent_reply`; frame = the tab, only while a request is out, at most 4096 bytes); 71 `agent_paused{on}` B→R; 72 `agent_window{line}` R→B (frame = the tab, only while a request is out, one at a time, at most 64 KiB); 73 `agent_window_reply{ok, message, fields, detail}` B→R.
- references (Chromium, read over HTTPS from `main`): `content/browser/renderer_host/render_frame_host_impl.cc` (`CreateNewWindow`: the browser validates a renderer's request for a new window and refuses it as a bad message when the frame may not open one; the user activation it checks is the browser's own record of input it routed: Dweller's `takeContext` keeps that shape and adds the agent's acting request as an activation the browser itself sent), `content/browser/devtools/protocol/target_handler.cc` (`CreateTarget` with `newWindow`, `background`, `hidden`, `browserContextId`: an automation client's page is an ordinary WebContents of the browser in ordinary renderers, hidden ones only in the background, in a browser context of its own when asked: the model of a hosted Space and of an isolated one's partition), `content/public/common/content_switches.cc` (`--single-process`: "Runs the renderer and plugins in the same process as the browser", a debugging switch: why Spaces get no in-process path).
- files: new `browser/ui/{new-space,start-hosted,host-tab,space-tab,space-of-slot,hosted-space,fallback-slot,leave-hosted,tab-number,space-acted,space-event,pause-hosted,stop-hosted,hand-back-hosted,take-hosted,hosted-state,poll-hosted,poll-tab-slot,hosted-answered,hosted-command,hosted-tab-new,hosted-tab-select,hosted-tab-close,hosted-spaces-reply,hosted-wait,list-tabs,opens-pending,watched-tab,draw-hosted-frame,answer-window-ask}.aye`, `browser/renderer/ask-window.aye`, `browser/agent/command-name.aye`, `browser/ipc/agent-acted_test.aye`; changed `browser/ui/{spaces,agents,tabs,ask-tab-renderer,answer-asked,poll-tab-processes,opened-slot,take-context,agent-commit-allowed,renderer-sent,tab-process,start-tab-process,end-tab-process,tab-input,forward-input,draw-watched,hand-back}.aye`, `browser/renderer/{answer-agent,answer-all,await-reply,renderer-host,tab-renderer}.aye`, `browser/ipc/{message,decode,put-payload,from-renderer}.aye`, `browser/agent/page-command.aye`; tests `tests/browser/window_spaces.rs`, `tests/browser/window_renderer.rs` (`open_files` shared); `docs/process-model.md` §2, §8.

## Status: in progress (first slice done, 2026-11-09)

Left:
- Navigations are fetched with a blocking `net.request` in the browser (`answerFetch`; only subresources are held), so a hosted Space's navigation to a slow server stalls the window's loop (`window_spaces_responsive` with `DWELLER_SPACES=renderer`: one iteration of 1502 ms). Holding navigation fetches like subresources (`holdFetch`, then `framingRefused`/`takesSwap`/`sendFetched` on completion) is the first thing before the flip; it fixes the person's `DWELLER_PROCESS=tab` tabs too.
- `isolated` Spaces still get a Space process: the browser has one cookie jar and one `localStorage`. A partition per isolated Space in `net/` and `engine/storage.aye` (Chromium: a `StoragePartition` per off-the-record profile), chosen by the renderer's partition in `answerCookie`/`answerStorage`/`answerFetch`, lets them be hosted.
- A popup opens in a renderer of its own, so its `opener` is null (`popup` session: `opener set name w1` becomes `opener null name`); openers across renderers need the proxies of Q2.9–Q2.11 (or same-site popups in their opener's renderer).
- Crashes: a hosted Space's renderer that dies fails the request on it with "the tab's renderer is gone" and the Space stays; §8's "renderer crashed" error and a `crashed` tab in `tabs` are not done, and `window_spaces_crash` still kills a Space process (it runs only on the old path).
- Then flip: hosted by default, `window_spaces_*_in_renderer` become the tests, the process half of `ui/spaces.aye`, the sharing and frame-file files and `dweller space` are removed, and `docs/agent-protocol.md`'s Spaces section is rewritten (the control-connection table goes).
- A watched Space shows its first tab (the old Space showed its shown tab, also the first unless it was closed); the outline of an agent's target is not drawn in it (as before). A `run`'s window commands use the request's connection; `wait` inside a `run` still waits in the renderer.
- `user_pointed` lines are not counted for `agents:N` (no golden needs it).
