# Q4.16o: the string natives pass core-js's feature tests

- goal: Q4.21's ranked step 6: on mistral axept's core-js replaced `endsWith`, `trim` and more with its own (slower) versions, because Dweller's natives failed core-js's feature tests. The tests are public (core-js 3, `internals/correct-is-regexp-logic`, `internals/string-trim-forced`), so they run here without the archive.
- what failed (`target/dweller js` on the tests, against node 22):
  - `es.string.ends-with` and `starts-with`: `'/./'.endsWith(/./)` must throw a TypeError (IsRegExp), and with `re[Symbol.match] = false` the same call must not. `endsWith` and `startsWith` never checked; `includes` checked the class, not `@@match`, so it threw in the second case.
  - `es.string.trim`, `trim-start`, `trim-end`: a string of every WhiteSpace and LineTerminator must trim to empty. `spaceAt` knew ASCII, U+00A0, U+FEFF, U+2028 and U+2029, not U+1680, U+2000 to U+200A, U+202F, U+205F or U+3000. And `trimEnd` of a string of only white space returned it whole (`trimSides`).
  - `trimLeft` and `trimRight` were their own functions; Annex B makes them the same function objects as `trimStart` and `trimEnd` (`''.trimLeft === ''.trimStart`, names `trimStart`, `trimEnd`).
- design (ECMA-262 22.1.3.7, 22.1.3.23, 22.1.3.32, 7.2.8 IsRegExp, 12.2 WhiteSpace and 12.3 LineTerminator; Annex B.2.2.15–16):
  - `isRegExp` returns false for a non-object, then reads `@@match`; `includes`, `startsWith` and `endsWith` call it after ToString of the receiver.
  - `spaceAt` (shared by trimming and StringToNumber, whose StrWhiteSpaceChar is the same set) knows the whole set in UTF-8.
  - `trimLeft`/`trimRight` are defined as the values of `trimStart`/`trimEnd`.
- files: `browser/js/builtins_string.aye`, `browser/js/is-regexp.aye`, `browser/js/numconv.aye`; new test `browser/tests/js/296_core_js_string_checks.{js,out}` (the core-js checks, all-white-space trims, `Number` and `parseFloat` with Unicode spaces, the aliases, a regexp-like object with a truthy `@@match`; `.out` from node 22).
- references: https://tc39.es/ecma262/#sec-string.prototype.endswith , https://tc39.es/ecma262/#sec-isregexp , https://tc39.es/ecma262/#sec-white-space ; core-js 3 `packages/core-js/internals/correct-is-regexp-logic.js`, `string-trim-forced.js`.
