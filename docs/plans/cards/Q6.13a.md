# Q6.13a: private names with escapes, Unicode white space

- goal: the largest one-cause cluster of `test262/language`: 818 tests fail with "Invalid or unexpected token".
- cause: the lexer read a private name only when `#` was followed by an identifier start byte, so `#\u{6F}` was not a token. The generated class-elements files (`rs-privatename-identifier*`, `rs-private-getter/setter/method*`, `rs-static-*`) all declare `#\u{6F}`, so every one of them failed to parse (777 tests). 18 more (`S11.*_A1.js`) failed on Unicode white space after a number: any byte of 0x80 or more counted as an identifier start.
- design:
  - `lex-word.aye` (`lexWord`): the identifier scan moved out of `Lexer.token`; a name may start with `#`, escapes are cooked for private names too (the cooked text keeps the `#`), and a private name is never a keyword. An escape must name an identifier character (`lex-escape-names.aye`: not U+0000, not ZWJ/ZWNJ first).
  - `lex-space-length.aye`: the `WhiteSpace` code points beyond ASCII (U+00A0, U+1680, U+2000 to U+200A, U+202F, U+205F, U+3000, U+FEFF). `skipSpace` skips them; a number may be followed by one; an identifier ends at one and at U+2028 / U+2029 (`lex-at-separator.aye`). `\r` alone is a line terminator (sets `nl`).
- references: ECMA-262 `PrivateIdentifier`, "White Space", "Line Terminators", "Identifier Names: Static Semantics: Early Errors". V8 does the same (`src/parsing/scanner.cc`, `ScanPrivateName` calls `ScanIdentifierOrKeywordInner`).
- files: `browser/js/lexer.aye`, `lex-word.aye`, `lex-space-length.aye`, `lex-at-separator.aye`, `lex-escape-names.aye` (new); `browser/tests/js/285_private_name_escapes.js` and `.out` (Node 22's output).
- verify:
  - `test262.py run test/annexB test/language test/built-ins -j 4`: language 17032 -> 17895/23210 (77.1%), built-ins 13428 -> 13429, annexB 431 -> 432. That run lost 6 tests (`grammar-privatename-identifier-invalid-{ues,zwj-error,zwnj-error}.js`: an escape that is not an identifier character); `lex-escape-names.aye` fixes them (rerun of the 42 `grammar-privatename-identifier*` files: all pass), so language is 17901.
  - `cargo test --release --test browser -- js_ jsbench`: 4 passed (`js_conformance` runs the new fixture).
  - `jsbench.py` with `BENCH_BASELINE` the binary of `2662662`: geometric mean 0.986 at 3 runs; the same binary against itself reads 0.96 to 0.97 on this machine (the second column runs warmer), `raytrace` 0.95 and `strings` 0.96 at 9 runs against 0.97 and 0.96 for baseline against baseline. No drop beyond the noise; the change is in the lexer only.
  - `check_taste.py` 0, `check_layers.py` 0, `gen_property_ids.py --check` 0, `aye check browser` 0.
