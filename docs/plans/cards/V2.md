# V2: native shell spike

The card is in `docs/plans/vision.md` (goal, design, verify). This file
holds its status, what was built, the numbers and what is left.

## Status: done, 2026-11-16 (the Mac numbers are in the Mac queue)

Done note:
- `examples/native/counter/` is an Aye program with its own `main`: a
  counter (text, `+1`, `Reset`), a text field with `Add`, and a list of
  1000 rows that scrolls. The document is a `dom.Document` built from
  code; styles are a CSS string through `css.parseSheet`. `README.md`
  beside it says how to build and run it; `counter.html` is the same app
  as a page.
- `browser/shell/` (new platform module, 44 small files) is the loop
  "window + document + style + layout + paint + input": `shell.run(alloc,
  css, build)`, `App.element/setAttr/setText/onClick` (a handler table
  keyed by node), hit testing on the box tree, the focus and text editing
  of a text field (`dom.insertText`, `deleteBackward`, `moveCaret`), wheel
  scrolling, and the headless options of the browser's window
  (`--frames`, `--events`, `--save`, plus `--dump`, `--timing`,
  `--full-layout`).
- Incremental: a handler's changes mark elements dirty; the next frame
  runs `css.restyleSubtrees` on them and `layout.rebuild` +
  `layout.relayout` on their boxes (the path of `engine/geometry.aye`
  `relayoutDirty`), and falls back to a full layout when a box cannot be
  rebuilt. The test compares its pixels with `--full-layout`: equal.
- How the app imports the engine: `aye.toml` with `dweller = { path =
  "../../../browser" }`, then `import dweller.shell`, `import
  dweller.dom`. What the compiler lacks for a cleaner boundary is gap 58
  in `browser/COMPILER_GAPS.md`.
- Linked modules (globals in `nm` of the binary): css, dom, encoding,
  font, html, idna, image, layout, paint, perf, sdl, shell, svg, url. No
  `js`, `engine`, `net`, `agent`, `wasm`, `ui`. `html` is still linked
  (its tables; `svg/` imports it, the V1 exception that V6 removes); the
  app never calls the parser.
- Seam in existing files: `browser/ui/sdl.aye` names SDL's types by
  aliases of the new `browser/sdl/` (`pub let SDL_Window =
  sdl.SDL_Window`), so `ui` and `shell` can be in one program (gap 58,
  point 4); `check_layers.py` lists `shell` and `sdl` as platform modules
  (so the shell is checked to import no front-end module);
  `docs/browser.md` lists both. Decision: the module is `browser/shell/`,
  not `browser/ui/surface.aye` as the card suggested, because `ui`
  imports `engine` and a module is a directory.
- Tests: `native::native_counter` (`tests/browser/native.rs`; goldens in
  `examples/native/counter/expected/`: the final DOM dump and two
  screenshots, fixed font, read before blessing: the count is 1, the
  field shows "hello word" with the focus ring, the last row is the added
  one) and the Aye test "shell: a click runs its handler and the change
  is laid out incrementally" (`browser/shell_test.aye`).
- Verify, 2026-11-16, cloud machine: `env -u HTTPS_PROXY -u https_proxy
  -u CURL_CA_BUNDLE -u SSL_CERT_FILE cargo test --release --test browser
  > target/v2.log` → 250 passed, 0 failed (the whole suite, which has
  `native_counter` and every `window_` test); `check_taste.py`,
  `check_layers.py`, `gen_property_ids.py --check`, `aye check browser`:
  all 0.

Numbers (this cloud machine, Linux x86_64, SDL dummy video driver, both
built `--mode fast`, window 800 x 600, system font):

| | counter (native) | `dweller counter.html` |
|---|---|---|
| binary | 2 405 048 bytes (2 223 568 stripped) | 7 986 408 (7 199 872 stripped) |
| first frame, median of 9 | 16 ms from `main` to the first present (15 to 19) | 76 ms `ui_first_paint` from the navigation's start (69 to 86) |
| whole process for one frame (`--frames 1`) | 22 to 33 ms | – (the window's first frame comes before the load) |
| scrolling, 120 frames, one wheel notch each | 0.99 ms a frame (max 1.03); the whole canvas is drawn | 0.95 ms `ui_draw` (max 4.5); damage only |
| idle, 10 s | 190 ms of CPU | 190 ms of CPU |
| resident memory, idle | 24 MB | 68 MB |

The safe build of the counter is 8 978 336 bytes (the browser's: 35 312
920). The idle CPU is the same for both because SDL's dummy driver polls
in `SDL_WaitEvent`; a real driver is needed for that number.

Left:
- V2b, text input: no caret or selection is drawn (the browser draws
  them in `ui/`, not in `paint/`), a click does not place the caret, no
  clipboard, no IME, and an app cannot listen for input or keys (only
  clicks; `Add` reads the field's value).
- Hit testing is `shell/box-at.aye` (the deepest box under the point),
  not the engine's: `engine/hit.aye` imports only core modules but lives
  in `engine`. Move it to the core (`paint/`) and use it here, after
  Q2.10 has changed it (lane proc-security).
- Drawing is the whole canvas each frame. The damage tracking and raster
  cache of `ui/pagedraw.aye` are written against `Ui`; sharing them is
  the "loop that both can share" of the card, not done: the browser's
  window does not use `shell` yet.
- `ui/sdl.aye` still declares SDL's functions and constants itself;
  `sdl/` has only the types and what the shell calls. Fold them when the
  four `ui` lanes of this wave have landed.
- No hover or active styles, no keyboard focus traversal, no container
  queries (`engine.layoutQueried`), no images (`layout.Images` is null),
  no element scrolling (only the document scrolls), no timers or
  animation frames, one window.
- Adding a row marks the list dirty, so its 1000 rows are styled and
  built again (27 ms in the leak-checking safe build): finer dirty marks
  for an appended child.
- `html` is linked through `svg` (V6).
