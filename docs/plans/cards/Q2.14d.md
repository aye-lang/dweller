# Q2.14d: the renderer's records reach the test

- goal: Q2.14a's proposed readiness row 3 (cause rows 6 and 10, 11 tests): a test that counts `DWELLER_TIMING` records or reads the page's console lines sees the same lines with `DWELLER_PROCESS=site` as in one process.
- source: `docs/plans/cards/Q2.14a.md`, "Proposed readiness rows" 3.
- what the code showed (the triage's cause was not the cause):
  - the renderer's stderr is already the browser's: `spawnRenderer` keeps fds 0 to 2 (`addinherit_np` on macOS; on Linux only fds from 4 are closed), the seccomp list allows `write`, and `rendererKeeps` passes every `DWELLER_*` variable. The first run's log shows the renderer's records in the window's stderr (`js_compile`, `cascade`, `layout`, `layout_dirty`, `restyle`, `paint_build`). The renderer echoes the console under `DWELLER_CONSOLE` (`renderer/serve.aye`). Nothing has to be forwarded over IPC.
  - what differs: (a) the renderer never writes `ui_relayout`: in one process the record comes from `pageview.relayout`, and the renderer lays out in `paintFrame` without a record (`window_relayout_incremental`, `window_container_queries`, `window_width_animation` count it); (b) `--until-idle` ends the run as soon as the renderer's page has loaded: `rendererSettled` looked only at `loading`, not at the renderer's timers and animation frames, so a page that animates (`webgl_three_cube`: no `timers` record at all, 25 window iterations) or steps with timers is cut before its records are written; (c) the window draws (`ui_draw`) while the renderer still loads, so "after the first `ui_draw`" counts the load's full layout (`window_relayout_floats`, `_attr`, `window_width_animation`); (d) the `--events` tests (`window_transition_kept`, `window_hover_local`) and the three "console" tests are the `--events` / `--frames` wait of Q2.14a row 1 and 5: `window_input_codes` and `window_pointer_lock` read the page's `--text` in stdout after `--frames 1` (no `[log]` line is involved), and `window_hidden_raf` drives `painted`, `frame` and `window:hidden` events.
  - the console in the person's window: in one process a window without `--frames` echoes the console to stderr (`window.aye`: `setConsoleEcho(frames == 0 && !exit_when_idle || DWELLER_CONSOLE)`); the renderer echoed only under `DWELLER_CONSOLE`.
- design (for (a), (b) and the console; (c) and (d) are left to Q2.14b):
  - `renderer/paint-frame.aye`: `perf.start()` before `layOut`, `perf.end("ui_relayout", ...)` after `paint.signature`: the same span as the window's `relayout` (layout, then the display list).
  - `renderer/report-settled.aye` (`reportSettled`, called by `reportPage` after each turn): settled = no frame due (`r.due`) and, with a page, none of what `pageSettled` checks in one process (`imagesLoading`, `decodesPending`, `canvasFramesPending`, `navigationPending`, `msUntilNextTimer`, `animationFrameRequested`). Sent as `settled{on}` when it changes (`settled_said`, false at start), never by an embedded frame (`engine.embedded()`; `childSent` would drop it).
  - `ui/renderer-sent.aye`: `settled{on}` with frame = the tab and `on` 0 or 1 sets `TabProcess.settled` (default false), else `bad settled`. `ui/renderer-settled.aye`: also needs `tp.settled`, except while the renderer is inside a long task (`tp.busy`, from `long_task`): a busy page may never end, and `window_renderer_status` ends its run on `renderer:busy` to read the busy status (run 1 failed it without this rule).
  - console: `engine.consoleEchoed()` (new); `startTabProcess` passes `--console` when it is on; the renderer's `serve` echoes with `--console` or `DWELLER_CONSOLE`.
  - the default mode: `rendererSettled` returns true before reading `tp.settled` when the slot has no renderer process (`slot.process` is null without `DWELLER_PROCESS=tab|site`); `paintFrame`, `reportSettled` and `--console` run only in a renderer. Nothing on the in-process path changes.
- IPC: one new message, R→B `settled{on}`, type code 78 (`ipc/message.aye`, `decode.aye`, `put-payload.aye`, `from-renderer.aye`; unit test `ipc/settled_test.aye`: round trip, from the renderer, code 78). 79 is unused.
- the untrusted renderer:
  - `settled`: a lying renderer can end a headless `--until-idle` run early or keep it going to its `--frames N`; the value is read nowhere else (`pageSettled` is used only by `--until-idle`). One bool per message, only on change; a flood is no worse than any other message.
  - stderr: a renderer could already write anything to the browser's stderr (fd 2, `write` allowed), including lines that look like the browser's own `DWELLER_TIMING` records; this slice adds no channel. The browser never reads its stderr, so the stream is a log for people and tests; a test that counts records trusts the page it loads (the test's own). Written in `docs/process-model.md` §6.
- files: new `browser/renderer/report-settled.aye`, `browser/engine/console-echoed.aye`, `browser/ipc/settled_test.aye`; changed `browser/renderer/{paint-frame,report-page,serve,tab-renderer}.aye`, `browser/ipc/{message,decode,put-payload,from-renderer}.aye`, `browser/ui/{renderer-sent,renderer-settled,start-tab-process,tab-process}.aye`, `docs/process-model.md` (§2 lifecycle row, §6 stderr).
