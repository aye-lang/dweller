# Q4.20: canvas draws mark paint only

- goal: a canvas draw (2D and WebGL, also in an iframe) no longer moves the DOM version, so a page whose only change is a canvas runs no relayout and builds no display list; the window re-rasters only the canvas's rect (Q4.18 and Q4.22 left: `canvasChanged` bumped `Script.version`, `paint_build` was 75% of an idle relayout).
- design:
  - `canvasChanged` (2D calls, WebGL framebuffer draws and frame reads) is gone, and `takeCanvasFrames` no longer bumps the version: nothing a canvas does moves `Script.version`, `layout_version` or `Page.mutations`. A canvas resize still goes through the width/height attribute write (layout).
  - The display item already references the canvas pixels (`Item.Image { pixels, ver }`: the slice of `Bitmap.pixels`, not a copy); `ver` is `Bitmap.shown()`, the count of pixel changes `settleCanvases` (Q4.17) saw. Only `ver` is stale after a draw, and it feeds the item's signature.
  - `engine.canvasShown(page, out)` lists `(pixels, shown())` of every canvas of the page and its frames. `pageview.canvasesDrawn(view)` (called at the end of the window's `afterScripts`, after the rAF, timers, events and WebGL readbacks) compares it with the last list; when it moved it calls `paint.refreshImages`, which sets `ver` in each `Image` item whose pixels pointer is a changed canvas's (also the copies inside iframe lists and mapped copies), and only then re-signs the list (`paint.signature`) and raises `repaint`. The window's damage diff then yields the rect of the items whose signature moved: the canvas's box, through the iframe offset when nested. No layout, no restyle, no `buildList`; `view.frames` keeps its cached iframe lists (their `framePrint` takes `shown()`, so the next real build rebuilds the iframe whose canvas moved).
  - A canvas drawn with the same pixels (Q4.17) changes no `shown()`: no re-sign, no damage. The tab-process renderer (`paintFrame`) builds its list per due frame as before; without the version bump its `layOut` is a no-op for a canvas-only page.
  - `image_neutral` stays for `changedText`; the canvas no longer needs it.
- references:
  - `third_party/blink/renderer/core/html/canvas/html_canvas_element.cc` (`DidDraw`): `SetShouldCheckForPaintInvalidation`/`SetHasCanvasInvalidation`, no style or layout invalidation. Dweller takes: a draw invalidates paint of the canvas only.
  - `third_party/blink/renderer/core/layout/layout_html_canvas.cc` (`InvalidatePaint`): the canvas box is paint-invalidated, layout only on a size change. Same.
- files: `browser/engine/canvas-shown.aye`, `browser/paint/shown-bitmap.aye`, `refresh-images.aye`, `refresh-image.aye`, `shown-ver.aye`, `browser/pageview/canvases-drawn.aye`, `same-shown.aye` (new); `browser/engine/canvas_api.aye`, `webgl_api.aye` (no version bump), `browser/pageview/page-view.aye`, `shutdown.aye` (`shown`), `browser/ui/window.aye` (`afterScripts` calls `canvasesDrawn`); `tests/browser/paint.rs` (`window_canvas_raf_no_relayout`), `browser/tests/ui/canvas_raf.html`, `canvas_raf_final.html`, `browser/tests/perf/canvas_only.html`.
- verify:
  - `aye check browser`, `aye test browser` (269 passed), `python3 browser/tools/check_taste.py`, `check_layers.py`, `browser/build.sh`: pass.
  - `cargo test --release --test browser -- worker_canvas jsdom_fixtures webgl window_ canvas imagebitmap fixtures aye_unit_tests` (124 passed, incl. `window_damage`, `window_frame_lists_reused`, `window_same_text_write_builds_nothing`, `canvas_animation`, `canvas_origin_clean`, `worker_canvas`, `window_webgl`, `jsdom_fixtures`) and the new `window_canvas_raf_no_relayout` (40 rAF ticks of a page canvas and an iframe canvas: at most 3 relayouts and 8 list builds, at least 40 frames draw pixels, last frame equals `canvas_raf_final.html` drawn at once; run under `DWELLER_DAMAGE_CHECK`, no mismatch). No golden re-blessed.
  - Perf (`DWELLER_TIMING=1 target/dweller PAGE --frames 300`, SDL dummy, before and after interleaved, 3 runs, medians; `target/q420/bench.py`):

    | page | relayouts before -> after | `paint_build` before -> after | `ui_raf` ms/frame before -> after |

    | `canvas_only.html` (page + iframe canvas) | 158 -> 1 | 316 -> 2 | 0.40 -> 0.28 |

    `ui_relayout` per relayout stays 6.5 to 6.8 ms where it runs (the observed same-text `textContent` replaces a node and still relays out, Q4.22 left); on the plain and canvas-only pages the idle relayout is gone and the frame costs the canvas draw plus `paint_sig` (0.005 ms on the canvas-only page, 0.26 ms on the 1500-row page) and the canvas rect's raster.

## Status: done, 2026-11-09

- left:
