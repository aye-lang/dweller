# Q3.7 — CSP level 1: script-src

## Done

- New module `browser/csp/`: directive parsing (`directiveOf`, first directive of a name wins), the
  fallback list `script-src-elem` → `script-src` → `default-src`, source matching (`*`, scheme
  sources, host sources with `*.` hosts, ports, `*` port, paths, `'self'`, `'none'`), nonce and
  sha256 hash sources (base64url accepted, algorithm case-insensitive), `'unsafe-inline'` ignored
  when a nonce, hash or `'strict-dynamic'` is present, `'unsafe-eval'`. Several policies (several
  headers, comma-separated, meta) must all allow.
- The page's policy (`Page.csp`): every `Content-Security-Policy` header (`net.appendHeaderValues`)
  plus every `<meta http-equiv=Content-Security-Policy>`. `Content-Security-Policy-Report-Only`
  is not read (Q3.8). `upgrade-insecure-requests` now reads the same policy through
  `csp.directiveOf` (`engine/meta-upgrades.aye` removed).
- Enforcement: parser and inserted external classic scripts are refused before the fetch (also
  skipped by the prefetch), fire `error`, log `Refused to load the script '…' because it violates
  the following Content Security Policy directive: "…".`; inline scripts (parser and inserted) are
  refused before compile; `eval`, direct eval, `new Function` and string timers throw `EvalError`
  (`js.refuseStringCode`, `Interp.eval_refusal`). A plain `securitypolicyviolation` event (no
  fields) fires at the refused script element.
- WPT area `content-security-policy/script-src` (static server; `content-security-policy/support`
  fetched, not run): 50/175 = 28.6 %, threshold 25. `conformance.py check`: no area fell.
