Slice 1 (2026-11-21, two causes, 107 -> 311 of 676; the area has 676 subtests since this WPT revision's `Origin.from` files run):
- `Origin` (`engine/origin.js`, a page prelude): `new Origin()` is opaque; `Origin.from()` takes a string (a URL, `TypeError` when it does not parse), a `URL`, an `Origin`, an `<a>` or `<area>` with `href`, an SVG `<a>` with `href`, a `MessageEvent` (its `origin`, `"null"` opaque), a window or a `Location` that the caller may access (a cross-origin one throws `TypeError`); anything else is a `TypeError`. A URL's origin is the URL spec's: a tuple for http(s), ws(s) and ftp, the inner URL's for a `blob:` of http(s), otherwise a new opaque origin each time. `opaque`, `isSameOrigin` (opaque: the same object only) and `isSameSite` (schemeful: the scheme and the host's site, `net.siteOf` through the new native `siteOfHost`). +154 (to 261/676).
- SVG `<a>`, `<image>` and `<use>` had no `href`: the `SVGURIReference` `href` is an `SVGAnimatedString` whose `baseVal` and `animVal` read the `href` attribute (or `xlink:href`) and whose `baseVal` sets `href` (`engine/prelude.aye`). +50.
- Chromium read: `third_party/blink/renderer/core/frame/origin.cc` and `origin.idl` (the `Origin` interface behind its flag), `core/svg/svg_uri_reference.cc`.
- verify (2026-11-21, Linux x86_64, 4 cores): `wpt.py run html/browsers/origin`: 311/676 (46.0%), target 39; the area's JSON written. `aye check browser`, `check_taste.py`, `check_layers.py`, `aye test browser`; the suite in site mode and in `single`; the areas below: see the batch's PR.
