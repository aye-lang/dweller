# Q5.8: EventSource (server-sent events), slice 1

- goal: `EventSource` as in the HTML standard ("Server-sent events"), measured by the WPT area `eventsource`. Row Q5.8 of `foundations.md` (F1, Chromium `modules/eventsource/`).
- facts found first:
  - No `EventSource` anywhere in `browser/` (grep of the prelude and the `.js` preludes).
  - No path gives a script a response body as it arrives. fetch's `Response.body` is a `ReadableStream` made from the whole body once the request ended (`prelude.aye`, `_stream`); XHR fires `readyState 3` and one `progress` with the whole body inside `_load`. In one process `ak.fetchStart`'s task runs only once the load ended (`net.loadState`); with `DWELLER_PROCESS=site`/`tab` the browser process answers the renderer's held fetch with the whole response (`ui/answer-fetch.aye`). The bytes do grow in `net/http.aye` `Sink.body` while libcurl runs, but nothing reads them before the end.
  - So the slice list below; this card is slice 1.
- slices:
  1. (this card) The API, the stream parser and reconnection on top of the delivery that exists: the whole body when the response ends. Verify: unit tests of the parser, the WPT area, `eventsource_last_event_id`.
  2. Incremental delivery in one process: net exposes the status, headers and the bytes received so far of a running script request (`Load.job.sink`), and `ak.fetchStart` gains a "part" callback (or a per-request part task) the loop queues when new bytes came; `EventSource` feeds each part to `ak.eventStream` (it already keeps `rest`, the id buffer and the split-CRLF flag between calls). The same path gives fetch a streaming `body` and XHR real `progress`. Verify: a test-server route that sends one event and holds the connection (`/held/` style), the message arrives before the response ends; the WPT files that keep the stream open.
  3. Incremental delivery with `DWELLER_PROCESS=site`/`tab`: the browser forwards the parts of a held fetch to the renderer (a new IPC message, `fetch_part{id, bytes}`), which feeds the same path. Verify: slice 2's test in the window with `DWELLER_PROCESS=site`.
  4. `EventSource` in dedicated and shared workers (`engine/workers/`).
- design (slice 1):
  - Parser in Aye (`engine/event-stream.aye` the state: data, event type, id buffers, the split-CRLF flag, `retry`; `next-stream-event.aye` reads lines from `from` up to the next empty line and returns the position after it, null when no full event is left; `take-stream-field.aye` the fields; `stream-retry.aye`; `stream-dispatch-end.aye` takes the LF of a CRLF that ends an event; `stream-start.aye` drops one leading BOM). It works on bytes, so lines end at CR, LF or CRLF anywhere; a CR at the end of one call and its LF at the start of the next is the flag.
  - `ak.eventStream(text, id, crlf, first)` (`ak-event-stream.aye`) parses what has come since the last dispatched event and answers `[rest, id, crlf, retry, dispatched, [type, data, lastEventId, ...]]`: no parser state lives in the engine, the JS object keeps `rest`, the id buffer and the flag. An unfinished event stays in `rest`; parsing its lines again is idempotent (fields only set buffers).
  - `EventSource` (`engine/event-source.js`, run right after the prelude so it keeps the native `dispatchEvent` and its events are trusted): the constructor resolves the URL against the document's base URL (SyntaxError when invalid), `withCredentials` picks `include` or `same-origin`, the request is CORS mode with `Accept: text/event-stream`, `Cache-Control: no-cache` and `Last-Event-ID` once there is one (UTF-8). A response that is not status 200 with the MIME essence `text/event-stream`, or a refused request (CORS, CSP), fails the connection (`CLOSED`, `error`); another network error and the end of the stream reconnect: `CONNECTING`, `error`, then a new request after the reconnection time (3000 ms, or `retry`). `open`, then each event as a `MessageEvent` (`data`, `origin` of the final URL, `lastEventId`), until `close()`. `onopen` is the object's own handler; `onmessage` and `onerror` are EventTarget's handler attributes.
  - Shared numbers: none (no host object tag; one more `ak` method, `eventStream`).
- references: spec https://html.spec.whatwg.org/multipage/server-sent-events.html . Chromium `third_party/blink/renderer/modules/eventsource/event_source_parser.cc` (taken: the byte-level line splitter with the BOM and CRLF flags, the id buffer becoming the last event ID at each empty line, `retry` with an empty value as the default 3000 ms) and `event_source.cc` (taken: the request headers, 200 plus `text/event-stream` or fail, access-check failures abort while other failures and the end of the body reconnect, `error` before each reconnection).
