# Q4.7: a layout result cache keyed by the constraint space

## Status: in progress, 2026-11-17 (paused with the wave; measurement half done, no code)

- goal (the integrator's row): first the measurement that says whether the cache pays. If under 5% of the layout time of the perf pages is repeated subtree layouts, close as "not needed".
- what exists: `keepsLayout` (layout/block.aye) keeps a child's layout in an incremental relayout when its containing block is the same (`Tree.keep_under`), and `has_intrinsic` keeps a box's intrinsic widths. There is no cache of a box's layout by its constraints inside one layout pass.
- probe (a throwaway build, not committed; it timed every `layoutContents` call and counted a call as repeated when the same box had its contents laid out earlier in the same pass, a pass being one `layoutRoot` or one `relayoutUp`; "same" when the box's width and containing-block height were equal too):
