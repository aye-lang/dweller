# Q2.4d: the browser derives top, referrer and headers of a renderer's request

- goal: with `DWELLER_PROCESS=tab` the browser no longer takes the security-relevant fields of a renderer's `fetch` message as given (Q2.4a left list). It derives the top-level site (SameSite cookies, the cert bypass host) from its own record of the tab, checks the referrer against the asking document, refuses forbidden or malformed methods, and drops the forbidden request headers, so `Cookie`, `Origin`, `Referer` and `Sec-*` come only from net.
- design:
  - `top`: the browser keeps `tp.top`, the final URL of the last top-level document it sent the renderer (`sendFetched` for a navigation it started). It is the URL of doc 0 (`fetchDoc`, `fetchInitiator`), and the `top` of every request that is not that navigation (`topOf`; `tp.committed` before the first one). `tp.committed` is not used for this, because a navigation sets it before the old page is gone: a request the old page sent before the renderer got `navigate` would be checked against the new site. The `top` in the message is only checked: "" or of the same site as the browser's (`topClaimed`, which also takes the same URL or origin as `commitMatches` does, for `file:` pages); anything else kills. A `Document` request that the browser did not start now always counts as a frame's document of the tab's top-level page, so a renderer can no longer get the SameSite context of a top-level navigation for it by leaving `top` empty.
  - `referrer`: "" or a URL that is not http(s) (net never sends it as a Referer, and it gives no cookie context), else of the same origin as the document the request names (`fetchDoc`: doc 0 is `tp.top`, a frame's document its final URL) (`referrerAllowed`); anything else kills. Net applies the referrer policy (`referrerOf`, strict-origin-when-cross-origin). In net, the SameSite initiator of a request without a referrer is now its `Initiator.Page` URL (`initiatorPage`), not the target, so an empty referrer does not make a cross-site frame's request same-site.
  - method: "" or a token that is not `CONNECT`, `TRACE` or `TRACK` (`net.methodAllowed`); anything else kills (as Chromium's `IsValidRequest`: "Forbidden method", "invalid characters in method"; Dweller refuses them in no-cors mode too, where the renderer never sends them either).
  - headers: a line that is not `token: value`, or has a CR or NUL, kills (Chromium's `HttpRequestHeaders` IPC traits refuse invalid names and values). A forbidden request header (the Fetch list, `access-control-request-private-network` as Chromium, `Proxy-*`, `Sec-*`, `X-HTTP-Method(-Override)` / `X-Method-Override` naming a forbidden method) is dropped, not a kill (`net.allowedHeaders`): Chromium's network stack sets its own `Cookie`, `Referer` and `Origin` too, and the renderer's JS drops them already, so only a compromised renderer sends them. Before this, a `Cookie` line in the request's headers went out next to net's own.
  - kind (destination), credentials and mode stay range-checked (`net.codedRequest`, Q2.4a); the request body stays bounded by the 1 MiB payload limit.
  - every failed check is `bad fetch` (stderr `error: bad message: bad fetch PID`), as the other `fetch` checks.
  - test hooks: `DWELLER_TEST_EVIL=top` (every page request claims `http://evil.example/` as its top), `referrer` (that URL as its referrer), `trace` (method `TRACE`), `headers` (its headers are `Cookie: evil=1`, `Referer`, `Sec-Fetch-Site` and `Origin` lines).
- Chromium read: `services/network/cors/cors_url_loader_factory.cc` (`IsValidRequest`: forbidden and malformed methods are a bad message; the initiator against `request_initiator_origin_lock`), `services/network/public/cpp/request_mode.h`, `net/http/http_util.cc` (`IsSafeHeader`: the forbidden names, `proxy-` / `sec-`, the method-override headers). Dweller takes: the browser kills on what Chromium reports as a bad message (method, the request's own top-level site and referrer), and drops the forbidden headers as net sets those itself.
- files: new `browser/net/{token,forbidden-method,method-allowed,method-allowed_test,forbidden-header,allowed-headers,allowed-headers_test,initiator-page}.aye`, `browser/net/http.aye` (the SameSite initiator without a referrer); `browser/ui/{tab-process,start-tab-process,end-tab-process,send-fetched,fetch-initiator,answer-fetch}.aye`, new `browser/ui/{top-of,fetch-doc,top-claimed,top-claimed_test,referrer-allowed,referrer-allowed_test}.aye`; `browser/renderer/ask-fetch.aye` (test hooks); new `browser/tests/net/request_headers.html`; `tests/browser.rs` (`window_renderer_net`).

## Status: done, 2026-11-08

Left:
- a navigation the browser starts for a renderer (`beginNavigation`: a link, a form) goes without a referrer and with `Initiator.Browser`, so net counts it as same-site for SameSite: under the flag a cross-site form POST sends Lax cookies and a cross-site link Strict ones (the window's own process has `noteNavigation`). The browser should give it the page that began it (the old `tp.committed` in `beginNavigation`) as its referrer and initiator: a next card (Q2.4e).
- a compromised renderer can still ask the browser to navigate its tab to any site (`begin_navigation`) and then acts as that site in the same process: process swap and site locks are Q2.6.
- `tp.top` follows only navigations the browser answers with a document; a page the renderer makes without one (`about:blank`) keeps the last top for its requests.
