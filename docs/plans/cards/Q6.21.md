# Q6.21: a named font-family is the OS font of that name

- goal: P1.S9's W3 review found three sites drawn in the wrong face because every `font-family` mapped to one of three fixed files (Arial, Times New Roman, Courier New): hn asks for Verdana and got Arial, go-docs' code (`SFMono-Regular, Consolas, Liberation Mono, Menlo, monospace`) got thin Courier New, zol's CJK names got serif. A named family now resolves to the installed OS font of that name.

## Decisions (given)

1. Only fonts that ship with the OS: `/System/Library/Fonts` (with `Supplemental`) on macOS, `/usr/share/fonts` on Linux; never `/Library/Fonts` or `~/Library/Fonts` (Safari's rule against font fingerprinting).
2. Machine independence: under `DWELLER_RECORD` / `DWELLER_REPLAY`, in `dump` and in tests the page sees the old fixed set, so archives, goldens and CI are the same on every machine. One switch.
3. Site mode: the matched faces work in a sandboxed renderer and with `DWELLER_PROCESS=single`.

## Design

- The switch: `font.useOsFamilies()` (`browser/font/use-os-families.aye`) turns matching on unless `DWELLER_REPLAY`, `DWELLER_RECORD` or `DWELLER_FONT_SET=fixed` is set; `font.osFamiliesOn()` reads it. Only the window (`ui/window.aye`, system fonts) and `screenshot` call it; `dump`, `print`, `wpt` never do. The browser passes `--os-fonts` to its renderers when it is on (`ui/start-tab-process.aye`), and the renderer calls `useOsFamilies()` (`renderer/serve.aye`). The test harness (`dweller_command()`) and `wpt.py` set `DWELLER_FONT_SET=fixed`.
- The index: on the first family name that is neither a web font nor a generic family, `osIndex` lists the OS font root recursively and opens every face of every `.ttf`, `.otf`, `.ttc` with FreeType: family name (FreeType's, the typographic family), weight range (`faceOf`: OS/2 weight class, or the `wght` axis), italic (style flag or a style name with Italic/Oblique: Helvetica Neue's Medium Italic has no flag), width class (OS/2). Hidden faces (a family starting with `.`) are left out, as Chromium does. Kept for the process, shared by its `System`s (the page's and the canvas's), freed with the last (`holdOsIndex` / `releaseOsIndex`).
- Resolution (`System.chainOf`, chromium `FontCache::GetFontPlatformData`): for each family of the list in order, its `@font-face` faces; else, with matching on, a generic family ends the list and an installed family adds its best face (`bestOsFace`, CSS Fonts 4 §5.2: width class nearest to normal, narrower first; then style; then weight with the existing `weightDistance`), loaded once per `System` (`osFaceLoaded`); an absent name is skipped (so go-docs reaches Menlo past `SFMono-Regular`). With matching off the old rule stays: the first known name ends the list. The chain now holds `WebFace` values, web and OS faces alike, so `pick` keeps per-character fallback through the chain, then the generic face, then the CJK and symbol fallbacks.
- Sandbox: macOS seatbelt already allows reading `/System/Library/Fonts` (directory listing and files); Linux Landlock allows reading `/usr`. Nothing is opened before entry.

## Numbers (this Mac, M-series, macOS 26, safe build)

- Index: 370 files, 787 faces, 675 kept (304 families); first lookup 26 ms in a renderer, 26 to 42 ms in one process (`DWELLER_TIMING` record `font_index`); 263 ms once with a cold page cache (a C copy of the same scan). Memory about 83 KiB. Under 50 ms, so not cached; a reader of only the `name` and `OS/2` tables would take 6 to 9 ms (C prototype) if it is ever needed.
- W8 live first paint, `window_perf.py report --live --chrome` (median of 3): hn 1218 ms (Chrome 1388), go-docs 1032 ms (Chrome 1220). The same binary with `DWELLER_FONT_SET=fixed` right after: hn 1813, go-docs 2034 (network noise is larger than the index's 26 ms). No slowdown.
- Widths on `browser/tests/fonts/os-families.html` (ten `m` at 50 px): Verdana 486.328 (Arial 416.504), Menlo 301.025 (Courier New 300.049), the same in site mode and in one process; pinned, Verdana and Menlo give Arial's and Courier New's widths.

- `cargo test --release --test browser -- fixtures text font screenshot window_renderer_sandbox wpt_reftest`; `check_taste.py`, `check_layers.py`, `gen_property_ids.py --check`, `check_plan.py`, `aye check browser`: exit 0. No golden changed.

## Left

- Linux without Landlock: seccomp refuses every open after entry, so a renderer's index is empty and named families fall back to the generic faces there (one process matches them). Chromium's font IPC (`font_open`, process-model §6) would bring them back, as for the fallback faces.
- zol stays a defect: its families (Microsoft YaHei, PingFang SC) are not in `/System/Library/Fonts` (PingFang lives in a private framework), and an unknown list still defaults to serif.
- Chrome's `monospace` on a Mac is Menlo and its `sans-serif` Helvetica; the generic faces are unchanged here (decision 2 keeps the fixed set).
- `font-stretch` is not a property yet; matching assumes `normal`.
