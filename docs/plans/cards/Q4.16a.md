# Q4.16a: where JS time goes on mistral and bbc

- goal: on mistral (idle, the rAF animation, ~28 ms of script a frame) and bbc (one W7 run, a 528 ms timer task in the longest loop iteration), measure time per bytecode op, natives, property-access cache hits and misses, GC, and the top JS functions; rank fixes by ms saved. Profile only; no engine optimization.
- method: `browser/build.sh` (safe) at 4c6482f plus the counter below, M2 Pro, `scripts/capped.sh`, archives `target/sites`. One run per site of `target/dweller URL --frames 210 --events ... --state` with `DWELLER_REPLAY`, `SDL_VIDEODRIVER=dummy`, `DWELLER_TIMING=1` (the same command `window_perf.py scroll` runs; bbc: 3 `frame`, then 40 `wheel:-3 frame` as W7; mistral: 200 `frame`, no input). Each site once without the profiler (baseline ms) and once with `DWELLER_JS_VM_STATS=t DWELLER_JS_NATIVES=1`. Mistral's idle numbers are the 210-frame run minus a 12-frame run (the load), so they cover 198 idle frames. Native hot spots from `sample PID 12` on a baseline run of each site (`target/q416a-*.sample`). Logs: `target/q416a-{bbc,mistral}-{base,prof}*.log`.
- new counter: `DWELLER_JS_VM_STATS=t` (off by default; it lives inside the existing `DWELLER_JS_VM_STATS` branch of the dispatch loop, plus one null check per `vmRun` entry and per IC slow path). It prints per interpreter at exit `info: DWELLER_JS_VM_PROF` lines: `op NAME NS COUNT` (time from one dispatch to the next is charged to the op, so an op includes the natives it calls but not JS frames it pushes), `fn NS INSNS NAME START SOURCE` (the same time by bytecode function, exclusive of JS callees), `slow NAME KIND COUNT` (named loads and stores that missed the inline IC: 0 primitive receiver, 6 shapeless or uncacheable object, 2 miss on a mono/poly site, 4 miss on a megamorphic site, 5 found the shape but the prototype case was stale, 1 poly/stub hit, 3 uncacheable store) and `allocs N` (heap allocations, summed at each GC). Files: `browser/js/vm-prof*.aye`, `vm-init-prof.aye`, `free-vm-prof.aye`, hooks in `vm.aye`, `vm-load-named.aye`, `vm-store-named.aye`, `bytecode.aye` (`BytecodeArray.func`), `heap.aye`/`gc.aye` (`allocs_before_gc`).
- overhead: two clock reads per instruction cost 22 ns (the cheapest ops measure 23–24 ns; the profiled runs are 1.4 s slower on mistral and 6.2 s on bbc, 21 ns × instructions). All op and function ms below have 22 ns × count subtracted; the corrected bbc total (5410 ms) matches the baseline script time (`timers` + `ui_raf` 5374 ms).

## Ranked fixes

Expected ms: mistral per frame (of 28.6), bbc per W7 run (of 5374 ms of script; the 528 ms task gets about a tenth of it if the profile is uniform, which this card did not measure per task).

1. Q4.16b, geometry reads skip the transition restyle when nothing changed. Goal: `metric` under 10 µs a call when style is clean (152 µs now). Files: `browser/engine/geometry.aye` (`metric`, `geometry`), `browser/engine/restyle-transitioning.aye`, `browser/animation/change-property.aye`. Verify: profiled mistral idle, `metric` ms; `ui_raf` per frame. Ref: blink `core/dom/document.cc` (`UpdateStyleAndLayoutTreeForElement` returns when the style is clean) as algorithm only; no V8 part. Expected: mistral −6 ms a frame; bbc −20 ms.
2. Q4.16c, canvas `drawImage` blends premultiplied rows without per-pixel `mix`/`premul`. Files: `browser/paint/raster.aye` (`Canvas.drawImage`, `blendPremul`), `browser/engine/canvas_api.aye` (`canvasComposite`). Verify: profiled mistral idle, `canvasDraw` ms; canvas WPT unchanged. Ref: skia `src/opts/SkBlitRow_opts.h`, `src/core/SkBlitRow_D32.cpp` (BSD). Expected: mistral −4 ms a frame (of 9.3).
3. Q4.16d, `List.items()` and the VM operand decode inline. Goal: no call for `items()` in `Heap.obj`, `Interp.slot`, `Ast.node`, `vmPushFrame`, and none for `vmImm`/`vmIdx` in `vmLoop` (check with `nm`/`sample`). Files: Aye std `list.aye` or the hot callers (`browser/js/heap.aye`, `interp.aye`, `vm.aye`, `vm-idx.aye`); a compiler change goes to the aye repo. Verify: `sample` share of `<deduplicated_symbol>` and `vmImm`; jsbench. Ref: v8 `src/interpreter/bytecode-decoder.cc` (operands decoded inline per operand scale). Expected: bbc −700 ms (28% + 9% of the samples); mistral −1 ms a frame.
4. Q4.16e, `Function.prototype.call`/`apply` stay in the dispatch loop. Goal: `CallProperty` on the call/apply builtin shifts the receiver and pushes the target frame without `callNative` → `invoke` → `vmRun`. Files: `browser/js/vm.aye` (`vmCallOp`), `browser/js/builtins.aye` (`functionCall`, `functionApply`). Verify: test262 `built-ins/Function/prototype/{call,apply}`; profiled bbc `call` calls under `vmRun` in `sample`. Ref: v8 `src/builtins/arm64/builtins-arm64.cc` (`Generate_FunctionPrototypeCall`, `Generate_FunctionPrototypeApply`). Expected: bbc −250 ms (1.58M re-entries at ~150 ns); mistral −0.5 ms a frame.
5. Q4.16f, `Array.prototype.concat` honors `Symbol.isConcatSpreadable` and `Symbol.species`, so core-js keeps the native. Files: `browser/js/builtins_array.aye`. Verify: test262 `built-ins/Array/prototype/concat`; on bbc the `concat` function line gone from the profile. Ref: v8 `src/builtins/builtins-array.cc` (`IsConcatSpreadable`, `Slow_ArrayConcat`). Expected: bbc −250 ms.
6. Q4.16g, `replace` substitutes `$<name>` from the `groups` of a custom `exec` result, so core-js keeps native `replace`/`exec`. Files: `browser/js/regexp.aye`, `browser/js/builtins_string.aye`. Verify: test262 `built-ins/RegExp/prototype/Symbol.replace`; bbc and mistral profiles without the wrapper. Ref: v8 `src/builtins/regexp-replace.tq`, `src/runtime/runtime-regexp.cc` (`GetSubstitution`). Expected: bbc −300 ms; mistral −0.5 ms a frame.
7. Q4.16h, a delete keeps the object shaped. Goal: `removeProp` moves to a new shape (or back to the parent shape when the last property is deleted) instead of `shape = NONE`; the `delete Function.prototype.x` repro hits. Files: `browser/js/heap.aye` (`removeProp`), `browser/js/shapes.aye`. Verify: the repro's `slow call 2` count 0; `js_conformance`. Ref: v8 `src/runtime/runtime-object.cc` (`Runtime::DeleteObjectProperty`, the map rollback), `src/objects/js-objects.cc` (`JSObject::OptimizeAsPrototype`). Expected: bbc −220 ms (3.7M slow loads); mistral −0.3 ms a frame.
8. Q4.16i, IC for primitive string receivers (method loads on `String.prototype`, `length`). Files: `browser/js/vm-load-named.aye`, `vm-ic-hit-prop.aye`, `vm-ic-load-case.aye`. Verify: profiled bbc kind-0 count; `js_conformance`. Ref: v8 `src/ic/ic.cc` (`LoadIC::Load`, the `IsStringMap` case), `src/ic/accessor-assembler.cc` (`kStringLengthFieldDescriptorIndex`). Expected: bbc −150 ms; mistral −0.2 ms a frame.
9. Q4.16j, an array `length` handler in `GetNamedProperty`. Files: `browser/js/vm-ic-hit-prop.aye`, `vm-load-named.aye`. Verify: bbc kind-6 `length` count near 0. Ref: v8 `src/ic/accessor-assembler.cc` (`kArrayLengthFieldDescriptorIndex`). Expected: bbc −70 ms; mistral −0.1 ms a frame.
10. Q4.16k, `Array.prototype.sort` with a comparator. Goal: a merge sort that calls the comparator through the dispatch loop, not `callAt`. Files: `browser/js/builtins_array.aye` (`arraySort`, `genericSort`, `sortLess`). Verify: test262 `built-ins/Array/prototype/sort`; mistral `sort` ms. Ref: v8 `third_party/v8/builtins/array-sort.tq` (TimSort). Expected: mistral −1 ms a frame.
11. Q4.16l, the CSSOM prelude caches the rule objects of a sheet. Files: `browser/engine/prelude.aye` (`ruleObject`), the `selectorText` native. Verify: bbc `ruleObject` and `selectorText` ms. Ref: blink `core/css/css_style_sheet.h` (`child_rule_cssom_wrappers_`) as algorithm only. Expected: bbc −400 ms.

Not worth a card now: GC (bbc 212 ms, mistral 0.27 ms a frame) and the simple ops (`Star`, `Ldar`, `Mov`: 2–4 ns each after the correction). The big costs are calls, IC misses and natives, not dispatch.
