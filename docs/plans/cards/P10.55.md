# P10.55: WPT runs have the test fonts of WPT's own runners

- goal: during `wpt.py run` and `conformance.py run` (and only there) the fonts `wpt run --install-fonts` installs are system fonts of Dweller, so tests that name `font-family: Ahem` without `@font-face` measure with Ahem, not with a fallback; `ch`, `ex`, ascent, descent and line-height with Ahem as the Ahem spec says.
- reference: wpt `tools/wptrunner/wptrunner/wptrunner.py` (`--install-fonts` installs `fonts/Ahem.ttf` only; `font.py` per OS), `tools/wptrunner/wptrunner/browsers/firefox_android.py` (copies `fonts/Ahem.ttf` into the profile), wpt `fonts/README.md`; Chromium content_shell's test fonts (idea only).
- before: reftests (`dweller screenshot`) got every font of wpt `fonts/` (Ahem, CanvasTest*, Lato-*, mark-anchor-test, ahem-visible-zwnj) as system families through `DWELLER_FONT_DIRS`; testharness tests (`dweller wpt`) had no font system at all: script geometry measured with `font.Fixed` (every glyph 0.5em, ascent 0.8em), whatever the family.
- design: `wpt.py run` copies the runner's font list (`TEST_FONTS = ["Ahem.ttf"]`, from `<wpt root>/fonts/`) into `target/wpt-test-fonts/` and sets `DWELLER_FONT_DIRS` to it for every child (reftests, crashtests, testharness). `dweller wpt` now makes a `font.System`, adds the `DWELLER_FONT_DIRS` fonts (`font.addEnvFonts`, the existing path `dweller screenshot` uses) and gives it to the engine as the default measurer (`engine.setDefaultMeasure`), which script geometry uses while the page has no measurer of its own (`p.measure`, set by a window's `layoutPage`). The window and `dweller screenshot` are unchanged; without `DWELLER_FONT_DIRS` no font is added.
- files: new `browser/engine/set-default-measure.aye`; `browser/engine/geometry.aye` (`layOut` takes the default measurer before `s.fixed`), `browser/main.aye` (`wpt`), `browser/tools/wpt.py` (`use_test_fonts`), `browser/tools/wpt_reftest.py` (no per-run font env).
- Ahem metrics (`target/wpt/zz-ahem/metrics.html`, a local testharness page, not committed): glyph advance 1em, line-height `normal` 1em, baseline at 0.8em: pass. `1ch` and `1ex` are still 0.5em: `css/values.aye`, `css/calc.aye` and `layout/grid.aye` turn `ch`/`ex` into `0.5em` at parse time, with no font, so they are wrong for Ahem (1em and 0.8em). Not fixed here (see left).
- verify: `cargo test --release --test browser -- style_fixtures layout_fixtures jsdom_fixtures errors screenshot_` → 0 (no golden changed); `cargo test --release --test browser -- wpt` → 0 (`wpt_reftest` still finds Ahem); `check_taste.py`, `check_layers.py` → 0; `conformance.py table` then `check` → 0.
