## Design

Chromium keeps the caches in the browser
(`content/browser/cache_storage/cache_storage_cache.cc`) behind a
renderer-side `Cache` (`modules/cache_storage/cache.cc`). Dweller has
that store already: the IndexedDB backend of Q5.11 is in the browser
process, per origin, transactional and saved in the profile. So the
Cache API is JavaScript (`engine/cache/cache.js`) over one reserved
database per origin, `dweller:cache-storage`: an object store `caches`
(auto-increment id, unique index on the name; creation order is key
order) and an object store `entries` (auto-increment key, index on the
cache id; insertion order is key order), an entry holding the request's
URL and headers, the values of the headers `Vary` names, and the
response's status, headers, body bytes, URL and type. Matching (URL
without fragment, `ignoreSearch`, `ignoreMethod`, `ignoreVary`) runs in
the page over the entries of one cache. `indexedDB.databases()` does
not list the reserved database.
