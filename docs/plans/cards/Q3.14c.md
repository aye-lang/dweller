# Q3.14c: Sec-Fetch-Dest for every destination, user activation, WPT fetch/metadata and referrer-policy

- goal: `Sec-Fetch-Dest` matches the Fetch spec's destination for every request kind Dweller makes: fonts send `font` (not `script`), worker scripts `worker`. `Sec-Fetch-User: ?1` goes only with a navigation the user activated: a script's `form.submit()`, `location` or `window.open` without transient activation does not get it. WPT `fetch/metadata` and `referrer-policy` become measured areas. Source: Q3.14's and Q3.14b's left lists.
- chain: on Q3.14b (#319, which contains #313).
- design:
  - destinations: `net.Kind` gets `Font` and `Worker` (request codes 5 and 6 over IPC, `codedRequest` takes them; `Accept: */*`; telemetry names `font` and `worker`). `secFetchDest` maps them to `font` and `worker`. `loadWebFonts` (`engine/fonts.aye`) prefetches, waits for and fetches fonts as `Kind.Font`. The page side of a worker's fetch (`worker-page.js` `h.fetch`, `wkFetch`) takes a fifth argument: true for the worker's main script and its module graph (`FETCH_SAME_ORIGIN`, `FETCH_MODULE`), which then load as `Kind.Worker`; `importScripts` stays `script`.
  - destination table checked against the other request kinds: document / iframe (`Kind.Document`, `top`), style (sheets, `@import`), image, script (classic, module, `modulepreload`), empty (`fetch`, XHR, preflight) are right. Dweller makes no `sharedworker`, `serviceworker`, websocket, audio, video, track, manifest, object or embed requests, so there is nothing to label. A `<frame>` sends `iframe` (left).
  - user activation: `Script.activation_ns` (`?u64`), the last activation-triggering input. `noteActivation` (`engine/note-activation.aye`) sets it, and the sticky `activated` bit, from `dispatchEvent` and `dispatchPointer` (the trusted input paths of the window, the tab renderer and the agent) for `keydown` (not Escape), `mousedown`, `pointerdown`, `pointerup`, `touchend`, `click` and the keyboard `__click`. `hasTransientActivation(page)` (`engine/has-transient-activation.aye`) is true within 5 s of it, and always for a page without scripts (only the user can make it navigate). `consumeActivation` clears it. `Page.follow`, `submitForm` and `location` (`akNavigate`) pass `hasTransientActivation` to `noteNavigation` instead of the old constants; `window.open` into `_self`/`_parent`/`_top`/a named frame now notes the navigation too (it had no referrer hint), and a `window.open` that opens a new context consumes the activation. The prelude's own `actUntil` (pointer lock, fullscreen) is unchanged.
  - tab process: `BeginNavigation` comes only from `runAct` and `submitAt`, which run on trusted input, so the browser's `user_activated = true` for the navigation it began stays right. Script navigations are not taken in the renderer yet.
  - WPT: `wpt_areas.json` has `fetch/metadata` and `referrer-policy` (`upstream`: `.sub.` and `common/security-features`). Thresholds are the measured score rounded down to a multiple of 5 points.
- references:
  - specs: https://w3c.github.io/webappsec-fetch-metadata/ , https://fetch.spec.whatwg.org/#concept-request-destination , https://html.spec.whatwg.org/multipage/interaction.html#transient-activation .
  - Chromium `services/network/sec_header_helpers.cc` (`SetSecFetchDestHeader`, `SetSecFetchUserHeader`), `third_party/blink/public/common/frame/user_activation_state.h` (`kActivationLifespan` 5 s, the transient bit's expiry and consumption; the `core/frame` path in the card does not exist at this checkout). Dweller takes: the 5 s transient lifespan and "consume on popup"; one page's state, without Blink's notify-ancestors / consume-whole-tree propagation.

## Status: done, 2026-11-08

Left:
- Fonts are fetched `no-cors` with credentials; the spec makes them `cors` (same-origin credentials), and WPT's `css-font-face` sets fail with "Failed to query for recorded headers". Workers send `no-cors`, not `same-origin` (Dweller's `Mode` has no `same-origin`).
- A worker's own `fetch()` loads as `Kind.Script` (`script`, not `empty`): it shares `importScripts`' `FETCH` path.
- A `<frame>` element's document sends `iframe`, not `frame` (the request does not know its element).
- `SharedWorker`, service workers, WebSocket, `<audio>`/`<video>`/`<track>`, `<embed>`/`<object>`, `<link rel=icon|manifest|prefetch>`, `<input type=image>`, `<video poster>` and SVG `<image>` make no requests; their WPT sets time out or error.
- Activation is per page: a click in a frame does not activate its ancestors, and `consumeActivation` clears only the opener page. A `window.open` into a new context does not carry the activation to the new tab's first request (no `?1` there).
- Most `fetch/metadata` navigation sets (`element-a`, `element-area`, `window-open`, `window-history`) fail in the harness itself (no `createElement` on the opened window, no `test_driver` clicks), so they say nothing yet about `Sec-Fetch-User`.
- From Q3.14b, still open: in the tab process a frame's and a `target=_blank` tab's document fetch carry no referrer and no policy; the image cache does not key on the referrer policy.
