- cause fixed: CSS 2.1 10.3.7 and 10.6.4 (and css-position-3) take the static position at the inline-start edge of the static-position containing block, and drop the end-side inset of an over-constrained box, both by `direction` and `writing-mode`. Layout always put the box's left (top) edge at the static point and let `left` (`top`) win; only `vertical-rl`'s block axis was handled (`staticFlip`, `leftWins`).
- design, per physical axis (as Chromium's `absolute_utils.cc`: the static position has an inline edge from the parent's direction, and with `normal` alignment the inset on the containing block's start side wins):
  - `staticFlip(t, i, horizontal)`: when the parent starts at the far end of the axis (`startsFar`: `rtl` on its inline axis, `vertical-rl` on x), the static point is the box's far margin edge. Only for parents that record the static point at their inline start (block containers, inline boxes); flex and grid parents keep their own alignment (`flexStaticShift`, `gridStaticShift`) and the old `vertical-rl` flip.
  - `endInsetWins(t, i, start, end, horizontal)`: the end inset places the box when the start one is `auto`, or when both are set and the containing block (or the root, for the initial containing block) starts at the far end.
  - one placement for both paths: `placeAbsolute` (was `placeTurnedAbsolute`) uses both rules for x and y, and `layoutAbsolute` ends with it. A turned box is placed physically in every case now, so its turned problem only gives the size (`leftWins` and `StaticSpot.placed` removed).
  - the static point itself: a block-level box in an `rtl` block starts at the content box's right (`flow`), an inline-level one on an otherwise empty `rtl` line at the line's right (`LineBuilder`). In a line with content the bidi order already gave the inline-start point.
- this also changes horizontal `rtl` pages: an absolutely positioned box with `left` and `right` both `auto` in an `rtl` block now ends at the static point, as in Chromium, and `right` wins over `left` in an `rtl` containing block.
- references: https://www.w3.org/TR/CSS21/visudet.html#abs-non-replaced-width , https://drafts.csswg.org/css-position-3/#abspos-insets , Chromium `third_party/blink/renderer/core/layout/absolute_utils.cc` (`GetStaticPositionInsetBias`, `GetAlignmentInsetBias`).
- files: `browser/layout/static-flip.aye`, `absolute.aye`, `place-absolute.aye` (renamed from `place-turned-absolute.aye`), `layout-turned-absolute.aye`, `block.aye` (`flow`, 3 lines), `inline.aye` (empty line, 3 lines), new `end-inset-wins.aye`, removed `left-wins.aye`; `docs/writing-modes.md`; new fixture `browser/tests/layout/absolute_rtl.html` and `.layout` (golden new, each box read against the rule: block-level static in `rtl` at x 275 = 315 - 40; after `ab` at 255; empty line at 275; over-constrained `left: 10px; right: 10px` at 265; `vertical-lr rtl`: static bottom edge at 575, over-constrained `top`/`bottom`: bottom wins, y 685).
