# Q4.28b: the JS-written built-ins call their own saved intrinsics, not the page's globals

- goal: the built-ins written in JavaScript (`browser/js/lib.aye` and the spec scripts `browser/js/*.js` that `installBuiltins` runs after it) look up `Array.from`, `Object.defineProperty`, `Math.min`, `TypeError` and the other globals when they run, so a page that replaces one (core-js replaced `Array.from` on mistral, Q4.28) can slow them down, break them or run page code inside them. Save the intrinsics once when the prelude runs, before any page script, and call the saved copies (Node's primordials: https://github.com/nodejs/node/blob/main/lib/internal/per_context/primordials.js).
- also: the native `Array.from` closes the iterator when `mapfn` throws (https://tc39.es/ecma262/#sec-array.from). This is the check core-js fails, so it replaces `Array.from` (Q4.28, "Found, not in this step").
- method: a Python regex count over the JS source (for lib.aye, the `\\` lines), with comment lines and quoted strings left out. It counts `Ctor.method` uses of 47 global constructors and namespaces (`Object`, `Array`, `Math`, `Reflect`, `Promise`, the typed arrays, …; not `.prototype`, not assignments), `Symbol.*` reads, bare global names, and the other `.name(` calls (method calls). `Date.UTC` was counted by hand. Before: at 6b97ad78 (origin/main + Q4.28).

## Change

- lib.aye: one block at the top of the prelude. `const { Object, Array, String, Number, Boolean, Symbol, BigInt, Math, JSON, Date, RegExp, Map, Set, WeakMap, WeakSet, Function } = G;` and `const { Error, EvalError, RangeError, ReferenceError, SyntaxError, TypeError, URIError, isNaN, isFinite, parseInt } = G;` (26 names) shadow the page's globals, so `new TypeError`, `String(x)`, `new Map()` and the `Symbol.iterator` reads (non-writable on the intrinsic) do not change. Then 24 static methods: `const ArrayFrom = Array.from;` … `const JSONParse = JSON.parse;` (`ArrayFrom`, `ArrayIsArray`, 12 `Object*`, 6 `Math*`, `BigIntAsIntN`, `DateUTC`, `StringFromCharCode`, `JSONParse`), and every call site calls them.
- `Promise.resolve`: `promiseResolve(C, v)` (PromiseResolve, https://tc39.es/ecma262/#sec-promise-resolve) is the body of `static resolve`. `await` in the async function and async generator drivers, the module loader and `finally` call it (6 sites), as the spec says. The 4 calls in `Promise.all`, `allSettled`, `race` and `any` stay: the spec reads `resolve` from the constructor there (test262 checks it).
- `ArrayBuffer.isView(v)` in `structuredClone` became `views.has(v)` (the prelude's own map).
- the spec scripts: the same kind of block at the top of the other 8 scripts (60 names, 39 static methods: for example `ReflectConstruct`, `ObjectDefineProperty`, `MathMin`, `PromiseResolve = Promise.resolve.bind(Promise)`). Their old captures (`apply`, `isArray`, `define`, `construct`) stay.
- after: in all 10 files, a `Ctor.method` left is a capture line, a `Symbol.*` read through the saved `Symbol`, or one of the 4 `Promise.resolve` reads above.
- `Array.from` (`arrayFrom`, `browser/js/builtins_array.aye`): with a callable `mapfn` and an iterable that the engine does not iterate itself (not an array, string, arguments, Map, Set or built-in iterator), `arrayFromIterator` (`browser/js/array-from-iterator.aye`) steps the iterator, maps each value at once, and calls `IteratorClose` (`closeIterator`) when `mapfn` throws. Before, it drained the iterator first and mapped after, so `return` was never called, and `next` and `mapfn` ran in the wrong order.
- `structuredClone` with `transfer`: a typed array over a transferred buffer came out empty (it read `length` after the buffer was detached). It now takes the offset and length from the view's slot. The fixture found it.
- fixtures (`.out` from node 22):
  - `browser/tests/js/299_prelude_saved_globals.{js,out}`: replaces the 26 global names and the 24 static methods with a function that counts and throws. Then `Promise.all` (over a Set), `allSettled` (over a generator), `any`, `new AggregateError(Set)`, `Uint8Array.from(generator, mapfn)`, `new Uint8Array(Set)`, `new Int16Array(array-like)`, `BigInt64Array`, `Float64Array#subarray`, a RangeError, `Intl.ListFormat`, `Intl.Segmenter` (word and grapheme), `structuredClone` with `transfer`, `Reflect.ownKeys`, `Object.getOwnPropertyDescriptors`, `copyWithin`, `Iterator#take`, `setUTCFullYear`, `unescape` all give node's results, and `await` and `finally` do not call a replaced `Promise.resolve`. It ends with `page replacements called 0`. Base: `Uncaught TypeError: Object.defineProperty is not a function` (the prelude's `hidden` read `Object` from the page) and nothing else printed.
  - `browser/tests/js/300_array_from_closes_iterator.{js,out}`, as test262's `iter-map-fn-err.js`: `mapfn` throws → `return` called once, on the iterator, with no arguments, and `mapfn`'s error wins over a throwing `return`; `next` throws → no `return`; normal end → no `return`; the `return` getter is read only when closing; `next` and `mapfn` alternate; a generator's `finally` runs. Base: 6 of the 11 lines differ.

## Left

- method calls through prototypes: 396 (lib.aye 287, regexp-spec.js 41, text-codec.js 29, disposable-stack.js 19, iterator-compose.js 13, promise-keyed.js 6, array-generic.js 1), for example `list.forEach`, `p.then`, `s.split`, `Function.prototype.apply.call`, `Object.prototype.toString.call`, `seen.has`. A page that replaces `Array.prototype.forEach` still runs inside `Promise.all`. Node's answer is uncurried copies (`ArrayPrototypeForEach(list, f)`); that is a larger step.
- host globals read when called: `G.reportError` (module loader) and `G.DOMException` (`structuredClone`'s DataCloneError). The window adds them after the prelude, so the prelude cannot save them.
- the window's prelude (`browser/engine/prelude.aye` 208 static calls, `browser/engine/*.js` 296, with `Array.from` 11 in prelude.aye: canvas `drawImage`, `setLineDash`, `isPointIn*`) has the same problem. Not in this step.
- `Promise.all`/`allSettled`/`race`/`any` read `Promise.resolve`, not `this.resolve` (spec: `GetPromiseResolve(C)`), and once per element, not once.
- `Array.from` still ignores `this` as a constructor and accepts a non-callable `mapfn`.
