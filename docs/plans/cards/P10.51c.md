# P10.51c: CSS transitions paint in the window; animations cost less per frame

- goal: (1) transitions painted and started without a script read (before-change styles kept only for elements whose `transition-*` applies; class/attribute, `:hover`/`:focus`, media changes start them; transform/opacity composite); (2) the window calls the discovery hook after its own layout; (3) per-frame cost: resolved keyframes cached, `ui_raf` < 1 ms for one box, no `layout_full` during an infinite animation; (4) the screenshot painter draws `rotate()`/`scale()`. P10.51b's "left" list.
- design (done):
  - No full layout during an infinite animation: a local restyle with boxes kept (`keep`) left the old values of each restyled element held in `Styles.shared`, so `restyle` counted them against `RESTYLE_ROUNDS * elements` and styled the whole document again every ~12 frames on a small page. After `keepRestyled` rebinds the boxes to the new values, `releaseRestyled` releases the old ones (they go to `Styles.free` and the next frame reuses them) and puts the round counter back when nothing moved: memory stays flat and the counter no longer grows.
  - The window runs the animation hook after its own layout (`afterLayout` → `runAnimationHook`), so a page whose `@keyframes` come from a linked sheet starts at the window's first layout.
- files: `browser/engine/release-restyled.aye`, `browser/engine/after-layout.aye`; wiring in `engine/geometry.aye` (2 lines), `ui/window.aye` (1 line), `css/cascade.aye` (`Styles.release` pub).
- reference: blink `core/animation/css/css_animations.cc` (CalculateTransitionUpdate, before-change style), `core/css/resolver/style_resolver.cc` (base style); https://drafts.csswg.org/css-transitions-1/#starting. Algorithm only.
- verify: `cargo test --release --test browser -- window_` and `-- screenshot_ paint scroll style_fixtures layout_fixtures jsdom_fixtures` (ANGLE fetched); `check_taste.py`, `check_layers.py` → 0.
- status: partial 2026-10-17.
  - infinite `rotate()` spinner (one box, fast build, 150 frames): `layout_full` 8 → 1 (the first layout), `style_full` 9 → 2, composited frames 61 → 65; `ui_raf` ~1.0 ms per frame (P10.51b's ~7 ms was a debug-build number; fast build was already ~1.06 ms).
  - linked-sheet one-box animation: `layout_full` 4 → 0 after the first paint; 35 composited frames.
  - tests: `window_` 54/55 (only `window_spaces` `takeover.jsonl`, the known race fixed by PR #182); `screenshot_ paint scroll style_fixtures layout_fixtures jsdom_fixtures` 15/15. No golden changed. `conformance.py` not run (no WPT checkout in this container; `wpt.py fetch` needed); no transition or animation logic changed.
- left:
  - transitions are still not painted. Findings from a first attempt (not committed):
    - `:hover` never matches (`css/selector.aye`, `.Hover => false`), and `mouseenter` is not dispatched by the window; a hover transition needs hover state in the DOM and its invalidation first. A `mousemove` handler that sets a class does reach a local restyle.
    - `Restyled.old` cannot serve as the before-change style: when the restyle is not local (`keep` false) `intern` releases and reuses the old array, so `old` already holds the new values. Keep snapshots instead, made at discovery for the elements whose `transitionsWanted` holds (walk `g.styles` after each layout, only when the geometry is current).
    - `Snapshot` values of an unset property are `Value.Initial`, which `partsOf` cannot interpolate: resolve them to `PROPERTIES[p].initial` (`ownValue`) before comparing.
    - painting: overlay the running values onto the element's interned values after `restyle` and before `keepRestyled` (copy, set `currentValue`, `Styles.intern(copy, now)`, remember the shown array so `styleChange` skips it as an after-change style); each transition frame notes a `style` change for the running elements and must move `Script.version`, or the window does not lay out again. With that, the class change restyled but no frame followed: the 16 ms timer is armed only by `watchTransitions` in JS, and the hook run after layout did not arm it (to look into first).
    - `anyWanted` keeps the transition timer running for every snapshot that wants transitions; snapshots made by discovery must not (a `read` flag set by `getComputedStyle`).
    - transitions interpolate only the four typed kinds: a `transform` transition does not run (use the Web Animations mixer, `ak.interpolate`).
  - per-frame JS cost: `valueAt` resolves both keyframe values through `getComputedStyle` with inline writes each frame; cache per animation and keyframe pair; `resync` re-reads 9 computed values per element per frame, and `discover` does again after each layout.
  - the screenshot painter does not draw `rotate()`/`scale()`.
