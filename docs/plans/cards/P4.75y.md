#### P4.75y: skip rule matching for elements that can share a sibling's style

- goal: cut mistral's `script_layout` (3.45–3.48 s over 8143 forced layouts after P4.75w; target ≤ 2.6 s) by (1) Blink's sibling style sharing: an element whose recently styled sibling has the same tag, the same attributes that selectors read, the same parent values and the same answers to the sibling-sensitive rules takes the sibling's computed values without matching; (2) the `style` attribute and presentational hints in the matched-properties cache key, so those elements can hit; (3) share and cache hit rates per site. github and react must not get slower; identical output.
- design (Blink's algorithms, no code copied):
  - candidates (`StyleSharing`, per `Computer`, so per styling pass): the last 16 elements styled in the pass that may share (`mayShare`: no `id`, not a shadow host, not slotted, not a `slot`, parent not a host, in the document's tree), each with its parent, the parent's values, its values and the hash of its hints (`noteShared`). Only elements styled in the same pass are candidates, so a partial restyle never reads a stale sibling.
  - `shareStyle` (before matching, in `styleElement`): a candidate with the same parent, the same parent values (pointer), the same hints hash, values still its current ones, the same tag and namespace; then per sheet (UA, quirks, author) `sameSiblingRules`: the attributes that the sheet's selectors read (`SiblingIndex.attr_names`: every attribute selector name, plus `class`, `style`, `id`, `part`, `slot`, `exportparts`) are equal on both (`sameReadAttrs`), and every sibling-sensitive rule that may match (`RuleIndex.siblingCandidates`) gives both the same result (`ruleSpec`). A rule is sibling-sensitive (`siblingSensitive`) when it has a `+` or `~` combinator anywhere, or its subject compound (with `:is()`/`:not()` arguments) has anything but type, class, id, attribute, `:hover` (never matches here) — so `:nth-*`, `:first-child`, `:empty`, `:has()`, `:focus`, `:checked`, `:lang()`, `:dir()`, `:link`, form states are compared, not assumed. No sharing in a sheet with more than 32 unkeyed sibling-sensitive rules or for an element with more than 32 candidates (the comparison would cost more than matching): github's sheet is one of those, so github shares nothing and pays three compares per element.
  - a share copies the candidate's values into the scratch (`matchedValues`), takes its custom-property level (when the candidate has its own level, its parent must be the parent's current level), and the rest of `compute` runs as before (`alignCenter`, change tracking, interning). `restyleSubtrees` sees own custom properties of a shared element through `StyleSharing.own_customs`.
  - matched-properties cache: hints and the `style` attribute add a key word pair each (`inlineKey`: a tag with kind and length, and the FNV hash of the text, in offer order) instead of making the element uncacheable. The matching code moved from `styleElement` to `matchElement`, unchanged otherwise.
