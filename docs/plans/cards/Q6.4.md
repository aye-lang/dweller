## Slice 1: transitions of sizes and box edges

- causes, three:
  - `getComputedStyle(e).padding` (and `margin`, `border-width`, ...) wrote the cascaded longhands, not the values of a running transition; the longhand read was right.
  - with `transition-behavior: allow-discrete`, a length property did not start a transition between values that cannot interpolate (`auto` and `40px`), and the first half of a discrete step read the internal `initial` instead of the initial value.
  - a transition between a length and a percentage did not run (`10px` to `100%`); it is `calc()`.
- design:
  - `animation.animatedCopy`: the element's values with those of its running transitions; `akComputedStyle` reads every shorthand and longhand from that copy (freed by `freeValues`).
  - `allowsDiscrete` also holds for the length properties (`PKind.Length`, `LengthNonNeg`). For every property it does not: `css/css-animations` loses 26 (`display-interpolation`, `transition-properties-not-animatable`), measured in Q6.3. `flipped` resolves an internal `initial` to the property's initial value.
  - `mixLengths`: `interpolate` falls back to (px, percent) pairs when the kinds differ; the result is `Px`, `Percent` or `Calc`.
  - `progressAt`: a transition is active at its start time (`local < 0`, not `<= 0`), so `step-start` shows the end value in the first frame (`css/css-transitions/allow-discrete-auto-inset.html`).
  - `writeComputedSides` frees the four side strings (a leak that the new fixture showed under `--leak-check`).
- references: https://drafts.csswg.org/css-transitions-2/#transition-behavior-property , https://drafts.csswg.org/css-values-4/#combine-mixed , https://drafts.csswg.org/css-transitions-1/#application . No Chromium file read.
- files: `browser/animation/allows-discrete.aye`, `interpolate.aye`, `value-at.aye`, new `animated-copy.aye`, `flipped.aye`, `mix-lengths.aye`, `length-pair.aye`; `browser/engine/window_api.aye` (`akComputedStyle`: six lines), new `free-values.aye`; `browser/css/write-computed-sides.aye`; new fixture `browser/tests/jsdom/transition_size_values.html` and `.tree` (golden new: `15px 15px`, `auto` then `40px`, `25%`); `browser/tools/conformance/css_box-sizing.json`.

## Slice 3: the `stretch` keyword

- cause: `stretch` (and the alias `-webkit-fill-available`) was not a value of `width`, `height`, their min/max or `flex-basis`, so the declaration was dropped.
- design (css-sizing-4, stretch-fit sizing):
  - the seven properties list the two keywords (`css.aye`, keyword strings only: no new property).
  - `fillsAvailable` and `heightOf` (new): a stretched width is the containing block's width less the box's margins (`contentSizeOf`), a stretched height is the containing block's height less the margins when that height is definite, else `auto`. `clampHeight` and `definiteContentHeight` go through `heightOf`; `replacedDims` and `replacedSize` through `widthOf`/`heightOf`.
  - absolutely positioned boxes fill the inset-modified containing block (`absolute.aye`); a flex item with `height: stretch` in a row fills its line whatever its alignment (`flex.aye`).
- references: https://drafts.csswg.org/css-sizing-4/#stretch-fit-sizing . No Chromium file read.
- files: `browser/css/css.aye`; `browser/layout/content-size-of.aye`, `block.aye`, `absolute.aye`, `flex.aye`, new `fills-available.aye`, `height-of.aye`; new fixture `browser/tests/layout/stretch_sizes.html` and `.layout` (golden new, eight boxes read: 56 high in a 60px block with 4px of margins, 94 wide float and inline-block, 84x46 abspos with insets of 10, `max-width` and `min-height`, `auto` in an indefinite block, a flex item).

## Slice 5: `aspect-ratio`: grammar, canonical text, interpolation

- cause: `aspect-ratio` was kept as raw text: any text was valid (`16 9`, `auto / 5`, `16px / 9px`), `16` and `16/9` were not written as `16 / 1` and `16 / 9`, and a transition or animation mixed the two numbers of the text one by one.
- design:
  - `aspectRatioValue` (css): `auto || <ratio>`, a ratio of one or two non-negative numbers, kept as the canonical text `[auto ]W / H` (`writeRatio`). The style attribute checks and writes it (`checksValue`, `validatesInline`). Layout's `aspectRatio` reads the same text as before.
  - `mixRatios` (animation, from `interpolateText`, so transitions, CSS animations and Web Animations share it): the logarithms of the two ratios are interpolated and the result is `R / 1`; a degenerate ratio (zero width or height) or `auto` on one side only does not interpolate, so it is discrete. `mixesText` lists `aspect-ratio`, which also lets `allow-discrete` apply.
- references: https://drafts.csswg.org/css-sizing-4/#aspect-ratio , https://drafts.csswg.org/css-values-4/#combine-ratio . No Chromium file read.
- files: `browser/css/values.aye` (one arm of `parseValue`), `checks-value.aye`, `specified-longhand.aye`, new `aspect-ratio-value.aye`, `write-ratio.aye`; `browser/animation/interpolate-text.aye`, `mixes-text.aye`, new `mix-ratios.aye`, `ratio-of.aye`; new fixture `browser/tests/jsdom/aspect_ratio_values.html` and `.tree` (golden new: the canonical forms, four refused values, `1 / 1` half way between `1 / 2` and `2 / 1`).
