# Q4.25e: the window scrolls the renderer's last frame while the renderer is busy

- goal: with `DWELLER_PROCESS=site` a wheel moves the page at once: the window shifts the renderer's last frame by the wheel and presents it, and the renderer's own frame at the new scroll replaces it when it comes. Before, the scrolled pixels waited for the renderer's task (bbc: up to 5 s).
- source: `docs/plans/cards/Q4.25.md` (c) and (d), row Q4.25e of `foundations.md`.
- slices:
  1. the window shifts the last frame (c2 of Q4.25's note), for pages where that is safe; the strip the frame does not hold shows the page's canvas color. Done, 2026-11-17.
  2. pixels outside the viewport (c1): the renderer paints a taller buffer, so the strip has content.
  3. where it is not safe today (c3): the regions with wheel listeners, fixed and sticky boxes as their own buffer, inner scrollers.
- design, slice 1:
  - IPC: one new message, kind 120 (this lane's range): R→B `scroll_info{max_y, pan, background}`. A tab's top renderer sends it from `paintFrame` (`sayScrollInfo`) when it changes: how far the page scrolls (CSS px), whether the window may shift (`pan`), the canvas color (RGBA). `pan` is 1 while the layout has no fixed or sticky box (`Tree.scrolled` empty) and no wheel of this page was cancelled by a listener or taken by an inner scroller or a frame (`TabRenderer.pan_off`, set in `wheelInput` and `scrollChain`, cleared by a new page). A child renderer never sends it; the browser kills one that does (`unexpected in a frame`). The browser checks it (`takeScrollInfo`: `max_y` finite and not negative, `pan` 0 or 1, else `bad scroll_info`).
  - window: `TabProcess.frame_y` (the scroll of the frame shown, from `frame`), `want_y` (where the window has the page), `max_y`, `pan_ok`, `pan_bg`. `forwardWheel` sends the wheel as before and, when it goes to the tab's top renderer, `panAhead` moves `want_y` by the wheel's `dy`, clamped to 0..`max_y`. `copyTabFrame` copies the shown buffer `tabPan` device px up or down (`want_y − frame_y`, both snapped as the renderer snaps), fills the rows the buffer does not cover with `pan_bg` (`fillPanGap`) and moves the child frames with it. A `frame` sets `frame_y` (`noteFrameScroll`); with no input open it also sets `want_y`, so a script's scroll is followed. The last `input_ack` sets `want_y` to the frame's scroll (`noteInputAcked`): the renderer has the last word, and a wheel it did not use snaps back once (it also turns `pan` off for that page).
  - records: `ui_pan` when a shifted frame is copied, `input_to_pan` from a wheel that moved `want_y` to the window's next present. `window_perf.py scroll` prints `input_to_pan_n_p50_p95`; `report --replay --process site` judges the wheel by it when every wheel was shifted, else by `input_to_frame`.
- Chromium read: `cc/input/input_handler.h` (`ScrollBegin`, `ScrollUpdate` on the compositor thread; `HasBlockingWheelEventHandlerAt` decides when the main thread sees the wheel first), `cc/trees/layer_tree_host_impl.cc` (the scroll moves the pending tree's snapshot; missing tiles are drawn as the background color, `CalculateRenderPasses`). Dweller takes: the window owns the root scroll during a wheel, shows the old pixels moved, and paints the canvas color where it has none.
- files: `browser/ipc/{message,decode,put-payload,from-renderer}.aye`, new `browser/ipc/scroll-info_test.aye`; new `browser/renderer/say-scroll-info.aye`, `browser/renderer/{tab-renderer,adopt-page,paint-frame,scroll-chain,wheel-input}.aye`; new `browser/ui/{take-scroll-info,tab-pan,pan-ahead,note-frame-scroll,fill-pan-gap}.aye`, `browser/ui/{tab-process,renderer-sent,note-input-acked,forward-wheel,copy-tab-frame,note-present,window}.aye`; `browser/tools/{window_perf,window_report}.py`; new `browser/tests/ui/pan_busy.html`, `tests/browser/window_renderer_pan.rs` (and its `mod` pair); `docs/process-model.md` §2 (the input row).
