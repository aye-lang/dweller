# P10.56: css/css-transforms toward its threshold

- goal: WPT area `css/css-transforms` to its 50% threshold. Most failures were in `animation/`: the interpolation files drive every case through CSS Transitions, Web Animations and CSS Animations and read `getComputedStyle`.
- cause groups at start (3633 failing of 5196; this checkout measured 1563/5196, 30.1%, not the 748 of the last table): CSS Transitions of `transform`, `translate`, `rotate`, `scale`, `transform-origin` never started (transitions kept only typed lengths, numbers and colours; ~1400); `none`/`initial` to a transform list or individual transform (~450, every method); `scale`/`translate` with different component counts (~110); composition `add`/`accumulate` (~900); lists with different functions (matrix decomposition, ~300); `svg-matrix` and `svg-origin-*` reftests (~120).
- design: transitions keep owned copies of the text computed values of the transform properties (`mixesText`): snapshots and running transitions own their keyword text (`ownValue`, `freeValue`, `freeValues`, `dropAt`), the current value is mixed text (`mixedAt`) and `currentValue` writes it. One text interpolation (`mixText`) serves transitions and `ak.interpolate`: the existing number-by-number mix; else `none` against a list becomes that list's identity (`identityOf`, `identityArg`: translations, skews and angles 0, scales 1, `matrix`/`matrix3d` identity, rotate axes kept; `perspective` not handled); else `scale`/`translate` with fewer components are padded (`mixPadded`, `padComponents`: translate `0px`, scale y = x, z = 1). Transitions do not touch layout or paint, so P10.51b's damage behaviour is unchanged.
