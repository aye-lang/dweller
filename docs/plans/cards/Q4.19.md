# Q4.19: unchanged frames reuse their display list

- goal: a frame rebuilds the display list only for the documents whose DOM, style or layout changed; an unchanged iframe reuses its previous list (Q4.18 left: on mistral the same-text `textContent` write into one `<p>` of the top document rebuilds the list of the whole tab, 6 builds a frame, 4.1 ms of the 5.0 ms `ui_relayout`). Then, if simple and safe, rebuild only the changed subtree of the changed document.
- profile (before, confirmed): `browser/build.sh` (safe) build of 751b401e (origin/main + #297, which has Q4.17's code), mistral replay, `window_perf.py idle` with `DWELLER_TIMING=1 --log`, through `scripts/capped.sh` (`target/q419-prof-before.log`). Steady frames (60 onwards), medians: `paint_build` records 6 a relayout frame (mean 6.81), `paint_build` 4.18 ms, `ui_relayout` 5.11 ms, `ui_loop` 29.2 ms. As Q4.18 said. The 4.18 ms counts each iframe twice: an iframe's `paint_build` runs inside the top document's.
- design:
  - The window's `PageView` keeps a `paint.FrameLists`: the display list of each iframe (frame document) it painted in the last build. `buildPromoted` takes it, the window's `Builder.subframe` asks `cachedFrame` for the iframe's list, and after the build `dropUnused` frees the lists that no frame used. Plain `paint.build` (shots, dumps, nested frames inside a frame's list) has no cache and builds as before.
  - A list is reused only when all three match: the same `Tree` pointer; the same `FrameView.stamp`, which `engine.layoutFrames` sets to `treeVersion(f.page)` (DOM version, image version, nested frames, navigation); and the same `framePrint` of the frame's tree. `framePrint` hashes the tree's `serial` (new `Tree.serial`, a counter set at `layoutDocumentWith`, so a new tree at a freed tree's address never matches), its viewport, `scroll_y`, each box's place, size, style and text pointers, every bitmap of its `Images` (pointer, `shown()`, pixels pointer and length, generation: covers decodes, evictions, canvas and WebGL frames, `settleCanvases`), and, recursively, its nested frames (tree, stamp, scroll). Anything that moves none of these leaves the pixels the same; anything that moves one rebuilds.
  - The cached list is copied into the parent's list as before (`frameItems`: clip, canvas color, items moved by the frame's place and scroll), so damage signatures are unchanged and an unchanged frame raises no damage.
  - The subtree splice inside the changed document was not done: the display list is a flat item list in paint order, with layers sorted by z-index and promoted groups, and no item knows its box, so a box's items cannot be found and replaced in place without per-box item ranges (see left).

Dweller takes the subsequence idea at the frame level: a frame document whose inputs did not change reuses its whole cached item range, keyed by its own versions instead of per-client invalidation flags.

## Status: done, 2026-11-08

- left:
  - Subtree splice in the changed document: the top document's own list is still built in full (1.8 ms a frame on mistral). It needs paint to record each box's item range (and its layer's place in the z-order) so that a box whose layout and style did not move keeps its items; the per-box change tracking would come from `paintChanges` / `layout_dirty`. A card of its own.
  - Idle CPU stays at 99%: the frame time is the page's rAF script (`ui_raf` about 28 ms). This card saves about 1 ms of `ui_relayout` a frame.
  - `framePrint` walks every box of each frame each build. On mistral it is well under the 1.1 ms saved, but it was not timed on its own. Time it if a page has very large iframes.
  - No Aye unit test for `framePrint` or `cachedFrame`: paint has no helper that builds a laid-out `Tree` in a unit test. The window test covers both.
