# Q4.16f: spec-correct `Array.prototype.concat`, so core-js keeps the native

- goal: on bbc, core-js (`cdn.privacy-mgmt.com/unified/wrapperMessagingWithoutDetection.js`) replaces `Array.prototype.concat` with its JavaScript polyfill because the native fails its feature test (Q4.16a: the polyfill was 283 ms, 5.2% of bbc's JS). Make the native follow ECMA-262 and keep a native fast path for plain arrays.
- the failing feature test (core-js `es.array.concat`, in the bbc archive; `V8_VERSION` from the user agent is below 51, so both run): `forced: !m || !v` with
  - `m`: `var e = []; e[Symbol.isConcatSpreadable] = false; return e.concat()[0] !== e` must be false. Dweller spread every array, so `[0]` was the array's first element (undefined).
  - `v` (`arrayMethodHasSpeciesSupport('concat')`): `var t = []; (t.constructor = {})[Symbol.species] = function () { return {foo: 1} }; return t.concat(Boolean).foo !== 1` must be false. Dweller always made a new Array.
  - Both failed (`target/dweller js` before: `core-js polyfills concat`).
- design:
  - `arrayConcat` (`browser/js/builtins_array.aye`) first runs `concatIsPlain`, a check without side effects: `this` is an Array whose prototype is `Array.prototype` and has no own `constructor`; `Array.prototype.constructor` is a data property that is `%Array%`; `Array[@@species]` is still the original getter; no object in the chain of `this` or of an object argument is a Proxy or has an own `@@isConcatSpreadable`. Then the old copy loop runs; a hole reads through the prototype (`concatElem`), so `Array.prototype[1] = x` shows in the result as the spec says.
  - Otherwise `concatSlow` calls `browser/js/array-concat.js`, the spec algorithm in JavaScript (ArraySpeciesCreate, IsConcatSpreadable, LengthOfArrayLike, the 2^53 − 1 checks, CreateDataPropertyOrThrow through `Object.defineProperty`, `Set(A, "length")` in strict mode). Its function is kept as a root in `Interp.concat_slow`.
  - New `Interp` fields: `sym_species`, `sym_is_concat_spreadable` (the well-known symbols' atoms), `array_ctor`, `array_species_get` (the original getter, rooted), `concat_slow`.
- files: `browser/js/builtins_array.aye`, `interp.aye`, `symbol.aye`, `install-spec-scripts.aye`; new `browser/js/array-concat.js`, `concat-is-plain.aye`, `plain-array-constructor.aye`, `no-spreadable.aye`, `concat-elem.aye`, `concat-slow.aye`, `install-concat.aye`; test `browser/tests/js/281_array_concat_spec.{js,out}` (the two core-js tests print `native is fine`; array-like spreadable, holes, subclass species, primitive `this`, a prototype element, a non-constructor species).
- references: ECMA-262 https://tc39.es/ecma262/#sec-array.prototype.concat ; v8 `src/builtins/builtins-array.cc` (`BUILTIN(ArrayConcat)`, `Fast_ArrayConcat`, `Slow_ArrayConcat`). Dweller takes V8's split: a fast path behind the `IsConcatSpreadableLookupChainIntact` and `IsArraySpeciesLookupChainIntact` conditions (checked per call on the objects, as Dweller has no protector cells) and the spec algorithm for everything else.
