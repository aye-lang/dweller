# Q4.15b: Q4.10 and Q4.15 measured on W7

- goal: measure what Q4.10 (#279, image decode off the main thread, 256 MB decoded-image budget) and Q4.15 (#283, the window redraws only damaged rects) did to W7 on bbc, zol, mistral and react, and say whether mistral's idle raster (2193 ms per 10 s in the Q4.1 profile) came from the whole-window redraw or from its canvas. Measurement only; no engine change.
- method: two `browser/build.sh` (safe) builds: 87f4863 (before #279) and 2f29716 (main with #279 and #283), worktrees `q4-15b-before` and `q4-15b`, `target/sites` linked to the shared archives. `scripts/capped.sh python3 browser/tools/window_perf.py report --replay --site bbc --site zol --site mistral --site react`, 3 runs of each build, one after the other (logs `target/q415b-w7-*.log`). For mistral also one `idle` and one `scroll` run per build with `DWELLER_TIMING=1 DWELLER_LAYOUT_WHY=1 --log` (`target/q415b-idle-*.timing`, `q415b-scroll-*.timing`), summed over the last 10 s of loop iterations.
- results: `browser/engine/PERF.md`, section "Q4.15b: Q4.10 and Q4.15 on W7 (2026-11-08)". In short, medians of 3 (loop ms / scroll p95 ms / idle): bbc 578 → 568 / 502 → 490 / 0.3%; zol 810 → 811 / 561 → 528 / 13.4 → 13.9%; mistral 1409 → 1562 / 366 → 346 / 99.2 → 99.3%; react 117 → 119 / 51.0 → 51.3 / 0.6 → 0.5%. No row changes between pass and fail.
  - Q4.10: mistral main-thread `image_decode` 1097 → 3 ms; p95 366 → 346 ms. The longest loop rose to 1562 ms because the load iteration (first paint 1050 ms, page script 784 ms) is now the longest, not an image task.
  - Q4.15: no change in idle. Mistral's idle raster is the page's canvas: every frame has one page damage rect of 482804 px (61% of the window) in both builds, `ui_draw` 3573 → 3480 ms per 10 s. The window redraw is not the cause.
  - Spread: under 10% except mistral before p95 (361–412) and zol idle (12.4–14.8%). Runs were sequential under capped.sh.
