# Q6.12: WPT css/css-animations

- goal: `css/css-animations` from 50.7% (713/1405) to the 60% threshold.
- cause, by cluster of the 692 failing subtests (`conformance.py run css/css-animations`): `text-decoration-inset-auto` 84 (property missing); `animation-range`, `animation-range-start`, `animation-range-end` (no such properties, ~190 with the shorthand and `animation-timeline` reset); the inline style (`e.style[p] = v`) accepted any text for the `animation-*` and `transition-*` longhands and the `animation` shorthand (every `*-invalid.html`, ~70); `e.style[longhand]` empty after a shorthand was set (the `test_shorthand_value` files); `@keyframes` with an invalid name stayed in `sheet.cssRules` (20).
- design:
  - `checksValue` (checks-value.aye) now covers the `transition-*` and `animation-*` longhands, so the inline setter runs them through `parseValue` like other typed longhands.
  - `animation-timeline` (reset-only, `auto`), `animation-range-start` and `animation-range-end` are appended to `PROPERTIES` (ids 179-181, `gen_property_ids.py`). The two range longhands are `PKind.Layers`, so `em` and `calc()` resolve at computed-value time through the existing layers path. `animationRangeValue` validates and canonicalises each comma layer (`<timeline-range-name>? <length-percentage>?`, `normal`; a default offset, `0%` for start and `100%` for end, is dropped).
  - `animation-range` shorthand: `addAnimationRange` splits each item into a start and an optional end (`rangeStartLength`), end defaults to the start's range name or `normal`; `writeAnimationRange` serialises (end omitted when implied); `getComputedStyle().animationRange` and the inline setter use it. The `animation` shorthand lists 11 longhands and resets the three new ones.
  - Inline shorthands `animation`, `transition` and `animation-range` are validated by `specifiedShorthand` (parse in a scratch sheet, drop when it declares nothing).
  - `shorthandLonghandText`: `style.getPropertyValue(longhand)` / `style[longhand]` reads the value a shorthand declaration in the style attribute gives it (uses the existing `shorthandValue`); later declarations win.
  - CSSOM shim (prelude.aye `validRule`): an `@keyframes` rule with an invalid name (CSS-wide keyword, `none`, `default`, number, empty string) is not in `cssRules`.
- references: `third_party/blink/renderer/core/animation/css/css_animations.cc` (read; Dweller takes from it the grammar and the rule that a name with a CSS-wide keyword or `none` is not a `<keyframes-name>`); parse and serialisation follow css-animations-1 and scroll-animations-1 `animation-range`.
- files: `browser/css/add-animation-range.aye`, `animation-range-value.aye`, `write-range-layer.aye`, `write-range-offset.aye`, `write-named-offset.aye`, `write-range-pair.aye`, `range-start-length.aye`, `write-animation-range.aye`, `range-end-implied.aye`, `specified-shorthand.aye`, `shorthand-longhand-text.aye`, `covers-longhand.aye` (new); `css.aye`, `property-ids.aye`, `values.aye`, `add-animation.aye`, `checks-value.aye`, `specified-value.aye`, `engine/dom_api.aye` (`styleValue`), `engine/window_api.aye`, `engine/prelude.aye`.
