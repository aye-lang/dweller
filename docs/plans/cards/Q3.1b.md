# Q3.1b: each `file:` document is cross-origin to every other

- goal: two `file:` documents cannot script each other, and a `file:` page cannot `fetch`/XHR a `file:` URL, as in Chromium. A `file:` page still loads its own `<script src>`, `<link>`, `<img>` (no-cors loads), `localStorage` still works.
- design (what Chromium really does, not "opaque origin" in the `url::Origin` sense):
  - `url::Origin` of a `file:` URL is a tuple origin that serializes as `file://`; Blink's `SecurityOrigin` calls `BlockLocalAccessFromLocalOrigin` by default (`allow_file_access_from_file_urls` false): `IsSameOriginWith` fails between two `file:` documents (`PassesFileCheck`), and the origin serializes as `null` (`SerializesAsNull`). It is not opaque: `CanAccessLocalStorage`, `CanAccessCookies` and the rest are `!IsOpaque()`, so `localStorage` keeps one area for the storage key `file://`, shared by all `file:` pages.
  - Dweller: `sameOrigin` (engine/windows.aye, the scripting check) is false between two different `file:` documents (same document, and `about:blank`/`srcdoc` frames of it, stay same-origin). `location.origin` was already "null" for `file:`.
  - `fileFetchRefused` (engine/file-fetch-refused.aye): `fetch` and XHR of a `file:` URL from a `file:` page fail as a network error (Chromium: "URL scheme file is not supported"). Subresources by element (script, style, image, font, worker script) are no-cors loads and still work; navigations and iframes of `file:` URLs still load.
  - `localStorage`/`sessionStorage`: unchanged. Storage events between `file:` pages use `sharesStorage` (engine/shares-storage.aye: both `file:`, else `sameOrigin`) because the area is shared although the pages are not same-origin.
  - Cookies: unchanged (net has no cookie for `file:` hosts; Chromium also does not store cookies for `file:` by default).
  - Site lock (`DWELLER_PROCESS=tab|site`): unchanged, one `file:` site (`ui/write-site.aye` gives "file:" to every `file:` URL), as Chromium's all-file site lock; the documents inside are cross-origin. `window_renderer_sites` and `window_session_restore_after_kill` pass.
  - `DWELLER_ALLOW_FILE_ACCESS_FROM_FILES=1` (engine/file-access-from-files.aye, Chromium's `allow_file_access_from_file_urls`) gives the old shared origin and allows `file:` fetch/XHR; `jsdom_fixtures` sets it, since its pages `fetch('scripts/items.json')` and frame `iframe_child.html` from `dump` of a file (they test the fetch API and DOM, not origins).
- fixtures: `agent_sessions`'s `frame_scripts` moved to `browser/tests/agent/http/` (run by `agent_forms_http` against the test server, `$BASE/frames/iframe_nav.html`: one http origin). `storage_between_tabs` needed no move (storage events fixed in code). `no_file_from_web`'s `file:` expectation now has `fetch TypeError` and `xhr error` (a `file:` page cannot read a file by script).
- references:
  - `third_party/blink/renderer/platform/weborigin/security_origin.cc` (`PassesFileCheck`, `SerializesAsNull`): Dweller takes the file/file scripting block and the "null" serialization.
  - `third_party/blink/renderer/platform/weborigin/security_origin.h` (`CanAccessLocalStorage` is `!IsOpaque()`): Dweller keeps `localStorage` on `file:`.
  - `url/origin.cc` (`Origin::Serialize`, `file://`): the storage key stays `file://`.
- files: `browser/engine/{windows,window_api,storage}.aye`, `browser/engine/{file-fetch-refused,file-access-from-files,shares-storage}.aye`, `browser/tests/file-origin/`, `browser/tests/agent/http/frame_scripts.{jsonl,out}`, `browser/tests/frames/iframe_nav.html`, `tests/browser/{security,jsdom}.rs`
