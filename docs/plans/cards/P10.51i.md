# P10.51i: form states and sibling sets restyle locally

- goal: (1) a checkbox click or an edit in a field restyles only the control and the elements whose selectors see its state (`:checked`, `:placeholder-shown`, `:valid`/`:invalid`), with no full restyle or layout; (2) hover in iframes restyles locally in the frame; (3) `Transitions.frames` stays bounded; (4) sibling invalidation sets (`+`/`~` after the state compound). P10.51h's "left" list.
- design:
  - `css.FORM_STATE_CHANGED` (`what` 6; `nameKey` now clear of 0..6) is a pointer-like state change (`isPointerState`). `stateKey` maps `:checked`, `:placeholder-shown`, `:valid`, `:invalid` to it, so `RestyleDeps.states` holds their uses; `simpleKeys` adds it to `:checked` and `:placeholder-shown` (next to their attribute keys) so a sibling use marks it deep.
  - `controlInput` (one control's part of `controlInputs`, split out) and `controlsInput` (the sum over some controls). `Controls.noted_inputs`: `controlInputs` subtracts it, and `noteFormStates` adds `after - before` for the controls it notes, so a noted change keeps `Geometry.controls` equal and an un-noted change still unshares the layout (full restyle and layout, as before).
  - `noteFormStates` (with a script): bumps `pointer_styled` (the non-shared path still restyles), notes `FORM_STATE_CHANGED` at each control, its `form`/`fieldset` ancestors and its form owner where a use can match (`noteFormOwners`, `stateMatters`), and `CHILDREN_CHANGED` at a text field (its box shows the value and is built again). `setCheckedNoted` (activation of a checkbox/radio: the radio group) and `fieldInput`/`noteFieldEdit` (typed text, Backspace/Delete in `fieldKey`) call it.
  - `Page.restyle` returns at once when the layout is shared and current (`sharesStyles`, also used by `layoutShared`): `layoutShared` restyles the noted changes, and anything un-noted falls back there.
  - Sibling sets: `StateUse.siblings` when the combinator right after the state compound is `+`/`~`; `stateRoots` then roots the following siblings that have the subject feature and their matching descendants (`addMatchingSiblings`). A sibling combinator further right (`form:invalid div + p`) stays inside the element's subtree and uses the descendant path; nested uses and `::slotted`/`::part` stay `around`.
