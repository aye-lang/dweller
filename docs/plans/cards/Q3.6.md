# Q3.6: X-Frame-Options and CSP `frame-ancestors`

- goal: a document response that is about to commit into a frame (`iframe`, `frame`, also after a link, form or `location` navigation of the frame) is checked against its `X-Frame-Options` and its enforced CSP `frame-ancestors`. A refused document is replaced by an error document of an opaque origin (no `contentDocument`; the frame's `load` event still fires) and the parent's console gets an error. WPT `x-frame-options` and `content-security-policy/frame-ancestors` become measured areas.
- design:
  - `net.parseFrameOptions` (`net/parse-frame-options.aye`, `net/frame-options.aye`): the spec's "check a navigation response's adherence to X-Frame-Options" on the raw header lines: every `X-Frame-Options` field line is split on commas and trimmed of HTTP whitespace, the values compare ASCII case-insensitively as a set; more than one distinct value with `deny`, `sameorigin` or `allowall` among them is `Conflict` (blocks), more than one without them is `Allow`, one value `deny` is `Deny`, `sameorigin` is `SameOrigin`, anything else is `Allow`.
  - `csp.frameAncestorsRefusal` / `csp.hasFrameAncestors` (`csp/`): reuse Q3.7's `directiveOf`, `sourceList`, `nextWord` and `sourceMatchesUrl`. Each ancestor is matched as its origin (the path is empty, so a source with a path matches nothing, as WPT `frame-ancestors-path-ignored` wants); `'self'` is the framed response's URL and never matches an ancestor of an opaque origin (a sandboxed one); `'none'` matches nothing.
  - `Page.header_csp` (header values only: a `<meta>` policy cannot carry `frame-ancestors`; `Content-Security-Policy-Report-Only` is never read, so it never blocks) and `Page.frame_options` are set by `pageOf` from the response. `placeChecked` (`engine/place-checked.aye`) replaces `placeFrame` in `framedDocument` (the frame loads of a page) and `showInFrame` (navigations of a frame): `framingRefusal` picks CSP when the response has an enforced `frame-ancestors` (it overrides XFO), else XFO; `SAMEORIGIN` and `frame-ancestors` walk every ancestor (`originPage`, so a srcdoc or blank parent counts as its creator). A refusal logs `[error] Refused to display 'URL' in a frame because it set 'X-Frame-Options' to 'deny'.` (also `'sameorigin'`, or `multiple ... conflicting values.`) or `Refused to frame 'URL' because an ancestor violates the following Content Security Policy directive: "frame-ancestors ...".` on the parent, and shows `errorPage` with `SB_ORIGIN | SB_SCRIPTS` so scripts do not run and the origin is opaque.
  - tab mode: frames are loaded by the engine inside the renderer (Q2.6a Left: navigations in frames stay in the renderer), through the same `framedDocument`/`showInFrame`, so the check runs there too; the browser process sees none of it.
  - test server: `browser/tests/server.py` serves `csp/NAME.headers` (lines `Name: value`) as extra response headers beside `NAME.policy`.
- references: https://html.spec.whatwg.org/multipage/document-lifecycle.html#the-x-frame-options-header , https://w3c.github.io/webappsec-csp/#frame-ancestors-navigation-response . Read: `content/browser/renderer_host/ancestor_throttle.cc` (frame-ancestors overrides XFO; XFO checked against every ancestor; the blocked frame commits an error page and the parent logs), `services/network/public/cpp/x_frame_options_parser.cc` (value parsing, conflict and invalid rules). Dweller takes: the decision order and the value rules; the check sits where the engine commits a frame.
